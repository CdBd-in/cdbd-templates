## 🎨 3토큰 색 매핑 — 검증된 코드 (D4가 그대로 쓴다)

프리셋의 hex는 **역할 자리표시자**다. 아래가 실제로 작동한 구현 (2026-07-16 A②-안1 검증: fills 17 · strokes 6 · **textRuns 40**).

```js
const hex2rgb = h => { h=h.replace('#',''); return {r:parseInt(h.slice(0,2),16)/255, g:parseInt(h.slice(2,4),16)/255, b:parseInt(h.slice(4,6),16)/255}; };
const rgb2hex = c => '#'+[c.r,c.g,c.b].map(v=>Math.round(v*255).toString(16).padStart(2,'0')).join('');
const MAP = { '#fafafa': TOK.bg, '#292929': TOK.tx, '#6c4cff': TOK.btn };
const mapPaint = p => {
  if (p.type !== 'SOLID') return null;
  const t = MAP[rgb2hex(p.color)];
  return t ? Object.assign({}, p, { color: hex2rgb(t) }) : null;   // ⚠️ opacity 보존 (틴트가 죽는다)
};
for (const n of [root, ...root.findAll(()=>true)]) {
  if (n.type === 'TEXT') {                       // 🚨 텍스트는 반드시 런별로
    for (const s of n.getStyledTextSegments(['fills']))
      if (s.fills.some(mapPaint)) n.setRangeFills(s.start, s.end, s.fills.map(p => mapPaint(p) || p));
  } else if (Array.isArray(n.fills) && n.fills.some(mapPaint)) n.fills = n.fills.map(p => mapPaint(p) || p);
  if (Array.isArray(n.strokes) && n.strokes.some(mapPaint)) n.strokes = n.strokes.map(p => mapPaint(p) || p);
}
```

🚨 **런별 처리 필수** — 한 텍스트에 색이 섞이면 `node.fills === figma.mixed` → `Array.isArray(n.fills)`가 **false** → **조용히 건너뜀**. (A① 안2 프로그램 퍼플 잔존 사고)

### 🚨 #1 좌우 여백 — 값으로 거르지 말고 **폭으로** 거를 것

```js
// ❌ 재발한 실패: if (n.paddingLeft === 20) → 16·24인 프레임을 건너뜀
// ✅ 카드 = 폭 380 (검증됨: w=380 카드 / w=340 프리셋 내부 → 내부는 건드리지 않는다)
if (n.paddingLeft !== undefined && n.width >= 379 && (n.paddingLeft > 0 || n.paddingRight > 0)) {
```

🚨 **예외 — 비대칭 큰 padding = 「여백」이 아니라 「폭 제약」** (2026-07-16 A④-안2 D3 자기 발견)
> **폭 가드가 구분선 프레임의 `paddingRight: 300`을 여백으로 오인**해 20으로 바꿨더니, 바가 `FILL`이라 **60×3 액센트바가 340×3 구조선으로 변질**됐다 — **#8이 금지하는 「한 페이지 = 한 언어」 위반을 통일 코드가 스스로 만든 것.**

- **판별**: 자식이 `FILL`인 얇은 바(높이 ≤4)이고 `paddingLeft`↔`paddingRight`가 **크게 비대칭**(예: `20/300`)이면 → 그 padding은 **바 길이를 정하는 수단**이다. **건드리지 말 것.**
- 같은 수법이 **짧은 중앙 구분선**에도 쓰인다(CLAUDE.md 4단계 팁: `padding: "20px 150px"` → 중앙 64px 라인).
- ✅ 통일 대상은 **카드 좌우 여백**이지 **바 길이**가 아니다.

### 〰️ #8 구분선 — 한 페이지 = 한 언어

- **판정**: 그 선을 쓰는 **(예외 아닌) 섹션이 2개 미만 = 기본 언어 ❌ → 제거** (또는 다른 섹션에 확장해 언어로). **애매하면 제거가 기본값.**
- **예외 = 위치**(섹션 종류 ❌): **최상단**(히어로·직후 섹션 = 강조 허용) · **최하단**(푸터 = 영역 경계선). 위치마다 **1개 언어까지**.
- **0개도 완전 통일** (미니멀 계열).
- ℹ️ **나열 항목 사이 구분선 = 프리셋 내부 구조**(항목↔항목)이지 강조선이 아니다 → 「2개 미만」 판정 대상 밖. 단 그것이 페이지의 **유일한** 선이면 그게 곧 그 페이지의 언어이므로 다른 선을 추가하지 말 것.

### R23. 📐 섹션 간 거리 측정 — 섹션 배경 채움이 오차를 만든다 (필수)

## 🔄 R25~R27 — 이선호 결정 반영 (2026-07-20 2차)

### R25. ✍️ 빈칸은 남기지 말고 **새로 구성해 채운다** (필수 · 기존 「창작 금지」 뒤집음)

- **답변에 없는 내용도 새로 구성해서 추가**한다. 시안은 유저에게 보여주는 완성된 그림이어야 하므로 빈칸·자리표시 문구가 남으면 안 된다.
- 근거: 1-9 유저 플로우 ③ — **「빈칸은 AI가 예시·기본값으로 채움」**이 제품 사양이다.
- 단 **주제·업종에 모순되지 않는 그럴듯한 값**으로. (예: 이자카야 영업시간 = 저녁~새벽)
- 유지되는 것: **3안은 같은 콘텐츠 팩**(R13) — 한 안에서 지어낸 값은 **3안 모두 동일하게** 반영.

### R28. 🧩 「섹션 래퍼 = 증발」을 기계적으로 적용하지 말 것 (2026-07-20)
「섹션 래퍼 auto-layout `paddingBottom`은 평탄화 시 증발」은 **래퍼가 여러 카드를 묶고 있을 때** 이야기다.
- **자식이 1개뿐인 섹션 래퍼 = 그 카드 자체** → 그 패딩은 **CdBd 카드의 내부여백**이라 증발하지 않는다. 옮기려 들면 오히려 망가진다.
- 판별: `section.children.length === 1` 이고 그 자식이 실제 콘텐츠(버튼·텍스트)면 **래퍼가 곧 카드**.

- 🔗 연결: **채움 있는 카드의 내부 하단 여백은 「여백」이 아니라 「색 면적」**이다. 색 깔린 버튼·틴트 카드 뒤 간격은 반드시 **그 카드 바깥**에서 만들 것.
