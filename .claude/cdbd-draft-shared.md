## 🎨 3토큰 색 매핑 — 검증된 코드 (D4가 그대로 쓴다)

프리셋의 hex는 **역할 자리표시자**다. 아래가 실제로 작동한 구현 (2026-07-16 A②-안1 검증: fills 17 · strokes 6 · **textRuns 40**).

```js
const hex2rgb = h => { h=h.replace('#',''); return {r:parseInt(h.slice(0,2),16)/255, g:parseInt(h.slice(2,4),16)/255, b:parseInt(h.slice(4,6),16)/255}; };
const rgb2hex = c => '#'+[c.r,c.g,c.b].map(v=>Math.round(v*255).toString(16).padStart(2,'0')).join('');
const MAP = { '#fafafa': TOK.bg, '#292929': TOK.tx, '#6c4cff': TOK.btn };
const mapPaint = p => {
  if (p.type !== 'SOLID') return null;
  const t = MAP[rgb2hex(p.color)];
  return t ? Object.assign({}, p, { color: hex2rgb(t) }) : null;   // ⚠️ opacity 보존 (틴트가 죽는다)
};
for (const n of [root, ...root.findAll(()=>true)]) {
  if (n.type === 'TEXT') {                       // 🚨 텍스트는 반드시 런별로
    for (const s of n.getStyledTextSegments(['fills']))
      if (s.fills.some(mapPaint)) n.setRangeFills(s.start, s.end, s.fills.map(p => mapPaint(p) || p));
  } else if (Array.isArray(n.fills) && n.fills.some(mapPaint)) n.fills = n.fills.map(p => mapPaint(p) || p);
  if (Array.isArray(n.strokes) && n.strokes.some(mapPaint)) n.strokes = n.strokes.map(p => mapPaint(p) || p);
}
```

🚨 **런별 처리 필수** — 한 텍스트에 색이 섞이면 `node.fills === figma.mixed` → `Array.isArray(n.fills)`가 **false** → **조용히 건너뜀**. (A① 안2 프로그램 퍼플 잔존 사고)

### 🐛 토큰 미매핑 색 = 「기준 1 테마 적응성」 위반 (매 조합마다 검사)

매핑 안 된 SOLID hex를 **집계해서 리포트**한다. 남은 색이 곧 위반 후보. (2026-07-16 이 검사로 **40개** 적발)

**알려진 정상 (무시)**: `#d7d7d7` 이미지 placeholder · `#8c8c94` placeholder 라벨 · `#fc2c19` **CdBd 폼 필수 별표(default 기능)** · `#e8e8e8` 서랍 셀 배경.
**그 외 hex가 남으면 = 버그** → 라이브러리 원본을 고치고(원본이 정본) 시안에 동기화. 발견 이력 = [[1-8. 섹션 프리셋 라이브러리]] 「🐛 하드코딩 색」.

// ❌ 재발한 실패: 이미 0(각진)인 카드를 건너뛰어 각진 카드가 잔존

### 🚨 #1 좌우 여백 — 값으로 거르지 말고 **폭으로** 거를 것

```js
// ❌ 재발한 실패: if (n.paddingLeft === 20) → 16·24인 프레임을 건너뜀
// ✅ 카드 = 폭 380 (검증됨: w=380 카드 / w=340 프리셋 내부 → 내부는 건드리지 않는다)
if (n.paddingLeft !== undefined && n.width >= 379 && (n.paddingLeft > 0 || n.paddingRight > 0)) {
  if (isBarWidthConstraint(n)) continue;          // ⚠️ 아래 예외 필수
  n.paddingLeft = LR; n.paddingRight = LR;
}
```

🚨 **예외 — 비대칭 큰 padding = 「여백」이 아니라 「폭 제약」** (2026-07-16 A④-안2 D3 자기 발견)
> **폭 가드가 구분선 프레임의 `paddingRight: 300`을 여백으로 오인**해 20으로 바꿨더니, 바가 `FILL`이라 **60×3 액센트바가 340×3 구조선으로 변질**됐다 — **#8이 금지하는 「한 페이지 = 한 언어」 위반을 통일 코드가 스스로 만든 것.**

- **판별**: 자식이 `FILL`인 얇은 바(높이 ≤4)이고 `paddingLeft`↔`paddingRight`가 **크게 비대칭**(예: `20/300`)이면 → 그 padding은 **바 길이를 정하는 수단**이다. **건드리지 말 것.**
- 같은 수법이 **짧은 중앙 구분선**에도 쓰인다(CLAUDE.md 4단계 팁: `padding: "20px 150px"` → 중앙 64px 라인).
- ✅ 통일 대상은 **카드 좌우 여백**이지 **바 길이**가 아니다.

### 〰️ #8 구분선 — 한 페이지 = 한 언어

- **판정**: 그 선을 쓰는 **(예외 아닌) 섹션이 2개 미만 = 기본 언어 ❌ → 제거** (또는 다른 섹션에 확장해 언어로). **애매하면 제거가 기본값.**
- **예외 = 위치**(섹션 종류 ❌): **최상단**(히어로·직후 섹션 = 강조 허용) · **최하단**(푸터 = 영역 경계선). 위치마다 **1개 언어까지**.
- **0개도 완전 통일** (미니멀 계열).
- ℹ️ **나열 항목 사이 구분선 = 프리셋 내부 구조**(항목↔항목)이지 강조선이 아니다 → 「2개 미만」 판정 대상 밖. 단 그것이 페이지의 **유일한** 선이면 그게 곧 그 페이지의 언어이므로 다른 선을 추가하지 말 것.

## 🔒 통일의 경계 — 어디까지 손대나 (D3 필수)

| ✅ 통일 대상 | 🔒 프리셋 정본 (건드리지 ❌) |
|---|---|
| **섹션 간** 여백 (= 마지막 카드 하단) | **프리셋 내부** 간격 — 타이틀↔구분선 · 구분선↔본문 · 항목↔항목 |
| **섹션 타이틀↔본문** 거리 — **구분선 없는 섹션만** | **구분선이 낀 섹션**의 타이틀↔본문 (그 사이가 내부 관계) |
| 8항목 | 프리셋 고유 레이아웃·구조 |

- **🔀 교차 사용 허용 — 같은 서랍 안에서만**: A 프리셋 타이틀 + B 프리셋 본문 = OK (둘 다 그 서랍에 **실재**하므로 창작 아님). **위계를 만드는 주요 수단.** ⚠️ 서랍 건너뛰기 ❌(미니멀 타이틀 + 볼드 본문 = 스타일 정의 붕괴).
- **🚫 창작 금지**: 타이틀 **크기·정렬·색 역할**은 **그 서랍에 실재하는 값**만. 조사법 = 해당 스타일 섹션의 TEXT를 `getStyledTextSegments(['fontSize','fontName'])`로 **집계 → 빈도순**.
  - 🔴 실패: `11px`·`16px {텍스트색}`·`20px` = 어느 서랍에도 없는 창작. 실측 = `12/14/18/22px · Bold · LEFT|CENTER`.
  - ℹ️ **서체는 예외** — 무드 교체 대상이라 창작 아님.
  - ⚖️ **「축별」이냐 「조합별」이냐 — 해석 확정 (2026-07-16 · D5가 충돌 발견)**
    > D5 스펙은 *"실재하지 않는 값"*(축별), 이 문서는 *"실재하는 조합만"*(조합별)이라 **서로 달랐다.** 조합별로 읽으면 **🔀 교차 사용(A 프리셋 타이틀 + B 프리셋 본문)과 정면 충돌**한다 — 교차 사용 자체가 「원본에 없던 조합」을 만드는 행위이기 때문.
    - ✅ **하드 게이트 = 축별** — `크기`·`정렬`·`색 역할` **각각이 그 서랍에 실재**하면 통과. (기록된 실패 `11/16/20px`는 전부 **크기 축**이라 이 해석으로 전부 잡힌다)
    - 💡 **권장 = 조합 실재 우선** — 같은 축 값을 쓸 수 있는 **실재 조합이 있으면 그걸 쓴다**. 예: 미니멀에 `22|Bold|CENTER|{텍스트색}`가 **7회** 실재하면 `22|Bold|CENTER|{버튼색}`(0회)보다 **전자를 쓴다**.
    - 🚨 **빈도 0인 조합을 쓸 땐 이유를 남길 것** — D5가 `PLAUSIBLE`로 올린다(하드 실패 ❌).
- **📐 타이틀↔본문 거리 = 「타이틀 하단 여백 + 본문 첫 카드 상단 여백」** — 둘을 **각각 페이지에서 한 값(PAD)**으로 → 시각 = 2×PAD. **역산만 하면 ❌**(카드 하나 지우면 리듬 붕괴 = 최우선 원칙 위반).
  - 측정: ⓵타이틀에서 위로 올라가 **섹션 직계 조상** 찾기 ⓶**다음 형제**(보이지 않는 형제는 건너뜀) ⓷**시각적 상단** ⓸`absoluteBoundingBox`로 역산(2~3패스).
  - 👁 **「보이는 것」** = TEXT · 채움 있는 박스 · **테두리만 있는 박스(채움 없어도!)** · 높이 ≥1.
- 🧹 **구조 찌꺼기 금지** — 요소를 지우면 **껍데기 래퍼도 함께** 제거(빈 래퍼 패딩이 거리를 밀고 측정까지 깨뜨림).

> ### 🚨 안1이 남긴 진짜 교훈 3개 (전부 이 문서의 규칙을 쓴 당사자가 어긴 것)
>
> 1. **틴트로 강약을 만들 땐 「섹션 경계가 살아있는지」 확인** — 폼·위치를 **인접한 채로 둘 다 틴트**했더니 두 패널이 맞붙어 **시각 간격 0px · 952px 한 덩어리**가 됐다. #5(인셋 카드 통일)를 지키려다 #3(섹션 간 여백)을 죽인 것. → **틴트 카드는 서로 떨어뜨리거나, 붙을 거면 경계를 다른 수단으로.**
> 2. **틴트를 「래퍼」에 걸지 말 것** — 위치안내 래퍼(카드 2장 묶음)에 배경+하단여백을 걸었다. **평탄화하면 둘 다 증발한다**(이 문서가 명시한 바로 그 함정). → **각 카드에 개별 부여** + 외부여백 0 → 카드들이 맞붙어 연속 띠.
> 3. **값 통일 ≠ 시각 균일** — `lastPadB`는 32로 완벽히 통일됐는데 **시각은 `52·40·58·32·0·20·62`로 붕괴**. 틴트가 여백을 삼켜서다. → **값만 재고 끝내지 말고 `absoluteBoundingBox`로 시각 거리도 잴 것.**
>
> 🥇 **비교**: 안3은 같은 틴트를 쓰고도 시각 `58×6 + 푸터 32`로 균일하다 — **틴트 카드가 섹션마다 떨어져 있고, 래퍼가 아니라 카드에 걸려 있기 때문.**

## 🔁 조합하면 매번 나오는 문제 4가지 (2026-07-16 A①·A② 연속 확인)

> **프리셋을 붙이면 반드시 이 4개가 나온다.** D3는 이걸 **체크리스트로** 돌 것 — 「나오면 고친다」가 아니라 **「나온다고 가정하고 찾는다」**.

1. **여백 카드 잔존** (`이름에 '여백'` + 높이 ≤1) → **제거**, 섹션 간 여백은 마지막 카드 하단으로.
2. **한 섹션에만 쓰인 구분선** → 일회용 → **제거** (상단·하단 예외 아니면).
3. **섹션 타이틀이 12~14px로 약함** → 그 서랍의 **실재하는 큰 값**(예: 미니멀 `22|Bold|CENTER`)으로 교차 사용.
4. **강약 수단 부족(1개)** → 그 시나리오의 **핵심 섹션**에 틴트 카드(`{버튼색}×8%`)를 줘서 주인공을 만든다. ⚠️ **인셋 카드끼리 통일**(#5) — 폼만 틴트하고 위치를 빼면 그 자체가 위반.
