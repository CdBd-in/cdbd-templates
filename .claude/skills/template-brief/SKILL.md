# template-brief — 외부 에이전트용 신규 템플릿 요청 프롬프트 생성

## 언제 쓰나

볼트/Figma/CdBd 에디터에 **접근할 수 없는 다른 AI 에이전트**(claude design·Google Stitch 등)에게 CdBd 신규 템플릿(모바일 원페이지) 제작을 맡길 때. 그 에이전트가 이 문서 하나만 보고 작업할 수 있도록, 볼트에 흩어진 정체성·규격·필수 정보 요소를 한 장의 self-contained 브리프로 합성한다.

이 스킬은 [[1. 작업 가이드/1-0. 템플릿 기획 워크플로우]]의 **1~3단계(콘텐츠 기획 → 외부 도구 시안 발산) 입력물**을 만드는 것. 산출된 목업/카피를 받아 **3단계(CdBd 카드 구조로 재구성)부터는 우리(Claude)가 이어간다.**

## 🎯 핵심 원칙 — 브리프는 디자인을 묶지 않는다 (design-free)

이 스킬은 **디자인 제약을 브리프에 넣지 않는다.** 색·폰트·모서리·여백·크기·정렬·간격·**페이지 구성(카드 순서·그룹핑·카드 선택)** 은 전부 외부 에이전트의 창작에 맡긴다.

- **이유**: 외부 도구에 맡기는 목적은 **아이디어·시각 발산**이다. 브리프가 팔레트·폰트·카드 옵션값·구성 순서까지 고정하면 여러 에이전트 결과물이 **똑같이 수렴**해 발산의 의미가 사라진다.
- **CdBd 구조·옵션값 매핑은 나중에 Claude가 한다** — 워크플로우 3단계(선정된 시안을 CdBd 카드 구조로 재구성)와 5단계(에디터 구현)에서 팔레트·폰트·카드 옵션값·여백 규칙을 그때 적용한다. 그래서 브리프 단계에서 미리 묶을 필요가 없다.
- **브리프가 유지하는 것(불가침, 시각 디자인 제약 아님)**: 편집 용이성(5대 원칙) · 가독성 3.6:1 · CdBd 14종 카드 · 규격(380px·OG·상세페이지) · 버튼 글자색=배경색 · 국문 본문=한글 폰트. 이건 "시각 디자인"이 아니라 **CdBd 템플릿 성립 조건**이라 남긴다.

> 과거엔 팔레트·폰트를 볼트 라이브러리로 고정하는 "기본 모드"와 자유 발산 "freeform 모드" 두 갈래가 있었으나, **디자인을 묶지 않는 것을 표준으로 통합**했다(2026-07-03). 팔레트·폰트 라이브러리는 브리프가 아니라 **Claude의 3단계 재구성 때** 참고한다.

## 입력

- **필수**: 템플릿 slug 또는 주제 (예: `gala-rsvp`, "VIP 임원 만찬 초대장"). 인자로 없으면 사용자에게 묻는다.
- **선택**: 특정 무드·톤 힌트. 넣더라도 **강제하지 말고** 브리프 목적 서술에 자연스럽게 녹여, 에이전트가 방향을 확장할 여지를 남긴다.

## 절차

### 1. 템플릿 스펙 확보

먼저 slug/주제로 기존 기획이 있는지 찾는다.

```bash
cd "$VAULT" && grep -rn "{slug}" "3. 신규 템플릿 기획/" | head
```

- **기획 문서에 있으면** (`3. 신규 템플릿 기획/3-0. 신규 템플릿 18건 정리.md`의 `#### 4.N {slug}` 섹션): 그 섹션을 Read 해서 이름·카테고리·부제목·본문·페르소나·통증·**페이지에 담을 정보 요소**·고유 제약을 추출한다.
- **없으면**: 사용자에게 주제·카테고리·타겟·페이지에 담을 정보를 물어 `1-0` 워크플로우 1단계(콘텐츠 기획)를 즉석에서 수행. 카테고리는 5종(초대·예약 / 홍보·카탈로그 / 프로필·명함 / 소식·매거진 / 가이드·신청) 중 1개. 미충족 분야(소식·매거진 0개, 가이드·신청 1개) 우선 고려.

> **팔레트·폰트 라이브러리는 여기서 열지 않는다.** 디자인은 외부 에이전트에게 맡기므로 `1-1. 색상 팔레트`·`1-2. 폰트 라이브러리` 추출 단계가 없다. (그 라이브러리는 나중에 Claude가 3단계 재구성 때 참고한다.)

### 2. 스켈레톤 채우기

`template.md`를 Read 한다. 아래 placeholder만 치환한다. **0장(5대 원칙)·2장(디자인 자유 방향)·3장(규격)·4장 카드 14종 용어집·5장(결과물)은 고정 상수이므로 건드리지 않는다** — 변경은 볼트 가이드가 바뀐 경우에만.

| placeholder | 채우는 값 |
|---|---|
| `{{SLUG}}` / `{{NAME}}` / `{{CATEGORY}}` / `{{ONELINE}}` | 1단계 스펙 |
| `{{PURPOSE}}` | 본문(목적) 서술. 무드 힌트가 있으면 여기 자연스럽게 녹임(강제 아님) |
| `{{PERSONA}}` | 페르소나 목록(불릿) |
| `{{PAINS}}` | 통증 목록(불릿) |
| `{{EXTRA_SPECS}}` | 이 템플릿 고유 규격 행(예: "좌석 배치도 이미지 최대 10MB, 가로 비율"). 없으면 비움 |
| `{{REQUIRED_ELEMENTS}}` | 페이지에 반드시 담을 **정보 요소** 불릿 (카드 타입·순서 지정 ❌) |

**`{{REQUIRED_ELEMENTS}}` 작성 규칙 (가장 중요)**: 카드 타입·순서를 지정하지 말고 **담아야 할 정보 요소만** 불릿으로 나열한다. 각 요소는 `- **{요소명}** — {무슨 내용/왜 필요한지}` 형식. 예: `- **행사 일시·장소** — 사용자가 언제 어디로 가는지 즉시 파악`, `- **참석 회신(RSVP)** — 참석/불참 선택 + 인원`. 기획 문서의 페이지 구성이 카드 순서로 돼 있으면, **카드 지정을 벗겨 "정보 요소" 단위로 환원**해서 옮긴다. (순서·구성·카드 선택은 에이전트가 정한다.)

> **RSVP·지도 등 시스템 기본 UI 주의**: 예약(RSVP) 카드는 화면에 **버튼 1개**로 보이고 클릭 시 빌더가 슬롯·정원·본인 인증 화면을 띄운다. 위치 안내는 지도 임베드가 기본. 이 사실은 `template.md` 4장 14종 용어집에 이미 인라인돼 있으니, `{{REQUIRED_ELEMENTS}}`에 해당 요소가 있으면 "슬롯·달력 UI를 직접 그리지 말 것"을 한 줄 덧붙여도 좋다.

### 3. 출력

치환 완료된 전체 브리프를 **하나의 fenced code block(```markdown)** 으로 감싸 채팅에 출력한다(사용자가 통째로 복사해 외부 에이전트에 붙여넣을 수 있게).

그다음 사용자에게 저장 여부를 묻는다:
- 저장 원하면 `3. 신규 템플릿 기획/브리프-{slug}.md`로 Write.

## 원칙

- **design-free** — 브리프는 색·폰트·모서리·여백·구성 등 **시각 디자인을 지정하지 않는다.** 발산이 목적. (CdBd 옵션값·팔레트·폰트 매핑은 Claude의 3단계 재구성에서.)
- **self-contained** — 브리프 안에 볼트 내부 wikilink·경로·전문용어를 남기지 마라. 외부 에이전트가 못 읽는다. 모든 규격을 실제 수치로 인라인.
- **모바일 웹 · 앱 아님 (고정 상수)** — 브리프는 항상 "모바일 웹 페이지(링크로 여는 세로 스크롤)"임을 강조하고 **상/하단 내비게이션 바·앱바·상태바·탭바 등 네이티브 앱 크롬을 그리지 말라**고 명시한다. (`template.md` 0장에 내장. claude design·Google Stitch 등 외부 도구가 습관적으로 앱 UI를 그리는 것을 차단.)
- **불가침(시각 디자인 아님) 유지** — 5대 원칙(편집 용이성) · 가독성 3.6:1 · 14종 카드 · 규격 · 버튼 글자색=배경색 · 국문 본문=한글 폰트. 이건 템플릿 성립 조건이라 디자인이 자유라도 남긴다.
- **결과물 형식 유연** — 기본은 HTML 목업 3종 + 카피 + 이미지 프롬프트. 사용자가 다른 형식(상세 스펙/실제 이미지 등)을 원하면 5장(Deliverables)만 조정.
