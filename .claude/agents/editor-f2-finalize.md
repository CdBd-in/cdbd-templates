먼저 `.claude/cdbd-edit-shared.md`를 읽는다.

## 입력
`editorId` · (선택) 직전 검증/수정 diff 목록 · Figma 시안 노드(제목/설명 참고) · (선택) 스크린샷 저장 경로.

## 절차
1. 드라이버 설치 확인(`window.__cdbd`). URL 진입 시 `/login` 리다이렉트면 shared의 로그인 절차.
2. **URL 정보(공유 메타 제목·설명)**: 헤더 설정에서 페이지 제목·설명 입력(OG 이미지와 별개 필드). 값은 Figma 시안/브리프에서.
3. **OG 이미지 = 수동 준비 안내(자동 생성 ❌)**: OG는 800×400 1배수 JPG(`og.jpg`)로 **이미지 생성은 사람이** — 기본값 「로고 타입」(단색 배경 + 브랜드 로고 중앙, 면적 9~10%). 규칙 전문은 아래 「🖼️ OG 이미지 체크리스트」 참조해 사용자에게 준비 항목을 안내. 파일이 준비되면 업로드는 함정23 `onDrop` 직접 호출로 자동화 가능(파일 업로드 레시피: skill `cdbd-card-automation`).
4. **모바일 프리뷰 캡처**: 셀렉터 `.max-w-1\/2.transform.origin-top` 스크린샷. **멀티페이지면 각 페이지를 명시적으로 1 클릭 후 전 페이지 각각 캡처**(마지막에 본 페이지만 열리는 함정 회피). 5단계(상세 페이지) 입력물.
5. **최종 검증(diff=0)**: `window.__cdbd.dumpState()` 재덤프 → (있으면) 직전 diff가 모두 해소됐는지 요약. 잔여 diff는 나열해 반환(파이프라인이 재수정 여부 판단).

## 자동화 불가/수동 위임
- OG 이미지 **생성**(디자인)은 사람. URL 정보 입력·스크린샷·재검증은 자동화.
- 카드 라벨 inline edit은 위험(shared 참조) — F2 범위 아님.

## 출력
`{screenshots:[경로...], remainingDiffs:[{cardId,field,...}], urlInfo:{title,description}, ogGuidance:"준비 안내"}` + 실행 위치 `https://www.cdbd.in/editor/{editorId}`.

## ⚠️ 자동화 함정 — 모바일 프리뷰 캡처

> 코드 레시피: skill `cdbd-card-automation`.

- [ ] **전체 페이지 캡처 = inner overflow 임시 확장** — mobile preview 컨테이너(`bg rgb(22,22,26)`)의 inner `[class*=overflow-y-scroll]`를 `height=scrollHeight`·`overflow=visible`·`position=static`으로 확장 → element 캡처 → 원복. 셀렉터 `.max-w-1\/2.transform.origin-top`는 deprecated(폴백).
- [ ] **멀티페이지는 각 페이지 명시 1클릭 후 각각 캡처**(마지막 본 페이지만 열리는 함정).
- [ ] **라이브 뷰어 모서리 각지게 = `*` 글로벌 셀렉터 ❌** (함정22) — 외곽 프레임(`rounded-t-\[20px\]`)만 타게팅. 안쪽 카드/버튼/아바타는 원래 모서리 유지.

## 🖼️ OG 이미지 체크리스트

> 공유(카톡·SNS) 썸네일 — 헤더 「URL 생성하기」 우측 URL 정보 편집 모달에서 업로드. **생성은 사람이**(수동), 파일 준비되면 업로드는 함정23 `onDrop` 자동화(skill `cdbd-card-automation`). 원본: `cdbd-design-service/룩북/2. 디자인 가이드/2-1. 공통.md`.

**📍 제작 위치 = 등록 보드의 해당 템플릿 사례 기획 섹션 안 (필수, 2026-07-10)**
- OG 프레임은 **별도 Figma 파일·별도 페이지에 만들지 말 것** ❌ (vip-dinner OG를 별도 파일로 만든 실수).
- 반드시 **[CdBd 템플릿 등록 파일](https://www.figma.com/design/oi8zIHLfy59O5zV8aysqq4/CdBd-%ED%85%9C%ED%94%8C%EB%A6%BF-%EB%93%B1%EB%A1%9D?node-id=1079-1064)의 해당 템플릿 「사례 기획」 섹션 안**에 OG 프레임(800×400)을 생성.
- 이유: 템플릿 1건의 산출물(시안·스크린샷·상세 페이지·OG)이 한 섹션에 모여 있어야 찾기·재사용·검수가 가능.
- 기존에 별도 파일로 만든 OG는 발견 시 해당 섹션으로 옮긴다.

**규격**: 800×400px(2:1) · **1배수**(일반 페이지 3배수의 예외) · JPG · 파일명 `og.jpg`.

**기본 = 「로고 타입」**(단색 배경 + 브랜드 로고 중앙). 룩(이미지) 타입은 별도 요청 시에만.
- [ ] **배경**: 페이지 테마색(`{배경색}` 또는 `{버튼색}`) 최우선 · White(`#FFFFFF`) · Black(`#000000`) 중 택1.
- [ ] **정렬**: 로고 수직·수평 중앙.
- [ ] **로고 크기 = 면적 기준 9~10%** — bounding box(배경·여백 제거) 면적이 OG 320,000px²의 **9~10%**(≈28,800~32,000px²). 너비% 환산 ❌(가로/세로로 긴 로고는 비중 어긋남). 예: `maje` 워드마크 268×113=30,284px²=9.46%.
- [ ] ❌ **사진+텍스트 오버레이를 기본으로 만들지 말 것**.

**샘플 로고 제작**(실제 브랜드 로고 없을 때) = `[심볼(선택)] + [워드마크]`:
- [ ] **폰트** = 페이지 무드에 맞는 CdBd 폰트([[1-4. 폰트]] 9무드 분류), 무드 일치(예: 럭셔리 페이지 → 럭셔리 무드 폰트).
- [ ] **심볼**(선택): 아이콘 라이브러리 검색 순서 **Griddy → Lucide → Bootstrap → Tabler**(적합 없으면 다음 순위). 가져오기 **24px · stroke 2px**.
