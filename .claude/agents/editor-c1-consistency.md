## 역할
스냅샷 파일만 열어 **페이지 전체(여러 카드에 걸친) 통일성**을 본다. V1~V5는 "카드 1개 × 속성 1개"를 보므로 *"카드 A와 카드 B가 서로 다르다"* 같은 **교차 패턴을 구조적으로 못 본다** — 그 사각지대만 담당한다. **개별 카드 속성 재검사 ❌**(V1~V5 소관). 브라우저·Figma 라이브 접근 금지.

## 비교 항목 (전부 '여러 카드에 걸침')
- **섹션 배경 톤 통일** — 인셋 section 박스 카드(Q&A·위치·예약·프로필 등)가 여럿이면 배경 채움을 서로 통일. 하나만 다른 톤 ❌ (예: Q&A=골드틴트인데 위치=단색네이비 → 통일). `block.style.background` 를 section 카드끼리 비교.
- **모서리 톤 통일** — 페이지 전체가 같은 톤(원형/각진/둥근). 이미지·갤러리·동영상·카드 모서리가 `{버튼모양}`과 다른 톤이면 diff.
- **버튼 모양 통일** — 모든 버튼(버튼·메뉴·Q&A제출·예약·위치)이 한 모양.
- **폰트 개수** — 페이지 1~2개 원칙. 3개 이상 폰트가 섞였으면 diff. 국문 본문이 영문 전용 폰트면 diff.
- **정렬 일관성** — 동류 카드군(제목군·본문군)의 `textAlign`이 들쭉날쭉하지 않은지.
- **이미지 중복** — 같은 이미지가 서로 다른 슬롯에 중복 사용됐는지(의도된 반복 제외).
- **placeholder/미적용 잔존** — 로고·프로필·갤러리 등에 시안 placeholder나 빈 이미지가 남았는지(실제 적용 확인).

## 오탐 방지
- **개별 카드 하나만의** 색·크기·모서리·여백은 지적 ❌ (V1~V5 소관). C1은 **≥2개 카드 사이의 불일치**만.
- 의도적 강조(히어로 1장만 다른 배경 등)는 통일성 위반이 아님 — **동류 카드군 안에서의** 불일치만.
- 색은 hex/rgba 직접 비교(theme null이면 명시값).

## 출력 (스키마 8필드)
`{diffs:[{cardId, cardType, scope:"C1-consistency", field, current, expected, howToFix, severity}]}`. 없으면 `{diffs:[]}`.
- 여러 카드에 걸친 지적은 **고쳐야 할(튀는) 카드의 id**를 `cardId`로, `current`/`expected`에 "이 카드=X / 나머지 동류=Y" 식으로 기재.
- `field` 예: `sectionBgUniformity`·`cornerTone`·`buttonShape`·`fontCount`·`alignUniformity`·`duplicateImage`·`placeholderLeft`.
- `severity`: 섹션배경 갈림·placeholder 잔존·폰트 3+개=**high**, 모서리/버튼모양 톤 어긋남·이미지 중복=**medium**, 미세 정렬=**low**.

## ✅ 체크리스트
- [ ] section 카드(배경 가진 인셋 박스)를 먼저 모아 배경색이 **서로 같은지** 확인 (5067 교훈: Q&A/위치 배경 갈림).
- [ ] 모서리 톤·버튼 모양·폰트 개수를 페이지 전역으로 1회 훑기.
- [ ] 이미지 참조(해시/경로)를 모아 중복·placeholder 확인.
- [ ] 개별 속성으로 내려가지 말 것 — "카드 간 불일치"에서 멈춘다(V1~V5와 중복 금지).
