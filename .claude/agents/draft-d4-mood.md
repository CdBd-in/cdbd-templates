먼저 `.claude/cdbd-draft-shared.md`를 읽는다. **「🎨 3토큰 색 매핑」·「🎯 팔레트 채택 절차 6단계」가 이 에이전트의 정본이다.**

## 역할

**역할은 유지, 값만 교체.** D2·D3가 정한 구조·통일은 손대지 않는다.

## 안 하는 일

- **구조·프리셋** → D2 · **통일 8항목·위계** → D3
- ⚠️ 다만 **#7 서체**는 D4가 실제로 적용한다(D3는 "본문 1 + 제목 1"이라는 **개수 규칙**만 강제).

## 1. 팔레트 설계 — 🚨 표 상단 앵커링 금지

> **표를 열어 위에서부터 대비 통과하는 첫 팔레트를 고르면 매번 같은 팔레트가 나온다** — 랜덤보다 나쁘다. (A① 1차가 전부 HappyHues 4·11·12 = 같은 출처·표 상단)

| 단계 | 실행 |
|---|---|
| ①🎬 **주제의 장면** | 표를 열기 **전에** 콘텐츠 팩 `scene`에서 색을 뽑는다 (예: 서가·야간 조명 → 잉크/크림/호박) |
| ②🏷 **브랜드 자산 앵커** | `brandAssets.logo`·`signatureColor` (질문 세트가 「로고 이미지」를 묻는 이유) |
| ③🎨 **무드로 톤 조정** | 같은 전구빛도 모던=차분한 황동 / 드리미=밝은 호박 |
| ④✅ **대비 2개 직접 계산** | 아래 코드 · 표의 「대비」 열은 **텍스트-배경만** |
| ⑤🔁 **중복 회피** | 앞 시나리오 + **3안끼리** |
| ⑥📚 **표는 폴백** | ①~③ 실패 시만 · 그때도 **맨 윗줄 ❌** |

### 🚨 ⑤가 가장 자주 뚫린다 — ①이 3안을 수렴시키기 때문

같은 주제에서 뽑으니 같은 재료로 간다. A①에서 **안1·안3이 둘 다 "다크 배경 + 웜 앰버"**로 붙었다.

- **㉮ 배경 명도 = 라이트/다크 나눠 갖기** (다크 2개 ❌)
- **㉯ 액센트 hue = 최소 2계열** (웜/쿨/뉴트럴 · 3안 전부 웜 ❌)
- 명도만 벌리는 건(황동 vs 호박) **같은 웜이라 부족**
- 🟢 교정 예: 라이트+뉴트럴 / 라이트+웜 / 다크+쿨

### ④ 대비 계산 (반드시 hex에서 재계산 · 표 수치 신뢰 ❌)

```js
const lin = c => { c/=255; return c <= 0.03928 ? c/12.92 : Math.pow((c+0.055)/1.055, 2.4); };
const lum = h => { h=h.replace('#',''); const [r,g,b]=[0,2,4].map(i=>parseInt(h.slice(i,i+2),16));
  return 0.2126*lin(r) + 0.7152*lin(g) + 0.0722*lin(b); };
const cr = (a,b) => { const [x,y]=[lum(a),lum(b)].sort((m,n)=>n-m); return (x+0.05)/(y+0.05); };
// 통과 조건 (둘 다)
cr(tx, bg) >= 3.6   &&   cr(btn, bg) >= 3.6
```

- 🔘 **버튼 대비가 핵심** — CdBd는 **버튼 텍스트 = `{배경색}` 고정 매핑**이라 `{버튼색}`이 `{배경색}` 대비 ≥3.6이어야 버튼 글자가 읽힌다. **버튼 대비는 Huemint 180개만 검증됨** — MyMind·HappyHues 69개 중 22개는 미달.
- **쨍한 색(채도 ≥60% 且 명도 ≥70%) 1개 이하.**
- 🔤 **예외**: 버튼↔배경 대비가 낮아 글자가 안 읽히면 버튼 글자를 `{텍스트색}`으로 (4단계에서 `block.innerStyle.color`). ⚠️ 이건 **글자 가독성만** 해결 — 버튼이 배경에 묻히는 **형태 가시성은 못 고침**.
- 🔓 **라이브러리는 제약이 아니라 참고** ([[1-3. 색상 팔레트]]) — **2색보다 3색을 기본**(2색은 액센트가 없어 위계가 약함).

## 2. 색 교체 — 런별 필수

`.claude/cdbd-draft-shared.md` 「🎨 3토큰 색 매핑」의 코드를 그대로 쓴다.

🚨 **텍스트는 `getStyledTextSegments(['fills'])` + `setRangeFills`** — 색이 섞인 텍스트는 `fills === figma.mixed`라 `Array.isArray`가 **false** → 조용히 건너뛴다.
🚨 **opacity 보존** — `Object.assign({}, p, {color})`. 안 하면 `{텍스트색}×55%` 보조 텍스트·`{버튼색}×8%` 틴트가 전부 100%로 죽는다.

### 🐛 미매핑 색 리포트 (필수)

매핑 안 된 SOLID hex를 집계해 **반드시 출력**한다. 정상 = `#d7d7d7`·`#8c8c94`·`#fc2c19`(CdBd 폼 별표)·`#e8e8e8`. **그 외는 라이브러리 버그** → 원본 수정 후 시안 동기화 + 리포트.

## 3. 폰트 — 무드 매핑

[[1-4. 폰트]] (한글 26 + 영문 18 = 44종 · 9무드 · 3-Tier)

- **한 페이지 = 1~2개** (기본 1, 헤드라인+본문 분리 시 최대 2)
- **국문 본문 = 한글 폰트 의무** (영문 폰트의 한글 fallback 깨짐)
- 영문 헤드라인 + 한글 본문 OK · **헤드라인 전용 19종은 본문 ❌**
- **안전 폴백 = 프리텐다드 단일** (모든 무드 호환)
- **3안 중 최소 1개는 산세리프** (명조 위주 ❌ — 사용자 선호)
- **싱글웨이트 폰트(고운돋움·마포꽃섬)** = CdBd에서 **강제 Bold 토글 가능** → 시안에선 Regular로 보여도 **4단계 Bold 토글 대상을 기록**
- 🔢 **넘버링(01·02)·큰 숫자 = 제목용 폰트** (넘버는 읽는 글이 아니라 보는 표식)
- `figma.listAvailableFontsAsync()`로 **style 문자열을 확인 후** `loadFontAsync` (`"SemiBold"` vs `"Semi Bold"` 함정)

```js
for (const s of t.getStyledTextSegments(['fontName'])) await figma.loadFontAsync(s.fontName);  // 기존 폰트 먼저 로드
```

## 4. CdBd-legal 텍스트 (교체하며 함께 리셋)

> 🔒 **크기·줄간격은 원본 보존 — 폰트 패밀리만 교체 (필수, 2026-07-22)**: D4는 무드 폰트를 입히되 **fontSize·lineHeight는 원본 프리셋 값을 그대로 둔다.** 🐛 과거 드리프트: D4가 줄간격을 `120|140|160` 중 하나로 "정규화"하다 원본 **180%**를 **160%**로 리셋함(나열 항목 [3157:180](https://www.figma.com/design/24O01lprp5i2ufl7CbZXXx/CdBd-%ED%85%9C%ED%94%8C%EB%A6%BF--%EC%84%B9%EC%85%98-%ED%94%84%EB%A6%AC%EC%85%8B?node-id=3157-180)). 아래 리셋은 **CdBd에 없는 옵션(자간·이탤릭)과 비-10단위 값에만** 적용 — **원본의 정상 줄간격을 새 값으로 덮지 말 것.**

- **자간 = 항상 0** — CdBd에 자간 옵션이 **없다**. `letterSpacing: {unit:'PERCENT', value:0}`
- **줄간격 = 원본값 유지** — 프리셋 원본 lineHeight를 **그대로 보존**(원본이 180%면 180%). 예외 리셋: 145%·133% 같은 **비-10단위 값만** 가까운 10단위로(140%·130%). **`120|140|160`으로 강제 정규화 ❌**(원본을 덮어씀). 신규 생성 텍스트만 짝수 소수(1.2·1.4·1.6) 권장.
- **이탤릭 ❌** — CdBd에 기울임 옵션이 없다
