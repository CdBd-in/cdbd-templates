## 0. 이 문서의 모델 — **3층**

기존 16개 레시피를 전수 분해해 보니 **예외 없이 같은 골격**이었다. 칸마다 다른 것은 **세 가지뿐**이다.

| 층 | 무엇 | 개수 | 바뀌는가 |
|---|---|:--:|---|
| **① 공통 골격** | 여는 부분 · 닫는 부분 | **1** | 27칸 전부 동일 |
| **② 배치 패턴** | 본체 순서 규칙 + 멀티 분할 | **6** | 칸마다 하나 지정 |
| **③ 칸별 카드** | ★결정 블록 · 보조 블록 · 조건부 | **27** | 칸의 정체 |

🔑 **이 구조를 쓰는 이유** — *"문의 섹션은 3안 모두 다른 프리셋"* 같은 **공통 규칙이 바뀌면 골격 한 곳만** 고친다. 구버전은 같은 규칙이 16군데 흩어져 있어 한 곳을 고치면 나머지가 낡았다.

### 재료 = 섹션 목적 13칸

아래는 **출발점**이다. 페이지 목적·유저 자료에 따라 **섹션을 더하고 빼고 순서도 바꾼다.** 한 페이지는 **읽히는 목적**(히어로·소개·자료)과 **동작하는 목적**(위치·폼·예약·문의·구매)을 섞어 짠다.

## 1. 공통 골격 — 27칸 전부 동일

```
┌ 여는 부분 ────────────────────────────────
│ [헤더]      선택 — 로고·발행처
│ [히어로]     필수 ★ — 페이지 첫 콘텐츠 섹션. 예외 없음
├ 본체 ─────────────────────────────────────
│ [도입]      선택 — 소개·스토리 (아래 규칙)
│ [★ 결정 블록] 필수 ★ — 그 칸의 정체 (§4)
│ [보조 블록]  0~n — 위치 안내 · 자료 · 안내 사항 ·
│                  프로모션 · 폼 · 핵심정보 · 나열 …
├ 닫는 부분 ────────────────────────────────
│ [문의]      사실상 필수
│ [푸터]      선택 — 담을 게 있을 때만
└───────────────────────────────────────────

  ★ 진짜 고정된 건 둘뿐 — 「히어로」와 「★결정 블록」.
    나머지는 전부 선택·조건부다.
```

### 골격에 걸린 공통 규칙 (여기 한 곳에만 적는다)

| 규칙 | 내용 |
|---|---|
| 🥇 **첫 섹션 = 히어로** | 어떤 칸이든 **임팩트 있는 히어로로 연다.** 작은 소개·프로필 카드로 시작 ❌. 인물형(2번 대분류)은 **프로필을 히어로 자리로 끌어올려** 겸한다 |
| 🧢 **헤더** | 3안 중 **1안 이상 포함 · 3안 전부 ❌**(유무가 차별화 레버) · 페이지와 반드시 구분(면 또는 하단선) · 로고 헤더를 넣은 안은 **히어로에서 로고 반복 ❌** |
| 📮 **문의** | **3안 모두 다른 프리셋** — 버튼만 있어 복붙되기 제일 쉬운 섹션. 채움/틴트/Outlined · 세로/가로 2단을 안마다 다르게 |
| 🦶 **푸터 = 선택** | **필수가 아니다** (2026-09-04 이선호). 푸터는 **담을 게 있을 때만** 둔다 — 브랜드 로고 · SNS 채널 · 발행처 · 사업자 정보. <br>❌ **개인 경조사(1-①) · 부고(1-⑥)엔 두지 않는다** — 브랜드도 SNS도 없고, 조사에 로고·SNS 아이콘을 붙이면 톤이 깨진다. 페이지는 **문의(연락처)로 끝난다**. <br>❌ 넣을 게 없는데 자리를 채우려고 빈 푸터를 만들지 말 것 |
| 🖼 **이미지 위 텍스트 ❌** | 레시피의 `[히어로: 화보 + 제목]`은 **이미지 위에 글을 얹으라는 뜻이 아니다.** 이미지 카드 + 별도 텍스트 카드 스택으로 |
| 🧱 **평탄화** | CdBd는 평면 카드 스택 — 섹션은 개념이지 컨테이너가 아니다. 여러 카드를 한 래퍼로 묶지 말 것 |
| 📏 **섹션 간 여백** | 각 섹션 **마지막 카드의 하단 여백 = 36** |
| 🏷 **섹션 타이틀** | 화면에 보이는 제목은 **고객 친화 국문**. 내부용어·업계용어 ❌ |

> 나머지 조립·통일·위계 규칙 = [[1-8. 섹션 프리셋 라이브러리]] 「🧷 페이지 조립 규칙」 (통일 8항목 · 타이틀 팔레트 8종 · 차별화 레버).

### 🚪 도입 블록은 언제 넣나 (2026-09-04 · 이선호 질문에서 규칙화)

> 🔑 **판정 한 줄** — **★결정 블록만 봐서 무슨 페이지인지 모르면 넣는다.** 알 수 있으면 뺀다.

식순만 덜렁 보여주면 무슨 행사인지 모른다 → **도입 필요**. 링크 목록은 위에 프로필이 있으니 그것만으로 안다 → **도입 불필요**.

> ⚠️ **도입은 「히어로에 흡수」되지 않는다** — 히어로와 별개인 **독립 선택 블록**이다. 넣을지 말지만 위 한 줄로 판정한다.

#### 넣지 않는 경우 3가지

| 경우 | 왜 | 해당 칸 |
|---|---|---|
| **① ★결정 블록이 곧 내용이다** | 공지 본문·기사 자체가 읽을 것 — 앞에 설명을 또 붙이면 중복 | `6-①` `6-②` `6-④` |
| **② 전환이 목적이다** (P5) | 도입이 CTA를 아래로 밀어낸다. **스토리는 결정 블록 뒤로** 보낸다 | `4-④` `4-⑥` |
| **③ 위에서 이미 알 수 있다 · 도입할 게 없다** | 링크 허브는 프로필만으로 "누구인지"가 끝난다. 자리를 채우려고 빈 소개문을 만들지 말 것 | `2-①` |

→ **도입 없는 칸 6개**: `2-①` `4-④` `4-⑥` `6-①` `6-②` `6-④`

#### 소개 / 스토리 — 무엇으로 쓰나

| | 무엇 | 길이 | 언제 |
|---|---|---|---|
| **소개** | **사실** — 누구인지 · 무엇인지 | 1~3줄 | 기본값. 행사·신청·명함 계열 전부 |
| **스토리** | **서사** — 왜 · 어떻게 | 문단 | **브랜드형**(4번 대분류 · 3-①) · 취지를 세워야 하는 것(5-② 모집 · 5-⑥ 후원) |

> 🛍 **브랜드형 고정 순서** — `히어로 → 브랜드 스토리 → 제품`. 제품·가격을 나열하기 전에 *브랜드가 누구이고 왜 이 컬렉션인지*를 먼저 짧게 세운다. *(4-④ 판매만 예외 — 전환 최우선이라 스토리가 뒤로.)*

#### ⚠️ 도입이 길어지면 도입이 아니다

도입은 **2~3줄**이다. 문단이 여러 개로 늘면 그건 **본체 섹션**이므로 **결정 블록 뒤로** 옮긴다. 도입 자리에 긴 글이 오면 스크롤 절반을 먹고 ★결정 블록이 화면 밖으로 밀린다.

#### ℹ️ 예외 — 도입 자리의 스토리가 ★결정 블록인 칸

`3-①` 소개 홈 · `5-⑥` 후원·기부 는 **「우리가 누구인가」/「왜 이 후원인가」 자체가 그 페이지의 정체**다. 이 둘은 도입이 아니라 **결정 블록**이므로 위 규칙(짧게·뺄 수 있음)을 적용하지 않는다.

## 2. 배치 패턴 6개 — 본체 순서 규칙

**P1~P3는 [[1-10. 초대장 사례 사전 (초안)]]의 말투 3갈래와 정확히 대응**한다. P4~P6은 그 밖(진열·전환·인물).

### 🔀 한 칸이 **여러 패턴을 쓴다** — 기본 패턴 + 조건부 (2026-09-04 이선호 지적)

> 🔴 **정정** — 처음엔 칸마다 패턴을 **하나씩 고정**해뒀다. 틀렸다.
> **기능이 붙거나 분량이 달라지면 배치가 바뀐다.** 전수 재점검 결과 **27칸 중 21칸이 조건에 따라 패턴이 변한다** — 1:1 고정은 6칸뿐이다.

#### 섞임 규칙 3 — 「+패턴」이 실제로 뜻하는 것

| 표기 | 조건 | 배치에 생기는 변화 |
|---|---|---|
| **＋P3** | 받는 기능이 붙는다 (참석·신청·예약·문의) | ★결정 블록 **뒤에** `[안내 사항] 마감일·수집 항목` + `[폼]`/`[예약]` 삽입 · **문의 CTA가 "회신하기"·"신청하기"로** 바뀜 |
| **＋P4** | 아이템이 **여러 개**가 된다 | ★가 **반복 단위**가 되고, **앞에 `[스토리]`**가 붙어 묶음을 세운다 |
| **＋P5** | 결제·전환이 목적에 들어온다 | **구매 CTA를 상단에도** 추가(상하 2회) · **`[스토리]`를 뒤로** 민다 |
| **→P1** | 내용이 짧아지고 받을 것도 없다 | 폼·위치·반복이 전부 빠지고 **본문 하나로** 줄어든다 (**대체**이지 추가가 아님) |

> 🔑 **＋는 「추가」, →는 「대체」다.** `P2＋P3`는 초대형 골격에 폼이 끼는 것이고, `P5→P1`은 전환형이 아예 알림형으로 바뀌는 것.

→ 공통점 = **기능 변주가 없고 아이템 개수도 안 변한다.** 부고는 조사라 기능을 붙이지 않고, 링크 허브·이력서·신청 폼은 ★ 자체가 이미 최종 형태다.

#### 무엇이 패턴을 바꾸나 — 트리거는 딱 둘

| 트리거 | 바뀌는 방향 | 누가 정하나 |
|---|---|---|
| **① 기능이 붙는다** (받기 · 결제) | ＋P3 · ＋P5 | **유저** — 목적 문장 변주(§3-C) |
| **② 아이템 개수** (하나 ↔ 여럿) | ＋P4 · →P1 | **자료 분석** — 사진 장수 · 제품 수 · 회차 수 |

> 🔑 **둘 다 「내용」에서 나온다.** 그래서 패턴은 유저에게 묻지 않는다 — **목적 문장과 업로드 자료에서 자동으로 정해진다.**
> ⚠️ **②는 자료 분석이 필요하다** — `4-①↔4-③`(하나 자세히 / 여럿 목록)을 가르는 것과 같은 정보다. §3-B의 미해결 항목과 같은 뿌리.

### P1 알림형 — 읽고 끝
> 말투 📢 **알림** "알아두세요"
```
히어로 → [★본문] → 부가 안내 → 문의(짧게)
```
- **가장 짧다** (5~7섹션) · **위치 ❌ · 폼 ❌**
- 긴급 상황이면 **로고·이미지·SNS를 전부 생략해도 성립**해야 한다
- ▸ **멀티 2P** — P1 요약 + [자세히 보기] / P2 전문·부가

### P2 초대형 — 오게 함
> 말투 🎉 **초대** "와주세요" (부고만 📢 알림 톤)
> 🏷 **「안내형」 → 「초대형」 개명** (2026-09-04 이선호) — 이 패턴의 정의는 *「오라고 부른다」*이고, **「안내」는 6번 대분류(읽고 끝)와 헷갈린다.**
> ⚠️ `1-⑥ 부고`도 P2지만 화면 문구엔 **「초대」를 절대 쓰지 않는다.** 패턴 이름은 **내부 이름**이라 유저에게 노출되지 않으므로 충돌이 아니다(§0 · 대분류 이름과 같은 논리).
```
히어로 → 도입(인사말·소개) → [★때·장소·프로그램] → 보조 → 위치 안내 → 문의
```
- **위치 안내 필수** (「가야 할 곳」이 이 패턴의 정의)
- ▸ **멀티 3P** — P1 표지·초대 / P2 프로그램·정보 / P3 회신·위치

### P3 접수형 — 받는 게 목적
> 말투 📝 **접수** "알려주세요"
```
히어로 → 도입(짧게) → 보조(왜 신청하나 = 혜택·분야·조건) → [★폼/예약] → 안내 사항(유의·마감) → 문의
```
- ⚠️ **폼이 화면 절반 안에** 들어와야 한다 — 설명이 길어져 폼이 바닥으로 밀리면 실패
- **문의는 폼과 별도로** 둔다(폼 거치지 않는 즉시 연결 = 전화·카톡)
- ▸ **멀티 3P** — P1 표지 / P2 안내·조건 / P3 폼

### P4 진열형 — 여러 개 보여줌
```
히어로 → 스토리(브랜드·컨셉) → [★아이템 반복] → 보조 → 문의
```
- **아이템 반복이 본체의 8할** · 아이템 1개 = 독립 섹션 단위
- 브랜드형이면 **히어로 직후 스토리**를 먼저 세운다(왜 이 컬렉션인가)
- ▸ **멀티 3~4P** — P1 표지+목차 / P2 반복 내지(대표 1P만 표기·실제론 복제) / P3 마무리

### P5 전환형 — 사게 함
```
히어로 → [★CTA·구매 1차] → 근거(핵심정보·프로모션·리뷰) → 상세 → 안내 사항 → [★CTA 재노출]
```
- 🔑 **CTA가 최상단 + 최하단 두 번** — P4와의 유일한 결정적 차이
- 스토리는 **뒤로** (전환 최우선이라 P4와 반대)
- ▸ **멀티 2~3P** — P1 판매(히어로·구매·가격) / P2 상세·근거 → 하단 CTA

### P6 인물형 — 사람이 주인공
```
[프로필 = 히어로 겸] → 소개 → [★실적·작업물·링크] → 보조 → 문의(연락처 저장)
```
- **프로필이 최상단** — 갤러리·이력·연락처를 프로필보다 위에 ❌
- ▸ **멀티 2P** — P1 프로필+주요 채널 / P2 더 보기

## 3-B. 🎛 유저에게 묻는 것 — **목적 질문 하나로 모인다** (2026-09-04 rev.2)

> 🔗 **근거 = 새 플로우 보드** [Figma 236-5375](https://www.figma.com/board/dA9nFFGnHhwjNuQYNVGR2B/AI-%EC%9C%A0%EC%A0%80-%EC%9B%8C%ED%81%AC%ED%94%8C%EB%A1%9C%EC%9A%B0?node-id=236-5375)

```
자료 있나요? → (URL·파일 / 직접 설명) → "이런 페이지 같아요, 맞나요?"
→ ★ "이 페이지로 가장 하고 싶은 일은 무엇인가요?"   ← 목적 질문 (추천 4 + 직접 입력)
→ "이 내용에는 [    ]를 추천해요"  → 원페이지 / 멀티페이지
→ 시안 A·B·C → 무드 확인 → "여기에 이런 걸 넣으면 좋아요"(플레이스홀더)
→ "마지막으로 확인해 주세요"(미입력 플레이스홀더 삭제 경고) → 에디터
```

### 🥇 목적 질문 = **27칸을 고르는 자리**

두 질문이 **각각 다른 것**을 정한다.

| 보드 단계 | 정하는 것 |
|---|---|
| **"이 페이지로 가장 하고 싶은 일은?"** | **27칸 중 하나** ← 이 문서의 분류 체계가 꽂히는 자리 |
| **"이 내용에는 [ ]를 추천해요"** | **원페이지 / 멀티페이지** |

#### 왜 목적을 물어야 하나 — 3가지

1. **내용만으로는 목적을 알 수 없다.** 카페 사진 + 메뉴 정보로 만들 수 있는 페이지가 최소 셋이다 — **메뉴 보여주기 `3-②`** / **예약 받기 `1-⑤`** / **가게 소개 `3-①`**. 자료는 *"무엇이 있나"*만 알려주고 *"무엇을 하고 싶나"*는 안 알려준다. **유저만 아는 정보라 물어야 한다.**
2. **목적축이 체계의 근간이다.** *"목적이 곧 구성 · 업종·주제는 구조를 안 바꾼다"*([[1-11. 대분류 재설계 (제안 초안)]] §1) — 목적을 안 물으면 그 축이 빈다.
3. **가장 싼 복구 지점이다.** 이 질문이 없으면 AI 추론이 틀렸을 때 **시안 3개를 다 만든 뒤에야** 알게 된다. 목적 질문은 시안 생성 **전**이라 되돌리는 비용이 거의 0.

#### 🗣 선택지 4개 = **27칸의 「화면 어휘」**

유저는 `1-⑥`을 보지 않고 **"장례 소식을 알리고 조문 안내를 하고 싶어요"**를 본다.
→ [[1-11. 대분류 재설계 (제안 초안)]] §0 **「내부 서랍은 닫히고(27) · 화면 어휘는 열린다」**가 정확히 여기서 쓰인다.

### 🔄 갈림 질문 5개 → **목적 선택지 안으로 흡수** (별도 단계 ❌)

AI가 "예약이냐 상담이냐" 갈리면 → **둘 다 선택지로 올린다.** 유저가 고르는 순간 갈림이 해결되므로 질문을 따로 띄울 필요가 없다.
→ 갈림 질문 5축은 이제 **화면 질문이 아니라 「선택지 4개를 뽑는 내부 로직」**이다. 정의는 [[1-11. 대분류 재설계 (제안 초안)]] §16 유지.

> ✅ **`4-①` ↔ `4-③`도 문장을 잘 쓰면 갈린다** (2026-09-04 정정) — 처음엔 *"둘 다 「제품을 소개하고 싶어요」라 못 가른다"*고 봤으나, **분량을 문장에 넣으면** 유저가 답할 수 있다: *"**제품 하나를 자세히** 소개하고 싶어요"* ↔ *"**여러 제품을 목록으로** 보여주고 싶어요"*. → §3-C.

### 🔄 기능 질문 → **대부분 안 묻는다** (플레이스홀더로)

보드 마지막에 이미 답이 있다 — **"여기에 이런 걸 넣으면 좋아요"(플레이스홀더) → "미입력 플레이스홀더 삭제 경고"**.
**일단 넣어서 보여주고, 안 채우면 지운다.** *「판단 어려운 건 묻지 말고 보여준다」* 원칙과도 맞고 탭도 안 늘어난다.

**→ 플레이스홀더로 처리**: `[위치 안내]` · `[프로모션]` · `[자료]` · `[안내 사항]`

#### ⚠️ 예외 3개 — **구조를 바꾸는 기능은 목적 문장에 녹인다**

나중에 지우는 걸로 안 되고 **처음부터 구조가 달라야** 하는 것들. (2026-09-04 이선호: *"주제보다 기능적으로 구조 차이가 생긴다"*)

| 기능 | 무엇이 바뀌나 |
|---|---|
| **참석·사전 신청을 받나** | P2 초대형 → **P3 접수형 성격이 섞임** · 폼 + 마감일 안내 추가 · CTA가 "위치 보기"→"참석 회신하기" |
| **시간을 골라 예약하나** | `[예약]`이 **페이지의 주인공**이 됨 |
| **지금 결제·주문을 받나** | **P5 전환형**이 되어 CTA가 상단·하단 반복 |

**→ 목적 문장에 녹이면 질문 하나로 둘 다 해결된다:**
- *"행사에 초대하고 싶어요"* → `1-②` (폼 없음)
- *"행사에 초대하고 **참석 신청도 받고 싶어요**"* → `1-②` + 폼

## 3-C. 🗣 목적 문장 세트 — **27칸의 화면 어휘** (2026-09-04)

> 보드의 **`AI 생성 목적` / `추천 목적2·3·4` / `직접 입력`** 자리에 들어갈 문장.
> 🔒 **유저가 보는 유일한 층** — 내부 칸 이름(`1-⑥`)은 절대 노출하지 않는다.

![[1-12. 목적 문장 세트 — 도식.png]]

> 🔄 소스 = `1. 작업 가이드/.data/1-12-sentences-diagram.html` (재생성 명령은 맨 위 「한 장 도식」과 동일)

### 🅐 설계 규칙 5

1. **1인칭 「~하고 싶어요」** — 질문이 *"이 페이지로 가장 하고 싶은 일은?"*이므로 답도 그 형태.
2. **한 줄** — 선택지 4개가 나란히 뜨므로 길면 못 읽는다.
3. **업종어·카테고리명 ❌** — 「랜딩페이지」·「상세페이지」·「초대·예약」 전부 금지. **상황 문장**으로.
4. **기능은 「~도」로 덧붙인다** — `행사에 초대하고 **참석 신청도** 받고 싶어요`. (구조를 바꾸는 기능 3개 · §3-B)
5. **「초대」를 아무 데나 쓰지 않는다** — 부고·공지는 **「알리고」**. 말투 3갈래를 동사가 지킨다.

### 🅑 동사가 하는 일 — **말투를 지키고, 패턴은 절반쯤 드러낸다**

> 🔴 **2026-09-04 자체 정정** — 처음엔 *"동사를 고르는 순간 패턴이 정해진다"*고 썼으나, **27개를 전수 대조하니 절반만 맞았다**(13/27). 정확히 쓰면 아래와 같다.

**✅ 확실한 대응** — 동사만 봐도 패턴이 정해진다

| 동사 | 패턴 | 해당 칸 |
|---|---|---|
| **받고 / 예약하게 하고** 싶어요 | **P3 접수형** | `1-⑤` `5-①②④` |
| **초대하고** 싶어요 | **P2 초대형** | `1-①②` |
| **팔고** 싶어요 | **P5 전환형** | `4-④` |

**⚠️ 여러 패턴에 걸치는 동사** — 동사만으로는 안 정해진다

| 동사 | 걸치는 패턴 |
|---|---|
| **알리고** | P1 `6-①` · P2 `1-④⑥` · P5 `4-⑥` |
| **보여주고** | P4 `3-②` `4-②③` `6-②` · P6 `2-③④` |
| **소개하고** | P6 `2-②` · P4 `4-①` · P2+P4 `3-①` |

**🎯 대신 동사가 확실히 지키는 것 = 「말투 3갈래」**

| 말투 | 동사 | 예 |
|---|---|---|
| 🎉 **초대** "와주세요" | **초대하고** | `1-①②` |
| 📢 **알림** "알아두세요" | **알리고** | `1-⑥` `6-①` `4-⑥` |
| 📝 **접수** "알려주세요" | **받고** | `5-①②④` `1-⑤` |

> 🕯 **부고에 「초대」가 절대 안 붙는 이유가 여기 있다.** `1-⑥`은 패턴이 P2(초대형)인데도 동사는 **「알리고」** — **톤이 패턴을 이긴다.**
> 💡 실무적 의미: **동사는 「패턴 판정기」가 아니라 「톤 검사기」**다. 문장을 쓸 때 *"이 칸에 이 동사가 맞나"*를 톤 기준으로만 확인하면 된다.

### 🅓 선택지는 **고정 문장이 아니다** — 유저가 준 정보로 채운다 (2026-09-04 이선호 지적)

> 🔴 **문제** — 위 27개 기준 문장을 **그대로 띄우면** 유저는 *"내가 올린 자료·설명이 반영이 안 됐네"* 라고 느낀다.
> 이미 **입력 단계에서 탈락한 후보**가 있는데 그게 선택지에 그대로 뜨면 **「AI가 내 말을 안 읽었다」는 신호**가 된다.
> 플로우상 바로 앞이 *"이런 페이지 같아요, 맞나요?"*(내용 확인)인데, 그 직후 화면이 일반 문장이면 **앞 단계가 헛일이 된다.**

#### ① 문장 = **템플릿 + 유저 어휘 슬롯**

기준 문장의 **목적어 자리가 슬롯**이다. 유저 어휘가 있으면 **그 말로 교체**하고, 없으면 기준어를 유지한다.

| 기준 문장 | 유저가 쓴 말 | 화면에 뜨는 문장 |
|---|---|---|
| **가족 행사**에 초대하고 싶어요 | "아들 돌잔치" | **돌잔치에** 초대하고 싶어요 |
| **제품 하나**를 자세히 소개하고 싶어요 | "가죽 토트백" | **토트백 하나**를 자세히 소개하고 싶어요 |
| **여러 제품**을 목록으로 보여주고 싶어요 | "가방 3종" | **가방 3종**을 목록으로 보여주고 싶어요 |
| **메뉴와 가격**을 보여주고 싶어요 | "카페 메뉴판" | **카페 메뉴와 가격**을 보여주고 싶어요 |
| **사람**을 모집하고 지원을 받고 싶어요 | "바리스타 채용" | **바리스타를** 모집하고 지원을 받고 싶어요 |
| **장례 소식**을 알리고 조문 안내를 하고 싶어요 | "아버지 장례" | **아버님 장례 소식**을 알리고 조문 안내를 하고 싶어요 |

> 🛟 **폴백** — 슬롯을 못 뽑거나 추출이 부정확하면 **기준 문장 그대로**. 틀린 말을 넣는 것보다 낫다.
> 🔒 **동사·구조는 안 바꾼다** — 바뀌는 건 **목적어(슬롯)뿐**. 동사가 톤을 지키므로(🅑) 여기까지 열면 부고에 「초대」가 섞일 수 있다.

#### ② 후보 개수는 **가변** — 억지로 4개를 채우지 않는다

| 상황 | 화면 |
|---|---|
| **확신 높음** (입력에 목적이 이미 있음) | **1개 + “맞아요”** · 아래에 작게 「다른 목적 보기」 |
| **갈림 2~3개** | **갈리는 것만** — 나머지 자리를 채우지 않는다 |
| **정보 부족** | 3~4개 + 직접 입력 |

**배제 규칙** — 입력이 이미 지운 후보는 **띄우지 않는다**.

| 유저가 쓴 말 | 지워지는 후보 |
|---|---|
| "온라인으로 팔아요" | `3-②` 메뉴(현장에서 파는 것) · `1-⑤` 예약 |
| "장례" | `1-①~⑤` 전부 (말투가 다름) |
| "사진 없어요" | `2-③` 포트폴리오 · `4-②` 룩북 |
| "혼자 하는 프리랜서" | `3-①` 소개 홈(상호를 내건 사업체) |

> 🚫 **관련 없는 선택지 1개가 섞이면 나머지 3개의 신뢰도까지 떨어진다.** 빈 자리를 남기는 게 낫다.
> ⚠️ **보드 변경 제안** — 현 보드([Figma 236-5375](https://www.figma.com/board/dA9nFFGnHhwjNuQYNVGR2B/AI-%EC%9C%A0%EC%A0%80-%EC%9B%8C%ED%81%AC%ED%94%8C%EB%A1%9C%EC%9A%B0?node-id=236-5375))는 `AI 생성 목적 + 추천 목적2·3·4 + 직접 입력` **고정 5칸**이다. **가변으로 바꾸는 것**을 제안한다.

#### ③ **추천 근거를 한 줄 보여준다**

*"내 정보가 반영됐다"*는 느낌은 **선택지가 아니라 근거 줄에서 온다.**

```
올려주신 자료에서 「가격표」와 「매장 사진」을 봤어요.
이 페이지로 가장 하고 싶은 일은 무엇인가요?
  ⓐ 카페 메뉴와 가격을 보여주고 싶어요            (추천)
  ⓑ 우리 카페가 어떤 곳인지 소개하고 싶어요
  ⓒ 우리 카페가 어떤 곳인지 소개하고 방문 예약도 받고 싶어요
  + 직접 입력
```

- 근거는 **유저가 준 것만** 인용한다(자료에서 본 것 · 유저가 쓴 말). **AI 추측을 근거처럼 쓰지 말 것.**
- 근거가 없으면(설명이 아주 짧으면) **근거 줄을 생략**하고 후보를 넓게 준다.

#### ④ 그 밖의 선택지 규칙 3

1. **기능 변주는 기준 문장과 짝으로** — 나란히 두면 유저가 기능 유무를 **스스로** 고른다 → 별도 질문 불필요
2. **후보는 서로 충분히 달라야** — 같은 대분류에서만 채우지 말 것(`4-①②③④`를 다 올리면 못 고른다)
3. **유저 어휘로 계속 부른다** — “아버지 장례”라 썼으면 이후 화면 내내 「부고장」, “49재”면 「49재 안내」

### 1. 행사·안내 (6)

#### 1-① 경조사 초대장
**P2 초대형** · 🎉 초대 · ★ **주인공 인물** (이름·사진 — 1인 또는 쌍)
　　┗ **정보 구조** `사진 + 이름(쌍) + 관계` 한 덩어리 · 인물이 화면 최대 면적
```
[헤더] ❌ 보통 안 씀
[히어로] 대표 이미지 + 「초대합니다」
[소개] 인사말·모시는 글
[★소개] 주인공 (신랑신부 / 아기·부모 / 주인공 어르신)
[핵심정보] 일시 · 장소
[자료] 갤러리 (선택)
[폼] 참석 회신 (선택)
[안내 사항] 마음 전하실 곳(계좌) (선택)
[위치 안내] 필수
[문의] 연락처
```
> 🔑 **개인화 초대장은 별도 칸이 아니다** — 이 카드에 「수신자 이름 삽입」이 얹힌 것(§3).
> 👵 **수신자가 어르신인 경우가 많다** — 한 장에 정보가 다 들어오고 글씨가 큼직하게. 링크 이동 최소화.

#### 1-② 행사 초대장
**P2 초대형** · 🎉 초대 · ★ **식순** (시간 + 순서 나열)
　　┗ **정보 구조** `시간 + 순서명` **2열 반복** · 인물 카드 없음
```
[헤더] 로고 (주최 기관)
[히어로] 행사명 + 일시
[소개] 주최자 인사말
[핵심정보] 일시 · 장소
[★나열] 식순 (시간 + 순서)
[나열] 내빈 · 연혁 (선택)
[폼] 참석 회신 (선택)
[안내 사항] 좌석 · 주차 · 복장
[위치 안내] · [문의]
```
> 📊 **CdBd 실사용 1위 유형** — 기업·기관 기념행사 초청장. 우선순위 높음.

#### 1-③ 세미나·강연 안내
**P2 초대형** · 🎉 초대 · ★ **연사 × N + 세션 목록**
　　┗ **정보 구조** `연사 카드(사진·이름·소속) × N` **＋** `시간 + 세션명 + 연사` 3열 — 인물이 따로 선다
```
[헤더] 로고
[히어로] 행사명 + 부제 + 일시
[소개] 이 행사는 무엇인가
[핵심정보] 일시 · 장소(또는 온라인)
[★소개] 연사 × N (사진 · 이름 · 소속)
[★나열] 세션 · 시간표
[안내 사항] 준비물 · 참가비 · 접속 방법
[폼/예약] 신청
[위치 안내] 조건부 (§3 온라인 전용)
[문의]
```
> 💰 **경쟁 우위 지점** — 연사·타임테이블·참여기업 섹션은 이벤터스에서 **월 30만원대 상위 요금제 기능**이다. CdBd는 기본 제공 가능.

#### 1-④ 개업·오픈 안내
**P2 초대형** · 🎉 초대 · ★ **기간 + 볼거리·혜택**
　　┗ **정보 구조** `시작~종료 + 운영시간` **＋** 참여 항목(점포·프로그램) 나열
```
[헤더] 로고
[히어로] 오픈 알림 + 공간 사진
[소개] 어떤 곳인가
[★핵심정보] 기간 (시작~종료) · 운영시간
[★나열] 볼거리 · 참여 점포 · 프로그램
[프로모션] 오픈 혜택 · 이벤트 (선택)
[자료] 공간 · 상품 사진 (선택)
[위치 안내] 필수
[문의]
```
> 하루가 아니라 **기간**이 주인공. 반복 회기(주 2회 × 6주)면 `[나열]`에 회차표(§3).

#### 1-⑤ 예약
**P3 접수형** · 📝 접수 · ★ **회차 예약 버튼** (시간 · 정원)
　　┗ **정보 구조** **버튼 1개 = 세션 1개** 세로 반복 (시간·정원) — 달력 UI 아님
```
[헤더] 로고
[히어로] 무엇을 예약하나
[소개] 짧게
[핵심정보] 가격 · 소요시간 · 대상
[★예약] 회차 버튼
[안내 사항] 취소 · 환불 · 준비물
[자료] 사진 (선택)
[위치 안내] 조건부 (§3 고객 집 방문)
[문의]
```
> 🎟 **버튼 1개 = 예약 세션 1개.** 회차가 여러 개면 세션마다 카드를 따로 놓는다. 시안에서 달력·시간표 UI를 그리지 말 것 — 뷰어에선 일반 버튼과 같아 보인다.
> 시간 슬롯 배분형(픽업 시간대별 정원)도 이 칸.

#### 1-⑥ 부고·추모
**P2 초대형** · 📢 **알림** · ★ **장례 정보** (빈소 · 발인 · 장지)
　　┗ **정보 구조** `빈소 / 발인 / 장지` **다중 일정** 라벨+값 — 일정이 여러 개인 게 이 칸의 특징
```
[헤더] ❌
[히어로] 「부고」 + 고인 성함    (사진 ❌ · 무채색)
[소개] 별세 알림 문장
[★소개] 고인 · 상주 · 유족 관계
[★핵심정보] 빈소 · 발인 · 장지 (다중 일정)
[위치 안내] 장례식장
[안내 사항] 마음 전하실 곳(계좌) (선택)
[문의] 상주 연락처
[푸터] ❌ 두지 않는다 — 페이지는 연락처로 끝난다
```
> 🕯 **알림 톤 규칙 (필수)** — 문구 *"초대합니다"·"모십니다"* ❌ → *"삼가 알려드립니다"* · 축하 표현 전면 ❌ · 색 **무채색·저채도** · 이모지·애니메이션 ❌ · 버튼 *"신청하기"·"참석하기"* ❌ → **"조문 안내"·"위치 보기"** · 카카오톡 공유 썸네일 문구도 동일 톤.
> 📚 국내 모바일 초대장 서비스 **12곳 전수 확인 — 부고는 어디서도 「초대장」에 묶지 않는다.**
> **중간 톤**(조사는 아니지만 초대도 아님): 감사장 · 연하장 · 폐업/이전 안내 → 6-①

### 2. 프로필·명함 (4) — 전부 P6

#### 2-① 프로필 (링크 모음)
**P6 인물형** · ★ **링크 목록**
　　┗ **정보 구조** `그룹 제목 + 전폭 버튼 세로 반복` × **최대 3그룹**
```
[헤더] ❌
[★소개] 프로필 (사진 + 이름 + 한 줄) — 히어로 겸
[★나열] 링크 — 성격별 그룹 × 최대 3 (그룹 제목 + 버튼 세로 반복)
[자료] 대표 사진·영상 (선택)
[프로모션] 진행 중 이벤트 (선택)
[문의] 연락 버튼
[푸터] SNS
```
> 🔗 **링크를 하나의 'LINK' 제목으로 통째로 묶지 말 것** — 성격별로 나눠 각자 제목(예: 음악·채널 / 공연·굿즈 / 문의). **최대 3그룹** · 1개짜리 그룹이 2개 이상 나오면 병합 신호.
> 🏷 **섹션 타이틀은 「링크 모음」에만** — 프로필·갤러리·프로모션엔 제목을 붙이지 않는다(미니멀·자명성).
> 🚫 **구분선 없는 좌정렬 타이틀 ❌** — 가운데 전폭 버튼 스택이 뼈대라 제목만 왼쪽에 뜬다. `⑥좌18+긴선` 또는 중앙 타이틀.
> 🔑 채널 버튼 = **버튼 카드 세로 반복**(SNS 카드는 푸터 아이콘 묶음 전용).

#### 2-② 영업용 명함
**P6 인물형** · ★ **사람 + 하는 일 + 연락 수단**
　　┗ **정보 구조** 프로필 **＋** 분야 나열 **＋** 연락 버튼(저장이 주 CTA) — 셋이 한 묶음
```
[헤더] 로고 (회사)
[★소개] 프로필 (사진 + 이름 + 직함 + 소속) — 히어로 겸
[소개] 무엇을 하는가 (1~2줄)
[나열] 취급 분야 · 서비스
[자료] 대표 실적 · 납품처 (선택)
[스토리] 회사 비전 (선택)
[폼] 상담 신청 (선택)
[★문의] 연락처 저장(주 CTA) + 전화 · 유선 · 이메일
[위치 안내] (선택)
```
> 🎖 **연락처 저장(vCard) = 주 CTA** — 전화·이메일과 같은 무게로 두지 말 것(위계 = 채움 > 틴트 > Outlined).
> 🏷 **섹션 타이틀 무조건 국문 2단어** — 영문 아이브로(CONTACT·SERVICE·CAREER) ❌ → `대표 실적`·`업무 분야`·`상담 신청`.
> 🔤 **명조(serif) 금지 → 산세리프** (신뢰·격식이 핵심).
> ⚠️ 신뢰 근거가 자격증이 아니라 **취급 브랜드 + 납품처**인 경우가 많다(B2B).

#### 2-③ 포트폴리오
**P6 인물형 + P4 진열형** · ★ **작업물** (이미지 중심)
　　┗ **정보 구조** **이미지 갤러리**(그리드·캐러셀) + 프로젝트 설명 — 이미지가 면적 지배
```
[헤더] 선택
[★소개] 프로필 — 히어로 겸
[스토리] 무엇을 하는 사람인가 · 철학
[★자료] 작업물 갤러리 (반복)
[나열] 경력 요약 (짧게)
[문의] 협업·의뢰 문의
[푸터] SNS
```
> 🎨 **변형 3종**(칸을 나누지 않고 프리셋으로) — **이미지형** / **프로젝트형**(프로젝트당 1P · 멀티 4P) / **영상형**(유튜브 카드 나열 — 갤러리 카드와 다름).
> ⚠️ **경력을 길게 쓰면 2-④로 가야 한다** — 여기선 짧게.

#### 2-④ 이력서·경력 🆕
**P6 인물형** · ★ **시간순 경력 목록** (텍스트 중심)
　　┗ **정보 구조** `기간 + 소속 + 역할` **3열 시간순** — 이미지 거의 없음
```
[헤더] ❌
[★소개] 프로필 (사진 + 이름 + 직함) — 히어로 겸
[소개] 한 줄 요약
[★나열] 경력 (기간 + 소속 + 역할) — 시간순
[나열] 학력 · 자격 · 수상
[자료] 대표 결과물 (선택 · 소수만)
[문의] 연락
```
> 🔑 **2-③과의 갈림 = 「사진이 주인공 / 글이 주인공」**(갈림 질문 ⑤). 결과물이 **글**인 직군(번역·편집·집필·연구)은 갤러리가 주인공이 될 수 없다.
> 📚 근거 — 리멤버 프로필 필수 필드(이름·직무·회사명·**재직기간**) + 이전 경력·업무 상세·강의/자문·논문/저서·학력 = 정확히 이 구성.

### 3. 소개·홈페이지 (2)

> 🔴 **확장 여부 미결** → [[1-11. 대분류 재설계 (제안 초안)]] §19 쟁점 ①. 레시피를 쓰다 갈라지면 그때 나눈다.

#### 3-① 소개 홈
**P2 + P4 혼합** (종합형) · ★ **우리가 누구·무엇을 하는지**
　　┗ **정보 구조** 스토리 문단 **＋** 제공 항목 나열 — 섹션 수 자체가 많은 **종합형**
```
[헤더] 로고
[히어로] 공간 · 로고 · 대표 이미지
[★스토리] 브랜드·조직 소개
[소개] 대표 · 팀 (선택)
[★나열] 무엇을 제공하나 (서비스 · 프로그램 · 메뉴 요약)
[핵심정보] 요금 · 영업시간
[자료] 공간 · 활동 사진
[프로모션] 진행 중 이벤트 (선택)
[안내 사항] 이용 안내 (주차 · 예약 방법)
[위치 안내] 필수
[문의]
```
> 🧩 **27칸 중 유일한 종합형** — 다른 대분류의 유형을 **페이지 단위로 품는다.** 멀티페이지 본진.
> ```
> 아트갤러리 홈페이지 (3-①)
> ├ P1 홈       갤러리 소개 · 현재 전시
> ├ P2 전시      ← 1-④ 유형을 빌려옴
> ├ P3 작품      ← 6-③ 도록 유형
> └ P4 방문 안내  ← 1-⑤ 예약
> ```
> 🔑 **구 「이용·방문 안내」는 이 칸의 섹션 묶음**(위치·영업시간·주차·예약 방법)이지 별도 칸이 아니다. 멀티의 한 장으로만 존재한다.
> 🎯 **네이버 모두 종료(2025-06)로 고아가 된 소상공인 수요**가 정확히 이 칸.

#### 3-② 메뉴·가격 안내
**P4 진열형** · ★ **품목 + 가격 반복**
　　┗ **정보 구조** **2단 양끝정렬**(좌 품목 / 우 가격) **1행 반복**
```
[헤더] 로고
[히어로] 매장 분위기
[스토리] 간단 소개 (선택)
[★핵심정보] 메뉴 · 가격 — 2단 카드 양끝정렬 반복
[제품 설명] 시그니처 설명 ↔ 디테일컷 (선택)
[자료] 음식 · 공간 사진 (선택)
[안내 사항] 가격 기준 · 추가 요금
[위치 안내] · [문의]
```
> ⚠️ **2단 카드는 값이 짧은 1행일 때만.** 값이 줄바꿈되면 좌우 균형이 깨진다 → 스택형(라벨↵값)으로.
> 💡 **정찰제 선언형**(가격 공개로 불신 해소)이면 `[스토리]`에 「왜 공개하나」를 넣는다 — 이 경우 성과는 매출이 아니라 **통화가 짧아지는 것**.
> 🔑 **4-③ 카탈로그와의 갈림 = 「현장에서 파나 / 배송하나」**(갈림 질문 ①).

### 4. 상품·홍보 (6)

> 🛍 **브랜드형 공통** — 순서는 **히어로 → 브랜드 스토리 → 제품**. 제품·가격을 바로 나열하기 전에 *브랜드가 누구이고 왜 이 컬렉션인지*를 먼저 짧게 세운다. *(전환 최우선인 4-④는 예외 — 구매가 위, 스토리는 뒤.)*

#### 4-① 상품 상세
**P4 진열형** · ★ **제품별 상세 블록 반복**
　　┗ **정보 구조** **제품 1개 = 섹션 여러 개** — 갤러리→이름·가격→설명→스펙→실측→구매 세로 스택
```
[헤더] 로고
[히어로] 브랜드 첫인상 + 컬렉션 제목
[스토리] 브랜드 설명
[★제품 블록 반복] ─ 갤러리(여러 컷) → 이름·가격 → 설명 → 스펙/소재 → 실측 → 구매

[안내 사항] 배송 · 교환 · 환불
[위치 안내] · [문의]
```
> 🛍 **"상세 정보가 있어야 상세 페이지"** — 제품마다 ①**여러 컷**(모델·정면·측면·내부·디테일) ②**스펙 상세** 필수. **2단 그리드 상품 카드로 압축 ❌** → 제품별 **전폭 단일 컬럼**.
> 🔁 **상세(스펙·실측·소재)는 「각 제품 바로 아래」** — 페이지 뒤에 모으지 말 것(어느 제품 건지 끊긴다).
> 🚫 **상세를 품은 제품 프리셋을 쓰면 별도 상세 섹션 ❌**(중복).
> 🎠 **갤러리 표현 = 3안 차별화 레버** — 세로 나열 2 + 캐러셀 1. ⚠️ **제품당 이미지 4장 이상일 때만 캐러셀.**
> 💲 **텍스트 위계** — 상품명 18 Bold {텍스트색} / **가격 {버튼색} 강조** / 설명 {텍스트색}×70% / 스펙 라벨 100%·값 70%.

#### 4-② 룩북·컬렉션

[히어로] 대형 화보 + 컬렉션 제목
[스토리] 컬렉션 컨셉
[★룩 섹션 반복] ─ 타이틀 「LOOK N」 → 화보·누끼 이미지 → 룩 설명 1줄
[구매] 구매 링크 (선택)
[문의]
```
> 👗 **룩 하나 = 독립 섹션 · 타이틀 = `LOOK 1`·`LOOK 2`…**(영문 넘버형). 한 덩어리로 뭉치지 말 것.
> 🚫 **룩북엔 상세 정보(소재·치수·실측·스펙) ❌** — 그건 4-① 전용. 룩북은 **화보 + 컬렉션 설명**만.
> 🎠 갤러리 = 3안 중 1안 이상 캐러셀 (룩당 이미지 4장 이상일 때만).

#### 4-③ 카탈로그 🆕
**P4 진열형** · ★ **여러 품목 목록** (얕게 · 많이)
　　┗ **정보 구조** **품목 1개 = 카드 1장** — 이름 + 대표컷 + 1~2줄 (스펙 ❌)

[헤더] 로고

> 📊 **CdBd 실사용의 절반이 패션·리테일 시즌 카탈로그** — 4-①②③④ 중 물량이 가장 큰 구역.

[헤더] 발행 정보 · 헤드라인

[★나열] 소식컷 (제목 + 요약 + 이미지) 반복   또는   [★스토리] 기사 본문
[나열] 지난 호 · 연관 기사 (선택)
[문의] · [푸터] SNS
```

#### 6-③ 도록·작품집
**P4 진열형** · ★ **이미지 + 캡션 나열**
　　┗ **정보 구조** `이미지 + 캡션 4항목`(제목·작가·재료·크기) — **2단 양끝정렬**
```
[헤더] 전시명
[히어로] 전시 대표 이미지
[핵심정보] 전시 기간 · 장소 · 관람 시간
[스토리] 기획 의도 · 작가 노트 (선택)
[★자료] 작품 이미지 + 캡션(제목·작가·재료·크기) 반복
[위치 안내] 전시장
[문의] 관람 문의
```
> 🔑 **작품 캡션 = 2단 카드 양끝정렬**(좌 항목명 / 우 값) 또는 이미지 아래 텍스트 카드 2줄(제목 런 + 정보 런).
> 🔑 **6-②와의 갈림 = 「글이 주인공 / 이미지가 주인공」**(갈림 질문 ⑤ — 2-③↔2-④와 같은 축).

#### 6-④ 가이드·이용안내
**P1 알림형(긴 버전)** · ★ **단계·항목별 안내 반복**
　　┗ **정보 구조** `번호 + 제목 + 설명` **순서 반복** — 넘버링 필수
```
[헤더] 로고
[히어로] 가이드 제목
[핵심정보] 이용 시간 · 요금 · 대상
[★나열] 단계 · 항목별 안내 반복      ← 🔢 넘버링 필수
[자료] 시설 · 이용 사진 (선택)
[안내 사항] 주의사항 · 금지사항
[폼] 자주 묻는 질문 (Q&A)
[위치 안내] · [문의]
```
> 🔢 **넘버링 필수** — 가이드는 「순서·단계」가 핵심. 이용방법·준비물·커리큘럼 나열에 번호(01·02·03…). **3안 중 최소 1안은 넘버 대신 이모지**(차별화 · 예 준비물 🧴 / 단계 1️⃣).
> 🌏 **다국어 변주** — 언어별 섹션 반복 또는 멀티페이지를 언어로 분할 · 글보다 그림·번호·색(§3).
> 🔒 **내부 문서 변주**(직원·점주용) — 마케팅 톤 ❌ · 프로모션·SNS 제거 · 페이지 비밀번호.
