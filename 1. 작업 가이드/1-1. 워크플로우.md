# 신규 템플릿 기획 워크플로우

> 사용자가 새 템플릿 기획을 요청하면 아래 6단계를 순서대로 진행. 각 단계마다 **사용자 피드백 게이트**가 있으며, 게이트 통과 후에만 다음 단계로 넘어감.
>
> ⚠️ **본 워크플로우는 실제 작업하며 변경될 수 있음** — 변경 시 본 노트와 [[../CLAUDE.md|CLAUDE.md]]의 "신규 템플릿 기획 워크플로우" 섹션을 동시 업데이트할 것.

---

## 🗺 단계 개요

| #   | 단계               | 출력물                                       | 게이트          |
| --- | ---------------- | ----------------------------------------- | ------------ |
| 1   | 콘텐츠 기획           | 카테고리 · 주제 · 무드 · 색·폰트 결정                  | 기획 피드백       |
| 2   | 피그마 스켈레톤         | **디폴트 테마(fafafa/292929/프리텐다드)** 카드 구성 + 이미지 자리(주석) | 스켈레톤 피드백     |
| 3   | 피그마 이미지 채움 + 색·폰트 배리에이션 적용 | 완성된 피그마 화면 (이미지 + 무드 색·폰트 적용) | 피그마 완성본 피드백  |
| 4   | CdBd 에디터 구현      | 라이브 페이지 + OG + 제목 + 모바일 스크린샷              | CdBd 페이지 피드백 |
| 5   | 상세 페이지 콘텐츠 (피그마) | 카탈로그 상세 페이지 섹션                            | 상세 페이지 피드백   |
| 6   | CdBd 어드민 등록      | 라이브 등록 완료                                 | —            |

## 1단계 — 콘텐츠 기획

**목적**: 사용자가 요청한 카테고리·주제에 맞는 페이지 콘텐츠 구성을 결정.

### 입력
- 사용자 요청 (카테고리, 주제, 톤·앤·매너 등)

### 작업
- **카테고리 선정** (5종 중 1개)
  - 카테고리 미충족 분야 우선 고려:
    - 🚨 소식·매거진 (0개)
    - 가이드·신청 (1개)
- **무드 결정** → [[1-2. 색상 팔레트]] + [[1-3. 폰트]] 9개 무드 동일 → 무드 1개 결정 시 색·폰트 동시 선정
  - ⚠️ 무드·색·폰트는 1단계에서 **결정**만 하고, 실제 **적용**은 3단계에서. 2단계 스켈레톤은 디폴트 테마로 제작.
- **페이지 콘텐츠 기획** — 어떤 정보를 어떤 순서로 배치할지 초안 작성 (텍스트 위주, 카드 단위 분리)

### 출력
- 카테고리 · 주제 · 무드 · 페이지 콘텐츠 초안 (색·폰트 결정값은 3단계에서 적용)

### 게이트
- → **사용자 기획 피드백**

---

## 2단계 — 피그마 스켈레톤 제작

**목적**: 실제 CdBd 카드 속성만 사용해서 페이지 구조를 피그마에 빠르게 시각화. **이미지 없이** 카드 구성과 레이아웃만 확인.

### 🎨 디폴트 페이지 테마 사용 (필수)

스켈레톤 단계에서는 **CdBd 디폴트 테마**를 고정으로 사용한다. 색·폰트 배리에이션은 3단계에서 일괄 적용.

| 역할 | 값 | 출처 |
|---|---|---|
| `{배경색}` | `#fafafa` | [페이지 색상 프리셋 #1] |
| `{텍스트색}` | `#292929` | [페이지 색상 프리셋 #1] |
| `{버튼색}` | `#292929` | [페이지 색상 프리셋 #1] |
| **버튼 텍스트색** | **`#fafafa` (= `{배경색}`)** | CdBd 라이브 자동 매핑 |
| 서체 | **프리텐다드** (Pretendard) 단일 | [페이지 서체 기본값] |
| 버튼 모양 | **원형 99px (pill)** | [페이지 버튼 모양 #1] |

> **🔘 버튼 텍스트 색 규칙 (필수)**: **버튼 텍스트 색 = `{배경색}`** 고정. CdBd 라이브 버튼은 `버튼 배경 = {버튼색}` · `버튼 텍스트 = {배경색}` 매핑으로 렌더링되므로, 2·3단계 시안도 동일하게 작성. 흰색 고정 · 별도 hex · `{텍스트색}` 사용 ❌ — 사용자가 테마 한 번 바꾸면 어긋남.

### 📝 텍스트 속성 분리 규칙 (필수)

**다른 텍스트 속성 = 다른 카드로 분리**. 한 텍스트 카드 안에 다른 속성(사이즈·Bold·정렬·색·줄간격)을 가진 텍스트를 섞지 말 것.

| 잘못된 예 | 올바른 예 |
|---|---|
| 한 카드 안에 "제목(24px Bold) + 본문(16px Regular)" 섞기 | 카드 2개 분리: 제목 카드 / 본문 카드 |
| 한 카드 안에 "본문(텍스트색 100%) + 보조설명(텍스트색 60%)" 섞기 | 카드 2개 분리: 본문 카드 / 보조설명 카드 |
| 한 카드 안에 좌정렬 + 중앙정렬 혼합 | 카드 2개 분리 |

**이유**:
- CdBd 텍스트 카드는 **카드 단위로 속성을 가짐** — 한 카드 안에서 인라인 속성 혼합 불가
- 시안에서 섞어 그리면 4단계 에디터에서 재현 불가
- 5대 원칙 #2(텍스트 카드 분리)의 시안 단계 적용

### 📐 Auto Layout 구조 규칙 (필수) — CdBd 카드 내부/외부 여백과 1:1 매핑

피그마 시안을 CdBd로 쉽게 옮기기 위해, **피그마 Auto Layout 속성이 CdBd 카드 옵션과 동일하게** 작동하도록 구조를 잡는다.

#### 페이지·카드 구조

| 레이어 | Auto Layout 설정 | 매핑 |
|---|---|---|
| **페이지 프레임** | `vertical` · `gap=0` · `padding=0` | CdBd는 페이지 자체에 패딩·gap 옵션 없음 |
| **카드 (페이지 직접 자식)** | `vertical`로 페이지에 쌓임 · 카드 간 gap=0 | CdBd 카드 보드 배치와 동일 |
| **카드 내부 여백** | 카드 프레임 자체에 `padding` 추가 | = CdBd 「카드 내부여백」 슬라이더 (0~40, 2단위) |
| **카드 외부 여백** | 카드를 **부모 Auto Layout 프레임으로 한 번 더 감싸고** 부모 프레임에 `padding` 추가 | = CdBd 「카드 외부여백」 슬라이더 (0~40, 2단위) |

#### 카드 간 여백 처리

- **상하 여백 조정** — 인접 카드의 외부여백 padding을 조정
- **여백 카드 삽입** — 빈 프레임(혹은 구분선 카드 두께 0) 사용
- ❌ **페이지 gap 사용 금지** — CdBd는 페이지 gap 옵션이 없으므로 4단계에서 재현 불가
- ❌ **카드 사이 임의 spacer 컴포넌트 금지**

#### 금지 사항

| ❌ 하지 말 것 | 이유 |
|---|---|
| 카드 자체에 margin 추가 (피그마는 margin 개념 없음, gap으로 흉내) | CdBd 외부여백과 매핑 안 됨 → wrapper 프레임 padding 방식만 사용 |
| 페이지 프레임에 padding 적용 | CdBd 페이지 자체에 padding 옵션 없음 |
| 페이지 프레임 gap 사용 (예: gap=16) | CdBd 페이지 gap 없음 → 카드별 외부여백으로 분산 표현 |
| 카드 외부에 절대 위치 요소 | CdBd는 absolute positioning 불가 |
| 한 카드 안에 자식 frame을 manual position | 모든 카드 내부 구조도 Auto Layout |

#### 예시

```
✅ 올바른 구조
페이지 프레임 (vertical, gap=0, padding=0)
├─ 카드1 wrapper (padding 16 = 외부여백 16)
│  └─ 카드1 (padding 20 = 내부여백 20)  ← 텍스트 카드
├─ 카드2 wrapper (padding 0 = 외부여백 0)
│  └─ 카드2 (padding 24 = 내부여백 24)  ← 이미지 카드
└─ 여백 카드 (높이 32, 빈 프레임)
   └─ 카드3 wrapper (padding 16)
      └─ 카드3 (padding 20)
```

> **목적**: 4단계 CdBd 에디터로 옮길 때, 피그마 frame padding 값을 그대로 CdBd 카드 내부/외부 여백 슬라이더에 입력하면 1:1 재현됨.

### 🎯 단일 depth 예외 — 배경·테두리 없는 카드 (필수)

**배경(fill)도 테두리(stroke)도 없는 카드는 wrapper를 만들지 말 것.** 카드 자체 단일 depth에만 padding을 부여하고, **CdBd 에디터에서는 "카드 내부여백" 슬라이더 1개로 관리**한다 (외부여백 0).

#### 이유

- 배경·테두리가 없으면 시각적으로 "카드 안과 밖"의 경계가 보이지 않음 → 내부여백과 외부여백이 시각적으로 구분 불가
- 사용자가 두 군데(외부+내부)에서 같은 시각 효과를 위해 여백을 조정해야 한다면 의미 없는 작업 → 단일 슬라이더로 통합 관리
- 5대 원칙 #1(범용성·편집 용이성)에 직결

#### 적용 매트릭스

| 카드 유형 | 피그마 구조 | CdBd 매핑 |
|---|---|---|
| **배경/테두리 없음** (대부분의 텍스트·이미지·버튼 카드) | 카드(단일 depth) — `padding`만 | "카드 내부여백" 슬라이더 1개 |
| **배경 또는 테두리 있음** (카드 배경 색 / outlined 카드 등) | wrapper(외부) → 카드(내부) — 두 depth | "외부여백" + "내부여백" 2개 슬라이더 |

#### 합쳐진 padding이 슬라이더 max를 초과할 때

- CdBd 슬라이더는 0~40px 범위 (2단위) → 합친 padding이 40을 초과하면 **40으로 cap**
- 시각적으로 더 큰 여백이 필요하면 **여백 카드(빈 프레임)** 를 인접에 삽입해서 분산
- 예: 첫 카드 padding-top 60 → 카드 padding-top 40 + 위에 높이 20 빈 프레임 카드 추가

#### 변환 예시 (배경 없는 카드 collapse)

```
변환 전 (두 depth):
페이지 (gap=0, padding=0)
├─ wrapper (padding-top=8, bottom=8, l=20, r=20)
│  └─ 텍스트 카드 (padding-top=12, bottom=12, l=20, r=20, bg❌)

변환 후 (단일 depth):
페이지 (gap=0, padding=0)
└─ 텍스트 카드 (padding-top=20, bottom=20, l=40, r=40, bg❌)
   ↑ wrapper padding + card padding 합산, max 40 cap
```

> **목적**: 사용자가 CdBd 에디터에서 한 슬라이더만 만지면 되도록 — 시각적으로 의미 없는 외부/내부 구분을 강제하지 않음.

### 📐 여백 우선순위 규칙 (필수) — 카드 padding 우선, 여백 카드는 예외

**여백을 설정할 때는 우선순위에 따라 결정**:

1. **1순위 — 4면 비슷한 padding** (top≈bottom≈left≈right)
   - 카드 padding을 4면 모두 비슷한 값으로 설정 (예: (24, 24, 20, 20) · (14, 14, 20, 20) · (8, 8, 12, 12))
   - 인접 카드와의 시각 간격은 **두 카드의 인접 padding 합**으로 자연스럽게 형성
   - 별도 spacer 카드 ❌

2. **2순위 — top=bottom symmetric** (4면 비슷이 불가능할 때)
   - 4면을 똑같이 못 맞춰도 **상/하만큼은 동일하게** (예: (8, 8, 20, 20))
   - 이유: 카드 삭제 시 시각 균형 유지 (텍스트 카드 분리의 목적은 사용자가 필요 없는 카드를 **삭제**해서 템플릿을 쓸 수 있게 하기 위함)
   - 비대칭 사례 (top=20, bottom=4 같이) — 그 카드를 삭제하면 시각 균형 깨짐

3. **3순위 — 여백 카드 (예외)**
   - 위 두 가지로 표현 불가능할 때만 사용
   - 주된 용도: **intra-section tight spacing** (분할된 텍스트 카드 사이 4~8px) — padding 합으론 표현하기 어려운 미세 간격
   - 페이지 단위 큰 간격을 굳이 여백 카드로 표현 ❌ → 1순위로 해결

#### 「여백 카드」 정의 — 구분선 카드 두께 0

- **CdBd 에디터에서**: **구분선 카드**를 추가하고 **두께 0**으로 설정. 카드는 보이지 않지만 카드 외부여백만큼의 공간 확보. 카드 외부여백 슬라이더를 사용해 원하는 높이 조정.
- **피그마 시안에서**: 빈 Auto Layout 프레임 (`fills=[]`, padding=0, 고정 height) 사용. 네이밍 `여백 — {용도}` (예: `여백 — 분할 카드 사이`)
- **표준 height 권장값** (intra-section 용도, CdBd 외부여백 슬라이더 0~40 범위 내):
  - 분할 텍스트 카드 사이: **4~8**
  - 그룹 내 미세 분리: **8**

#### 🟢 예외 — 페이지 최상단·최하단 카드는 asymmetric 허용

**페이지의 첫 카드와 마지막 카드는 4면 비슷 규칙의 예외**. 이 위치엔 삭제될 인접 카드가 없어 균형이 깨질 위험이 없기 때문.

- **첫 카드(페이지 최상단)**: `padding-top`을 크게 줘도 됨. 페이지 상단 여백을 이 카드의 top padding으로 흡수 (별도 spacer 불필요).
- **마지막 카드(페이지 최하단)**: `padding-bottom`을 크게 줘도 됨. 페이지 하단 여백을 이 카드의 bottom padding으로 흡수.
- **표준 권장값**:
  - 첫 카드 padding-top: **24~40**
  - 마지막 카드 padding-bottom: **24~40**
- 중간 카드는 무조건 **1순위(4면 비슷) → 2순위(상/하 symmetric)** 우선 — 이 예외를 일반화하지 말 것.

```
✅ 1순위 (4면 비슷) 권장 패턴 — 모든 카드 padding으로 간격 해결, spacer 없음
페이지
├─ 프로필 카드 (padding 24/24/20/20)       ← top=24 페이지 상단 흡수 + bottom=24 인접 간격 흡수
├─ 일시 카드 (padding 14/14/20/20)         ← 4면 비슷 (14+14=28 → 이전 카드와 합쳐 38 시각 간격)
├─ 장소 카드 (padding 14/14/20/20)
├─ 갤러리 카드 (padding 14/14/20/20)
├─ ...
├─ 마지막 버튼 (padding 14/36/20/20)        ← bottom=36 페이지 하단 흡수
```

```
✅ 3순위 (여백 카드) 적용 예 — intra-section tight spacing
페이지
├─ ...
├─ 일시 카드 (padding 14/14/20/20)
├─ 여백 — 분할 카드 사이 (height 4)         ← intra-section 미세 분리만 spacer
├─ 장소 카드 (padding 14/14/20/20)
├─ ...
```

#### 변환 예시 (구버전 symmetric+spacer → 신버전 4면 비슷)

```
❌ 구버전 (spacer 남용)
페이지
├─ 프로필 카드 (padding 24/4/20/20)        ← bottom=4 (인접 spacer 의존)
├─ 여백 — 섹션 구분 (height 20)             ← 불필요한 spacer
├─ 일시 카드 (padding 4/4/20/20)            ← top/bottom=4 (spacer 의존)

✅ 신버전 (padding으로 흡수)
페이지
├─ 프로필 카드 (padding 24/24/20/20)       ← bottom=24 (spacer 흡수)
├─ 일시 카드 (padding 14/14/20/20)         ← 4면 비슷
```

> **이유 재강조**: 카드 단위 복제·삭제·재배치가 자유로워야 한다는 본 워크플로우의 5대 원칙 #1(범용성)에 직결. 카드는 항상 "자체로 시각 균형이 잡힌 단위" 여야 함. 4면 비슷 padding은 균형이 가장 잘 유지되는 패턴.

이유:
- 색·폰트 선정과 구조 검토를 **분리** → 스켈레톤 게이트에서는 "콘텐츠 흐름·카드 구성"에만 집중
- 디폴트 테마는 모든 무드에 중립 → 구조 평가 시 색이 판단 흐릴 일 없음
- 3단계에서 무드별 색·폰트 입혔을 때 디폴트 대비 변화량을 한눈에 확인 가능

### 🃏 카드 디자인 옵션은 CdBd 제공값 범위 내에서 조정 (필수)

**디자이너가 조정 가능**: 간격 · 모서리 · 버튼 모양 · 정렬 · 텍스트 사이즈 · 패딩 등 모든 카드 디자인 옵션은 **시안 의도에 맞게 의도적으로 조정**한다.

#### 시안 작성 룰
- ❌ **임의값 금지** — CdBd 슬라이더·세그먼트에 없는 값 (예: 모서리 6px·8px·12px / 카드 내부여백 21px / Q&A 질문 간격 18px) 적지 말 것
- ✅ **시안 의도 표현 OK** — default를 벗어나는 조정은 시안 의도에 맞게 자유 (예: 페이지 톤이 부드러우면 버튼 모양 "원형" → "둥근 16px", 카드 모서리 "각진" → "둥근", 카드 내부여백 20 → 28)
- ✅ **default 외 값은 시안 주석** — 어떤 옵션을 바꿨는지 4단계 에디터 구현 시 재현하기 위해 표기 권장 (예: "버튼 모양: 둥근 / 카드 모서리: 둥근 / 갤러리 단 수: 3")

#### 🔒 Q&A 카드 — 디자이너 조정 가능 옵션은 **3가지뿐**

Q&A 카드는 다른 카드와 달리 **사용자가 디자인보드에서 조정할 수 있는 옵션이 제한적**이다 ([[4-10. 질문과 답변 카드#디자인 탭]] 참조). 시안에서도 동일하게 다음 3가지만 조정한다.

| 조정 가능 | 옵션 |
|---|---|
| ✅ **텍스트 크기** | 제목·질문·옵션 사이즈 슬라이더 (12~60, 16단계) |
| ✅ **정렬** | 좌·중(default)·우 |
| ✅ **질문 간 간격** | 16·24·32(default)·40 |

**Q&A 카드 구성 규칙 (추가)**:
- **제목은 한 카드당 1개만** — 복수 제목 불가. 여러 주제 합치려면 한 카드에 하나의 통합 제목 사용
- **질문 자동 넘버링 없음** — "Q1.", "Q2." 같은 표기는 시안에 추가하지 않음. 질문 텍스트만 표시
- **필수(\*) 표시는 질문별 토글** — 4-10 §질문 목록 "필수 ON/OFF" 옵션. 필수 ON이면 질문 텍스트 끝에 `*` 표시. 시안 작성 시 어떤 질문이 필수인지 결정해서 표기
- 유형: 직접 만들기 / 상담 신청서 / 만족도 조사 / 사전 참석 신청서 — 직접 만들기 default. 프리셋 선택 시 자동 질문 셋 추가 ([[4-10. 질문과 답변 카드#질문 목록 탭]])

## 3단계 — 피그마 이미지 채움 + 색·폰트 배리에이션 적용

**목적**: 스켈레톤 피드백 반영 후 **실제 이미지 추가**와 **1단계에서 결정한 무드 색·폰트 적용**을 함께 수행하여 완성된 페이지 화면 제작. 사용자 선택을 위해 **3가지 무드 시안**을 가로로 나란히 제작.

### 🎨 3가지 시안 작성 규칙 (필수)

3단계는 **3가지 무드 시안을 동시에 작성**해서 사용자가 비교·선택할 수 있게 한다.

#### 시안 구성 원칙

| 항목 | 규칙 |
|---|---|
| **시안 수** | **3개 고정** (시안 A·B·C) |
| **무드 선정** | 1단계 추천 무드 후보 + 차별 무드 1개를 합쳐 3가지. **밝은 톤 2개 + 다크 톤 1개**가 권장 (시각 다양성·차별화) |
| **색상 팔레트** | 각 시안 1개 팔레트 — [[1-2. 색상 팔레트]] 무드별 추천 팔레트에서 선정. WCAG 3.6:1 재검증 |
| **폰트** | 각 시안 1~2종 — [[1-3. 폰트]] 무드별 추천 폰트에서 선정. 한 페이지 1~2개 원칙 유지 |
| **이미지** | 각 시안 무드 톤에 맞춰 [[1-4. 이미지]] 규칙대로 (Thiings 3D / Google Flow 실사 / 사진 자산). 이미지 자리는 무드 톤 색상 패치로 placeholder 채우고, 시안 선택 후 실제 이미지 생성도 가능 |
| **2단계 스켈레톤** | **그대로 유지** (지우지 않음) — 복제해서 작업. 시안과 스켈레톤 비교 가능하게 |
| **배치** | 3개 시안 모바일 프레임을 **가로로 나란히** 배치 (380 × N, 좌→우 A·B·C). 시안 라벨 상단 표기 |
| **시안 라벨** | `시안 A — 🌸 페미닌/로맨틱 · HappyHues 15 · 본명조` 형식 (무드 + 팔레트명 + 폰트명) |

#### 시안 ↔ 2단계 정합

- **카드 구조 그대로** — 2단계에서 확정한 카드 구성·순서·옵션 조정값(모서리·간격)을 시안에 그대로 적용
- **변경되는 것은 색·폰트·이미지만** — 새 카드 추가·삭제·구조 변경 ❌
- 카드 디자인 옵션(둥근 16 등)은 2단계 결정값 유지

#### 색·폰트 적용 매핑

| 디폴트 (2단계) | 시안 (3단계) |
|---|---|
| 배경 `#fafafa` | 팔레트 배경 hex |
| 텍스트 `#292929` | 팔레트 텍스트 hex |
| 버튼 `#292929` | 팔레트 버튼 hex |
| **버튼 텍스트 `#fafafa` (= 배경색)** | **팔레트 배경 hex (= `{배경색}`)** — 항상 배경색과 동일 |
| 보조 텍스트 (텍스트색 × N%) | 팔레트 텍스트 hex × N% (그대로) |
| 프리텐다드 | 무드 추천 폰트 |

> **🔘 버튼 텍스트 색 = `{배경색}`** (필수). CdBd 라이브 매핑(버튼 배경 = `{버튼색}` / 버튼 텍스트 = `{배경색}`)을 시안도 그대로 따라야 함. 흰색 고정·별도 hex·`{텍스트색}` 사용 ❌. 사용자가 무드 한 번에 교체 시 따라오게 유지.

- 사용자가 1개 시안 선택

## 4단계 — CdBd 에디터 구현

**목적**: 피그마 최종 화면을 실제 CdBd 라이브 에디터에서 구현 + 등록에 필요한 부가 메타 설정.

### 작업
1. **라이브 에디터 페이지 제작** — [[1-5-1. CdBd 에디터]] 가이드 준수
   - 피그마 카드 구성을 1:1로 옮김
   - 테마 변수(`{버튼색}`·`{배경색}`·`{텍스트색}`) 적용
   - 카드별 default 기능 신뢰
   - 🎨 **페이지 테마 첫 변경 시** — "기존 설정을 덮어씁니다" 경고 모달의 **「이 페이지에서 앞으로 경고 보지 않기」 체크박스 무조건 ON** → 변경 진행. 이후 같은 페이지에서 테마 조정 반복해도 모달 안 뜸. 멀티페이지면 페이지마다 1회씩. ([[1-5-1. CdBd 에디터#🚨 페이지 테마 변경 시 — 경고 모달 처리 (필수)]])
2. **OG 이미지 설정** (에디터 헤더 「URL 생성하기」 우측 URL 정보 편집 모달) — 규격·디자인 규칙은 [[1-5-1. CdBd 에디터#🖼️ OG 이미지(썸네일) 규칙]] 준수 (800×400, 1배수 JPG, 기본 로고 타입 면적 9-10%)
3. **페이지 제목 설정**

### ⚡ 4단계 속도 최적화 — 5가지 규칙 (2026-06-22)

피그마 → 에디터 전이 시간을 줄이는 규칙. **실행 순서가 중요** — 아래 순서대로.

#### 규칙 1: 피그마 → 카드 매니페스트 추출 (시작 전 필수)

`use_figma`로 확정 시안 프레임의 레이어 트리를 1회 순회 → 카드 구성을 JSON으로 뽑는다. 눈으로 재해석할 필요가 없어지고 텍스트 오타·사이즈 누락·여백값 오입력이 제거됨. 이 JSON이 규칙 2~5의 공통 입력.

```json
[
  {"type":"text","label":"회사명","content":"ABC 컴퍼니","size":24,"bold":true,"align":"center","padInner":[24,24,20,20],"lineHeight":160},
  {"type":"image","label":"로고","srcNode":"123:45","ratio":"1:1","shape":"원형","padInner":[20,20,20,20]},
  {"type":"button","label":"지원하기","content":"지금 지원하기","shape":"둥근","padInner":[14,14,40,40]},
  {"type":"divider","label":"여백","thickness":0,"padOuter":[4,4,0,0]}
]
```

#### 규칙 2: 페이지 테마 먼저, 카드 나중

카드 1개도 추가하기 전에 **테마(배경·텍스트·버튼·폰트·버튼모양) + "경고 보지 않기" ON**을 완료. 이후 추가되는 카드가 테마를 상속 → 카드별 색 지정 작업이 사라짐.

#### 규칙 3: 이미지 자산 일괄 사전 준비

매니페스트의 `srcNode` 기준으로 **피그마에서 모든 이미지를 투명 PNG 일괄 export** ([[1-5-1. CdBd 에디터#✂️ Figma 노드 투명 배경 PNG export]] rawImages 패턴) → `/tmp/{label}.png` 저장. 카드 생성 시점에 onDrop 직접 호출로 업로드. "찾기 → 받기 → 올리기" 왕복이 배치 1회로 줄어듦.

> **⚠️ Temp 파일 정리 필수**: `/tmp/{label}.png`는 업로드 완료 직후 `rm /tmp/{label}.png`. 규칙 4 드라이버 스크립트 안에서 업로드 직후 rm 포함.

#### 규칙 4: 카드 일괄 생성 (드라이버 패턴)

매니페스트 JSON을 입력받아 `type`별 카드 추가 → 텍스트/속성/이미지 설정을 순서대로 실행하는 **재사용 드라이버 스크립트**. 13가지 자동화 함정 해법이 내장. `/skillify`로 codify하면 다음 템플릿부터 즉시 실행.

드라이버 스크립트 책임:
1. 카드 추가 (위→아래 순서, modal-scoped selector)
2. 텍스트 입력 (Lexical: Meta+A×2 → Backspace×2 → type/Enter 한 줄씩)
3. 속성 설정 (Bold · 사이즈 · 정렬 — `getComputedStyle.visibility==="visible"` 필터)
4. 이미지 업로드 (onDrop 직접 호출) → 완료 후 `/tmp/{label}.png` rm
5. 카드 라벨 설정 (label-value 클릭 패턴)
6. 순서 조정 필요 시 dnd-kit `onDragEnd` 직접 호출

#### 규칙 5: 종단 1회 diff 검증 (카드별 루프 ❌)

일괄 생성 완료 후 **모바일 프리뷰 전체 스크린샷 1장**을 피그마 시안 export와 나란히 비교. 어긋난 카드만 사후 수정. 기존 "카드 단위 스크린샷 검증" 직렬 루프(기존 권장 원칙 #2)는 드라이버 패턴에서 해제.

> 이유: 카드 추가는 append-only(위→아래 순서)라 중간 오염 위험이 낮음. 종단 1회 diff로 어긋난 카드를 한 번에 파악해 일괄 수정이 더 빠름.

### 🚨 4단계 자동화 시 주의사항 (2026-06-18 기록)

CdBd 에디터의 mobile preview · 카드 보드 · 우측 패널 · 모달은 **모두 같은 DOM 트리에 공존**. 잘못된 selector·focus는 의도치 않은 곳에 입력을 보낸다. **검증 없는 다단계 자동화는 데이터 오염 위험**.

#### 권장 작업 패턴
1. **카드는 위→아래 순서로 "추가만"** — 사용자 인사이트: "위부터 순서대로 추가만 하면 되는데 왜 드래그앤드롭?". 드래그앤드롭 자동화 회피.
2. **카드 단위로 작업 → 매 단계 스크린샷 검증 → 다음 단계** — 한꺼번에 다단계 진행하지 말 것.
3. **자동화 가능 영역**: 카드 추가/순서, 텍스트 콘텐츠 변경(Lexical), 우측 패널 토글(Bold/사이즈/정렬), 모달 input(Playwright `$B fill`), 캘린더 날짜 선택.
4. **수동 위임 권장**: 카드 디자인 세부값(배경색/패딩/모서리), 카드 reorder(드래그), 카드 라벨 inline edit, 이미지 업로드(파일 시스템).

#### 발견된 자동화 함정 13가지 → [[1-5-1. CdBd 에디터#🤖 CdBd 에디터 자동화 함정]]

대표 함정:
- "last contenteditable" focus = 인사팀 버튼 텍스트 (mobile preview 최하단). 결과: 의도치 않게 버튼 텍스트 덮어쓰기
- 카드 라벨 ✏️ pencil 우발 활성화로 라벨 오염 (예: "이미지" → "2026 ABC 컴퍼니 채용...")
- React form state(react-hook-form)는 native input setter로 갱신 안 됨 → `$B fill` 사용 필요
- 카드 추가 모달 누적 오픈 + ESC 안 먹음 → 명시적 X 버튼 click (`div.absolute.right-\\[24px\\].top-\\[30px\\]`)
- Q&A 질문 유형 변경 in-place 불가 → 삭제 후 신규 추가만 가능 (신규는 마지막에 배치 → reorder 수동)
