## 1단계 — 콘텐츠 기획 + 기획 문서 작성

**목적**: 카테고리·주제·타겟·무드(방향)를 정하고, claude.ai/design에 넣을 **기획 문서(개방형 디자인 명세)**를 작성.

- **카테고리 + 세부 카테고리** 선정 — 4대분류 × 세부 4 = 16개 ([[1-9. AI 유저 플로우]] ①②단계와 동일 축). 미충족 우선: 🚨 소식·매거진 0개 / 가이드·신청 1개
- **무드 방향** 결정 (9무드 중 1 — 색·폰트는 지정하지 않고 **방향만**)
- 🔀 **페이지 유형(원/멀티)은 여기서 정하지 않는다** — 2단계 ⓐ에서 **양쪽 안을 만들어 보고** 고른다. 기획 문서에 "원페이지"/"멀티페이지"를 못박지 말 것.
- **기획 문서 작성**: [[1-2. 기획 문서 템플릿]] (= 생성 계약 Part A + 브리프 양식 Part B) 복사 → `{slug} — 기획.md` → **Part B**(**콘텐츠 인벤토리** + 무드 방향)만 채움. 🧩 **카드 구조·순서·타입은 지정하지 않음(개방)** — 담을 정보(WHAT)만 넣는다. Part A(생성 계약)는 고정.
- **🔓 개방형 명세 (필수, 2026-07-06)**: 색 팔레트·폰트 **+ 카드 구성·순서·레이아웃**을 **지정하지 않는다.** claude.ai/design이 무드 방향에 맞게 **자유 탐색**하도록 열어둔다 (색·폰트만 다른 결과 방지 → 구조가 다른 시안). 단 3토큰 모델·WCAG 3.6:1·버튼텍스트=배경·1~2폰트·국문=한글 + **평면 카드 스택·15카드·카드 고정 스펙** 규칙은 생성 계약이 강제 → CdBd-legal 유지.
- **🎨 변주 축 (2026-07-06)**: 시안마다 **① 도입/히어로 ② 정보 밀도 ③ 이미지 비중 ④ 카드 타입 선택 ⑤ 섹션 순서·강조**에서 최소 3개 이상 다르게. 풀 축·문구는 [[1-2. 기획 문서 템플릿]] Part A 📤 (콘텐츠 인벤토리·기능상 고정 카드는 시안 공통 — 변주 대상 ❌).
- **게이트**: 기획 피드백

## 2단계 — Claude Design 시안 생성 (ⓐ 페이지 유형 → ⓑ 3안)

**목적**: 기획 문서를 claude.ai/design에 넣어 시안 생성. (옛 피그마 수작업 스켈레톤·색폰트 시안 대체)

⚠️ **생성은 브라우저(claude.ai)에서 사용자가** 한다 — 코드가 생성을 트리거하는 도구는 없음. 코드는 결과를 **DesignSync로 pull**하는 쪽(읽기).

### ⓐ 페이지 유형(원/멀티) 결정 — 묻지 말고 보여준다 (2026-07-10 신설)

- 기획 문서로 **같은 디자인의 원페이지 안 1개 · 멀티페이지 안 1개**를 만들어 **나란히 놓고 비교** → 유형 확정.
- ✅ **디자인은 동일, 구조만 다르게** — 색·폰트·무드를 두 안이 똑같이 가져가야 **유형 차이만** 보인다. (무드 비교는 ⓑ에서.)
- ✅ **모든 세부 카테고리가 두 안을 만든다** — "이건 원페이지 전용" 예외 ❌. 짧아 보이는 페이지(공지·개인 맞춤 초대장·프로필 페이지)도 멀티 안을 만들어 보여준다. 다만 [[1-8. 섹션 프리셋 라이브러리]]가 **"원페이지가 기본값에 가깝다"**는 힌트를 레시피에 달아둔 경우가 있다.
- **멀티 = 원페이지 조립 + 페이지 분할 + 내비게이션**(표지 목차 + 서브페이지 복귀 헤더). 분할 방식 = 각 레시피의 `▸ 멀티페이지` 블록.
- **게이트**: **페이지 유형 선택** (원 / 멀티)

> 🔗 [[1-9. AI 유저 플로우]] ④단계와 같은 장치. 옛 "카테고리 가중치(원2:멀티1)로 자동 결정"은 **2026-07-10 폐기**.

### ⓑ 시안 3안 — 확정된 유형 안에서

- **기획 문서 전체(Part A+B)를 claude.ai/design에 붙여넣어** 시안 생성.
- 색·폰트 **+ 카드 구성**이 열려 있으므로 **구조가 다른 여러 시안**을 생성해 비교·선택 (색·폰트만 다른 결과 ❌). 시안마다 변주 축(도입/정보밀도/이미지비중/카드타입/순서)에서 최소 3개 이상 다르게 — 위 1단계 🎨 참조.
- 🧩 **섹션 프리셋 재사용**: 검증된 섹션 배리에이션(히어로·일시·라인업 등)은 [[1-8. 섹션 프리셋 라이브러리]]에 축적 → 시안을 0에서 만들지 않고 **섹션 프리셋을 골라 조립 + 무드(색·폰트) 교체**로 재사용.
- **게이트**: 시안 선택 (1개 채택 또는 혼합 대상 다수 선택)

> 💸 **생성 횟수 = 원/멀티 2 + 3안 3 = 최소 5회.** ⓐ 때문에 2단계 비용·시간이 늘어난다. 무인 파이프라인 예산 산정 시 반영할 것.

## 3단계 — Figma 반입 + 채택·혼합·수정 + 무드 색·폰트·이미지 확정

**목적**: 선택 시안을 Figma로 가져와 Claude Code가 다듬고, 무드 색·폰트·실제 이미지를 확정.

- **반입**: 선택 시안 HTML을 `DesignSync get_file`로 pull → Figma 반입.
- **채택·혼합·수정 (Claude Code)**: 여러 시안의 좋은 부분 결합, **CdBd-legal 정합 확인**(평면 스택·15카드·카드 고정 스펙·평탄화).
- **무드 색·폰트 확정**: 1단계 무드에 맞춰 [[1-3. 색상 팔레트]](3토큰, WCAG 3.6:1·버튼대비 재검증) + [[1-4. 폰트]](1~2개, 국문=한글) 적용.
- **이미지 생성**: [[1-5. 이미지]] 규칙 (OpenAI gpt-image-1 · Thiings 3D · Unsplash).
- **게이트**: 완성본 피드백

## 4단계 — CdBd 에디터 구현

**목적**: 완성 시안을 CdBd 라이브 에디터에서 구현 + OG·제목.

- [[1-6-1. CdBd 에디터]] 가이드 준수. 자동화 = skill `cdbd-card-automation` / `cdbd-editor-pipeline`.
- 🖼 **OG 이미지** = F2 마무리 에이전트 `.claude/agents/cdbd-edit-f2-finalize.md` 「OG 이미지 체크리스트」 (기본 로고 타입, 800×400 1배수 JPG, 면적 9~10%).
  - 📍 **제작 위치(필수, 2026-07-10)**: 별도 Figma 파일·페이지 ❌ → [등록 파일](https://www.figma.com/design/oi8zIHLfy59O5zV8aysqq4/CdBd-%ED%85%9C%ED%94%8C%EB%A6%BF-%EB%93%B1%EB%A1%9D?node-id=1079-1064)의 **해당 템플릿 「사례 기획」 섹션 안**에 OG 프레임(800×400) 생성. 템플릿 1건의 산출물(시안·스크린샷·상세 페이지·OG)이 한 섹션에 모이도록.
- 🎨 페이지 테마 첫 변경 시 "이 페이지에서 앞으로 경고 보지 않기" ON.

### ⚡ 4단계 속도 최적화 — 5가지 규칙

①시안 → 카드 매니페스트 JSON 추출 → ②페이지 테마 먼저(카드 추가 전) → ③이미지 `/tmp/{label}.png` 일괄 export → ④카드 일괄 생성(드라이버 스크립트, 업로드 후 rm) → ⑤종단 1회 diff 검증(카드별 루프 ❌).

- **게이트**: CdBd 페이지 피드백 → 확정 후 **모바일 프리뷰 스크린샷** 캡처 (셀렉터 `.max-w-1\/2.transform.origin-top`, 멀티페이지는 전 페이지).

## 5단계 — 템플릿 상세 페이지 콘텐츠 (피그마)

## 🤖 무인 자동 제작 파이프라인 (매일 1개)

> 설계·구현 정본 = skill **`cdbd-daily-orchestrator`**. 위 1~5단계를 매일 밤 20:00 무인 실행(6단계 어드민 등록 보류), 아침 리포트 1장.

- **구조**: 매니저(오케스트레이터) + 단계별 담당자(서브에이전트) + 검수자(`critic-checklists.md`). 사람 피드백 게이트 → 자기비평 루프로 대체.
- **하루 흐름**: 20:00 자가진단 → 주제 1개 선택(최근 무드 회피) → [1 기획 문서] → [2 Claude Design 시안] → [3 반입·혼합·수정·무드·이미지] → [4 에디터+OG] → [5 상세페이지] → 청소 → 아침 리포트.

- ⚠️ **열린 항목 (2026-07-06)**: 2단계(Claude Design 생성)는 **브라우저 기반이라 코드가 트리거 불가** → 무인 파이프라인의 2단계 자동화 방식은 **재설계 필요**. (DesignSync는 결과 pull만 가능, 생성 트리거 아님)
