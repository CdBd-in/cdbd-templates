## ⏭ 작업 흐름

사용자가 "X 카테고리 템플릿 만들어줘" 요청 시:

1. **상세 페이지 콘텐츠 기획** → [[1-7. 템플릿 상세 페이지]] 참조
   - 카테고리 / 제목 / 사용 성과(수치 포함) / 추천 타겟 2가지 / 주요 기능 2가지

2. **에디터 페이지 구조 설계**
   - 카테고리 타겟·주요 기능과 직결된 카드 선정 — 콘텐츠→카드 룩업([[1-6-2. CdBd 카드 기능]]) + 카테고리별 조립 레시피([[1-8. 섹션 프리셋 라이브러리]]) 활용
   - 원페이지 vs 멀티페이지 결정
   - 카드 순서 + 각 카드의 텍스트/이미지 내용
   - 카드 결정 체크리스트 9단계 검증

3. **디자인 통일성 확보**
   - 페이지 테마: 19개 기본 프리셋 OR [[1-3. 색상 팔레트]]에서 무드 매칭
   - 카드 배경·모서리·구분선·여백 전략

4. **에디터에서 실제 생성**
   - 빈 페이지 시작 (`/templates` → 빈 페이지로 시작하기)
   - 카드 하나씩 추가하며 위 설계 반영

## 🤖 4단계 서브에이전트 파이프라인 (생성→검증→수정 자동화)

> **범위**: 워크플로우 [[1-1. 워크플로우|4단계(CdBd 에디터 구현)]]. 카드 생성부터 Figma↔CdBd 대조 QA·수정까지 전부를 세부 스코프로 나눠, 각 서브에이전트가 **자기 범위만 검증·수정**하게 한다.
> **상태**: 설계(spec) — 구현 전. 공통 원칙·계정·URL은 [[../CLAUDE.md|CLAUDE.md]], 자동화 기법은 `.claude/cdbd-edit-shared.md`(공통 함정)·각 스코프 에이전트 체크리스트 + skill `cdbd-card-automation`, 카드 옵션은 [[1-6-2. CdBd 카드 기능]] 참조.

### 🎯 목적·결정 요약

4단계는 범위가 커서(테마·카드 15종·텍스트·이미지·링크·예약·모양·레이아웃·여백·OG…) 한 컨텍스트로 정확히 처리하기 어렵다. 세부 스코프로 나눠 각자 검증·수정하는 서브에이전트로 분할한다.

**확정된 4개 결정 (2026-07-06):**

| 결정 | 값 | 근거 |
|---|---|---|
| **작업 범위** | 생성 → QA 전부 | 카드 추가·구성부터 대조·수정까지 스코프별 분담 |
| **분할 축** | 검증 = 속성별(병렬) / 수정 = 카드별(직렬) | 일관성(속성) + 선택 최소화·충돌 회피(카드) |
| **예약 분리** | 예약 정보는 독립 스코프 | 크레딧 소모·서버측 모달·방문체크 종료 함정 → 부분완료 리포트 대상 |
| **산출 형태** | 하이브리드 | 스코프는 재사용 자산(.claude/agents), 제어는 결정론(Workflow) |

### 🧱 왜 이 구조인가 (설계 근거)

- **E1 · 단일 에디터 세션 충돌** — 브라우저 1개 + React 공유 상태. 여러 에이전트가 동시에 mutate하면 서로 덮어씀(보드 스크롤 드리프트·라벨 +1 시프트·테마 재조정 루프). → **검증은 스냅샷 데이터 분석(브라우저 안 건드림, 병렬 안전), 수정만 브라우저(직렬).**
- **E2 · 의존 순서** — 카드가 올바른 순서·라벨로 존재하고 페이지 테마가 잡혀야 나머지 검증이 의미. → **토대(테마·구성)를 최우선 직렬.**
- **E3 · 속성 vs 카드 축** — 에디터는 카드 단위로 구성(카드 선택 → 그 카드 모든 옵션이 한 우측 패널). 속성별로만 수정하면 매번 모든 카드를 재선택 → 컨텍스트 스위치 비용↑. → **검증은 속성별(일관성), 수정은 카드별 배치(선택 1회에 그 카드 전 diff 적용).**

### 🏗 아키텍처 — 4-Phase 파이프라인

```
Phase 1 · 토대 (직렬, 최우선)
   S1 페이지 토대 ──▶ S2 카드 구성
        │
Phase 2 · 콘텐츠 채움 (직렬, 카드별)
   S3 텍스트 내용 ──▶ S4 이미지 ──▶ S5 링크·기능 ──▶ S6 예약 정보
        │
   [ 스냅샷 1회 : window.__cdbd.blocks() + Figma get_design_context ]
        │
Phase 3 · 디자인 검증 (병렬, 읽기전용 → diff 리포트)
   V1 텍스트디자인 ∥ V2 이미지·모양 ∥ V3 버튼·구분선 ∥ V4 레이아웃 ∥ V5 카드디자인
        │
   [ 모든 diff를 카드ID로 그룹핑 ]
        │
Phase 4 · 수정·마무리 (직렬, 카드별)
   F1 카드별 수정 적용자 ──▶ F2 마무리(OG·캡처·최종대조)
```

- Phase 1·2·4 = **직렬**(브라우저 구동). Phase 3 = **병렬**(스냅샷 데이터 분석만, 브라우저 미접촉).
- Phase 2의 각 채움 스코프(S3~S6)는 **자기 산출물을 스스로 1차 검증**한 뒤 다음으로 넘김("생성부터 QA까지"의 스코프 자기검증).

### ⚙️ 핵심 메커니즘 — 스냅샷 기반 병렬 검증

병렬 검증이 단일 브라우저에서 가능한 이유:

1. **스냅샷 1회(직렬)** — 채움 완료 후 `window.__cdbd.blocks()` 전체 블록 JSON(`style`·`content`·이미지참조·`reservation`·`location`·`multiCard`…)을 덤프 + Figma `get_design_context`/`get_metadata`로 최종 시안 스펙 덤프.
2. **검증 N개(병렬·브라우저 미접촉)** — 각 속성 에이전트는 *두 데이터 구조를 비교*만 하므로 순수 분석 → 진짜 병렬. 산출 = 카드ID 붙은 **diff 리스트**.
3. **수정(직렬·카드별)** — 모든 diff를 카드ID로 묶어 **카드 1회 선택 = 그 카드의 텍스트·이미지·모양·여백 diff를 한 번에 적용**. (보드 스크롤·라벨 시프트·테마 루프 회피)

**diff 스키마 (Phase 3 공통 출력):**
```
{ cardId, cardType, scope, field, current, expected, howToFix, severity }
```
- `howToFix` = 적용 방법 힌트(예: `block.style.fontSize=24 후 정렬버튼 .click() 트리거`). Phase 4 F1이 그대로 실행.

### 📋 13개 스코프 정의

#### Phase 1 — 토대 (직렬)

**S1 · 페이지 토대** (전역 설정)
- 담당: 페이지 테마(배경·텍스트·버튼 3색), 서체, `{버튼모양}`, 페이지 배경이미지+필터, 페이지 제목, 스크롤 애니메이션, (멀티페이지) 페이지 목록·네비 구조
- 입력: Figma 최종 시안(테마·폰트·페이지 구조), 1단계 무드 결정
- 출력: 테마 적용된 빈 페이지(들)
- 참조: S1 에이전트 「페이지 테마 체크리스트」 · skill `cdbd-card-automation`(페이지 색상 `setThemeColor` 재조정 루프·경고모달)
- 자기검증: `themeColors()` 3색 일치 · 서체·버튼모양 확인

**S2 · 카드 구성**
- 담당: 15종 카드 추가(드라이버 배치)·순서·상하 고정(핀)·카드명(라벨)
- 입력: Figma 카드 매니페스트(타입·순서·라벨)
- 출력: 올바른 순서·라벨의 빈 카드 스택
- 참조: skill `cdbd-card-automation`(`openAddModal`·`pickCardType`·`reorderCard`·`openPin`/`pinTo`·`setTitle` 수렴루프·예약 크레딧 확인)
- 자기검증: `cardOrder()` 타입 시퀀스 일치 · 라벨 `firstBad()===-1` · 핀 위치

#### Phase 2 — 콘텐츠 채움 (직렬·카드별)

**S3 · 텍스트 내용**
- 담당: 텍스트가 있는 모든 카드의 텍스트 필드 채우기(**버튼 텍스트 포함**) + **줄바꿈 위치 대조**
- 대상 필드: 텍스트 본문 / 프로필 이름·소개글 / 메뉴명 / 버튼 텍스트 / Q&A 제목·질문·선택지·주관식 placeholder·제출버튼 / 예약 버튼텍스트·(모달)제목·장소·호스트 / 상품명·가격·버튼텍스트 / 위치 주소·버튼텍스트 / 2단 구성요소 텍스트
- 참조: skill `cdbd-card-automation`(텍스트=복제 후 Lexical 콘텐츠), `block.content`(JSON 문자열)
- 자기검증: `block.content` `JSON.parse` → 텍스트 + **linebreak/문단 노드 위치가 Figma 줄 구조와 일치**
- 🔑 **줄바꿈(위치)은 내용 → S3 소관. 줄간격(line-height)은 디자인 → V1 소관.** 혼동 금지.

**S4 · 이미지**
- 담당: 이미지가 들어가는 모든 슬롯 업로드·적용(**순서 포함**) — 이미지/갤러리(≤15)/프로필 아바타/버튼 이미지/예약 버튼이미지/상품 이미지/2단 셀 이미지/메뉴 아이콘 + **카드 배경이미지** + **레이어 이미지** (페이지 배경이미지는 S1)
- 입력: 준비된 이미지 파일(`~/Desktop/{템플릿명}/`), Figma 슬롯↔이미지 매핑
- 참조: skill `cdbd-card-automation`(`openImageUpload`·`uploadImage`·`applyImage`), [[1-5. 이미지]]
- 자기검증: 각 슬롯 이미지 표시(스크린샷) · 순서 일치 (사이즈·모양은 V2 소관)

**S5 · 링크·기능**
- 담당: 링크 연결 6종(URL·전화 `call`·문자·이메일·연락처 vCard·페이지이동) / 위치 주소 **지오코딩**(검색 선택) / Q&A 폼 구조(질문유형 객·주관식·필수·복수선택·프리셋·제출) / 유튜브 URL·자동재생·컨트롤러 / SNS 채널·URL
- 참조: skill `cdbd-card-automation`(`onUpdateItem` 전화=`type:'call'` · 위치 지오코딩 좌표 생성)
- 자기검증: `linkButton.type`/`href` · 위치 `lat`/`lng`/`naverMapsUrl` 존재 · Q&A 질문 구조

**S6 · 예약 정보** *(분리 스코프)*
- 담당: 예약 카드 데이터 — 날짜·시간·정원·**방문체크 종료 일시(필수)**·크레딧 확인
- 참조: skill `cdbd-card-automation`(예약 정보 관리 모달 · 방문체크 종료 필수 · 크레딧 다이얼로그)
- 자기검증: 모달 닫힘=저장 · 우측 패널 예약정보 표시
- ⚠️ **부분완료 리포트 대상** — 크레딧 부족 시 LoadingButton 멈춤 → 나머지 파이프라인은 진행하고 예약만 리포트

#### Phase 3 — 디자인 검증 (병렬·읽기전용 → diff)

> 입력 공통: 스냅샷(CdBd blocks JSON) + Figma spec. 출력 공통: diff 리스트(위 스키마). 실행: 병렬·브라우저 미접촉. Figma 실측은 `get_design_context`(추정 ❌).

**V1 · 텍스트 디자인** — 폰트·사이즈·웨이트(Bold ON/OFF)·색·**줄간격**·정렬 (줄바꿈 제외=S3)
**V2 · 이미지·모양** — 이미지 비율(원본/1:1/3:2/2:3)·모양(8종)·크기, 갤러리 이미지 모서리, 프로필 이미지 비율·크기·모양
**V3 · 버튼·구분선** — 버튼 가로(1~10)·세로(1~10)·모양(원형/각진/둥근) + 구분선 두께·모양(실선/대시/점선/물결)·색·상하여백
**V4 · 레이아웃 유형** — 프로필(기본형/강조형/명함형)·갤러리(나열/넘겨보기/그리드+단수·간격·자동넘김)·메뉴(한눈에/햄버거+프리셋)·버튼 이미지유형(가로/카드형/배경형)·상품(그리드/바)·Q&A(정렬·질문간격)·2단(2~4분할·비율·정렬)
**V5 · 카드 디자인** — 배경(색/이미지+필터)·테두리(색+두께)·모서리(각진/둥근)·내부여백·외부여백 + 레이어 배치(크기·X·Y)

#### Phase 4 — 수정·마무리 (직렬·카드별)

**F1 · 카드별 수정 적용자**
- 담당: V1~V5 diff를 **카드ID로 그룹핑** → 카드 1회 선택 = 그 카드 모든 diff 적용
- 참조: [[1-6-2. CdBd 카드 기능]] · [[../CLAUDE.md|CLAUDE.md]] 4단계 "`block.style`/`block.*` 직접 변경 + 트리거" · skill `cdbd-card-automation`
- 자기검증: 적용 후 **재스냅샷 → 해당 diff 해소** 확인 (루프)

**F2 · 마무리**
- 담당: OG 썸네일(**수동 준비·안내** — 자동화 불가) · URL 정보(제목·설명 자동) · 모바일 프리뷰 캡처(멀티=전 페이지, 셀렉터 `.max-w-1\/2.transform.origin-top`) · 최종 diff=0 확인
- 출력: 5단계(상세 페이지) 입력물인 모바일 스크린샷

### 🧪 파일럿 검증 (2026-07-06, editor 5025)

de-risk 슬라이스(계획 T1~T3)에서 확인·확정:
- **스냅샷 = `window.__cdbd.dumpState()`** (드라이버 추가) — 17/17 카드 full block(`style`·`content`·`title`) 캡처, sortable 순서 보존, 읽기전용. 병렬 검증 입력으로 확정.
- **🔑 텍스트 디자인은 두 곳에 저장** — `block.style`(카드 기본) + `block.content`(Lexical) 안 text 노드 inline `style`/`format`(1=Bold). 5025 실카드에서 실제 divergence(`gounDotum` vs `gounBatang`) 관측, **렌더는 content 우선**. → V1은 content 기준 비교, F1은 content까지 갱신. (S3=줄바꿈 구조 / V1=inline 디자인 — 둘 다 content를 읽되 부분이 다름.)
- **🔑 F1 영속화 = 참조 변경 + reorder-commit** — block 객체를 `blockById`로 참조 회수 → `style`/`content` 직접 mutate → **`reorderCard` 라운드트립**으로 커밋(`onDragEnd`의 `n({...l,blocks})`가 재직렬화·autosave). **정렬버튼·패널 트리거(synthetic·real click 모두)는 커밋 안 됨** — 검증 완료. 드라이버에 `blockById` 추가.
- **설계 함의** — 참조 변경 + 단일 reorder-commit → **수정 시 카드별 선택 불필요**(모든 diff 배치 mutate 후 1회 커밋이 최적). "수정=카드별"의 선택-최소화 근거는 약화 → 실질은 "배치 mutate + 일괄 commit". (이미지 업로드 등 패널 필요 수정만 예외.)
