# 신규 템플릿 기획 워크플로우

> 사용자가 새 템플릿 기획을 요청하면 아래 6단계를 순서대로 진행. 각 단계마다 **사용자 피드백 게이트**가 있으며, 게이트 통과 후에만 다음 단계로 넘어감.
>
> ⚠️ **본 워크플로우는 실제 작업하며 변경될 수 있음** — 변경 시 본 노트와 [[../CLAUDE.md|CLAUDE.md]]의 "신규 템플릿 기획 워크플로우" 섹션을 동시 업데이트할 것.

---

## 🗺 단계 개요

| #   | 단계               | 출력물                                       | 게이트          |
| --- | ---------------- | ----------------------------------------- | ------------ |
| 1   | 콘텐츠 기획           | 카테고리 · 주제 · 무드 · 색·폰트 결정                  | 기획 피드백       |
| 2   | 피그마 스켈레톤         | **디폴트 테마(fafafa/292929/프리텐다드)** 카드 구성 + 이미지 자리(주석) | 스켈레톤 피드백     |
| 3   | 피그마 이미지 채움 + 색·폰트 배리에이션 적용 | 완성된 피그마 화면 (이미지 + 무드 색·폰트 적용) | 피그마 완성본 피드백  |
| 4   | CdBd 에디터 구현      | 라이브 페이지 + OG + 제목 + 모바일 스크린샷              | CdBd 페이지 피드백 |
| 5   | 상세 페이지 콘텐츠 (피그마) | 카탈로그 상세 페이지 섹션                            | 상세 페이지 피드백   |
| 6   | CdBd 어드민 등록      | 라이브 등록 완료                                 | —            |

## 1단계 — 콘텐츠 기획

**목적**: 사용자가 요청한 카테고리·주제에 맞는 페이지 콘텐츠 구성을 결정.

### 입력
- 사용자 요청 (카테고리, 주제, 톤·앤·매너 등)

### 작업
- **카테고리 선정** (5종 중 1개)
  - 카테고리 미충족 분야 우선 고려:
    - 🚨 소식·매거진 (0개)
    - 가이드·신청 (1개)
- **무드 결정** → [[1-1. 색상 팔레트 라이브러리]] + [[1-2. 폰트 라이브러리]] 9개 무드 동일 → 무드 1개 결정 시 색·폰트 동시 선정
  - ⚠️ 무드·색·폰트는 1단계에서 **결정**만 하고, 실제 **적용**은 3단계에서. 2단계 스켈레톤은 디폴트 테마로 제작.
- **페이지 콘텐츠 기획** — 어떤 정보를 어떤 순서로 배치할지 초안 작성 (텍스트 위주, 카드 단위 분리)

### 출력
- 카테고리 · 주제 · 무드 · 페이지 콘텐츠 초안 (색·폰트 결정값은 3단계에서 적용)

### 게이트
- → **사용자 기획 피드백**

## 2단계 — 피그마 스켈레톤 제작

**목적**: 실제 CdBd 카드 속성만 사용해서 페이지 구조를 피그마에 빠르게 시각화. **이미지 없이** 카드 구성과 레이아웃만 확인.

### 🎨 디폴트 페이지 테마 사용 (필수)

스켈레톤 단계에서는 **CdBd 디폴트 테마**를 고정으로 사용한다. 색·폰트 배리에이션은 3단계에서 일괄 적용.

| 역할 | 값 | 출처 |
|---|---|---|
| `{배경색}` | `#fafafa` | [페이지 색상 프리셋 #1] |
| `{텍스트색}` | `#292929` | [페이지 색상 프리셋 #1] |
| `{버튼색}` | `#292929` | [페이지 색상 프리셋 #1] |
| 서체 | **프리텐다드** (Pretendard) 단일 | [페이지 서체 기본값] |
| 버튼 모양 | **원형 99px (pill)** | [페이지 버튼 모양 #1] |

이유:
- 색·폰트 선정과 구조 검토를 **분리** → 스켈레톤 게이트에서는 "콘텐츠 흐름·카드 구성"에만 집중
- 디폴트 테마는 모든 무드에 중립 → 구조 평가 시 색이 판단 흐릴 일 없음
- 3단계에서 무드별 색·폰트 입혔을 때 디폴트 대비 변화량을 한눈에 확인 가능

### 🃏 CdBd 실제 카드 default 속성 준수 (필수)

스켈레톤의 각 카드는 **CdBd 카드 기능 정의 문서**(`/Users/leesunho/Documents/GitHub/design/cdbd-design-system/디자인 시스템/4. 카드 기능 정의/`)에 정의된 **default 옵션값**을 그대로 시각화한다. 임의 라운드·임의 패딩·임의 정렬을 박지 말 것 — 사용자가 에디터를 처음 열었을 때 보는 화면과 시안이 일치해야 함.

#### 카드 공통 default ([[4-1. 공통]])

| 옵션 | Default 값 |
|---|---|
| 카드 모서리 | **각진 (0px)** |
| 카드 내부여백 | **20px** (슬라이더 기본값) |
| 카드 외부여백 | **0px** |
| 카드 테두리 | **0 (없음)** |
| 카드 배경 | **없음 (투명)** — 페이지 배경이 보임 |

#### 카드별 핵심 default 요약

| 카드 | 주요 default |
|---|---|
| **프로필** ([[4-4]]) | 유형 = 기본형 (이미지→이름→소개글 세로 중앙, gap 32) · 이미지 비율 1:1 · 이미지 모서리 **원형** · 이미지 크기 40 · 이름 사이즈 25 · 소개글 사이즈 16 |
| **텍스트** ([[4-5]]) | 사이즈 16 · 정렬 **중앙** · 줄간격 1.6 · 볼드 OFF |
| **이미지** ([[4-6]]) | 비율 **원본** · 크기 100 · 모양 **각진** · 정렬 중앙 |
| **갤러리** ([[4-7]]) | 유형 **나열하기** · 간격 16 · 이미지 모서리 **각진** · 비율 원본 |
| **버튼** ([[4-9]]) | 모양 **원형 99px** · 색상 {버튼색} · 텍스트 16 Bold · 색상 {배경색} · 가로 100% · 세로 padding 16 |
| **Q&A** ([[4-10]]) | 제목 20 Bold · 질문 16 Bold · 옵션 16 Regular · 정렬 중앙 · 질문 간격 **32px** · 제출 버튼 원형 |
| **예약** ([[4-11]]) | 버튼 모양 원형 · 버튼 텍스트 16 Bold |
| **위치 안내** ([[4-13]]) | 지도 비율 **1:1** · 모서리 **각진** · 주소 텍스트 16 · 길찾기 버튼 원형 |

#### 시안 ↔ 라이브 정합 체크
- ❌ 카드 모서리에 4·6·8·12·16px 등 임의 라운드 박지 말 것 (default = 각진 0)
- ❌ 버튼에 8·12·16px 라운드 박지 말 것 (default = 원형 99px = pill)
- ❌ Q&A 질문 간 12·16·24px 간격 박지 말 것 (default = 32px)
- ❌ 카드 패딩 12·16·24px 박지 말 것 (default = 20px)
- ✅ 모든 카드는 페이지 배경 위에 투명하게 얹힘 — 카드별 배경색 박지 말 것
- ✅ 프로필 명함형은 **가로 배치**가 default 구조 — 세로로 그릴 거면 기본형(default) 사용
- ✅ 모서리·크기 옵션을 명시적으로 바꿔야 할 때는 시안에 **주석으로 표기** ("default 변경: 이미지 모서리 둥근")

## 3단계 — 피그마 이미지 채움 + 색·폰트 배리에이션 적용

**목적**: 스켈레톤 피드백 반영 후 **실제 이미지 추가**와 **1단계에서 결정한 무드 색·폰트 적용**을 함께 수행하여 완성된 페이지 화면 제작.

### 작업

#### 1. 이미지 채움
[[1-3. 이미지]] 규칙 준수:
- **Thiings 3D** (3D 오브젝트 — 펀/플레이풀 무드)
- **Google Flow (Nano Banana)** (실사 인물·제품 — 럭셔리/엘레강스, 페미닌, 프로페셔널 등)
- 9개 무드별 추천 이미지 소스 매핑 따르기

#### 2. 색상 배리에이션 적용
1단계에서 결정한 무드의 팔레트를 디폴트 테마(fafafa/292929/292929)에 덮어쓴다.
- 팔레트 역할 매핑 ([[../CLAUDE.md|CLAUDE.md]] 참조):
  - 2색 팔레트: 색1 = `{배경색}`, 색2 = `{텍스트색}` + `{버튼색}` (동일)
  - 3색 팔레트: 색1 = `{배경색}`, 색2 = `{텍스트색}`, 색3 = `{버튼색}`
- 보조 텍스트는 별도 hex ❌ → `{텍스트색} × N%` 투명도 유지
- WCAG 대비 **3.6:1 이상** 재검증

#### 3. 폰트 배리에이션 적용
1단계에서 결정한 무드의 폰트를 프리텐다드에 덮어쓴다.
- 한 페이지 = **1~2개 폰트** (헤드라인+본문 분리 시 최대 2개)
- 국문 본문 = **한글 폰트 의무**
- 헤드라인 전용 폰트 19종은 본문 ❌
- 망설여지면 **프리텐다드 단일 유지** (안전 폴백)

### 게이트
- → **사용자 피그마 완성본 피드백** (이미지·색·폰트 모두 평가)

## 4단계 — CdBd 에디터 구현

**목적**: 피그마 최종 화면을 실제 CdBd 라이브 에디터에서 구현 + 등록에 필요한 부가 메타 설정.

### 작업
1. **라이브 에디터 페이지 제작** — [[1-4-1. 에디터 페이지]] 가이드 준수
   - 피그마 카드 구성을 1:1로 옮김
   - 테마 변수(`{버튼색}`·`{배경색}`·`{텍스트색}`) 적용
   - 카드별 default 기능 신뢰
2. **OG 이미지 설정** (에디터 헤더 「URL 생성하기」 우측 URL 정보 편집 모달) — 규격·디자인 규칙은 [[1-4-1. 에디터 페이지#🖼️ OG 이미지(썸네일) 규칙]] 준수 (800×400, 1배수 JPG, 기본 로고 타입 면적 9-10%)
3. **페이지 제목 설정**

### 게이트
- → **사용자 CdBd 페이지 피드백**

### 게이트 통과 후 — 📱 모바일 스크린샷 캡처 (5단계 입력물)

페이지 확정 후 **모바일 프리뷰 스크린샷** 캡처:
- 셀렉터: `.max-w-1\/2.transform.origin-top` (라이브 템플릿 페이지의 모바일 프리뷰)
- **멀티페이지인 경우 모든 페이지 스크린샷 필요** — 페이지 1, 페이지 2, … 각각 캡처
- 자동화: gstack `browse` 사용 가능

```bash
# 예시 (필요 시)
$B goto https://www.cdbd.in/templates/{slug}
$B screenshot --selector ".max-w-1\\/2.transform.origin-top" /tmp/{slug}-p1.png
# 멀티페이지: 페이지 2 클릭 후 다시 캡처
```

### 🚨 4단계 자동화 시 주의사항 (2026-06-18 박제)

CdBd 에디터의 mobile preview · 카드 보드 · 우측 패널 · 모달은 **모두 같은 DOM 트리에 공존**. 잘못된 selector·focus는 의도치 않은 곳에 입력을 보낸다. **검증 없는 다단계 자동화는 데이터 오염 위험**.

#### 권장 작업 패턴
1. **카드는 위→아래 순서로 "추가만"** — 사용자 인사이트: "위부터 순서대로 추가만 하면 되는데 왜 드래그앤드롭?". 드래그앤드롭 자동화 회피.
2. **카드 단위로 작업 → 매 단계 스크린샷 검증 → 다음 단계** — 한꺼번에 다단계 진행하지 말 것.
3. **자동화 가능 영역**: 카드 추가/순서, 텍스트 콘텐츠 변경(Lexical), 우측 패널 토글(Bold/사이즈/정렬), 모달 input(Playwright `$B fill`), 캘린더 날짜 선택.
4. **수동 위임 권장**: 카드 디자인 세부값(배경색/패딩/모서리), 카드 reorder(드래그), 카드 라벨 inline edit, 이미지 업로드(파일 시스템).

#### 발견된 자동화 함정 13가지 → [[1-4-1. 에디터 페이지#🤖 CdBd 에디터 자동화 함정]]

대표 함정:
- "last contenteditable" focus = 인사팀 버튼 텍스트 (mobile preview 최하단). 결과: 의도치 않게 버튼 텍스트 덮어쓰기
- 카드 라벨 ✏️ pencil 우발 활성화로 라벨 오염 (예: "이미지" → "2026 ABC 컴퍼니 채용...")
- React form state(react-hook-form)는 native input setter로 갱신 안 됨 → `$B fill` 사용 필요
- 카드 추가 모달 누적 오픈 + ESC 안 먹음 → 명시적 X 버튼 click (`div.absolute.right-\\[24px\\].top-\\[30px\\]`)
- Q&A 질문 유형 변경 in-place 불가 → 삭제 후 신규 추가만 가능 (신규는 마지막에 배치 → reorder 수동)

#### 4단계 자동화 가능/수동 매트릭스 (T-NEW1 학습)

| 작업 | 자동화 | 비고 |
|---|---|---|
| 카드 9개 보드 배치 (위→아래 순서) | ✅ | modal-scoped selector 사용 |

## 6단계 — CdBd 어드민 등록

**목적**: 피드백 반영된 상세 페이지 콘텐츠 확정 후 실제 어드민에서 템플릿 등록.

### 어드민 진입
- **URL**: https://cdbd-admin.vercel.app/login (CdBd와 동일 계정)
- **경로**: 템플릿 → 템플릿 관리 → 템플릿 추가

### 어드민 폼 구조
**좌측 컬럼** (기본 메타)
- 언어 \* · 템플릿명 \* · 제목 \* · 슬러그 \* · 썸네일 이미지 \* · 에디터 ID \* · 카테고리(5종 체크) · 활성화

**우측 상단 박스 "상세 정보"** = 피그마 소개 frame
- 상세 이미지(대표 프로필) · 부제목 라벨 · 부제목 설명 · 본문 · 항목(+추가, 추천 대상 반복)

**우측 하단 박스 "스와이퍼 영역"** = 피그마 주요기능-N frame (반복)
- 각 항목: 제목 \* · 설명 \* · 표시 순서 · 아이콘 이미지(38×38) · 설명 이미지(360×300)
