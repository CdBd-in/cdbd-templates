## 9. 국내 근거 보강 (2026-09-03)

### ✅ 국내 목적축 2곳도 **7칸**
- **웨이브온** — 페이지 H1이 **"목적에 맞는 템플릿으로 시작하세요"**. `예약·등록 / 상담·견적 / 회사·서비스 소개 / 교육·수강 / 이벤트·캠페인 / 광고 랜딩 / 기타`
  - 물량 분포: **회사·서비스 소개 11 · 광고 랜딩 10 · 상담·견적 7** ← 국내 수요가 어디 몰리는지
  - ⚠️ **업종 URL은 sitemap에 있으나 전부 목적 페이지로 열림 = 업종축이 죽어 있음.** 목적축이 실사용에서 이겼다는 신호
- **아임웹** — `쇼핑몰 / 비즈니스 홍보 / 블로그·미디어 / 이벤트·프로젝트 / 포트폴리오 / 커뮤니티 / 예약·기타`

### 🚨 「부고는 초대장 카테고리 밖」이 **업계 관행이었다**
국내 모바일 초대장 서비스 12곳을 전수 확인한 결과:
> **부고/상조는 어느 서비스에서도 「초대장 카테고리」 안에 없다. 항상 별도 사이트·별도 서비스로 분리된다.**
> (moumoon만 「기타 서비스」에 모바일 부고장을 둠 · 레드에이트는 아예 별도 도메인)

→ **2026-09-03 이선호 지적("부고 같은 부정적 소식은 초대 키워드와 안 맞는다")이 업계 관행과 정확히 일치.**
→ 우리는 1번을 **「행사·안내」**로 넓혔으므로 담을 수 있다. 단 **말투 그룹 「📢 알림」**으로 분리 필수 ([[1-10. 초대장 사례 사전 (초안)]] §2).

### 🗣 국내에선 「랜딩페이지」·「상세페이지」라는 말이 **실무자끼리도 안 통한다**
아이보스 스레드(조회 3,124·댓글 16)에서 답변이 서로 어긋남:
| 답변 | 입장 |
|---|---|
| A | "회사마다 랜딩페이지가 다를 거 같애요" |
| B | "이벤트페이지가 될 수도 있죠" |
| C | "랜딩 = 곧 사라질 이벤트페이지" |
| D | "**DB 남기는 용도가 있으면 랜딩, 없으면 상세**" |
| E | 글 제목 자체가 `상세페이지(=랜딩페이지)` |

→ **랜딩 = 유입 경로 기준 / 상세 = 콘텐츠 기준 → 축이 달라서 합의 불가.**
→ **비디자이너 대면 라벨은 반드시 「목적 문장형」.** 해외에선 `squeeze/splash`가 문제였는데, **국내에선 「랜딩」·「상세」부터 안 통한다.**

### ℹ️ 참고 — 「상세페이지」의 국내 위치
- **목적 카테고리로 둔 국내 랜딩 빌더는 0곳**
- 미리캔버스: **제작물 규격**(형제 = 프레젠테이션·카드뉴스·로고) · **「이벤트페이지 ⊂ 상세페이지」**로 URL에 못박음
- 카페24: **제작 서비스 항목** (`기획전 상세페이지 제작`)
→ 우리 「상품·홍보 ① 상세 페이지」는 **랜딩 카테고리가 아니라 커머스 규격**에 가깝다는 점 인지 필요.

### 📊 바른손 letterB, 실제 운영 현황 (경쟁 로드맵)

## 12. 대분류 이름 확정 (2026-09-03 이선호)

| # | 이름 | 확정 경위 |
|---|---|---|
| 1 | **행사·안내** | 「초대·예약」이 부고·공지를 못 담아 확장 |
| 2 | **프로필·명함** | 유지 |
| 3 | **브랜드·단체 홈페이지** | 「매장·브랜드 소개」 → **「매장」은 업종어**라 목적어로 교체 · 「홈」은 어려운 말이라 **「홈페이지」**로 (비디자이너에게 가장 익숙 · 네이버 모두도 "무료 홈페이지") |
| 4 | **상품·홍보** | 「룩북·카탈로그」 → Carrd 2위 `Landing`(출시·서비스 알림)을 담기 위해 확장 |

| 6 | **소식·자료** | 「소식·읽을거리」 → **구어체**라 교체. 공지=소식 · 매거진·도록·가이드북=자료 |

### 이름 규칙
- **업종어 금지** (카페·병원·학원) → **목적어**로. 대분류는 목적축이므로 업종이 섞이면 축이 오염된다
- **업계 전문어 금지** (랜딩·상세·스퀴즈) → 국내에선 **실무자끼리도 안 통한다**(아이보스 스레드 · Baymard 62% 연구)
- **구어체 금지** (읽을거리) → 문서·제품 라벨 톤 유지

## 13. 판별 기준 — **상시인가, 한 건인가** (2026-09-03)

같은 주체가 만들어도 **목적이 다르면 다른 대분류**다. 테스트 케이스 = 「아트갤러리」.

| 만들려는 것 | 대분류 |
|---|---|
| 아트갤러리 **홈페이지** (공간을 상시 소개) | **3 브랜드·단체 홈페이지** |
| 《○○ 개인전》 **초대장** (전시 한 건) | **1 행사·안내** |
| 《○○ 展》 **도록** (작품 기록) | **6 소식·자료** |
| 작품 **판매** 페이지 | **4 상품·홍보** |

### 3번이 「종합형」이라는 뜻 — 멀티페이지 예시
```
아트갤러리 홈페이지  (대분류 = 3)
├ P1 홈      갤러리 소개 · 대표 이미지 · 현재 전시
├ P2 전시     전시명 · 기간 · 작가 · 오프닝 안내   ← 1번 유형을 빌려옴
├ P3 작품     작품 이미지 + 캡션                  ← 6번(도록) 유형
└ P4 방문 안내  위치 · 관람시간 · 휴관일 · 예약     ← 1번(예약)
```
→ **대분류는 3번 하나인데, 안의 페이지들이 1·4·6의 유형을 빌려온다.** 이래서 멀티페이지 본진.

> 🔑 **일반 규칙**: 대분류 3번(종합형)은 **다른 대분류의 유형을 페이지 단위로 품는다.** 나머지 5칸은 단일 목적이라 이런 중첩이 없다.
