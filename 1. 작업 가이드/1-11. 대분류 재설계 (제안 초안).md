> ⚠️ **확정 전 초안.** 확정되면 [[1-9. AI 유저 플로우]] ①② 절과 [[1-8. 섹션 프리셋 라이브러리]] 조립 레시피에 반영.

## 0. 🔒 이 체계의 용도 — **순수 내부 기준** (2026-09-04 이선호 확정)

> **유저는 대분류도 세부 카테고리도 보지 않는다.** 이 체계는 **AI 페이지 빌더 기능**의 내부 기준일 뿐이다.

| 역할 | 쓰임 |
|---|---|
| **① 조립 레시피 서랍** | AI가 페이지를 만들 때 "어떤 섹션을 어떤 순서로" |
| **② 질문 세트 열쇠** | 이 유형이면 무엇을 물어야 하나 |
| **③ 커버리지 지도** | 템플릿·프리셋 제작 시 빈칸 확인 |

### 이 확정이 바꾼 것

- 🗑 **카테고리 이름을 「유저가 찾기 쉽게」 다듬는 작업 종료.** 내부 이름의 기준은 **정확성**뿐 (§12 이름 규칙은 *분류 판단이 흔들리지 않게* 하는 용도로만 유효).
- 🗑 **「행사·안내가 부고를 밀어낸다」류 문제 소멸** — 유저가 그 이름을 볼 일이 없다. *(부고 자체는 이후 §0-C로 대상에서 제외됐다)*
- 🗑 **§5 「내부 불일치」 소멸** — 어드민 카테고리·템플릿 진열대(`cdbd.in/templates`)는 **템플릿 상품 진열용**으로 **그대로 유지**하며, 이 주제 25개과 **맞출 필요가 없다**(별개 기준 허용).
- ✅ **주제을 나누는 잣대가 하나로 좁혀짐** — **「섹션 구성이 다른가」**. *「물어볼 항목만 다르다」*는 **질문 세트의 조건부 필드**로 처리하고 주제을 나누지 않는다(§15 층위 규칙 ②).

### 유저에게 닿는 유일한 층 = **화면 어휘** (내부 이름과 별개)

새 플로우의 *"이 내용에는 **[가맹점 모집 안내]**를 추천해요"* 에 나오는 이름은 **내부 주제 이름(`5-②` 모집)과 같을 필요가 없다.**

| | 성격 | 개수 |
|---|---|---|
| **내부 서랍** | 닫힘 · 구성 기준 · 정확성 우선 | **주제 25개 고정** |
| **화면 어휘** | 열림 · 유저 말을 따라감 (직원 채용 공고 · 가맹점 모집 · 체험단 모집 · 서포터즈 모집…) | **무한** |

→ 같은 `5-②` 서랍이라도 유저가 "직원 뽑아요"라 쓰면 「채용 공고」, "가맹점 찾아요"라 쓰면 「가맹 모집 안내」로 부른다. **내부 주제은 안 늘고 유저 어휘만 늘어난다.**
→ 2026-09-03 확립한 *「선택지는 닫혀야 하고, 사전은 열려야 한다」*가 여기서 완성된다.

### 🚫 0-C. 대상 범위 — **비즈니스용 페이지만** (2026-09-04 이선호 확정)

> **CdBd의 지향점은 「비즈니스용 모바일 페이지」**다. 따라서 **개인 경조사(청첩장·돌잔치·환갑·백일)와 부고·추모는 이 체계에서 제외**한다.

| | 처리 |
|---|---|
| **제외된 주제 2개** | 옛 `1-①` 경조사 초대장 · 옛 `1-⑥` 부고·추모 |
| **결과** | 1번 대분류 **6개 → 4개** · 전체 **주제 25개 → 주제 25개** |
| **번호** | 1번 대분류만 재번호 (옛 ②③④⑤ → 새 **①②③④**) |

**왜 빼는가**
1. **사업이 아니다** — 개인 경조사·부고는 사업자의 영업·홍보·운영 활동이 아니다. 주제 25개의 나머지는 전부 「사업체가 고객·지원자·후원자에게 무언가를 하려는」 페이지다.
2. **말투가 체계 전체와 어긋난다** — 부고 하나 때문에 「초대 어휘 금지」·「푸터 금지」·「무채색 강제」 같은 **예외 규칙이 여러 곳에 번졌다**. 빼면 그 예외들이 함께 사라진다.
3. **경쟁이 포화** — 모바일 청첩장·부고장은 전용 서비스가 이미 촘촘하다(§14). 우리 강점(B2B 기관·사업체)과 겹치지 않는다.
4. **실사용 근거도 얇다** — CdBd 실사용 549건 중 개인 경조사는 4건 남짓(§18).

⚠️ **입력이 경조사·부고로 판정되면 「대응 주제 없음」**으로 처리한다 — 억지로 가까운 주제(`1-①` 행사 초대장 등)에 넣지 말 것. 톤·구성이 전부 다르다.
ℹ️ 아래 §14(부고는 업계에서도 초대장 밖) · §17(20건 검증)의 부고 관련 서술은 **이 결정 이전의 근거 기록**이라 그대로 둔다.

## 1. 결론 — **축은 맞았다. 주제이 모자랐다.**

CdBd 원칙(`목적 = 페이지 구조, 업종·주제 = 자유입력`)은 **업계 최선 관행과 일치**한다. 문제는 **목적 축의 주제이 4개로 좁았던 것**.

## 4. 주제을 균등하게 채우려 하지 말 것

## 13. 판별 기준 — **상시인가, 한 건인가** (2026-09-03)

같은 주체가 만들어도 **목적이 다르면 다른 대분류**다. 테스트 케이스 = 「아트갤러리」.

| 만들려는 것 | 대분류 |
|---|---|
| 아트갤러리 **홈페이지** (공간을 상시 소개) | **3 소개·홈페이지** |
| 《○○ 개인전》 **초대장** (전시 한 건) | **1 행사·안내** |
| 《○○ 展》 **도록** (작품 기록) | **6 소식·자료** |
| 작품 **판매** 페이지 | **4 상품·홍보** |

### 3번이 「종합형」이라는 뜻 — 멀티페이지 예시
```
아트갤러리 홈페이지  (대분류 = 3)
├ P1 홈      갤러리 소개 · 대표 이미지 · 현재 전시
├ P2 전시     전시명 · 기간 · 작가 · 오프닝 안내   ← 1번 유형을 빌려옴
├ P3 작품     작품 이미지 + 캡션                  ← 6번(도록) 유형
└ P4 방문 안내  위치 · 관람시간 · 휴관일 · 예약     ← 1번(예약)
```
→ **대분류는 3번 하나인데, 안의 페이지들이 1·4·6의 유형을 빌려온다.** 이래서 멀티페이지 본진.

> 🔑 **일반 규칙**: 대분류 3번(종합형)은 **다른 대분류의 유형을 페이지 단위로 품는다.** 나머지 5개은 단일 목적이라 이런 중첩이 없다.

## 16. 🔀 갈림 질문 5개 — 판별 기준을 **제품 안에서 작동시킨다** (2026-09-04 이선호 제안)

> 🔄 **2026-09-04 rev.2 — 화면 질문이 아니라 「내부 로직」으로 재배치.** 새 플로우 보드([Figma 236-5375](https://www.figma.com/board/dA9nFFGnHhwjNuQYNVGR2B/AI-%EC%9C%A0%EC%A0%80-%EC%9B%8C%ED%81%AC%ED%94%8C%EB%A1%9C%EC%9A%B0?node-id=236-5375))에 **「이 페이지로 가장 하고 싶은 일은 무엇인가요?」(목적 질문 · 추천 4 + 직접 입력)** 단계가 있고, **그 질문이 곧 주제 25개을 고르는 자리**다.
> → 갈림 질문을 **별도 단계로 띄우지 않는다.** AI가 갈리면 **후보 둘을 목적 선택지로 함께 올리고** 유저가 고르게 한다. 아래 5축은 **선택지 4개를 뽑는 내부 판정 로직**으로 유효하다.
> ⚠️ 예외 — `4-①`↔`4-③`은 목적이 같아(*"제품을 소개하고 싶어요"*) 이 방식으로 못 갈린다(**깊이** 차이). 자료 분석이나 보조 질문 필요. 상세 = [[1-12. 조립 레시피 (제안 초안)]] §3-B.

> 🔑 **핵심**: 판별 기준을 문서에 적어두면 죽은 규칙이 된다. **AI가 서랍을 고르다 갈릴 때, 유저에게 직접 묻는다.**

### 왜 「묻는」 게 맞나 — 기존 원칙과 충돌하지 않는다

[[1-9. AI 유저 플로우]]의 *「판단 어려운 건 묻지 말고 보여준다」*(원/멀티 · 무드)와 상충하는 것처럼 보이지만, **대상이 다르다**.

| | 묻는다 | 보여준다 |
|---|---|---|
| **무엇** | 유저만 아는 것 = **내 상황** | 유저가 미리 판단 못 하는 것 = **어떻게 보일지** |
| 예 | "손님이 시간을 직접 고르나요?" | 원/멀티 · 무드 · 시안 3안 |

➕ **이 답은 버려지지 않는다.** "회차를 고른다"고 답하면 → 예약 카드가 필요하고 → 회차 정보를 물어야 한다. **질문이 늘어난 게 아니라, 어차피 받을 정보를 앞당긴 것.**

### 5개 축이 경계 10개를 전부 가른다

| 축 | 화면 문구 (유저 언어) | 가르는 경계 |
|---|---|---|
| **① 오나 / 안 오나** | "이 페이지를 본 사람이 **어딘가로 오게 되나요?**" | **1번 ↔ 6번** · 3-② 메뉴 ↔ 4-③ 카탈로그 |
| **② 보여주기 먼저 / 받기 먼저** | "**내용을 충분히 보여주고** 받을까요, **바로 받을까요?**" | 1-②↔5-① · 2-②↔5-④ · 4-①↔4-④ |
| **③ 지금 돈을 받나** | "**지금 주문·결제를 받나요?**" | 4-④↔4-⑤ · 5-②↔4-④ |
| **④ 자리·시간이 정해져 있나** | "**고를 수 있는 시간(또는 정원)이 있나요?**" | 1-④↔5-④ · 5-②↔5-④ |
| **⑤ 사진이 주인공 / 글이 주인공** | "보여줄 게 **사진·작업물**인가요, **경력·이력**인가요?" | 2-③↔2-④ · (6-②↔6-③ 동일 축) |

> 🥇 **①이 가장 상위.** *「행사·안내」라는 이름이 부고를 밀어낸다*는 문제가 여기서 사라진다 — 유저는 **이름을 볼 일이 없고**, "장례식장으로 오시나요?"에 답하면 AI가 알아서 부고장 서랍을 연다.

### 작동 방식 — **갈릴 때만, 최대 1개**

새 플로우([Figma 236-4870](https://www.figma.com/board/dA9nFFGnHhwjNuQYNVGR2B/AI-%EC%9C%A0%EC%A0%80-%EC%9B%8C%ED%81%AC%ED%94%8C%EB%A1%9C%EC%9A%B0?node-id=236-4870))의 **"이 내용에는 [ ]를 추천해요"** 자리에 붙인다.

**확신할 때** (지금과 동일)
```
이 내용에는 「부고장」을 추천해요
```

**갈릴 때** (추천을 미리 찍어두고 확인만 · 최대 1탭)
```
이 내용에는 「예약 페이지」를 추천해요
하나만 확인할게요 —
 ⓐ 손님이 날짜·시간을 직접 고른다        ✅추천
 ⓑ 연락처를 남기면 내가 연락한다
```

### 설계 시 지킬 것 3가지
1. **카테고리 이름을 문구에 쓰지 않는다** — "예약형인가요 상담형인가요" ❌ → **상황 문장**으로. (§9 근거: 국내에선 「랜딩페이지」·「상세페이지」가 실무자끼리도 안 통한다)
2. **"둘 다예요"에 대비** — 둘 다면 **더 많이 담는 쪽**으로 (예: 예약+상담 → 예약 페이지에 문의 버튼 추가). 되묻지 않는다
3. **상한 1개** — 갈림이 2개 이상 겹치면 나머지는 AI가 정하고 **시안에서 보여준다**(기존 원칙). 안 지키면 *「카테고리를 안 고르게 하려고 만든 플로우」*가 다시 설문이 된다

## 19. 🔴 남은 쟁점

### 쟁점 ① — 3번(소개·홈페이지) 세부를 확장할 것인가
- **경위**: 2026-09-03에 *「3개 → 6개 확장」*까지 구두 결정했으나 **어떤 6개인지 기록이 남지 않았다.** 그 사이 3-③이 삭제되어 현재 **2개**.
- **당시 근거**: *"업종에 따라 중간 블록이 다르다"* → 하지만 **잣대가 바뀌었다**(§0). 이제 *「섹션 구성이 진짜 다른가, 필드만 다른가」*로 다시 걸러야 한다.
- **실제 쟁점**: **「프로그램·수업 운영」**(실사례 20 체험마을 = 소개+프로그램+인원별 요금+소요시간+주차+식사)이 **3-② 메뉴·가격과 구성이 다른가?**
- **권고**: 🅰 **일단 2개으로 두고 레시피를 짜다가 갈라지는 지점에서 나눈다.** 레시피가 곧 구성이므로, 써 보면 나눌지 말지가 저절로 드러난다. (주제을 먼저 늘리면 §15 층위 규칙 ②를 또 위반할 위험)

### 쟁점 ② — 6번 「소식·자료」 존치 (§6에서 이월)
- 모바일 단일 페이지 서비스엔 블로그 축이 거의 없다 → **유지하되 우선순위 최하위** 권고. 미확정.

### 쟁점 ③ — 포트폴리오 변형
- 2-③ 안에 **이미지형 · 프로젝트형**(인테리어 · 멀티 4p) **· 영상형**(유튜브 카드 나열)이 있다.
- **권고 A**: 세부 1개 유지 + **프리셋 변형 3종**으로. (구성 차이가 「섹션이 다름」이 아니라 「같은 섹션의 카드 타입이 다름」이므로 층위 규칙 ②에 가깝다) 미확정.

### 쟁점 ⑤ — `5-② 모집` ↔ `5-⑤ 공모전·대회` 합칠 것인가 (2026-09-04 발견)

목적 분류별로 정보 구조를 전수 대조하다 발견한 **경계선 짝**.

| | `5-② 모집` | `5-⑤ 공모전·대회` |
|---|---|---|
| 공통 | 정원·자격·마감 + **지원 폼** | 정원·자격·마감 + **참가 폼** |
| 차이 | 혜택·처우 | **부문 나열** + **시상 내역** |

- 차이가 **「섹션 2개 추가」뿐**이라 새 잣대(「섹션 구성이 다른가」)로는 통과하지만 **약하다.**
- **`5-③ 채용`을 `5-②`에 흡수한 것과 같은 논리**를 대면 합쳐야 할 수도 있다(부문·시상을 `5-②`의 조건부 필드로).
- **권고**: 레시피를 실제로 써 본 뒤 판정. 지금 합치면 층위 규칙 ①(섹션 구성이 다르면 분할)을 반대로 위반할 위험.
