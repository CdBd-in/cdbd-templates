# 입력 단계 안내 문구 — 작성 규칙 (정본)

## 이게 뭔가
AI 페이지 빌더의 「내용 채우기」 단계에서, 오른쪽 시안 미리보기 **위쪽에 뜨는 한 줄**.
왼쪽 입력 패널의 제목/설명과는 **별개**(그건 이미 있음). 여기는 짧은 한 줄만.

## 상태 3가지
| 상태 | 성격 | 지속 |
|---|---|---|
| **기본 = 팁** | 그 칸을 채울 때 알면 좋은 것 | 계속 |
| **방금 채움 = 반응** | 채우거나 고친 직후 | 2초 → 팁 복귀 |
| **마일스톤** | 절반 / 하나 남음 / 완료 | 그 단계 내내 |
우선순위 `방금 채움 > 마일스톤 > 팁`

## 단계 만드는 법
[[4-4. 조립 레시피]] §4의 그 주제 레시피 카드(섹션 목록)를 그대로 단계로 변환.
- 순서: **메인 이미지 → 로고 → 히어로 텍스트 → (레시피 섹션 순서대로) → 문의 → SNS**
- 히어로 텍스트 단계는 칸이 2개(제목 / 설명) → 칸마다 팁
- 🚫 **「제목 위 문구」(eyebrow)는 편집 범위에서 제외** (2026-09-10 이선호) — AI가 넣고 유저는 건드리지 않는다. 단계·칸으로 만들지 말 것
- 헤더·푸터·위치 안내처럼 자동/조건부인 건 단계로 만들지 않음(단, 주소를 받아야 하면 핵심정보 칸에)
- **6~10단계**가 적정. 억지로 늘리지 말 것

## 🔴 채움 주체 — AI가 채울 수 있는 것 / 비워둘 것 (필수)

표에 **「채움」 열을 반드시 넣는다.** 두 가지뿐이다.

| 표기 | 뜻 | 무엇이 여기 해당하나 |
|---|---|---|
| **AI** | AI가 문장을 **지어서 채워둔다** | 표현·문장 — 인사말 · 소개글 · 초대의 말 · 스토리 · 섹션 제목 · 설명 문구 · 카피 · 안내 문구 톤 |
| **사실** | **자료에 있으면 뽑아 채우고, 없으면 비워둔다.** 지어내기 절대 ❌ | 이름 · 일시 · 기간 · 장소 · 주소 · 가격 · 금액 · 계좌 · 연락처 · 정원 · 마감일 · 회차 · 스펙 · 실측 · 자격 요건 · 경력 · 학력 · 수상 · 작품 정보(작가·연도·재료·크기) · 통계 · 후기 |

**이미지**는 `사실`로 본다 — 유저 업로드가 원칙, 「AI 이미지 생성」 버튼은 유저가 누를 때만.

### 왜 나누나
AI가 **일시·가격·연락처를 그럴듯하게 지어내면** 유저가 못 알아채고 그대로 발행한다 → 잘못된 정보가 나간 페이지. 표현은 틀려도 고치면 그만이지만, **사실은 틀리면 사고**다.

### 팁 쓸 때 달라지는 점
- **AI 칸**은 이미 채워져 있는 상태로 마주하므로 팁은 **「고칠 때 기준」** — 예 `두세 문장이면 충분해요`
- **사실 칸**은 **비어 있는 채로** 마주하는 일이 많으므로 팁이 더 중요하다 — **왜 중요한지 / 무엇을 고르는 기준인지 / 어떻게 보이는지**
- 사실 칸에는 **내용 조언 절대 금지**(규칙 4)가 그대로 적용된다

---

## 팁 규칙 (가장 중요)
1. **15자 안팎 한 줄.** 두 줄 되면 아무도 안 읽음
2. **그 칸에서만 성립해야 함.** 다른 칸에도 그대로 해당되면 팁이 아니라 공통 안내 → 쓰지 말 것
   - ❌ `엔터로 줄을 나눌 수 있어요` (모든 텍스트 칸)
3. **당연한 건 쓰지 말 것**
   - ❌ `적은 순서대로 표시돼요` · `전화번호를 누르면 바로 연결돼요`
4. **사실 정보에는 내용 조언 ❌** — 이름·일시·장소·개수·연락처·가격·경력처럼 **원래 있는 것**은 유저가 정하는 게 아님
   - ❌ `3~5개가 읽기 좋아요` · `너무 길 수 있어요`
   - ✅ 대신 셋 중 하나: **어떻게 보이는지** / **무엇을 넣을지 고르는 기준** / **왜 중요한지**
   - 예: `가장 많이 확인하는 정보예요` · `참석자가 알아야 할 순서만 넣어요`
5. **유저가 「정하는」 것(사진·문장·색·톤)에는 조언 OK**
   - 예: `행사 분위기가 보이는 사진이 좋아요` · `두세 문장이면 충분해요`
6. **안심(`없어도 괜찮아요`)은 기본 팁으로 쓰지 말 것.** 채우려는 순간에 출구를 보여주면 껍데기 페이지가 나옴. 안심은 망설일 때(8초 무입력)만
7. **기능·동작 안내는 값어치 있을 때만.** 모르면 못 쓰는 것이어야 함
   - ✅ `검색해서 고르면 지도에 표시돼요` (모르면 지도가 안 뜸)
8. **팁이 없으면 비워둘 것.** 매 단계 뭔가 떠 있으면 정작 중요한 말이 묻힘
9. **`맞는지 봐주세요` 계열 금지** — 왼쪽 패널이 이미 확인을 요청함
10. 같은 주제 안에서 **팁 문장이 겹치면 안 됨**

## 반응 규칙
- 그 단계에서 **실제로 좋아진 점**을 말할 것. `좋아요!` 같은 뭉뚱그린 칭찬 ❌
- **매 단계 달라야 함**(반복되면 3번째부터 안 읽힘)
- AI가 채워둔 걸 유저가 확인만 하고 넘어가면 반응 없음. **고쳤을 때만**
- 반복 입력(항목 여러 개)은 칭찬 대신 **개수 변화**: `5개가 됐어요`

## 마일스톤
단계 수에 맞춰 배치. 8단계 기준:
`벌써 절반이나 왔어요!` (4/8) · `이제 하나 남았어요` (마지막 직전) · `다 채우면 다른 시안도 보여드릴게요` (마지막)

## 문체
해요체 · 능동형 · 긍정형. `~해야 합니다` `~하세요` ❌ → `~하면 좋아요` `~해도 돼요`

## 🅰 왼쪽 패널 문구 — 제목 + 기대효과 (2026-09-10 추가)

지금까지 만든 **팁·반응**은 오른쪽 미리보기 **위쪽 한 줄**이다.
이것과 별개로 **왼쪽 입력 패널의 제목·설명**이 있고, 이건 **단계 단위**다(칸마다 ❌).

### 상태에 따라 두 벌
| 상태 | 제목 | 설명 |
|---|---|---|
| **비어 있음** | `{항목}을(를) 추가하면 좋아요` | **기대효과 한 줄** ← 이번에 작성할 것 |
| **채워져 있음** (AI 생성 또는 자료 추출) | `{항목}을(를) 미리 채워뒀어요` | `수정할 곳이 없는지 확인해 주세요.` (고정) |

### 기대효과 문구 규칙
1. **보는 사람(방문자) 관점의 이득**을 적는다. 만드는 사람의 편의 ❌
   - ✅ `어디서 여는 행사인지 알 수 있어요.`
   - ❌ `나중에 수정하기 편해요.`
2. **25자 안팎 한 문장 · 마침표로 끝냄**
3. 어미는 `~할 수 있어요.` `~하기 쉬워져요.` `~해요.`
4. **팁과 내용이 겹치면 안 됨** — 기대효과는 **「왜 넣나」**, 팁은 **「넣을 때 무엇을 알면 되나」**
5. 사실 정보 칸이어도 **「왜 필요한지」는 말해도 된다**(내용 조언이 아니므로)
6. 항목 이름을 그대로 되풀이하지 말 것 — ❌ `프로그램이 있으면 프로그램을 알 수 있어요.`

### 실제 예시 (1-① 행사 초대장 · Figma 확정본)
| 단계 | 제목 | 기대효과 |
|---|---|---|
| 메인 이미지 | 메인 이미지를 추가하면 좋아요 | 첫 화면에서 어떤 행사인지 바로 알 수 있어요. |
| 로고 | 로고 이미지를 추가하면 좋아요 | 어디서 여는 행사인지 알 수 있어요. |
| 프로그램 | 프로그램을 추가하면 좋아요 | 몇 시에 무엇을 하는지 알면 시간을 내기 쉬워져요. |
| SNS | SNS 채널을 추가하면 좋아요 | 앞으로 계속 소식을 받아볼 수 있어요. |

### 표 형식 (열 6개)
`# | 단계 / 칸 | 채움 | 왼쪽 제목 + 기대효과 | 팁 | 방금 채움`
- **왼쪽 제목 + 기대효과**는 **단계의 첫 행에만** 적고, 같은 단계의 나머지 칸은 `〃` 로 둔다
- 형식: `제목 / 기대효과` (슬래시로 구분)

### ⚖️ 제목 형태는 「런타임 상태」가 정한다 — 문서에는 **비어 있을 때 버전만** 적는다 (2026-09-10 확정)
한 단계 안에 AI 칸과 사실 칸이 섞이는 경우가 많다(히어로 = AI 카피 + 행사명·일시).
그래서 제목을 문서에서 미리 고정하지 않는다.

- **문서(이 표)에는 항상** `{항목}을 추가하면 좋아요 / {기대효과}` **만 적는다.** 채움이 `AI`인 단계도 마찬가지 — 자료가 없어 못 채우는 경우가 있으므로 기대효과는 늘 필요하다.
- **채워진 상태의 문구는 공식이라 표에 적지 않는다** — 화면에서 `{항목}을 미리 채워뒀어요 / 수정할 곳이 없는지 확인해 주세요.` 로 자동 전환.
- 판정 단위는 **단계**다. 그 단계의 칸이 **하나라도 비어 있으면** 「추가하면 좋아요」, **전부 채워져 있으면** 「미리 채워뒀어요」.

### 🎙 반응(방금 채움) 톤 — 담백하게 (2026-09-10 이선호 지시)
지나치게 구어적이고 감상적인 표현은 **전문적으로 보이지 않는다.** 반응은 **무엇이 어떻게 됐는지 담백하게 서술**한다.

**🚫 쓰지 말 것**
| 유형 | 예 |
|---|---|
| 의인화 | `이름이 앞에 섰어요` · `발행처가 자리 잡았어요` · `간판이 걸린 느낌이에요` |
| 화자 감상 | `감이 와요` · `내 얘기구나 싶어져요` · `그려지네요` · `궁금해지네요` |
| 감탄·이모지 | `멋진 메인 이미지네요 👀` · `대회 느낌이 살아났어요` |
| 과장 | `숫자가 확 들어와요` · `힘있게 자리잡았어요` |
| 모호한 정서 | `말투가 잘 살았어요` · `분위기가 전해져요` |

**✅ 쓸 것 — 두 갈래**
1. **반영 사실** — `{요소}가 채워졌어요 / 반영됐어요 / 표시됐어요 / 추가됐어요 / 정리됐어요`
2. **담백한 결과** — `{무엇}이 분명해졌어요` · `언제 어디서 하는지 분명해졌어요`
3. **개수 변화**(반복 입력) — `5개가 됐어요` (그대로 유지)

**교체 예시**
| ❌ | ✅ |
|---|---|
| 말투가 잘 살았어요 | 초대의 말이 채워졌어요 |
| 멋진 메인 이미지네요 👀 | 첫 화면이 채워졌어요 |
| 이름이 앞에 섰어요 | 이름이 반영됐어요 |
| 숫자가 확 들어와요 | 혜택 숫자가 반영됐어요 |
| 내 얘기구나 싶어져요 | 대상이 분명해졌어요 |
| 어떤 곳인지 느낌이 와요 👀 | 어떤 곳인지 분명해졌어요 |

**길이·중복** — 12자 안팎 · 마침표 없음 · 같은 주제 안에서 서술어가 연달아 겹치지 않게 6종(채워졌어요·반영됐어요·표시됐어요·추가됐어요·정리됐어요·분명해졌어요)을 돌려 쓴다.

### 🚫 채움이 `AI`인 칸은 「방금 채움」 반응이 없다 (2026-09-10 이선호 지시)
AI가 이미 문장을 지어 채워둔 칸이므로 **유저가 「채우는」 행위 자체가 없다.** 열에 `—`를 적는다.

- 유저가 그 문장을 **고쳤을 때도 반응 없음** — `채워졌어요`는 사실과 다르고, 고친 것을 칭찬하면 과하다
- 반응은 **`사실` 칸에만** 나온다(유저가 실제로 입력하는 자리)
- 결과적으로 반응이 붙는 칸이 줄어드는데, **그게 맞다** — 반응이 매 칸마다 나오면 무시된다
