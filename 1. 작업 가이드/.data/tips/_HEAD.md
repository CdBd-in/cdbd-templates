# 입력 단계 안내 문구 — 주제 25개

> **무엇** — 유저가 시안을 보며 내용을 채우는 화면의 **모든 문구**.
> **어디서 나왔나** — 단계 구성은 [[1-12. 조립 레시피]] §4 레시피 카드, 문구 규칙은 `.data/tips/_SPEC.md`(정본).
> **검수** — 272행 전수 자동 검사 통과(열 수 · 팁 20자 · 기대효과 마침표 · 주제 내 중복 · 금지표현).

## 화면 구조 — 문구가 놓이는 자리 4곳

```
┌ 왼쪽 입력 패널 ─────────┐   ┌ 오른쪽 미리보기 ──┐
│ ●●●○○○○○  3/8          │   │  ③ 팁 · 반응 ·    │
│ ① 제목                  │   │     마일스톤      │
│ ② 기대효과              │   │ ┌───────────────┐ │
│ [ 입력칸 ]              │   │ │   시안        │ │
└─────────────────────────┘   └─┴───────────────┴─┘
```

| 자리 | 단위 | 언제 |
|---|---|---|
| **① 제목** | 단계 | 항상 |
| **② 기대효과** | 단계 | 항상 |
| **③ 팁** | **칸** | 기본값 |
| **③ 반응** | 칸 | 채우거나 고친 직후 2초 |
| **③ 마일스톤** | 단계 | 절반 · 하나 남음 · 완료 |

우선순위 `반응 > 마일스톤 > 팁`

## 규칙 요약 (풀버전 = `.data/tips/_SPEC.md`)

**채움 열 — AI / 사실**
- **AI** = 문장을 지어서 미리 채워둠 (인사말·소개글·스토리·카피)
- **사실** = 자료에 있으면 뽑아 채우고 **없으면 비워둠. 지어내기 절대 ❌** (이름·일시·장소·가격·계좌·연락처·정원·마감일·스펙·경력·작품 정보·통계·후기·이미지)
- 왜 — 표현은 틀려도 고치면 그만이지만 **사실은 틀리면 사고**

**제목 — 런타임 상태가 정한다**
- 그 단계에 **한 칸이라도 비어 있으면** `{항목}을 추가하면 좋아요`
- **전부 채워져 있으면** `{항목}을 미리 채워뒀어요 / 수정할 곳이 없는지 확인해 주세요.`
- 표에는 **비어 있을 때 버전만** 적는다

**팁 10규칙(요약)** — 15자 안팎 · **그 칸에서만 성립** · 당연한 말 ❌ · **사실 정보에 내용 조언 ❌**(개수·분량 권유 금지) · 안심(`없어도 괜찮아요`)은 기본값 ❌ · `맞는지 봐주세요` ❌ · **마땅치 않으면 비워둘 것**

**기대효과** — **보는 사람(방문자)이 얻는 이득** · 25자 안팎 · 마침표 · 팁과 내용 겹침 ❌(기대효과=「왜 넣나」 / 팁=「넣을 때 알아둘 것」)

**공통 안내**(팁 아님 · 최초 1회) — `엔터로 줄을 나눌 수 있어요`

🚫 **「제목 위 문구」(eyebrow)는 편집 범위에서 제외** (2026-09-10) — AI가 넣고 유저는 건드리지 않는다. 단계·칸에 등장하지 않는다.

| 1   | 메인 이미지        | 사실  | 메인 이미지를 추가하면 좋아요 / 첫 화면에서 어떤 행사인지 바로 알 수 있어요.    | 행사 분위기가 보이는 사진이 좋아요  | 멋진 메인 이미지네요 👀          |

| 3   | 히어로 · 제목      | 사실  | 행사 제목과 설명을 추가하면 좋아요 / 첫 화면만 보고도 무슨 행사인지 알 수 있어요. | 제목은 짧을수록 눈에 잘 들어와요   | 제목이 더 또렷해졌어요            |
