# 75안 제작 페르소나 규격 (2026-09-04 · 이선호 지시)

> 🔑 **전제 — 이 75안은 「개정된 7단계 플로우를 실제로 통과한 결과물」이다.**
> 이상적인 유저 25명이 아니라, 숙련도·자료가 제각각인 25명이 플로우를 밟은 뒤 나온 페이지.

## 1. 페르소나 레코드 필수 필드

| 필드 | 내용 |
|---|---|
| `id` | 주제 분류 코드 (예 `3-①`) |
| `who` | 이름·나이·업종·구체 상황 (지어낸 상호·지역·가격까지) |
| `skill` | 상 / 중 / 하 |
| `mat` | 풍부 / 보통 / 빈약 |
| `step2_want` | ② 「하고 싶은 일」로 고른 문장 |
| `step2b_target` | ②-B AI 추론 타겟 → **그대로 확인 / 다른 추천으로 변경 / 직접 입력** 중 하나 |
| `step3_answers` | ③ 문항별 실제 답변 |
| `step3_none` | 「이건 없어요」로 **끈** 문항 (→ 그 섹션 제외) |
| `step3_skipped` | 그냥 **건너뛴** 문항 (→ 빈 자리 처리 규칙 적용) |
| `chips` | AI가 미리 켠 「함께 담을 것」 **최대 3개 + 근거 한 줄** |
| `step4_type` | ④ 통보 결과 (원/멀티) + 근거 한 줄 |
| `holes` | 빈 자리 처리 결과 — 무엇이 「○○ 문의」로 대체됐고 무엇이 섹션째 빠졌나 |

## 2. 분포 (3-5. 200 페르소나 검증의 축소판)

- **숙련도**: 상 6 · 중 11 · 하 8
- **자료 상세도**: 풍부 8 · 보통 10 · 빈약 7
- **목적 명확성**: 명확 15 · 보통 8 · 모호 2
- ⚠️ **자료 빈약 7명은 섹션 수가 적고 「문의」 대체 자리가 있는 페이지가 나와야 정상.**
  전부 풍성하게 만들면 플로우 검증이 아니라 프리셋 전시가 된다.

## 3. 칩 규칙 (1-9 ③ · 1-12 §3-B)

- **자료 근거가 있을 때만 켠다** → 자료 빈약 페르소나는 칩이 0~1개
- **보조 블록만** (★ 결정 블록은 칩 대상 ❌)
- **최대 3개** · 3개 이상 켜지면 ④에서 멀티 가중

## 4. 빈 자리 처리 규칙 (1-12 §1)

| 무엇이 비었나 | 처리 |
|---|---|
| 값만 빔 (가격·요금·기간) | 「가격 문의」·「일정 문의」 + 문의 버튼 |
| 반복 항목이 전부 빔 | **섹션째 제거** (제목만 남기는 것이 최악) |
| 보조 블록이 빔 | 섹션째 제거 |
| ★ 결정 블록·히어로가 빔 | 제거 불가 → 다시 물음 |

## 5. ④ 원/멀티 4관문 (1-9 검토 중 ⓒ)

0. 목적이 P1 알림·P2 초대·P3 접수 → **원페이지 확정**
1. 묶음(챕터) 3개 미만 → 원페이지
2. 장면형(룩북·포트폴리오) → **멀티**
3. 카드 35장 이상 → 멀티 / 미만 → 원페이지

→ 이번 75안은 **원페이지 스택**으로 제작하되, 멀티 판정이 난 주제는 프레임 밖에 표시.
