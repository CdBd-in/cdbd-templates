# 폰트 라이브러리

CdBd 에디터의 **페이지 서체** 설정에서 선택 가능한 모든 폰트(한글 26종·영문 18종)를 색상 팔레트와 동일한 9개 무드로 분류하고, 어울리는 한·영 조합을 정리합니다.

> 원본 폰트 목록은 `cdbd-design-system/디자인 시스템/4. 카드 기능 정의/4-2. 페이지 테마.md` 2번 항목 참조.

## ✅ 사용 원칙 (필수 준수)

### 0. 🚨 이 44종 밖 폰트 사용 절대 금지 (2026-07-20 · 필수)
> **왜**: `/draft` 시안 36안 검수에서 D4가 **CdBd에 없는 폰트를 다수 채택** → 4단계 CdBd 에디터에서 **재현 불가**(그 폰트가 서체 목록에 없음). 무드가 맞아도 목록 밖이면 무의미.

- **🔴 CdBd에 없음 = 사용 금지(발견된 오용)**: `IBM Plex Sans KR` · `Black Han Sans` · `Space Grotesk` · `Gothic A1` · `Fredoka` · `Jua` · `Syne` · `Cormorant`(≠ EB Garamond) · `제주명조`(≠ 조선일보명조) · `Unbounded`
- **대체 예**: IBM Plex/Gothic A1 → Pretendard·본고딕 · Space Grotesk → Montserrat·Poppins · Cormorant → EB Garamond · 제주명조 → 조선일보명조·본명조 · Fredoka·Jua·Syne·Black Han Sans·Unbounded → 아래 44종 중 무드 일치 폰트
- **절차**: 폰트 확정 전 **반드시 아래 44종(또는 `listAvailableFontsAsync` ∩ 이 문서) 대조**. 목록에 문자열이 없으면 채택 ❌.
- ⚠️ **파셜산스는 44종에 있으나 「플레이풀 전용」** — 프로/비즈니스·포트폴리오 무드에 사용 ❌ ([[../3. 신규 템플릿 기획/3-5. B·C·D 36안 피드백 개정 계획 (2026-07-20)]] R19).

### 1. 한 페이지 = 1~2개 폰트
- **기본은 1개** — 페이지 전체에 페이지 테마 `{서체}` 하나만 적용. 모든 카드의 텍스트가 동일 폰트로 통일됨.
- **2개까지 허용** — 디스플레이(헤드라인·로고·강조 문구)와 본문에서 다른 폰트를 쓸 때만. 그 이상은 ❌
- 두 번째 폰트는 **텍스트 카드 단위 커스텀 서체** 또는 **이미지(로고/타이포그래피)로 처리**.

### 2. 국문 템플릿 본문 = 한글 폰트 필수
- 페이지 테마 `{서체}` = **반드시 한글 폰트**. 본문·캡션·버튼 텍스트 가독성의 절대 기준.
- **예외 허용**: 영문 헤드라인·로고·캐치프레이즈 등 **장식적 영문 텍스트만** 영문 폰트 OK.
- 이유: 영문 폰트로 한글 본문을 적용하면 → fallback 폰트(시스템 기본)로 렌더링되어 페이지 통일성 깨짐.

### 3. 무드 = 색상 팔레트와 일치
- 폰트 무드는 [[1-3. 색상 팔레트]]의 9개 카테고리와 동일 체계.
- 페이지 테마 결정 시 **같은 무드의 컬러 팔레트 + 폰트** 조합이 가장 안전.

### 4. ⚠️ Figma 시안 제작 시 주의 (2026-07-10 실측)
> 아래 3건은 **CdBd가 아니라 Figma 쪽 제약**. 시안(2·3단계)에서만 걸리고, 4단계 CdBd 에디터에선 해당 없음.

- **나눔명조·나눔고딕은 Figma에 없음** → 시안에선 **조선일보명조 / 본명조 / KoPub바탕**으로 대체. (CdBd 에디터엔 정상 존재 — 위 무드 표의 나눔 계열은 그대로 유효)
- **KoPub바탕(KoPubWorldBatang Pro)은 Regular가 없음** (Medium·Bold만) → 본문은 **Medium** 사용.
- **싱글웨이트 폰트 = 시안에선 Regular로 보이지만 4단계에서 Bold 토글 대상** — 고운돋움·조선일보명조·파셜산스·에스코어드림·마포꽃섬 등. CdBd 에디터는 Regular만 있는 폰트도 **강제 Bold 토글**이 되므로, 시안에서 **헤드라인·버튼 텍스트로 쓴 항목을 기록해 두고** 4단계에서 Bold 적용. *(고운바탕은 Bold 있음 — 시안에서 바로 적용 가능)* → [[../CLAUDE.md]] 폰트 원칙 7

## 🤝 어울리는 폰트 조합 가이드

### 조합 원칙
1. **본문 폰트는 항상 한글** (국문 템플릿 기준).
2. **헤드라인 = 영문 디스플레이 + 본문 = 한글 산세리프/명조** 조합이 가장 자주 쓰이는 패턴.
3. 같은 무드 내에서 조합하거나, **인접 무드끼리 조합** (예: 럭셔리 + 빈티지, 모던 + 프로페셔널).
4. 헤드라인이 굵으면 본문은 가볍게, 헤드라인이 얇으면 본문은 단단하게 — **굵기 대비**가 핵심.

## 🗺 폰트 선택 의사결정 가이드

```
1. 페이지 무드 결정 (9개 중 1개) — 색상 팔레트와 동일 무드 권장
        ↓
2. 본문 한글 폰트 1개 선택 (해당 무드의 "본문 권장 한글 폰트" 표 참조)
        ↓
3. 헤드라인 처리 결정
   ├── A. 본문과 동일 폰트로 통일 (가장 안전, 1폰트 페이지)
   ├── B. 같은 한글 폰트의 굵은 weight으로 차별화 (1폰트 페이지)
   └── C. 어울리는 디스플레이 폰트 1개 추가 (2폰트 페이지, 위 조합 표 참조)
        ↓
4. 한 페이지 = 1~2개 폰트 한도 준수 확인 ✅
```

### 망설여질 때의 안전 선택지
- **헤드라인+본문 모두 프리텐다드** — 어떤 카테고리에서도 실패하지 않는 폴백.
- **헤드라인+본문 모두 본명조** — 명조 계열 페이지의 폴백 (격조·신뢰).
- **본문 KoPub바탕 + 헤드라인 Playfair Display** — 럭셔리 페이지의 검증된 조합.

## ⚠️ 자주 하는 실수

| 실수 | 왜 문제인가 | 올바른 처리 |
|---|---|---|
| 국문 본문에 영문 폰트(Lato, Montserrat 등) 적용 | 한글이 fallback 폰트로 렌더링되어 페이지 통일성 깨짐 | 본문은 항상 한글 폰트, 영문은 헤드라인·로고에만 |
| 한 페이지에 폰트 3개 이상 사용 | 시각적 노이즈, 브랜드 통일성 저하 | 최대 2개 — 그 이상은 텍스트→이미지로 처리 |
| 디스플레이 폰트(베이글팻·HS산토끼체·평창평화체)로 본문 작성 | 가독성 급감, 장문 읽기 피로 | 디스플레이는 헤드라인·강조 전용, 본문은 모던/프로페셔널 무드 폰트 |
| 무드 간 충돌 조합 (예: HS산토끼체 + EB Garamond) | 톤 충돌로 어색함 | 같은 무드 또는 인접 무드 내에서 조합 |
| 영문 디스플레이 + 본문 모두 영문 (국문 템플릿) | 한글 본문 fallback 문제 재발 | 영문 헤드라인 + 한글 본문으로 분리 |
