# 카드 블록 라이브러리

> **카드 블록** = 여러 CdBd 카드를 묶어 하나의 기능·의미 단위를 이루는 **재사용 가능한 부분 템플릿**.
> 예: **히어로 블록** = 이미지 + 프로필 + 구분선 + 텍스트(들).
>
> **목적**: 신규 템플릿 제작 시 **주제·카테고리별로 검증된 블록 + 배리에이션**을 골라 쓰면, 매번 0에서 구성·디자인하지 않고 **빠르게 완성**. (템플릿의 최우선 원칙 = 편집 용이성의 연장 — 페이지뿐 아니라 **블록 단위 재사용**.)
>
> 각 블록은 **원본 1 + 배리에이션 N**으로 축적. 배리에이션은 **컬러·폰트를 제외한** 디자인 요소(레이아웃·정렬·여백·모서리·이미지 모양·구분선 모양·텍스트 정렬·사이즈)로만 변주한다.

---

## 🎯 개념 — 왜 "블록"인가

- 페이지 전체가 아닌 **부분(섹션) 단위** 자산: 히어로·정보·CTA·푸터 등.
- **워크플로우 연계** ([[1-1. 워크플로우]]): 2·3단계(claude.ai/design 시안 → Figma 반입·혼합)에서 검증된 블록을 **출발점**으로 재사용. 블록이 CdBd-legal이므로 4단계 CdBd 구현에 그대로 전이.
- **카테고리별로 정리**: 프로필·명함 / 초대·예약 / 홍보·카탈로그 / 가이드·신청 / 소식·매거진.

### 🔀 변주 축 2종 (색·폰트는 항상 고정)
섹션 배리에이션은 아래 두 축 중 하나, 또는 둘 다로 만든다. **공통: 색·폰트 고정 → 구조 차이만 보이게.**
1. **카드 구성 변주** — **같은 정보를 다른 카드 타입으로 통째 교체.** 예: 라인업 = 갤러리 vs 프로필×3 vs 텍스트 나열. (→ [[1-2. 기획 문서 템플릿]] 변주축 ④) — CdBd의 카드 다양성을 살리는 방식.
2. **디자인 속성 변주** — **같은 카드에서** 레이아웃·정렬·여백·모서리·이미지 모양·구분선·텍스트 정렬/사이즈만 변경. 예: 히어로 블록 A/B/C(초대·예약).
> 성숙한 프리셋은 둘을 겸함 — 카드 구성을 바꾸고, 그 안에서 디자인도 최적화.

## 🔄 섹션 프리셋 제작 워크플로우 (3단계)

> 신규 템플릿을 0에서 구성하지 않고 **검증된 섹션 프리셋을 골라 조립**하기 위한 생산 방식.

1. **Claude Design 시안 3종 (탄탄한 풀페이지)** — [[1-1. 워크플로우]] 2단계. 무드 방향만 주고 **구조가 다른 3종** 생성(색·폰트·카드 구성 자유 탐색). *생성 트리거는 브라우저에서 사용자가 — 코드는 DesignSync로 pull.*
2. **섹션별 배리에이션** — 3종 시안을 바탕으로 페이지를 **섹션 묶음**(히어로·일시·라인업·티켓·위치·푸터…)으로 쪼개 각 섹션을 **A/B/C 프리셋**으로. **색·폰트 고정**, 변주는 위 **2종 축**.
3. **채택 → 템플릿화 → 재사용** — 각 섹션 우수 프리셋을 **기준 2**로 채택 → Figma/CdBd 블록으로 정제(평탄화·CdBd-legal) → **이 라이브러리에 등록** → 신규 템플릿마다 **섹션별로 골라 조립 + 무드(색·폰트) 갈아끼워** 재사용.

**🧩 섹션 조립 모델** — 페이지 = **섹션마다 프리셋 하나씩** 골라 세로 조립(예: 히어로 B + 일시 A + 라인업 C). 섹션은 **묶음 개념**일 뿐 중첩 컨테이너 ❌ → 최종은 **평면 카드 스택**.

**🔒 기능 고정 카드는 변형 대상 ❌** — **예약·위치안내·SNS·Q&A** 등 기능 고정 카드는 프리셋마다 바꾸지 않고 **항상 같은 구성** ([[1-6-2. CdBd 카드 기능]]).

**🧷 섹션 구분 = 내용 기준 / 반복 요소 통일 = 페이지 조합 시에만 (2026-07-07)** — 섹션은 **담는 내용**으로 구분한다(히어로·일시·라인업·타임테이블·티켓·위치·푸터…). **반복 요소**(구분선 모양·두께·색, 섹션 라벨 스타일, 버튼 모양·크기, 여백 리듬)의 **통일은 「여러 섹션을 하나의 페이지로 조합할 때」만** 적용 — **프리셋 개별 제작 단계에선 강제 ❌**(각 프리셋은 자기 무드/원본 디자인을 따라도 됨). 즉 최종 페이지 완성 시 반복 chrome을 한 스타일로 정돈.

## 🧱 블록 기준 (필수)

### 기준 1 — 테마 적응성: 색·폰트는 대상 페이지 테마로 교체

- **원본과 모든 배리에이션은 컬러·폰트를 「적용할 페이지 테마」에 맞게 수정할 수 있어야 한다.** 블록은 특정 색·폰트에 종속되지 않는다.
- 블록의 **자산 가치 = 구조·레이아웃·정렬·여백·모양·위계**. 색·폰트는 **중립**이며, 사용 시 대상 템플릿의 무드에 맞춰 갈아끼운다:
  - 색 = **3토큰**(`{배경색}`/`{텍스트색}`/`{버튼색}`) 역할로만 표기 · 보조색 = `{텍스트색}×N%` · 강조배경 = `{버튼색}×N%` (→ [[1-2. 기획 문서 템플릿]] Part A, [[1-3. 색상 팔레트]])
  - 폰트 = 페이지당 1~2개 · 국문 본문 = 한글 폰트 · **텍스트 웨이트 = Regular/Bold 2종만**(CdBd Bold 토글과 정합) (→ [[1-4. 폰트]])
- 따라서 블록 제작 시 **특정 hex·특정 폰트에 종속되는 디자인 금지**(예: 그 색이어야만 성립하는 장식 ❌).
- **배리에이션끼리 비교·평가할 때도 색·폰트는 동일하게 고정**하고 **구조 차이만** 본다 — 변주 축(구조)을 색·폰트 차이로 오염시키지 않기 위해.

### 기준 2 — 좋은 배리에이션 판별 체크리스트

> A/B/C 실제 평가에서 정제한 재사용 기준. 새 블록의 배리에이션을 만들 때마다 이 체크리스트로 검수.

**✅ 배리에이션이 되려면**
- **원본과 한눈에 다른 레이아웃** — 구성·배치가 **실질적으로** 달라야 한다.
- 그러면서 **레이아웃이 안정적** — 정렬·간격·위계가 무너지지 않는다.
  - 🟢 *좋은 예(A): 좌측 정렬 에디토리얼 — 기존과 확연히 다르면서 레이아웃도 안정적.*

**❌ 배리에이션으로 인정 안 됨**
- **단일 요소만 변경** — 구분선 모양 하나만 바꾸고 나머지 레이아웃은 기존과 거의 같음 → 배리에이션 ❌. **레이아웃·구성 차원에서 달라야** 한다.
  - 🔴 *반례(B): 구분선 모양 말고는 기존 레이아웃과 차별점이 거의 없음.*
- **개별 요소 모양이 전체 톤과 부조화** — 한 요소(예: 이미지 모양)가 블록 전체 무드와 안 어울림 → 재검토.
  - 🔴 *반례(B): 01 이미지의 모양이 전체 톤과 안 어울림.*

**⚠️ 멀티 컬럼(2단) 레이아웃 3원칙**
1. **label ↔ contents 텍스트 사이즈 균형** — 라벨과 값의 크기 차이가 과하면 시각적으로 불안정. 위계는 주되 안정 범위 안에서.
2. **라벨 줄바꿈 금지** — 고정폭 라벨이 **한 줄**에 들어와야 한다. 안 되면 폭을 늘리거나 라벨을 축약/재배치.
3. **인접 요소와 정렬 일관성** — 2단 블록이 좌정렬인데 바로 위 제목이 초대형 중앙정렬이면 시각 불균형. **정렬·스케일을 이웃 요소와 맞춘다.**
   - 🔴 *반례(C): 2단 시도는 좋으나 ① label-contents 사이즈 차이 과다 ② '드레스코드' 라벨 줄바꿈 ③ 위 초대형 중앙 제목 ↔ 아래 좌정렬 2단 → 셋 다 불안정.*

**🔁 리비전 원칙** (정렬·정돈 수정 시 "재차별화" 유지)
- **정렬을 원본에 맞추더라도 다른 축에서 차별성 유지** — 정렬 불일치를 고치려 원본과 같은 정렬로 되돌리면 **원본과 다시 유사**해질 수 있다. 정렬은 맞추되 **구조(패널·색 밴드)·위계·이미지 처리** 등 다른 차원에서 차별점을 확보. *(C 리비전: 중앙정렬 통일 → 정보에 색 밴드 패널로 재차별화.)*
- **강한 요소가 구분 역할을 하면 구분선 제거** — 풀블리드 이미지·색 밴드처럼 이미 시각적 분리를 만드는 요소가 있으면 구분선을 겹쳐 넣지 않는다(장식 최소화, 5대 원칙 #5와 통함). *(B 리비전: 이미지가 상·하를 가르므로 구분선 삭제.)*
