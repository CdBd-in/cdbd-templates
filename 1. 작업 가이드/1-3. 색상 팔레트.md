CdBd는 **비즈니스용 모바일 페이지**가 핵심 키워드 → 가독성이 절대 기준. 무드 9개 × **총 316개**.

**검증 기준:** 배경 ↔ 텍스트 contrast ratio ≥ 3.6:1 (표의 「대비」 열)
- AAA (≥7:1): 236개 — 모든 텍스트에 안전
- AA (4.5-7:1): 54개 — WCAG AA Normal Text 통과
- AA-Large (3.6-4.5:1): 26개 — 작은 본문엔 약함, 중간 크기 이상 권장

## 🔓 이 라이브러리는 **제약이 아니라 참고다** (2026-07-10 확정)

> 시안 팔레트를 **이 표 안에서만 고르지 말 것.** 표에 갇히면 무드가 뻔해지고 시안끼리 비슷해진다.

- **자유롭게 새 팔레트를 만든다** — 주제·브랜드 자산(로고 색)·무드에서 출발해 3토큰(`{배경색}`/`{텍스트색}`/`{버튼색}`)을 직접 설계.
- **지켜야 하는 건 딱 두 가지 대비뿐**: `텍스트↔배경 ≥ 3.6:1` **그리고** `버튼↔배경 ≥ 3.6:1`. (버튼 글자 = `{배경색}` 고정이므로)
- **2색보다 3색을 기본으로** — 2색은 액센트가 없어 위계가 약하다. 버튼색을 텍스트색과 다르게 잡으면 포인트 컬러가 자동으로 생긴다.
- 이 표는 **막힐 때 꺼내 보는 검증된 출발점**이자 무드별 톤 감각의 레퍼런스로 쓴다.

## 🎯 팔레트 채택 절차 — 6단계 (2026-07-16 신설 · 필수)

> **왜 신설했나**: 위 「참고일 뿐」 원칙만으론 안 지켜졌다. 2026-07-16 A① 시안 3안을 만들 때 **무드 표를 열어 위에서부터 대비 통과하는 첫 팔레트를 채택** → 결과가 **HappyHues 4·11·12**(전부 같은 출처 · 전부 표 상단). **300개 넘는 팔레트** 중 3개를 뽑았는데 하필 다 그 자리인 건 **표 상단 앵커링**이다.
> ⚠️ **표 상단 앵커링은 랜덤보다 나쁘다** — 랜덤은 그래도 매번 다르지만, 앵커링은 **매번 같은 팔레트**를 낸다. 시나리오 16개를 그렇게 돌리면 시안 48개가 전부 비슷해진다.

**아래 순서를 밟는다. ①이 출발점이며 표(⑥)는 폴백이다.**

1. **🎬 주제의 실제 장면에서 색을 뽑는다** — 그 페이지가 실제로 존재하는 공간·사물의 색. **표를 열기 전에 한다.**
2. **🏷 브랜드 자산을 앵커로** — 답변에 **로고 색·시그니처 색**이 있으면 3토큰 중 하나에 반영. (질문 세트가 「로고 이미지」를 묻는 이유 = 색 재료)
3. **🎨 무드로 톤 조정** — 같은 재료라도 무드에 따라 채도·명도가 달라진다. (같은 "전구빛"이 모던=차분한 황동 / 드리미=밝은 호박)
4. **✅ 대비 2개 검증** — `텍스트↔배경 ≥ 3.6:1` **그리고** `버튼↔배경 ≥ 3.6:1`. **직접 계산할 것**(표의 「대비」 열은 텍스트-배경만)
5. **🔁 중복 회피 — 3안은 「명도 방향」과 「액센트 hue」를 둘 다 분산** *(2026-07-16 구체화 · 필수)*
   - ⚠️ **①주제에서 뽑기는 3안을 수렴시킨다** — 같은 주제니까 같은 재료로 간다. A①(서점의 밤)에서 **안1·안3이 둘 다 "다크 배경 + 웜 앰버 액센트"**로 붙어버렸다. **①을 지키면 ⑤가 더 중요해진다.**
   - **㉮ 배경 명도** — 3안이 **명도 방향을 나눠 가진다**. **금지 = 3안 전부 같은 방향**(3라이트·3다크). 🔀 **비율은 자유**(2026-07-21 이선호): **밝음2:다크1** 이든 **다크2:밝음1** 이든 OK(옛 "다크 2개 ❌"는 폐기 — 전부 같은 방향만 금지). 겹치는 2안은 **hue(온도)로라도 갈라야** 한다.
   - **㉰ 순백/순흑 탈피 (2026-07-21 이선호)** — 배경을 **화이트-근접·블랙-근접만** 쓰지 말 것. "라이트"=크림·오트·베이지·연한 유채(세이지·더스티블루) · "다크"=순블랙 대신 딥네이비·딥그린·에스프레소·잉크 · **중간 명도 배경**도 OK. 주제 장면(①)에서 뽑으면 자연히 유채·중간톤. 대비 2개(④)만 지키면 됨. (근거: B 12안이 전부 near-white/near-black이라 단조)
   - **㉯ 액센트 hue** — **최소 2계열**(웜 / 쿨 / 뉴트럴). **3안 전부 웜 ❌**. 명도만 벌리는 건(황동 vs 호박) **같은 웜이라 부족**했다.
   - **앞 시나리오와도 회피** — 이미 쓴 팔레트·출처·색 계열을 기록하고 피한다.
   - 🟢 **교정 예(A① 최종)**: 안1 **라이트+뉴트럴**(종이·차콜) / 안2 **라이트+웜**(크림·가죽) / 안3 **다크+쿨**(야간·달빛블루) → 명도는 안1·안2가 겹치지만 **hue가 뉴트럴 vs 웜**으로 갈리고, 안3은 명도·hue 둘 다 혼자다.
6. **📚 표는 폴백** — ①~③으로 안 나올 때만 꺼낸다. **그때도 맨 윗줄부터 고르지 말 것** — 무드 안에서 주제에 가까운 톤을 찾아 들어간다.

**적용 예 — A① 「밤의 문장들」 북토크 · 책방 오래** (2026-07-16 · [Figma 조합 테스트](https://www.figma.com/design/24O01lprp5i2ufl7CbZXXx/CdBd-%ED%85%9C%ED%94%8C%EB%A6%BF--%EC%84%B9%EC%85%98-%ED%94%84%EB%A6%AC%EC%85%8B?node-id=3322-70))

재료는 답변에 이미 있었다 — **로고 = 검정 단색** · **메인 이미지 = 서가 · 야간 조명**.

## 🎯 역할 매핑 규칙

| 팔레트 종류 | 색상 1 | 색상 2 | 색상 3 |
|---|---|---|---|
| **2색** | `{배경색}` | `{텍스트색}` + `{버튼색}` (동일) | — |
| **3색** | `{배경색}` | `{텍스트색}` | `{버튼색}` |

> ⚠️ 보조 텍스트(캡션·유의사항)는 `{텍스트색} × 60%` 또는 `× 40%`로 투명도 조절. 별도 회색 지정 ❌
> ⚠️ AA-Large 등급(대비 3.6-4.5)은 본문 14pt 이하에선 가독성이 떨어짐. 헤드라인·CTA 위주로 활용.

### 🔤 「버튼글자」 열 — 버튼 안 글자색 (2026-07-16 신설)

| 값 | 뜻 |
|---|---|
| `–` | **CdBd 기본** = 버튼 글자에 `{배경색}` 사용 (306개) |
| **`텍스트색`** | **예외** — 버튼 글자에 `{텍스트색}` 사용 (6개) |

**왜 예외가 필요한가**: CdBd는 버튼 글자 = `{배경색}` 고정이라, **버튼↔배경 대비가 낮으면 버튼 글자도 같이 안 읽힌다**(같은 두 색의 대비이므로 숫자가 똑같다). 이때 글자만 `{텍스트색}`으로 바꾸면 버튼이 살아난다.
- 예: `HappyHues 14` — 흰 배경 + 노란 버튼. 버튼 글자를 흰색(=배경색)으로 쓰면 대비 1.39로 안 보이지만, `{텍스트색}`(`#272343`)을 쓰면 **10.71**로 또렷해진다.
- 🛠 **4단계 구현**: 버튼 카드의 `block.innerStyle.color`를 `{텍스트색}`으로 지정 (기본은 `{배경색}`). 별도 버튼 카드에서만 가능 — **위치 안내 카드 내부 '지도 보기' 버튼은 채움·글자색 고정이라 이 예외를 못 쓴다.**
- ⚠️ 이 예외는 **버튼 글자 가독성만 해결**한다. **버튼이 배경에서 안 떠 보이는 문제(형태 가시성)는 그대로**이므로, 버튼이 배경에 묻히는 팔레트는 이 예외로 살릴 수 없다.

## 🔄 팔레트 추가 방법 (2026-07-16 기록)

### 🅐 Huemint에서 새로 뽑기

> generate 버튼을 수백 번 누를 필요 없다. **huemint는 API가 열려 있다.**

**엔드포인트**: `POST https://huemint.com/api/` (`Content-Type: application/json`)

```json
{
  "mode": "transformer", "num_colors": 3, "temperature": "1.3", "num_results": 50,
  "adjacency": ["0","75","50","75","0","50","50","50","0"],
  "palette": ["#F5F1E8", "-", "-"],
  "page": "website-1", "preset": "green"
}
```
- `adjacency` = **website-1 실측값**(색끼리 얼마나 붙어 쓰이는지). 다른 페이지 유형은 값이 다름 → 화면에서 `input#matrix-0-1`·`0-2`·`1-2` 읽어 확인.
- `palette` = 3칸이 각각 **배경·텍스트·버튼**. `"-"` = huemint가 채움, hex = **잠금(lock)**.
- `preset`: `default` `high-contrast` `bright-light` `pastel` `vibrant` `dark` `hyper-color` + 색상별 `red` `orange` `yellow` `green` `cyan` `blue` `violet` `pink`.
- 응답: `{"results":[{"palette":[...], "score":...}]}`

**🔑 무드를 맞추는 핵심 3가지** (시행착오로 확정)
1. **배경색은 반드시 잠글 것.** 3칸 다 `"-"`로 자유 생성하면 무드가 깨진다 (페미닌에 네이비+민트, 럭셔리에 흰 배경+핫핑크가 섞였음). 무드별 배경 시드를 20개쯤 준비해 돌려가며 잠근다.
2. **버튼색(액센트) 색상(hue) 범위를 검증**할 것. 배경만 잠가선 부족 — 럭셔리 배경에 형광 마젠타 버튼이 붙는다.
3. **텍스트색도 검증**할 것. 2번까지만 하면 럭셔리 다크 배경에 **네온 민트 텍스트**가 들어온다. 럭셔리 텍스트 = 크림/화이트/골드(채도 ≤35% 또는 hue 25~60)로 제한.

### 🅑 레퍼런스 이미지에서 추출하기

- **hex가 명시된 팔레트만** 쓴다. 눈대중 추출 ❌ (대비 계산이 어긋남).
- 🥇 **텍스트 = '배경과 대비가 가장 센 색'으로 자동 확정** (2026-07-16 확정 규칙). 브랜드 팔레트(색 5~7개)에서 조합을 뽑을 때 **배경을 고르면 텍스트는 계산으로 결정**되고, **버튼만 나머지 색 중에서 고르면 된다**. 순열을 전부 열거하면 「거울쌍」(텍스트/버튼만 바뀐 쌍)과 「색깔 본문 글씨」 같은 이상한 조합으로 표가 오염되는데, 이 규칙이 그걸 원천 차단한다.
- 배경·텍스트가 같고 **버튼만 다른 조합**은 서로 다른 팔레트로 등재해도 되지만, **버튼이 배경과 같은 색 계열이면 제외**(액센트 효과 없음).
- **배경/텍스트 쌍만 주는 레퍼런스**(예: Colours Cafe)는 **2색 팔레트**(버튼=텍스트)로 등재 — 「역할 매핑 규칙」의 2색 행 그대로.

### 🅓 문서 ↔ 피그마 양방향 동기화 (필수, 2026-07-16 확정)

> **어느 쪽에서 고쳐도 된다.** 문서에서 대량 추가하든, 피그마에서 보고 지우든 양쪽 다 반영된다.
> 🔑 **충돌 시 = 피그마 우선** (사용자 결정) · ⏱ **시점 = 팔레트를 건드리는 작업마다 자동** (따로 시키지 않아도 작업 끝에 맞추고 보고)

#### 왜 스냅샷이 필요한가 (이게 핵심)

문서와 피그마 **둘만 비교하면 "다르다"는 건 알아도 "누가 바꿨는지"를 모른다.**
> 문서엔 `Sapphire 01`이 있는데 피그마엔 없다 → 문서가 **추가**한 건가, 피그마에서 **지운** 건가? 처리가 정반대인데 구분 불가.

→ **마지막으로 맞춘 상태를 스냅샷으로 저장**해두면 3자 비교로 답이 나온다.

| 스냅샷 | 문서 | 피그마 | 판정 |
|---|---|---|---|
| 없음 | 있음 | 없음 | 문서가 **추가** → 피그마에 그리기 |
| 있음 | 있음 | 없음 | 피그마에서 **삭제** → 문서에서 빼기 |
| 있음 | 없음 | 있음 | 문서에서 **삭제** → 피그마에서 지우기 |
| 있음 | 값A | 값B | **양쪽 수정 = 충돌** → **피그마(값B) 채택** |

- 📄 **스냅샷 파일**: `1. 작업 가이드/.data/palette-sync.json` (uid·이름·무드·출처·3색·**btnText**). **동기화 성공 후 반드시 갱신** — 안 하면 다음 동기화가 오판한다.
- 🔤 **`btnText`**: `bg`(기본=버튼글자 배경색) / `tx`(예외=버튼글자 텍스트색). 피그마 카드엔 `sharedPluginData("cdbdpal","btnText")`로 심고, 예외 카드는 `preview>button`의 라벨 fill을 텍스트색으로 + `meta`에 `btnTextNote`(⚠ 버튼글자 = 텍스트색) 추가. 문서는 「버튼글자」 열.
- 🆔 **고유번호(uid)**: `p001`~`p316`. 피그마 카드의 `sharedPluginData("cdbdpal","uid")`에 심겨 있음(화면엔 안 보임). **이름을 바꿔도 살아남아** 개명을 추적할 수 있다 (검증 완료). 새 팔레트는 마지막 번호 +1.
- 🎨 카드에 `mood`도 함께 심겨 있어 **다른 무드 그리드로 옮기면 무드 이동으로 감지**된다.

#### 동기화 절차

1. **읽기 3곳** — ① 문서 표 ② 피그마 카드(uid·색·이름·무드는 `getSharedPluginData` + fills에서 되읽기) ③ 스냅샷
2. **3자 비교** — 위 표대로 판정. uid로 매칭(이름 ❌ — 개명 때문에)
3. **규칙 재검증 (필수)** — 병합 결과 전체를 「🅒 공통 필터 규칙」으로 다시 검사
4. **양쪽 반영** — 문서 표·개수·분포표·총계 / 피그마 카드·제목 개수·헤더 총계
5. **스냅샷 갱신**
6. **보고** — 추가/삭제/수정/충돌 건수를 사람 말로

#### 🚨 피그마 우선의 예외 — 규칙 위반은 조용히 받지 말 것

**값은 피그마를 따르되, 규칙은 매번 재검증한다.** 피그마에서 고친 색이 `대비 <3.6`이거나 `쨍한 색 2개 이상`이면 **자동 반영 ❌ → 사용자에게 보고하고 물어본다**.
> 이유: 이 라이브러리의 존재 이유가 **"여기 있는 건 전부 통과한 것"**이라는 보증이다. 위반을 조용히 넣으면 라이브러리가 무의미해진다.

- **대비 수치는 충돌 대상이 아니다** — hex에서 계산되는 값이므로 색이 바뀌면 **항상 다시 계산**해서 덮어쓴다.

### 🅒 공통 필터 규칙

- `대비(배경, 텍스트) ≥ 3.6` **그리고** `대비(배경, 버튼) ≥ 3.6`
- **'쨍한 색' ≤ 1개** — 쨍한 색 = **채도 ≥60% AND 명도 ≥70%**(HSV). 2개 이상이면 눈이 아파서 제외. *(같은 색이 두 역할에 쓰이면 1개로 셈 — 안 그러면 2색 팔레트가 전부 오탐)*
- 세 색이 전부 달라야 함 + **텍스트≈버튼이면 액센트가 사라지므로 제외**

> 🚨 **"텍스트≈버튼" 판정에 WCAG 대비를 쓰지 말 것 (2026-07-16 실수 기록)**
> WCAG 대비는 **밝기(휘도)만** 잰다. 그래서 **흰색 `#FBFBFB` vs 네온그린 `#B2FF00` = 대비 1.18** → "거의 같은 색"으로 오판된다. 눈에는 전혀 다른 색인데도.
> → **실제 색차(Lab ΔE)로 판정**: `ΔE < 12` 면 같은 색으로 보고 제외 (흰색↔네온그린은 **ΔE 103**, `ΔE ≈ 2` 미만이 사람 눈에 구분 불가).
> 이 오판 때문에 「검정 배경 + 흰 텍스트 + 네온그린 버튼」 같은 **멀쩡한 조합이 후보에서 통째로 빠졌다.** (잘못된 걸 넣은 게 아니라 **좋은 걸 놓친** 방향의 버그)
