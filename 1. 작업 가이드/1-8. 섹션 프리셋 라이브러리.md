# 섹션 프리셋 라이브러리

> **카드 섹션** = 여러 CdBd 카드를 묶어 하나의 기능·의미 단위를 이루는 **재사용 가능한 부분 템플릿**.
> 예: **히어로 섹션** = 이미지 + 프로필 + 구분선 + 텍스트(들).
>
> **목적**: 신규 템플릿 제작 시 **주제·카테고리별로 검증된 섹션 + 배리에이션**을 골라 쓰면, 매번 0에서 구성·디자인하지 않고 **빠르게 완성**. (템플릿의 최우선 원칙 = 편집 용이성의 연장 — 페이지뿐 아니라 **섹션 단위 재사용**.)
>
> 각 섹션은 **원본 1 + 배리에이션 N**으로 축적. 배리에이션은 **컬러·폰트를 제외한** 디자인 요소(레이아웃·정렬·여백·모서리·이미지 모양·구분선 모양·텍스트 정렬·사이즈)로만 변주한다.

## 🔄 섹션 프리셋 제작 워크플로우 (3단계)

> 신규 템플릿을 0에서 구성하지 않고 **검증된 섹션 프리셋을 골라 조립**하기 위한 생산 방식.

1. **Claude Design 시안 3종 (탄탄한 풀페이지)** — [[1-1. 워크플로우]] 2단계. 무드 방향만 주고 **구조가 다른 3종** 생성(색·폰트·카드 구성 자유 탐색). *생성 트리거는 브라우저에서 사용자가 — 코드는 DesignSync로 pull.*
2. **섹션별 배리에이션** — 3종 시안을 바탕으로 페이지를 **섹션 묶음**(히어로·일시·라인업·티켓·위치·푸터…)으로 쪼개 각 섹션을 **A/B/C 프리셋**으로. **색·폰트 고정**, 변주는 위 **2종 축**.
3. **채택 → 카드 데이터로 승격 → 재사용** — 각 섹션 우수 프리셋을 **기준 2**로 채택 → **CdBd 카드 데이터로 승격**(마스터 프리셋 에디터 + `presets/` 파일, 평탄화·CdBd-legal) → 신규 템플릿마다 **섹션별로 골라 조립(inject) + 무드(색·폰트) 갈아끼워** 재사용. (정본 = 카드 데이터 · Figma는 초안 → 「🗄 프리셋 저장 방식」)

**🧩 섹션 조립 모델** — 페이지 = **섹션마다 프리셋 하나씩** 골라 세로 조립(예: 히어로 B + 일시 A + 라인업 C). 섹션은 **묶음 개념**일 뿐 중첩 컨테이너 ❌ → 최종은 **평면 카드 스택**.

**🔒 기능 고정 카드 = 내부 구조·간격 고정, 카드 디자인은 배리 가능 (2026-07-07 개정)** — **예약·위치안내·SNS·Q&A** 등은 **내부 요소 구성·간격을 항상 동일**하게(사용자가 못 바꾸는 부분 = 프리셋마다 안 바꿈). **단, 카드 디자인 — 배경·테두리·모서리·제목(별도 텍스트 카드)·정렬·바깥 배치 — 로는 배리에이션 가능.** 세부: **위치안내 지도 = 실제 에디터 옵션만**(각진/둥근 × 가로/1:1), **주소 중앙·gap 16**, **Q&A 제목 무조건 중앙·제출 버튼 내장**. (→ [[../CLAUDE.md]] 🧩⑥, [[1-6-2. CdBd 카드 기능]])

**🧷 섹션 구분 = 내용 기준 / 반복 요소 통일 = 페이지 조합 시에만 (2026-07-07)** — 섹션은 **담는 내용**으로 구분한다(히어로·일시·라인업·타임테이블·티켓·위치·푸터…). **반복 요소**(구분선 모양·두께·색, 섹션 라벨 스타일, 버튼 모양·크기, 여백 리듬)의 **통일은 「여러 섹션을 하나의 페이지로 조합할 때」만** 적용 — **프리셋 개별 제작 단계에선 강제 ❌**(각 프리셋은 자기 무드/원본 디자인을 따라도 됨). 즉 최종 페이지 완성 시 반복 chrome을 한 스타일로 정돈.

## 🎯 개념 — 왜 "섹션"인가

- 페이지 전체가 아닌 **부분(섹션) 단위** 자산: 히어로·정보·CTA·푸터 등.
- **워크플로우 연계** ([[1-1. 워크플로우]]): 2·3단계(claude.ai/design 시안 → Figma 반입·혼합)에서 검증된 섹션을 **출발점**으로 재사용. 섹션이 CdBd-legal이므로 4단계 CdBd 구현에 그대로 전이.
- **섹션 목적으로 정리** (2026-07-09 확정): 프리셋은 **목적 서랍**(히어로·소개·정보·나열·예약·폼·문의…13칸)으로 모은다. **카테고리는 서랍이 아니라 「조립 레시피」**(어떤 목적을 어떤 순서로) → 「🗂 분류 체계」·「🧩 조립 레시피」.

## 🗂 프리셋 분류 체계 — 섹션 "목적"으로 분류 (2026-07-09 확정)

> 프리셋을 **어떻게 나눠 보관하고 찾을지**의 뼈대. **정본 도식** = [Figma 보드 (node 9-108)](https://www.figma.com/board/dA9nFFGnHhwjNuQYNVGR2B/AI-%ED%85%9C%ED%94%8C%EB%A6%BF-%EC%9B%8C%ED%81%AC%ED%94%8C%EB%A1%9C%EC%9A%B0?node-id=9-108) — 「섹션 프리셋 분류 기준」 4열(분류·조립·채우기·디자인 결정). 근거 = [[1-9. AI 유저 플로우]] 「프리셋 기준으로의 다리」.
>
> ✅ **보드 = 이 문서와 동기화됨 (2026-07-10)** — 「조립」 열은 **대분류 1줄 × 세부 4칸 = 16개 + 부록 1**이며, 각 세부 아래 **원페이지(파랑) + 멀티페이지(보라)** 두 장이 붙는다. 「디자인 무드」 열의 `페미닌` 중복도 `드리미`로 정정(9종 정본 = [[1-3. 색상 팔레트]]·[[1-4. 폰트]]).

**분류 서랍 = 섹션의 "목적"** (그 카드 묶음이 페이지에서 하는 일). 카테고리·색·폰트·카드 타입이 아니라 **목적**으로 나눈다 — 히어로는 어느 카테고리든 '도입'이라, 목적으로 나눠야 재사용된다.

> 🧭 **"목적"이 두 개라 헷갈리지 말 것**: **페이지 목적(주제)** = "무엇을 모을까"(→ 조립) · **섹션 목적** = "이 조각을 어느 서랍에"(→ 분류). **분류 서랍 = 섹션 목적.**

## 🧱 섹션 기준 (필수)

### 기준 1 — 테마 적응성: 색·폰트는 대상 페이지 테마로 교체

- **원본과 모든 배리에이션은 컬러·폰트를 「적용할 페이지 테마」에 맞게 수정할 수 있어야 한다.** 섹션은 특정 색·폰트에 종속되지 않는다.
- 섹션의 **자산 가치 = 구조·레이아웃·정렬·여백·모양·위계**. 색·폰트는 **중립**이며, 사용 시 대상 템플릿의 무드에 맞춰 갈아끼운다:
  - 색 = **3토큰**(`{배경색}`/`{텍스트색}`/`{버튼색}`) 역할로만 표기 · 보조색 = `{텍스트색}×N%` · 강조배경 = `{버튼색}×N%` (→ [[1-2. 기획 문서 템플릿]] Part A, [[1-3. 색상 팔레트]])
  - 폰트 = 페이지당 1~2개 · 국문 본문 = 한글 폰트 · **텍스트 웨이트 = Regular/Bold 2종만**(CdBd Bold 토글과 정합) (→ [[1-4. 폰트]])
- 따라서 섹션 제작 시 **특정 hex·특정 폰트에 종속되는 디자인 금지**(예: 그 색이어야만 성립하는 장식 ❌).
- **배리에이션끼리 비교·평가할 때도 색·폰트는 동일하게 고정**하고 **구조 차이만** 본다 — 변주 축(구조)을 색·폰트 차이로 오염시키지 않기 위해.

### 기준 2 — 좋은 배리에이션 판별 체크리스트

> A/B/C 실제 평가에서 정제한 재사용 기준. 새 섹션의 배리에이션을 만들 때마다 이 체크리스트로 검수.

**✅ 배리에이션이 되려면**
- **원본과 한눈에 다른 레이아웃** — 구성·배치가 **실질적으로** 달라야 한다.
- 그러면서 **레이아웃이 안정적** — 정렬·간격·위계가 무너지지 않는다.
  - 🟢 *좋은 예(A): 좌측 정렬 에디토리얼 — 기존과 확연히 다르면서 레이아웃도 안정적.*

**❌ 배리에이션으로 인정 안 됨**
- **단일 요소만 변경** — 구분선 모양 하나만 바꾸고 나머지 레이아웃은 기존과 거의 같음 → 배리에이션 ❌. **레이아웃·구성 차원에서 달라야** 한다.
  - 🔴 *반례(B): 구분선 모양 말고는 기존 레이아웃과 차별점이 거의 없음.*
- **개별 요소 모양이 전체 톤과 부조화** — 한 요소(예: 이미지 모양)가 섹션 전체 무드와 안 어울림 → 재검토.
  - 🔴 *반례(B): 01 이미지의 모양이 전체 톤과 안 어울림.*

**🔢 배리에이션 개수 = 원본 + 3 (2026-07-07)**
- 각 변주 섹션은 **원본 1 + 배리에이션 3 = 4열**로 축적. "**원본 제외 3개**"이며 **원본을 배리에이션 수에 포함하지 않는다**(원본+2 = 미달).

**🎚 차별화 깊이 — 카드 순서만 ❌, 정렬·배경·구분선 ✅ (2026-07-07)**
- 3종이 **카드 순서만 다르고 강약·레이아웃이 거의 동일**하면 배리에이션 ❌ (기준 2 "레이아웃·구성 차원" 재확인).
- 실질 차별화 레버: **정렬**(좌/중) · **배경**(투명 / 틴트 카드 / 화이트+테두리 / 각진 밴드) · **구분선**(짧은 액센트바 / 풀 divider / 없음) · **이미지 위치·타입**(상단 히어로 / 2×2 그리드 / 넘겨보기) · **번호·아이콘 리드**.

**🔁 반복 하위 섹션 = "섹션 구분 방식"을 변주 축으로 (2026-07-07)**
- 원본에 **반복되는 하위 섹션**(반별·회차·항목 세트)이 있으면 배리에이션에도 **그 반복 세트를 모두 포함**하고, **여러 섹션을 구분하는 방식 자체를 변주**한다: 간격 / 풀 구분선 / 틴트 카드 박싱 / 번호(01·02) 리드.
  - 🟢 *예(밀과버터 Classes): 입문반+심화반 반복 세트를 A=간격 · B=구분선 · C=틴트카드 · D=번호로 구분.*

**⚠️ 멀티 컬럼(2단) 레이아웃 3원칙**
1. **label ↔ contents 텍스트 사이즈 균형** — 라벨과 값의 크기 차이가 과하면 시각적으로 불안정. 위계는 주되 안정 범위 안에서.
2. **라벨 줄바꿈 금지** — 고정폭 라벨이 **한 줄**에 들어와야 한다. 안 되면 폭을 늘리거나 라벨을 축약/재배치.
3. **인접 요소와 정렬 일관성** — 2단 섹션이 좌정렬인데 바로 위 제목이 초대형 중앙정렬이면 시각 불균형. **정렬·스케일을 이웃 요소와 맞춘다.**
   - 🔴 *반례(C): 2단 시도는 좋으나 ① label-contents 사이즈 차이 과다 ② '드레스코드' 라벨 줄바꿈 ③ 위 초대형 중앙 제목 ↔ 아래 좌정렬 2단 → 셋 다 불안정.*

**🔁 리비전 원칙** (정렬·정돈 수정 시 "재차별화" 유지)
- **정렬을 원본에 맞추더라도 다른 축에서 차별성 유지** — 정렬 불일치를 고치려 원본과 같은 정렬로 되돌리면 **원본과 다시 유사**해질 수 있다. 정렬은 맞추되 **구조(패널·색 밴드)·위계·이미지 처리** 등 다른 차원에서 차별점을 확보. *(C 리비전: 중앙정렬 통일 → 정보에 색 밴드 패널로 재차별화.)*
- **강한 요소가 구분 역할을 하면 구분선 제거** — 풀블리드 이미지·색 밴드처럼 이미 시각적 분리를 만드는 요소가 있으면 구분선을 겹쳐 넣지 않는다(장식 최소화, 5대 원칙 #5와 통함). *(B 리비전: 이미지가 상·하를 가르므로 구분선 삭제.)*

## 🏛 프리셋 3층 구조 — 섹션 / 페이지 / 멀티 (2026-07-09)

> 재사용 단위는 한 층이 아니라 **3층**. **섹션이 기본 원자**, 그 위에 페이지·멀티가 얹힌다. 페이지를 통째로 얼려 저장하면 개수 폭발·편집 경직 → **아래 층은 항상 위 층을 "참조"**(복사 ❌).

| 층 | 무엇 | 분류 축 | 재사용 성격 |
|---|---|---|---|
| **① 섹션 프리셋** | 카드 묶음 = 하나의 목적 단위(히어로·위치…) | **섹션 목적 13칸** (카테고리 가로지름) | 원자 — 경제성·유연 |
| **② 페이지 프리셋** | 섹션들의 **검증된 조합** (= 조립 레시피를 특정 배리에이션으로 채운 완성본) | **카테고리** (그 카테고리 전용) | 조합 — 속도·일관성 |
| **③ (멀티)템플릿** | 페이지 프리셋 여러 장 + **내비게이션** | 카테고리 | 완성 — 바로 클론 |

- **섹션은 목적으로, 페이지는 카테고리로 분류.** "카테고리는 분류 서랍이 아니라 조립 레시피"는 **섹션 층** 얘기 — **페이지 층에선 카테고리가 자연스러운 서랍**("행사 초대 페이지"는 통째로 그 카테고리 소속). 층이 다를 뿐 모순 아님.
- **페이지 프리셋 = 아래 「조립 레시피」를 특정 섹션 배리에이션으로 채운 것.** 레시피(목적 순서)=설계도, 페이지 프리셋=완성 샘플.
- **멀티페이지 = 페이지 프리셋들 + 내비게이션.** 내비게이션(표지 목차·서브페이지 복귀 헤더)은 **13 목적 서랍이 아니라 구조 뼈대(헤더/푸터)의 멀티용 확장.** ⚠️ **목차 = 페이지 이동(구조), '나열'(콘텐츠) 아님.** 멀티는 조립이 **2단계**(어떤 섹션을 어느 페이지에 배분 → 페이지 내 순서).
- 🔑 **얼리지 말 것**: 페이지·멀티는 섹션을 **참조**(레시피 + 배리 선택)로 담는다 — 섹션이 개선되면 따라오고, 개수 폭발도 없음.

## 🔀 변주 축 2종 — 색·폰트는 항상 고정
섹션 배리에이션은 아래 두 축 중 하나, 또는 둘 다로 만든다. **공통: 색·폰트 고정 → 구조 차이만 보이게.**
1. **카드 구성 변주** — **같은 정보를 다른 카드 타입으로 통째 교체.** 예: 라인업 = 갤러리 vs 프로필×3 vs 텍스트 나열. (→ [[1-2. 기획 문서 템플릿]] 변주축 ④) — CdBd의 카드 다양성을 살리는 방식.
2. **디자인 속성 변주** — **같은 카드에서** 레이아웃·정렬·여백·모서리·이미지 모양·구분선·텍스트 정렬/사이즈만 변경. 예: 히어로 섹션 A/B/C(초대·예약).
> 성숙한 프리셋은 둘을 겸함 — 카드 구성을 바꾸고, 그 안에서 디자인도 최적화.

## 🧩 카테고리별 조립 레시피 (유연한 기준)

> **② 페이지 프리셋의 설계도.** 카테고리가 정하는 것 = "어떤 프리셋인가"가 아니라 **"어떤 목적(섹션)을 어떤 순서로 이어붙일까".** ([[1-6-1. CdBd 에디터]]에서 이관 2026-07-08 · 세분화 10개로 갱신 2026-07-09 · **4대분류 × 세부 4 = 16개로 확장 2026-07-10**.)
>
> 🧾 **각 레시피의 슬롯을 실제로 채우는 질문** = [[1-9. AI 유저 플로우]] 「📝 1구간 후반 — 콘텐츠 수집 질문」 (대분류 → 세부 → 기능 애드온 3층).
>
> **⚠️ 유연한 기준 — 고정 틀 아님.** 아래는 **출발점**일 뿐, 페이지 목적·자료에 따라 **섹션을 더하거나 빼고 순서도 바꾼다.** 한 페이지는 **읽히는 목적(히어로·소개·자료…)과 동작하는 목적(위치·폼·예약·문의·구매)을 섞어** 짠다.
> **표기 = 섹션 "목적"**(괄호 = 대표 카드 힌트).
> **🔖 모든 카테고리 = 원페이지 스택 + ▸ 멀티페이지 분할 — 둘 다 필수.** [[1-9. AI 유저 플로우]] ④단계에서 **같은 디자인의 원페이지 안·멀티페이지 안을 1개씩 만들어 보여주고 유저가 고르므로**, 16개 레시피 전부 두 벌이 있어야 한다. (옛 '원N:멀티N 가중치'·'원페이지 고정' 예외는 2026-07-10 폐기.) 멀티는 **최대 3~4장** · **반복 내지(제품군·기사·프로젝트…)는 대표 1P만 표기**(실제 템플릿은 복제해 늘림) · 내비 = **표지 목차/이동 버튼 + 서브페이지 상단 복귀 헤더**(→ [[../CLAUDE.md]] 멀티페이지 네비 패턴).

## 🗄 프리셋 저장 방식 — 정본은 "CdBd 카드 데이터" (2026-07-07 결정)

**왜 카드 데이터인가**

- 프리셋이 Figma에 있으면 쓸 때마다 **Figma→CdBd 수동 이식**(비싼 4단계)이 껴 조립 이점 소멸.
- 미래 제품 에이전트도 카드 데이터를 소비 → 처음부터 카드 데이터로 쌓으면 그 투자가 그대로 이월.

**어디에 보관 — 2계층**
1. **마스터 = 멀티페이지 "프리셋 라이브러리" 에디터** — CdBd 에디터 하나에 **페이지 = 프리셋 하나씩**(섹션×배리에이션) 정리. 사람이 보고·수정·테스트하기 쉬운 실물 라이브러리. *(에디터 페이지 수 한계 시 카테고리별로 라이브러리 에디터 분할.)*
2. **버전 보관 = vault 파일** — 마스터에서 각 프리셋 카드 데이터를 `dumpState`로 떠서 `presets/{섹션}/{원본|A|B|C}.json`으로 저장(git 버전관리). 인덱스·평가로그·무드 매핑은 **본 노트(카탈로그)** 가 담당.

**⭐ 초반 필수 — "공통 설정(디폴트 테마) 계약"을 먼저 고정**
모든 프리셋을 **하나의 디폴트 테마 + 3토큰 역할**로 제작(색·구분선 모양·버튼 모양·여백 리듬·섹션 라벨 스타일을 프리셋마다 제각각 하드코딩 ❌ → 페이지 공통 설정을 가리키게).
- 그래야 조립 후 **통일 = 페이지 테마 한 번 적용 → 전 섹션 일괄 반영**(거의 공짜).
- 프리셋마다 색·크롬을 박아두면 통일 시 섹션마다 수정(비쌈).
- = 「기준 1 테마 적응성」의 실행판. 디폴트 테마 = Pretendard · 배경/텍스트/버튼 3토큰 · 버튼 원형 · Regular/Bold · 자간0 · 짝수 줄간격.

**만들고·쓰는 절차**
- **캡처**: 섹션을 에디터에서 한 번 제대로 만들고 검증 → 카드 데이터 dump → hex를 3토큰 역할로 치환 → `presets/` 저장.
- **재사용**: 프리셋을 새 템플릿에 **inject(조립)** → 섹션별 맥락 다듬기 → **페이지 테마 일괄 적용(통일)**.
- **도구(초반 투자)**: `dump→저장 / 로드→inject` 2기능을 skill `cdbd-card-automation`에 추가.

**Figma의 역할(변경됨)**: 시안 탐색·A/B/C 비교의 **초안 도구**. 아래 카탈로그의 Figma 링크 = **디자인 출처**이며 재사용 정본은 카드 데이터(미승격 항목 = 승격 대상).

**⏳ 당분간 = 피그마 우선 (전환 기준 포함, 2026-07-08 결정)**
> 정본은 카드 데이터지만, **지금 단계에선 피그마로 먼저** 쌓는다. 이유: 내부 제작이 우선이고 **CdBd 자동화가 피그마보다 시간·비용 부담이 큼** → 프리셋 디자인·**조합 실험은 피그마에서**(조합이 잘 어울리나는 "눈으로 보는 일" = 그림 도구가 쌈). 카드 데이터 승격 + `dump/inject` 도구 제작은 **아래 전환 기준 충족 시**로 미룬다.
- **⚑ 전환 기준(예시)**: ① 핵심 섹션(히어로·소개·일시장소·신청·푸터 등)마다 **프리셋 3~4개** 축적 · ② **조합 규칙**(반복 요소 통일·섹션 순서·간격 리듬) 안정 · ③ **실제 템플릿 2~3개**로 규칙 검증 → 충족 시 **카드 데이터 승격 + 뽑기/넣기 도구 제작**.
- **⚠️ 그동안 지킬 것**: (a) 프리셋은 **무조건 CdBd-legal**로 그림(피그마↔CdBd 재현 격차 방지) · (b) 어차피 매일 만드는 **실제 템플릿에서 조합이 실제로 되는지 검증**(별도 비용 0) · (c) "피그마 먼저"가 **"피그마 영원히"** 안 되게 위 기준을 게이트로.
- 💡 주의: "조합이 비싸다"는 조합 자체가 아니라 **뽑기/넣기 도구 부재** 탓 — 도구 생기면 CdBd 조합도 저렴해진다.

### 🔧 조합 규칙 — 이 라이브러리를 페이지로 조립할 때 (2026-07-16 사용자 확정)

1. **색 = 3토큰 매핑** — 프리셋의 hex는 **역할 자리표시자**다. `#6C4CFF`→`{버튼색}` · `#fafafa`→`{배경색}` · `#292929`→`{텍스트색}` (= 「기준 1 테마 적응성」의 실행판)
2. **☑ 카드 간 통일 8항목** — 아래 체크리스트대로 **페이지 하나에서 한 값으로** 맞춘다. (조합의 핵심 작업)
3. ⚠️ **프리셋 값 = 절대값 아님** — **통일을 위해 수정되는 것이 정상**. 프리셋을 그대로 얼려 붙이지 말 것
4. **스타일 간 중복 배치는 의도된 것** — 여러 레이아웃 스타일에 어울리는 프리셋은 **각 스타일 서랍에 중복 노출**. 따라서 **296 = 노출 수**이며 **고유 프리셋 수는 그보다 적다.** 이 중복은 「기준 3」의 **근-중복 등재 ❌와 별개**(같은 자산의 교차 노출 ↔ 구분 안 되는 유사 변형)

### 〰️ 구분선 사용 패턴 — 한 페이지 = 한 언어 (2026-07-16 사용자 확정)

> **왜 추가**: 8항목 #8이 「구분선 **색상**」만 잡고 있어서, **선의 역할·모양이 섞여도 통과**했다. 실제로 A① 안2에서 `초대의 말` 아래 **60×3 진한 액센트바**와 위치안내의 **340×1 흐린 구조선**이 공존했다 — 색은 같은 `{버튼색}`이라 #8을 통과했지만 **시각 언어는 둘**이었다.

- **기본 언어 1개를 정하고 페이지 전체가 따른다** — 예: 「구조선 = 340×1 · `{버튼색}`×8%」.
- **선의 역할이 다르면 값도 달라야 하는 게 아니라, 역할을 하나로 줄인다.** 섹션 구분은 이미 **섹션 간 여백**(#3)이 하므로 선을 겹쳐 넣지 않는다. (→ 「🔁 리비전 원칙」 *강한 요소가 구분 역할을 하면 구분선 제거*)
- **구분선을 아예 안 쓰는 것도 통일**이다 (미니멀 계열). 0개 = 완전 통일.

**🚨 판정 규칙 — 「한 섹션에만 쓰인 선」 = 기본 언어가 아니라 일회용 → 제거** *(2026-07-16 추가)*

> **왜 못 박나 — 자기합리화를 막기 위해.** A① 안2의 위치안내에 있던 `340×1` 선 2개를 **"이게 이 페이지의 기본 언어"라고 부르며 통과**시켰다. 그 선을 쓰는 섹션이 **위치안내 하나뿐**이었는데도. **표본 1개는 언어가 아니다.** 위 규칙("선을 겹치지 말 것"·"0개도 통일")에 답이 이미 있었는데도 판정을 느슨하게 했다.

- **판정법**: 그 선을 쓰는 **(예외 아닌) 섹션이 2개 미만이면 기본 언어로 인정 ❌** → **제거**하거나 **같은 역할의 다른 섹션에도 확장해서 언어로 만든다**. **둘 다 유효한 해결**이며, 어느 쪽을 기본값으로 삼을지는 **선의 「종류」로 가른다** ↓

**🆕 선의 종류로 기본 해결이 갈린다 (2026-07-21 사용자 확정 · A①·A③ 3회 연속)**

> **왜 갱신**: "애매하면 제거가 기본값"은 **구조 구분선**엔 맞지만, 사용자가 A①·A③에서 **섹션 타이틀 아래 짧은 액센트바**를 만날 때마다 **제거가 아니라 「모든 타이틀에 확장」**을 택했다(3회 연속). 두 종류는 통일 축이 다르기 때문이다.

| 선의 종류 | 정체 | 한 섹션에만 있을 때 **기본 해결** |
|---|---|---|
| **구조 구분선** (긴 선이 섹션을 가름 · 예 340×1) | 섹션 **구분** 장치 | **제거** — 구분은 여백(#3)이 이미 한다(중복) |
| **섹션 타이틀 액센트바** (짧은 바가 타이틀 바로 아래 · 예 60×2~3) | **섹션 타이틀 디자인(#2)의 일부** | **모든 타이틀에 균일 확장** — 타이틀은 통일 대상이라 하나만 다르면 **확장이 정답, 제거 ❌** |

- **판별**: 그 선이 **섹션을 가르는가**(구조선) vs **타이틀에 붙는 장식인가**(액센트바). 타이틀 바로 아래 짧게 붙으면 후자.
- **액센트바의 확장 범위 = 타이틀 있는 콘텐츠 섹션 전부** — 타이틀 없는 히어로·폼·푸터엔 넣지 않는다(붙을 타이틀이 없으므로).
- **스타일별 있음/없음 = 차별화 레버** — 한 스타일(미니멀·에디토리얼)은 액센트바를 페이지 언어로 쓰고, 다른 스타일(볼드)은 0개로 두고 틴트 카드·큰 텍스트로 강약을 낸다. **안마다 통일**되면 되고 **안 사이는 갈려도 된다**(→ 「🔀 시안 간 차별화 레버」).
- 애매하면(둘 다로 보이면) 여전히 **제거가 기본값** — 섹션 구분은 여백(#3)이 이미 한다.
- 📐 **확장 시 값·위치는 그 섹션 「원본」 액센트바 하나를 기준으로 복제** — 색·크기·정렬·패딩을 페이지에서 한 값으로. A③ 실측: 미니멀 `60×2·#c9a227·중앙(pad 좌우 160)` / 에디토리얼 `60×3·#57564f·좌측(pad 좌 20/우 300)`.

**🔓 예외 — 페이지 「최상단」과 「최하단」** *(푸터 추가 2026-07-16)*

### 🏷 섹션 타이틀 팔레트 + 타이틀↔본문 조합 규칙 (2026-07-21 사용자 확정 · 필수)

> **왜 만들었나**: 프리셋마다 섹션 타이틀이 **내장**돼 있고 **타이틀↔본문 간격이 제각각**이라(하단여백 8·12·16 혼재) 조합하면 간격이 들쭉날쭉했다. → **타이틀을 프리셋 원본에서 분리**해 **공용 팔레트 8종**으로 모으고, **타이틀 하단여백 + 본문 첫 카드 상단여백을 통일**해 **어떤 조합이든 간격이 일정**하게 만들었다. (= 「최우선 원칙 = 편집 용이성」의 연장 — 페이지뿐 아니라 **타이틀·본문 단위 재조합**)

**📐 여백 통일 스펙 — 시각 간격 항상 16**
- **모든 타이틀 하단여백 = 8** · **모든 본문 첫 카드 상단여백 = 8** → 붙이면 **시각 간격 = 8+8 = 16** 고정. **어떤 타이틀 × 어떤 본문**이어도 동일.
- 좌우 대칭(8+8)인 이유 = **삭제 내성**. 에디터에서 유저가 **타이틀만 지워도** 본문 상단 8이 남아 위 섹션과의 균형이 유지된다(→ 「📐 타이틀↔본문 거리」와 동일 원리).
- **구분선 있는 타이틀(⑤⑥⑦)**은 **구분선 하단여백 = 8**로 통일. 타이틀↔구분선 간격은 **타이틀 고유 디자인**이라 건드리지 않는다. 즉 **「타이틀 유닛의 마지막 요소 하단 = 8」**.

- **본문 자체가 구분선을 쓰면**(예: 나열·리뷰 리스트에서 항목 위아래·사이를 구분선으로 감싸는 본문) → **구분선 없는 타이틀 = ① ② ③ ④ ⑧** 만 조합. **구분선 타이틀 ⑤ ⑥ ⑦ ❌**.
- **왜**: 본문이 이미 구분선 언어를 쓰는데 타이틀에도 구분선을 얹으면 **구분선이 겹쳐 탁해진다**(8항목 #8 「한 페이지 = 한 언어」의 연장).
- **규칙 A와 함께(교집합) 적용** — 예: **구분선 있는 + 배경 없는 + 왼쪽정렬 본문** = A(좌 ①③⑤⑥) ∩ B(무구분선 ①②③④⑧) = **① ③** · **구분선 있는 + 중앙정렬 본문** = ② ④ ⑧.

### 🔒 통일의 경계와 방법 — 어디까지 손대나 (2026-07-16 신설 · 필수)

> **왜 신설**: *"프리셋 값은 절대값이 아니다"*를 **"뭐든 바꿔도 된다"**로 해석해 **프리셋 내부 관계까지 건드리고, 원본에 없는 속성을 창작**했다. A① 제작 중 같은 종류의 지적이 **5번 반복**됐다. 경계를 못 박는다.

**🧭 손대는 것 / 손대지 않는 것**

| ✅ 통일 대상 (조합 시 맞춘다) | 🔒 프리셋 정본 (건드리지 않는다) |
|---|---|
| **섹션 간** 여백 (= 각 섹션 **마지막 카드 하단 여백**) | **프리셋 내부** 요소 간 간격 — 타이틀↔구분선 · 구분선↔본문 · 항목↔항목 |
| **섹션 타이틀↔본문** 거리 — **구분선이 없는 섹션만** | **구분선이 낀 섹션**의 타이틀↔본문 (= 그 사이가 프리셋 내부 관계) |
| 카드 좌우 여백 · 모서리 · 카드 배경 · 버튼 모양 · 서체 · 구분선 언어 (= 8항목) | 프리셋 고유 레이아웃·구조 |

> ⚠️ **실패 사례**: 안2 「초대의 말」의 타이틀↔본문 거리를 16으로 맞추려다 **구분선 래퍼의 상단 패딩(프리셋 원본 14)을 0으로 깎았다.** 통일 대상이 아닌 **프리셋 내부 관계**였다.

**🔀 프리셋 교차 사용은 허용 — 「같은 레이아웃 유형 안에서」** *(2026-07-16 사용자 확정)*
- **같은 스타일 서랍**(미니멀/에디토리얼/볼드) 안에서라면 **A 프리셋의 섹션 타이틀 + B 프리셋의 본문**을 **섞어 써도 된다.**
- 이건 **창작이 아니다** — 둘 다 그 서랍에 **실재하는 속성**이기 때문. (아래 「창작 금지」와 충돌하지 않음)
- 💡 **위계(🎚)를 만드는 주요 수단** — 한 프리셋 안에 원하는 크기 조합이 없어도, **같은 서랍의 다른 프리셋에서 가져와** 섹션 주인공을 만들 수 있다.
- ⚠️ **서랍을 건너뛰는 교차는 ❌** — 미니멀 타이틀 + 볼드 본문 같은 조합은 레이아웃 스타일 정의가 깨진다.

**🚫 창작 금지 — 「원본에 있는 속성 조합」만 쓴다**
- 섹션 타이틀의 **크기·정렬·색 역할**은 **그 스타일 서랍에 실제로 존재하는 조합**에서 고른다. (조사법: 해당 스타일 섹션의 `LABEL`/`섹션 제목` 텍스트 노드 속성을 집계 → 빈도순)
- 🔴 실패 사례: `11px` · `16px {텍스트색}` · `20px` — **어느 서랍에도 없는 값을 창작**했다. 🏷 **섹션 타이틀은 이제 「8유형 팔레트」만**(→ 위 「🏷 섹션 타이틀 팔레트」) — `좌22·중22·좌18·중14·pill중13`(+구분선 변형). **크기×정렬은 자유 조합 ❌** — `좌14·중18·좌13` 등은 없음(14=중앙 · 18=좌 · 22=좌/중 · 13=pill중앙). (Bold·색 역할 `{버튼색}|{텍스트색}`은 동일)
- ✅ **「프리셋 값은 절대값이 아니다」 = 통일을 위한 「값 조정」**이지 **「없는 속성 창작」이 아니다.**
- ℹ️ **서체는 예외** — 폰트는 **무드 교체 대상**(기준 1)이라 프리셋의 Pretendard를 무드 폰트로 바꾸는 건 창작이 아니다.

**📐 타이틀↔본문 거리 = 「타이틀 하단 여백 + 본문 첫 카드 상단 여백」을 함께 본다** *(2026-07-16 사용자 지적 · 3회 연속 실패 지점)*

> 🔑 **타이틀의 하단 여백만 확인하면 안 된다.** **본문 첫 카드의 상단 여백까지 함께** 봐야 **실제로 시각적으로 통일돼 보인다.**

**🔴 3번 반복한 실패**
1. **래퍼 패딩만 맞춤** → 실제 거리는 `12·12·32·12`. 카드마다 **자체 내부여백**이 달랐다(위치 카드가 20 보유).
2. **채움(fill)만 「보이는 것」으로 판정** → **테두리만 있고 채움 없는 카드**를 놓쳐, 안2 문의의 실제 거리 **0**을 "16 통과"로 오판.
3. **타이틀 래퍼가 섹션 직계라고 가정** → 안3 INVITATION은 래퍼가 한 겹 더 있어 인덱스가 깨지고 **`null` → 조용히 건너뜀**(그래서 38로 방치).

**🥇 목표는 「시각 균일」이 아니라 「값 통일 + 시각 균일」** *(2026-07-16 사용자 확정 · 최우선 원칙의 연장)*

> **에디터로 가져가서 유저가 특정 카드를 지워도 레이아웃 균형이 유지돼야 한다.** → **섹션 타이틀의 하단 여백**과 **본문 첫 카드의 상단 여백**을 **각각 페이지에서 한 값으로** 통일한다.

- 🔴 **역산만 하면 안 된다** — 시각 거리만 맞추려고 카드마다 다른 값(`4`·`16`·`12`…)을 넣으면 **지금은 균일해 보여도 유저가 카드를 하나 지우는 순간 리듬이 깨진다.** 이는 **[[../CLAUDE.md]] 최우선 원칙(편집 용이성 > 디자인 완성도)** 위반.
- ✅ **둘 다 만족시키는 법**: `타이틀 하단 = PAD` · `본문 첫 카드 상단 = PAD` (대칭) → **시각 거리 = 2×PAD**. 이때 **여백이 카드 상단 한 곳에만 있게** 하려면 **안쪽 래퍼의 자체 상단여백을 0으로 몰아준다**(위치 카드가 내부 20을 갖고 있어 시각이 24로 벌어졌던 원인).
- 🧹 **구조 찌꺼기를 남기지 말 것** — 알약 배경을 지우고 **빈 래퍼**를 남겼더니 그 패딩(하단 16)이 거리를 32로 밀었고, **타이틀이 섹션 직계가 아니게 되어 측정까지 깨졌다.** 요소를 제거하면 **껍데기 래퍼도 함께 걷어낸다.**
- 🔍 A① 최종: 안1 `6+6=12` · 안2 `8+8=16` · 안3 `8+8=16` — **값·시각 모두 균일**.

**✅ 측정 절차 (이대로)**
1. 타이틀에서 **위로 올라가 「섹션의 직계 자식」인 조상**을 찾는다 (래퍼가 몇 겹이든).
2. 그 **다음 형제** = 본문 첫 카드. **보이지 않는 형제**(높이 0 여백 카드 등)는 **건너뛰고** 그 다음을 본다.
3. 본문 첫 카드의 **「시각적 상단」** = 카드가 **보이면 카드의 상단**, 안 보이면 **그 안의 첫 보이는 요소**.
4. `absoluteBoundingBox`로 **타이틀 하단 → 시각적 상단** 거리를 재고 **목표값까지 역산**(2~3 패스 수렴).

**👁 「보이는 것」의 정의 (틀리면 전부 틀어진다)**
- TEXT · **채움 있는 박스** · **🆕 테두리 있는 박스**(채움 없어도!) · 높이 ≥ 1
- **배경 또는 테두리가 있는 카드는 「카드 상단」이 본문 시작**이고, 둘 다 없으면 **그 안의 텍스트·이미지**가 시작이다.

**🚨 측정이 `null`이면 「통과」가 아니라 「미측정」** — 조용히 건너뛰지 말 것. (거짓 클린 함정과 같은 종류)

**🧱 섹션 간 여백 = 마지막 카드 하단 내부여백 (여백 카드 최대한 ❌)**
- **여백 카드(구분선 두께 0)는 최대한 쓰지 않는다** (2026-07-16 사용자 확정) → **카드 하단 여백**으로 처리.
- ⚠️ **섹션 래퍼(Figma auto-layout)의 `paddingBottom`에 걸면 안 된다** — **평탄화하면 증발**한다(CdBd엔 래퍼가 없다). 🔴 실패: 래퍼에 32를 걸어 "통일했다"고 했으나 마지막 카드 실측은 `20/20/24/8/0/20`이었다.

**🔄 프리셋 원본이 바뀌면 시안에 동기화**
- 조합 후에도 **원본이 정본**. 원본 수정(예: 나열 항목 간 여백 8→14)이 생기면 **해당 시안의 같은 값을 갱신**한다.
- 단 **통일 대상(8항목)은 통일값 우선** — 예: 나열 **마지막** 항목의 하단은 프리셋의 14가 아니라 **섹션 간 여백 32**.

### 🎚 위계 기준 — 「통일」이 단조가 되지 않게 (2026-07-16 신설 · 필수)

> 🔑 **세 번째 축이다.** 8항목 = **같게**(페이지 안) · 차별화 레버 = **다르게**(시안 사이) · **위계 = 강약**(페이지 안). **앞의 둘 어느 쪽도 「한 시안 내부의 강약」을 안 본다** → 통일만 강화하면 **균일한 회색 죽**이 된다.
> 🔴 실제 사례: A① 안1이 「히어로부터 프로그램까지 비슷한 사이즈가 중앙정렬로 반복」돼 단조롭다는 지적. **8항목은 전부 통과한 상태**였다.

**⚠️ 차별화와 위계는 상충한다 — 한 축을 죽이면 다른 축으로 보상해야 한다**

### 🎨 단조로움 보완 실전 규칙 — 프리셋 교체 · 문의 버튼 변주 (2026-07-21 신설 · 필수)

> 🔑 위 「위계 기준」이 **왜 단조로운가**를 진단한다면, 여기는 **무엇으로 바꾸는가**의 구체 처방 2가지다. 강약 수단 ③(카드 배경)·⑤(구분선)·②(버튼 형태)를 실제 프리셋으로 꺼내 쓰는 법.

**① 텍스트만 계속 나열되면 → 페이지 중간을 「배경 있는」/「구분선 있는」 프리셋으로 교체**
카드 배경도 구분선도 없어 **단순 텍스트가 연달아 쌓이는** 구간(회색 죽)은, 페이지 **중간의 한두 섹션**을 아래로 대체해 리듬을 만든다:
- **카드 배경이 있는 프리셋** — [섹션 프리셋 3755-1407](https://www.figma.com/design/24O01lprp5i2ufl7CbZXXx/CdBd-%ED%85%9C%ED%94%8C%EB%A6%BF--%EC%84%B9%EC%85%98-%ED%94%84%EB%A6%AC%EC%85%8B?node-id=3755-1407) (강약 수단 ③ 카드 배경·틴트)
- **구분선이 있는 프리셋** — [섹션 프리셋 3755-1421](https://www.figma.com/design/24O01lprp5i2ufl7CbZXXx/CdBd-%ED%85%9C%ED%94%8C%EB%A6%BF--%EC%84%B9%EC%85%98-%ED%94%84%EB%A6%AC%EC%85%8B?node-id=3755-1421) (강약 수단 ⑤ 구분선)
- ⚠️ **8항목 통일과 충돌 없음** — 카드 배경·구분선은 **페이지 전체가 아니라 한 구간에만** 넣어 리듬을 주는 것이지, 넣을 거면 **그 종류의 언어를 페이지 전체에서 일관**되게(구분선 언어 = 「한 페이지 = 한 언어」 #8, 카드 배경 톤 = `{버튼색}×N%` 통일). **교체는 「같은 목적 서랍의 다른 프리셋」**으로 — 없는 구조 창작 ❌.

**② fill 버튼이 이미 여러 번 쓰였으면 → 「문의」 섹션 버튼은 다른 형태로**
페이지에 **채움(fill) 버튼이 여러 번 반복**되면 마지막 「문의」 버튼까지 같은 채움이라 위계가 죽고 단조롭다. 문의 버튼은 **형태를 달리**한다 (Outlined·텍스트 링크·2단 등):
- 대체 형태 예시 — [3491-184](https://www.figma.com/design/24O01lprp5i2ufl7CbZXXx/CdBd-%ED%85%9C%ED%94%8C%EB%A6%BF--%EC%84%B9%EC%85%98-%ED%94%84%EB%A6%AC%EC%85%8B?node-id=3491-184) · [3463-179](https://www.figma.com/design/24O01lprp5i2ufl7CbZXXx/CdBd-%ED%85%9C%ED%94%8C%EB%A6%BF--%EC%84%B9%EC%85%98-%ED%94%84%EB%A6%AC%EC%85%8B?node-id=3463-179) · [3755-1575](https://www.figma.com/design/24O01lprp5i2ufl7CbZXXx/CdBd-%ED%85%9C%ED%94%8C%EB%A6%BF--%EC%84%B9%EC%85%98-%ED%94%84%EB%A6%AC%EC%85%8B?node-id=3755-1575)
- 💡 **페이지 상단에서 쓴 유형의 반복이면 통일성 확보에도 좋음** — 상단에 이미 등장한 버튼 형태를 문의에서 되받으면 변주이면서 동시에 통일(수미상관). 예: [3330-88](https://www.figma.com/design/24O01lprp5i2ufl7CbZXXx/CdBd-%ED%85%9C%ED%94%8C%EB%A6%BF--%EC%84%B9%EC%85%98-%ED%94%84%EB%A6%AC%EC%85%8B?node-id=3330-88)
- ⚠️ **버튼 「모양」(원형/각진/둥근)은 그대로 통일** — 여기서 바꾸는 건 **채움 여부·형태**(fill ↔ Outlined ↔ 텍스트 링크, `block.innerStyle`)이지 8항목 #6 **모양(테마 전역)이 아니다**. 모양은 페이지 1종 유지.
- ⚠️ **위치 안내 카드 내부 「지도 보기」 버튼은 Outlined 불가**(채움 고정) — 이 규칙은 **별도 버튼 카드**에만 적용.

### 🔀 시안 간 차별화 레버 — 「통일」의 반대편 (2026-07-16 신설 · 필수)

> 🔑 **같은 속성이 두 역할을 한다.** 페이지 **안에서는 통일**(위 8항목) · 시안 **사이에서는 차별화**.
> ⚠️ **8항목만 보고 조합하면 3안이 「각자 잘 통일된 쌍둥이」가 된다.** A① 1차가 실제로 그랬다 — 세 시안이 전부 12px 라벨 · 원형 버튼 · 다크+웜이었고, **각 시안 안에서는 완벽히 통일**돼 있었다. 통일 체크리스트는 이걸 못 잡는다.

| 레버 | 페이지 **안** (통일) | 시안 **사이** (차별화) |
|---|---|---|
| **버튼 모양** | 한 페이지 = **1종**(테마 전역) | **최소 2종**(각진·둥근·원형 중) — **3종 강제 ❌** |
| **섹션 타이틀 형식** | 한 페이지 = **1형식** | **언어(영/국) · 정렬 · 크기 · 서체**를 시안마다 다르게 |
| **모서리** | 이미지·지도·카드 = **1값** | **각진 ↔ 둥근**으로 가름 |
| **🆕 좌우 여백** | 한 페이지 = **1값** | **무드·스타일별로 벌린다** — 미니멀 32(큰 여백) / 에디토리얼 20 / 볼드 16(꽉 참). **20 고정 ❌** |
| **색** | 3토큰 역할 고정 | **명도 방향 + 액센트 hue 분산** (→ [[1-3. 색상 팔레트#🎯 팔레트 채택 절차 — 6단계 (2026-07-16 신설 · 필수)]] ⑤) |
| **구조** | — | **변주 축 5개 중 3개 이상** (도입/정보밀도/이미지비중/카드타입/순서 → [[1-2. 기획 문서 템플릿]] Part A) |

### 🐛 하드코딩 색 = 「기준 1 테마 적응성」 상시 위반원 (2026-07-16 2차 발견 · 필수)

> **왜 또 나오나**: 프리셋을 눈으로 보면 멀쩡하다. **테마를 바꿔야 드러난다.** 1차(`#FFFFFF` 카드 배경 25개)에 이어 **2차에서 40개 더** 나왔다 — 조합 시 **토큰 3개(`#fafafa`·`#292929`·`#6c4cff`)에 매핑 안 되는 SOLID 색**을 전수 집계하면 즉시 잡힌다.

**🔍 검출법 (조합할 때마다 돌릴 것)** — 클론에 토큰 맵을 적용한 뒤 **매핑 안 된 hex를 집계**해 리포트. 남은 색이 곧 위반 후보.
