# 섹션 프리셋 라이브러리

> **카드 섹션** = 여러 CdBd 카드를 묶어 하나의 기능·의미 단위를 이루는 **재사용 가능한 부분 템플릿**.
> 예: **히어로 섹션** = 이미지 + 프로필 + 구분선 + 텍스트(들).
>
> **목적**: 신규 템플릿 제작 시 **주제·카테고리별로 검증된 섹션 + 배리에이션**을 골라 쓰면, 매번 0에서 구성·디자인하지 않고 **빠르게 완성**. (템플릿의 최우선 원칙 = 편집 용이성의 연장 — 페이지뿐 아니라 **섹션 단위 재사용**.)
>
> 각 섹션은 **원본 1 + 배리에이션 N**으로 축적. 배리에이션은 **컬러·폰트를 제외한** 디자인 요소(레이아웃·정렬·여백·모서리·이미지 모양·구분선 모양·텍스트 정렬·사이즈)로만 변주한다.

## 🎯 개념 — 왜 "섹션"인가

- 페이지 전체가 아닌 **부분(섹션) 단위** 자산: 히어로·정보·CTA·푸터 등.
- **워크플로우 연계** ([[1-1. 워크플로우]]): 2·3단계(claude.ai/design 시안 → Figma 반입·혼합)에서 검증된 섹션을 **출발점**으로 재사용. 섹션이 CdBd-legal이므로 4단계 CdBd 구현에 그대로 전이.
- **섹션 역할로 정리** (2026-07-08 개정): 프리셋은 **역할 서랍**(히어로·소개·라인업·위치·폼·예약·푸터…)으로 모은다. **카테고리는 서랍이 아니라 「조립 레시피」**(어떤 역할을 어떤 순서로) → 「🗂 분류 체계」·「🧩 조립 레시피」.

### 🔀 변주 축 2종 (색·폰트는 항상 고정)
섹션 배리에이션은 아래 두 축 중 하나, 또는 둘 다로 만든다. **공통: 색·폰트 고정 → 구조 차이만 보이게.**
1. **카드 구성 변주** — **같은 정보를 다른 카드 타입으로 통째 교체.** 예: 라인업 = 갤러리 vs 프로필×3 vs 텍스트 나열. (→ [[1-2. 기획 문서 템플릿]] 변주축 ④) — CdBd의 카드 다양성을 살리는 방식.
2. **디자인 속성 변주** — **같은 카드에서** 레이아웃·정렬·여백·모서리·이미지 모양·구분선·텍스트 정렬/사이즈만 변경. 예: 히어로 섹션 A/B/C(초대·예약).
> 성숙한 프리셋은 둘을 겸함 — 카드 구성을 바꾸고, 그 안에서 디자인도 최적화.

## 🗂 프리셋 분류 체계 — 두 집안(E·F)

> 프리셋을 **어떻게 나눠 보관하고 어떻게 찾을지**의 뼈대 (2026-07-08 수립). 근거 = [[1-9. AI 유저 플로우 (제품 설계도)]] 「프리셋 기준으로의 다리」 — 유저에게 묻는 신호가 곧 프리셋을 찾는 열쇠.

**모든 섹션 프리셋을 두 집안으로 먼저 가른다.** 이 한 번의 가름이 "많아질 때"의 관리 부담 대부분을 없앤다.

| | **E집안 — 표현형** (보여주고 설득) | **F집안 — 기능·범용** (실제로 동작) |
|---|---|---|
| 들어가는 섹션 | 히어로 · 소개 · 라인업/목록 · 일시 · 소식컷 · 홍보컷 | 위치안내 · 신청폼(Q&A) · 예약/CTA · 푸터 SNS · 유튜브 |
| **1차 서랍** | **섹션 역할** — 카테고리로 안 나눔 | **섹션 역할** |
| 카테고리 | **태그(약한 힌트)** + 조립은 「조립 레시피」가 담당 | 태그(약한 힌트) |
| 고르는 법 | 역할 서랍 → **구조 톤**(격식/절제/대담)으로 픽 | 역할 서랍 → **카드 디자인**으로 픽 |
| 성장 규칙 | **개방형** — "새 방향"일 때만 추가 | **정원 6** — 꽉 차면 약한 걸 교체(누적 ❌) |
| 왜 | 창의성·다양성이 자산 | 내부 구조·간격 고정 → 소수면 충분 |

**🧭 섹션 역할 = 그 카드 묶음이 페이지에서 맡은 일(목적·내용).** 카드 타입도·레이아웃도·카테고리/색/폰트도 아니다 — 초대든 홍보든 "첫인상 자리"면 **히어로**. (카드 라벨을 「목적·내용 이름」으로 붙이는 것을 **섹션 단위**로 올린 개념.) 역할 이름은 **고정 목록**으로 둬 이름 난립(히어로/메인/헤더)을 막는다 → 많아져도 안 흩어짐.

**⭐ 확장성이 풀리는 지점**
- **F집안은 카테고리마다 복제 안 됨** — 위치·푸터·폼을 **한 벌만** 만들면 5개 카테고리가 다 쓴다 (많아짐의 최대 원인 차단).
- **E집안도 역할 서랍 하나로 모임** — 같은 "좌측 에디토리얼 히어로"를 카테고리마다 다시 안 만든다. **교차 사용이 기본값.**
- **무드로 교차 사용**은 **속 무드(구조 톤 = 여백·정렬·이미지 비중·격식)** 로 잡는다. 겉 무드(색·폰트)는 프리셋에 없고 **맨 끝 테마 한 번**(→ 기준 1).

**🔗 1-9 플로우 신호 → 프리셋 조회**

| 유저에게 얻는 신호 | 프리셋에서 하는 일 |
|---|---|
| 카테고리 | E 섹션의 **조립 레시피** 선택(아래) + 태그 우선순위 |
| 목적·타겟 | 어떤 역할을 **몇 개·어떤 순서로** (레시피 조정) |
| 기능(결과) | **F집안**에서 해당 기능 섹션 꺼냄 |
| 무드 | 조회엔 안 씀 → 색·폰트는 맨 끝 테마 |
| 자료 | 꺼낸 프리셋 **빈칸 채움** |

## 🧩 카테고리별 조립 레시피 (유연한 기준)

> **[[1-6-1. CdBd 에디터]] 「카테고리별 표준 시퀀스」에서 이관 (2026-07-08).** 위 분류 체계에서 **카테고리를 E 서랍에서 뺀 대신, 그 역할이 여기로 옮겨졌다** — 카테고리가 정하는 것 = "어떤 프리셋인가"가 아니라 **"어떤 역할(섹션)들을 어떤 순서로 이어붙일까".**
>
> **⚠️ 유연한 기준 — 고정 틀 아님.** 아래 시퀀스는 **출발점**일 뿐, 페이지 목적·자료에 따라 **카드(섹션)를 더하거나 빼고 순서도 바꾼다.** 기존 17개에서 추출한 흐름 패턴이며, 한 페이지는 **E 역할(히어로·소개…)과 F 역할(위치·Q&A·예약·푸터)을 섞어** 짠다.

**프로필 · 명함**
```
[로고/메인 비주얼 이미지]
[프로필 (혹은 이미지 + 텍스트 이름·직책)]
[연락처 텍스트 × N]
[연락처 저장 버튼]
[구분선]
[비전/소개 텍스트]
[Q&A 상담 폼]
[로고/SNS 푸터]
```

**초대 · 예약**
```
[로고/메인 이미지]
[초대장 제목 텍스트 (대형 헤딩)]
[초대 본문 텍스트]
[일시/장소 텍스트]
[위치 안내]
[구분선]
[프로그램/일정 — 텍스트 반복 N개]
[갤러리 (이벤트 사진, 선택)]
[Q&A RSVP/설문]
[버튼 또는 예약]
[로고/SNS 푸터]
```

**홍보 · 카탈로그** (멀티페이지 75%)
```
Page 1 [표지]: 로고 + 메인 이미지 + 컬렉션 제목
Page 2 [본문]: 제품/컬렉션 — 이미지+텍스트(설명) 반복 또는 2단 카드
Page 3 [부가]: 프로모션·쿠폰 또는 화보
Page 4 [액션]: 매장 위치/메뉴/공식몰 버튼/SNS 푸터
```

**가이드 · 신청**
```
[홍보 카피 텍스트]
[프로필]
[본문 + 이미지]
[카드박스 형식 비교 정보 — 텍스트 다수]
[Q&A 정보 일치 확인]
[서명 안내 + 버튼]
[로고/마지막 인사말]
```

**소식 · 매거진** — *아직 사례 0개(신규 개척 분야 · [[../CLAUDE.md]] 우선순위). 잠정 레시피: `[헤드라인/발행정보] → [대표 이미지] → [소식컷(제목+요약+이미지) 반복] → [더 보기 버튼/SNS 푸터]`. 첫 템플릿 제작 시 확정.*

## 🗄 프리셋 저장 방식 — 정본은 "CdBd 카드 데이터" (2026-07-07 결정)

> **정본(재사용·미래 제품이 실제로 실행하는 원본) = CdBd 카드 데이터(에디터 네이티브)**. **Figma는 상류 디자인·비교 초안**으로만 쓰고, 채택된 디자인은 카드 데이터로 **승격**해 정본화한다.

**왜 카드 데이터인가**
- 사용 사이클(**조립 → 섹션별 맥락 다듬기 → 전체 통일**)이 전부 카드 데이터 위 조작: 조립=카드 스택 이어붙이기 · 다듬기=카드 속성 편집 · 통일=페이지 테마 일괄 적용.
- 프리셋이 Figma에 있으면 쓸 때마다 **Figma→CdBd 수동 이식**(비싼 4단계)이 껴 조립 이점 소멸.
- 미래 제품 에이전트도 카드 데이터를 소비 → 처음부터 카드 데이터로 쌓으면 그 투자가 그대로 이월.

**어디에 보관 — 2계층**
1. **마스터 = 멀티페이지 "프리셋 라이브러리" 에디터** — CdBd 에디터 하나에 **페이지 = 프리셋 하나씩**(섹션×배리에이션) 정리. 사람이 보고·수정·테스트하기 쉬운 실물 라이브러리. *(에디터 페이지 수 한계 시 카테고리별로 라이브러리 에디터 분할.)*
2. **버전 보관 = vault 파일** — 마스터에서 각 프리셋 카드 데이터를 `dumpState`로 떠서 `presets/{섹션}/{원본|A|B|C}.json`으로 저장(git 버전관리). 인덱스·평가로그·무드 매핑은 **본 노트(카탈로그)** 가 담당.

**⭐ 초반 필수 — "공통 설정(디폴트 테마) 계약"을 먼저 고정**
모든 프리셋을 **하나의 디폴트 테마 + 3토큰 역할**로 제작(색·구분선 모양·버튼 모양·여백 리듬·섹션 라벨 스타일을 프리셋마다 제각각 하드코딩 ❌ → 페이지 공통 설정을 가리키게).
- 그래야 조립 후 **통일 = 페이지 테마 한 번 적용 → 전 섹션 일괄 반영**(거의 공짜).
- 프리셋마다 색·크롬을 박아두면 통일 시 섹션마다 수정(비쌈).
- = 「기준 1 테마 적응성」의 실행판. 디폴트 테마 = Pretendard · 배경/텍스트/버튼 3토큰 · 버튼 원형 · Regular/Bold · 자간0 · 짝수 줄간격.

**만들고·쓰는 절차**
- **캡처**: 섹션을 에디터에서 한 번 제대로 만들고 검증 → 카드 데이터 dump → hex를 3토큰 역할로 치환 → `presets/` 저장.
- **재사용**: 프리셋을 새 템플릿에 **inject(조립)** → 섹션별 맥락 다듬기 → **페이지 테마 일괄 적용(통일)**.
- **도구(초반 투자)**: `dump→저장 / 로드→inject` 2기능을 skill `cdbd-card-automation`에 추가.

**Figma의 역할(변경됨)**: 시안 탐색·A/B/C 비교의 **초안 도구**. 아래 카탈로그의 Figma 링크 = **디자인 출처**이며 재사용 정본은 카드 데이터(미승격 항목 = 승격 대상).

**⏳ 당분간 = 피그마 우선 (전환 기준 포함, 2026-07-08 결정)**
> 정본은 카드 데이터지만, **지금 단계에선 피그마로 먼저** 쌓는다. 이유: 내부 제작이 우선이고 **CdBd 자동화가 피그마보다 시간·비용 부담이 큼** → 프리셋 디자인·**조합 실험은 피그마에서**(조합이 잘 어울리나는 "눈으로 보는 일" = 그림 도구가 쌈). 카드 데이터 승격 + `dump/inject` 도구 제작은 **아래 전환 기준 충족 시**로 미룬다.
- **⚑ 전환 기준(예시)**: ① 핵심 섹션(히어로·소개·일시장소·신청·푸터 등)마다 **프리셋 3~4개** 축적 · ② **조합 규칙**(반복 요소 통일·섹션 순서·간격 리듬) 안정 · ③ **실제 템플릿 2~3개**로 규칙 검증 → 충족 시 **카드 데이터 승격 + 뽑기/넣기 도구 제작**.
- **⚠️ 그동안 지킬 것**: (a) 프리셋은 **무조건 CdBd-legal**로 그림(피그마↔CdBd 재현 격차 방지) · (b) 어차피 매일 만드는 **실제 템플릿에서 조합이 실제로 되는지 검증**(별도 비용 0) · (c) "피그마 먼저"가 **"피그마 영원히"** 안 되게 위 기준을 게이트로.
- 💡 주의: "조합이 비싸다"는 조합 자체가 아니라 **뽑기/넣기 도구 부재** 탓 — 도구 생기면 CdBd 조합도 저렴해진다.

## 🔄 섹션 프리셋 제작 워크플로우 (3단계)

> 신규 템플릿을 0에서 구성하지 않고 **검증된 섹션 프리셋을 골라 조립**하기 위한 생산 방식.

1. **Claude Design 시안 3종 (탄탄한 풀페이지)** — [[1-1. 워크플로우]] 2단계. 무드 방향만 주고 **구조가 다른 3종** 생성(색·폰트·카드 구성 자유 탐색). *생성 트리거는 브라우저에서 사용자가 — 코드는 DesignSync로 pull.*
2. **섹션별 배리에이션** — 3종 시안을 바탕으로 페이지를 **섹션 묶음**(히어로·일시·라인업·티켓·위치·푸터…)으로 쪼개 각 섹션을 **A/B/C 프리셋**으로. **색·폰트 고정**, 변주는 위 **2종 축**.
3. **채택 → 카드 데이터로 승격 → 재사용** — 각 섹션 우수 프리셋을 **기준 2**로 채택 → **CdBd 카드 데이터로 승격**(마스터 프리셋 에디터 + `presets/` 파일, 평탄화·CdBd-legal) → 신규 템플릿마다 **섹션별로 골라 조립(inject) + 무드(색·폰트) 갈아끼워** 재사용. (정본 = 카드 데이터 · Figma는 초안 → 「🗄 프리셋 저장 방식」)

**🧩 섹션 조립 모델** — 페이지 = **섹션마다 프리셋 하나씩** 골라 세로 조립(예: 히어로 B + 일시 A + 라인업 C). 섹션은 **묶음 개념**일 뿐 중첩 컨테이너 ❌ → 최종은 **평면 카드 스택**.

**🔒 기능 고정 카드 = 내부 구조·간격 고정, 카드 디자인은 배리 가능 (2026-07-07 개정)** — **예약·위치안내·SNS·Q&A** 등은 **내부 요소 구성·간격을 항상 동일**하게(사용자가 못 바꾸는 부분 = 프리셋마다 안 바꿈). **단, 카드 디자인 — 배경·테두리·모서리·제목(별도 텍스트 카드)·정렬·바깥 배치 — 로는 배리에이션 가능.** 세부: **위치안내 지도 = 실제 에디터 옵션만**(각진/둥근 × 가로/1:1), **주소 중앙·gap 16**, **Q&A 제목 무조건 중앙·제출 버튼 내장**. (→ [[../CLAUDE.md]] 🧩⑥, [[1-6-2. CdBd 카드 기능]])

**🧷 섹션 구분 = 내용 기준 / 반복 요소 통일 = 페이지 조합 시에만 (2026-07-07)** — 섹션은 **담는 내용**으로 구분한다(히어로·일시·라인업·타임테이블·티켓·위치·푸터…). **반복 요소**(구분선 모양·두께·색, 섹션 라벨 스타일, 버튼 모양·크기, 여백 리듬)의 **통일은 「여러 섹션을 하나의 페이지로 조합할 때」만** 적용 — **프리셋 개별 제작 단계에선 강제 ❌**(각 프리셋은 자기 무드/원본 디자인을 따라도 됨). 즉 최종 페이지 완성 시 반복 chrome을 한 스타일로 정돈.

## 🧱 섹션 기준 (필수)

### 기준 1 — 테마 적응성: 색·폰트는 대상 페이지 테마로 교체

- **원본과 모든 배리에이션은 컬러·폰트를 「적용할 페이지 테마」에 맞게 수정할 수 있어야 한다.** 섹션은 특정 색·폰트에 종속되지 않는다.
- 섹션의 **자산 가치 = 구조·레이아웃·정렬·여백·모양·위계**. 색·폰트는 **중립**이며, 사용 시 대상 템플릿의 무드에 맞춰 갈아끼운다:
  - 색 = **3토큰**(`{배경색}`/`{텍스트색}`/`{버튼색}`) 역할로만 표기 · 보조색 = `{텍스트색}×N%` · 강조배경 = `{버튼색}×N%` (→ [[1-2. 기획 문서 템플릿]] Part A, [[1-3. 색상 팔레트]])
  - 폰트 = 페이지당 1~2개 · 국문 본문 = 한글 폰트 · **텍스트 웨이트 = Regular/Bold 2종만**(CdBd Bold 토글과 정합) (→ [[1-4. 폰트]])
- 따라서 섹션 제작 시 **특정 hex·특정 폰트에 종속되는 디자인 금지**(예: 그 색이어야만 성립하는 장식 ❌).
- **배리에이션끼리 비교·평가할 때도 색·폰트는 동일하게 고정**하고 **구조 차이만** 본다 — 변주 축(구조)을 색·폰트 차이로 오염시키지 않기 위해.

### 기준 2 — 좋은 배리에이션 판별 체크리스트

> A/B/C 실제 평가에서 정제한 재사용 기준. 새 섹션의 배리에이션을 만들 때마다 이 체크리스트로 검수.

**✅ 배리에이션이 되려면**
- **원본과 한눈에 다른 레이아웃** — 구성·배치가 **실질적으로** 달라야 한다.
- 그러면서 **레이아웃이 안정적** — 정렬·간격·위계가 무너지지 않는다.
  - 🟢 *좋은 예(A): 좌측 정렬 에디토리얼 — 기존과 확연히 다르면서 레이아웃도 안정적.*

**❌ 배리에이션으로 인정 안 됨**
- **단일 요소만 변경** — 구분선 모양 하나만 바꾸고 나머지 레이아웃은 기존과 거의 같음 → 배리에이션 ❌. **레이아웃·구성 차원에서 달라야** 한다.
  - 🔴 *반례(B): 구분선 모양 말고는 기존 레이아웃과 차별점이 거의 없음.*
- **개별 요소 모양이 전체 톤과 부조화** — 한 요소(예: 이미지 모양)가 섹션 전체 무드와 안 어울림 → 재검토.
  - 🔴 *반례(B): 01 이미지의 모양이 전체 톤과 안 어울림.*

**🔢 배리에이션 개수 = 원본 + 3 (2026-07-07)**
- 각 변주 섹션은 **원본 1 + 배리에이션 3 = 4열**로 축적. "**원본 제외 3개**"이며 **원본을 배리에이션 수에 포함하지 않는다**(원본+2 = 미달).

**🎚 차별화 깊이 — 카드 순서만 ❌, 정렬·배경·구분선 ✅ (2026-07-07)**
- 3종이 **카드 순서만 다르고 강약·레이아웃이 거의 동일**하면 배리에이션 ❌ (기준 2 "레이아웃·구성 차원" 재확인).
- 실질 차별화 레버: **정렬**(좌/중) · **배경**(투명 / 틴트 카드 / 화이트+테두리 / 각진 밴드) · **구분선**(짧은 액센트바 / 풀 divider / 없음) · **이미지 위치·타입**(상단 히어로 / 2×2 그리드 / 넘겨보기) · **번호·아이콘 리드**.

**🔁 반복 하위 섹션 = "섹션 구분 방식"을 변주 축으로 (2026-07-07)**
- 원본에 **반복되는 하위 섹션**(반별·회차·항목 세트)이 있으면 배리에이션에도 **그 반복 세트를 모두 포함**하고, **여러 섹션을 구분하는 방식 자체를 변주**한다: 간격 / 풀 구분선 / 틴트 카드 박싱 / 번호(01·02) 리드.
  - 🟢 *예(밀과버터 Classes): 입문반+심화반 반복 세트를 A=간격 · B=구분선 · C=틴트카드 · D=번호로 구분.*

**⚠️ 멀티 컬럼(2단) 레이아웃 3원칙**
1. **label ↔ contents 텍스트 사이즈 균형** — 라벨과 값의 크기 차이가 과하면 시각적으로 불안정. 위계는 주되 안정 범위 안에서.
2. **라벨 줄바꿈 금지** — 고정폭 라벨이 **한 줄**에 들어와야 한다. 안 되면 폭을 늘리거나 라벨을 축약/재배치.
3. **인접 요소와 정렬 일관성** — 2단 섹션이 좌정렬인데 바로 위 제목이 초대형 중앙정렬이면 시각 불균형. **정렬·스케일을 이웃 요소와 맞춘다.**
   - 🔴 *반례(C): 2단 시도는 좋으나 ① label-contents 사이즈 차이 과다 ② '드레스코드' 라벨 줄바꿈 ③ 위 초대형 중앙 제목 ↔ 아래 좌정렬 2단 → 셋 다 불안정.*

**🔁 리비전 원칙** (정렬·정돈 수정 시 "재차별화" 유지)
- **정렬을 원본에 맞추더라도 다른 축에서 차별성 유지** — 정렬 불일치를 고치려 원본과 같은 정렬로 되돌리면 **원본과 다시 유사**해질 수 있다. 정렬은 맞추되 **구조(패널·색 밴드)·위계·이미지 처리** 등 다른 차원에서 차별점을 확보. *(C 리비전: 중앙정렬 통일 → 정보에 색 밴드 패널로 재차별화.)*
- **강한 요소가 구분 역할을 하면 구분선 제거** — 풀블리드 이미지·색 밴드처럼 이미 시각적 분리를 만드는 요소가 있으면 구분선을 겹쳐 넣지 않는다(장식 최소화, 5대 원칙 #5와 통함). *(B 리비전: 이미지가 상·하를 가르므로 구분선 삭제.)*

### 기준 3 — 채택 관문: 라이브러리에 들일지 거르는 게이트 (2026-07-08)

> 프리셋이 많아져도 **품질·중복**을 지키는 문. 후보(원본/배리에이션)가 아래를 통과해야 라이브러리에 등재. (「🗂 분류 체계」가 *어디에 넣나*라면, 여기는 *들일지 말지*.)

**공통 관문 (E·F 모두)**
- ☑ **테마 적응성** — 색·폰트 중립(3토큰 역할 · `{텍스트색}×N%`), 특정 hex/폰트 종속 ❌ (= 기준 1)
- ☑ **CdBd-legal** — 평면 카드 스택 · 15카드 · 카드 고정 스펙 · 자간 0 · 짝수 줄간격 · 이탤릭 ❌ · 버튼 원형
- ☑ **슬롯 명확** — 정확히 **한 개의 섹션 역할** 서랍에 들어간다. 두 역할에 걸치면 **쪼갠다.**
- ☑ **빈칸 규칙 명확** — 유저가 채울 칸 vs 고정 칸이 분명.

**E집안 추가 — "새 방향"만 (개방형이지만 문은 있다)**
- ☑ 같은 역할 서랍의 **기존 프리셋과 한눈에 다른 레이아웃** (= 기준 2). 실질 차원(정렬·배경·구분선·이미지 위치/타입)에서 다름.
- ❌ 근-중복(카드 순서만 다름)은 등재 안 함.
- 💡 역할별 **구조 톤이 유한**(좌측·중앙·타이포리드·그리드·풀블리드…)해 자연히 6~10개 안쪽으로 수렴 → **하드 정원 불필요.**

**F집안 추가 — 정원 6 + 교체**
- ☑ 내부 요소 구성·간격 = **CdBd 빌트인 그대로**(사용자가 못 바꾸는 부분). 배리는 **카드 디자인**(배경·테두리·모서리·제목·정렬·바깥 배치)으로만.
- ☑ 역할 서랍 정원 **6**. 꽉 찬 서랍에 더 좋은 후보가 오면 **가장 약한 걸 교체**(무한 누적 ❌).

**🩺 커버리지 표 (선택) — 빈 칸 한눈에**
- E = (역할 × 구조 톤) · F = (역할 × 채움/6) 표로 **부족한 방향·꽉 찬 서랍**을 즉시 확인 → 신규 제작 우선순위를 여기서 뽑는다.

> ※ **개수 규칙 정리**: 기준 2의 「원본+3」 = 한 섹션 **처음 만들 때** 범위를 증명하는 **제작 최소치**. **F 정원 6** = 라이브러리 **보관 상한**. **E**는 하드 상한 없이 「새 방향」 게이트로 관리.
