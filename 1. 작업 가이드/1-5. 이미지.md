> 실제 디자인 톤·색상 매칭은 [[1-6-1. CdBd 에디터]], [[1-3. 색상 팔레트]] 참조.

## 🎨 이미지 톤 = 페이지 톤 매칭 (필수 · 2026-07-03)

**이미지(특히 메인·헤더 이미지)의 밝기·대비·색온도는 페이지의 무드/팔레트와 일치해야 한다.** 이미지 자체가 잘 나와도 페이지 톤과 어긋나면 이질감이 생겨 교체 대상.

| 페이지 무드 | 어울리는 이미지 톤 | 생성 프롬프트 키워드 |
|---|---|---|
| **밝고 따뜻·부드러움** (크림·베이지·파스텔 배경) | **하이키·저대비·소프트** — 은은한 자연광, 최소 그림자, 화사·연한 톤 | `bright, airy, high-key, soft diffused light, low contrast, minimal shadows, warm pastel, dreamy, soft focus` · `no harsh darks, no silhouettes` |
| **다크·시크·드라마틱** (딥네이비·차콜 배경) | **딥·고대비·무디** — 저녁/블루아워, 강한 명암, 실루엣 | `moody, low-key, dramatic contrast, blue hour, deep shadows, cinematic` |
| **중립·프로페셔널** (오프화이트·그레이) | **중간톤·균형** — 자연광, 과하지 않은 대비 | `natural daylight, balanced, clean, neutral` |

**규칙**:
1. **팔레트 색온도 맞추기** — 페이지가 웜(크림·브론즈)이면 이미지도 웜톤, 쿨(인디고·세이지)이면 쿨톤. 반대 색온도 이미지는 배제.
2. **배경 밝기 맞추기** — 밝은 배경 페이지에 어둑·드라마틱 이미지 ❌ (그 이미지는 다크 배경용). 반대도 마찬가지.
3. **`natural daylight`만 쓰면 AI가 어둑하게 감** — 밝은 톤이 필요하면 `bright · airy · high-key` 형용사를 명시 (제품컷 규칙과 동일, 아래 참조).
4. **생성 후 검수** — 이미지를 시안에 올린 뒤 **페이지 전체 스크린샷으로 톤 일치 확인**. 튀면 재생성.

> ⚠️ **밝게 ≠ 세피아 단색 (2026-07-03)**: `bright · high-key · warm pastel`을 과하게 밀면 AI가 화면 전체를 **균일한 세피아·오렌지 틴트로 뭉갠다**(포토샵 모노톤 필터 먹인 느낌). 밝기를 살리되 자연 색을 유지하려면 프롬프트에 `natural neutral white balance · realistic color separation · NOT a sepia/monotone color filter · not oversaturated`를 함께 명시 → 우드·벽·창빛의 색 구분이 살아난다. (밝음 = "색을 뺀 단색"이 아니라 "빛이 많은 자연색")

### 🪧 소형 로고(마크) 이미지 (2026-07-03)

- **소형 인페이지 로고(≈40~60px)는 심볼/마크 1개 위주** — 국문·영문 워드마크는 소형에서 판독 불가. 단순 상징(십자가·건물 실루엣 등)으로 단순화.
- **색은 페이지 액센트 컬러와 일치** (예: 브론즈 무드 → 브론즈 라인 마크). 로고도 톤 매칭 대상.
- **투명 배경(`background: transparent`) + 여백 타이트 크롭** — 투명 배경으로 생성 후 알파 bounding box로 잘라 정사각 패딩하면 작은 타일에서도 마크가 또렷. (기술 함정 — auto-layout 프레임 fill 실패 시 사각형 노드에 적용: [[../CLAUDE.md]] `upload_assets` 항목 참조)

### 🖼 이미지·로고 슬롯 캡션·모양 규칙 (필수 · 2026-07-21 이선호)

> **왜**: 시안 이미지 슬롯 캡션이 「서가 · 야간 조명」처럼 **AI가 생성할 그림을 지시하는 문구**로 채워지곤 했다. 하지만 **엔드유저는 자기가 준비한 이미지를 업로드**한다(제품 플로우 ③) — 슬롯은 **생성 지시서가 아니라 「무엇을 넣는 자리」 안내**여야 한다.

- **이미지 슬롯 캡션 = 무드·장면·연출 지시 금지 · 중립 문구만** — ❌「서가 · 야간 조명」·「흑백 인물(측면)」·「로스팅 머신」·「안주 사진」 / ✅「이미지」·「메인 이미지」·「프로필 이미지」·「지도 임베드」(역할 구분 필요 시 「매장 사진」·「제품 사진」 같은 무드 없는 카테고리 명사까지만).
- **로고 슬롯 캡션 = 전부 「로고」** — 브랜드명(「책방 오래」 등)으로 채우지 말 것(브랜드명은 텍스트 카드가 따로 표시).
- **로고 모서리 = 「각진」(radius 0) 기본, 원형 디자인 로고만 원형 예외** — 대부분 투명 PNG가 각진으로 들어감. ⚠️ **프로필 이미지는 반대**(둥근/원형만) · **로고·프로필은 8항목 모서리 통일에서 제외**(브랜드 자산).
- 🔗 파이프라인 실행 규칙 = `.claude/cdbd-draft-shared.md` R38(이미지 슬롯)·R39(로고 슬롯)·R24(자리표시 라벨 집계 제외).

> **이 섹션은 역사적 기록으로만 보존.** Flow는 이미지 생성 표준에서 제외됨(무인 갱신 불가·throttle). 아래 내용은 참고용이며 신규/무인 작업에서 **사용하지 말 것**. 실사는 OpenAI gpt-image-1 / Unsplash 사용.

**URL**: https://labs.google/fx/ko/tools/flow

- Google의 AI 영상·이미지 생성 도구 (Veo 모델 기반)
- 실사 사진풍 이미지 생성에 적합
- 프롬프트 기반 — 자연어로 장면·피사체·분위기 묘사

### 사용 컨텍스트

- ✅ **인물 사진** — 강사, 대표, 팀원, 후기 작성자 등
- ✅ **Special Gift / 사은품 섹션** — 굿즈, 패키지, 선물 박스
- ✅ **제품·소품 컷** — 사실적인 제품 사진이 필요할 때
- ❌ 상징적 메시지 전달 → Thiings 일러스트로

### 선정 기준 (절대 규칙)

| ✅ 반드시 | ❌ 절대 금지 |
|---|---|
| **사실적인 실사** — 다큐/스냅사진 톤 | 연출샷·광고샷 — 인위적 포즈·세팅 |
| 자연광·평범한 환경 | 스튜디오 라이팅·화려한 배경 |
| 깨끗한 구도 | **로고·텍스트·워터마크 (완전 배제)** |
| 피사체에 집중 | 과장된 카메라 각도·필터 |

> ⚠️ **로고/텍스트 금지**: AI는 텍스트 렌더링이 부정확 → 글자가 들어간 컷은 모두 폐기.
> 패키지·박스·티셔츠 등에 글자가 보이면 다른 컷으로 교체.

### 프롬프트 작성 원칙

**목표**: "연출되지 않은, 우연히 찍힌 듯한 자연스러운 실사"

| 요소 | 작성 방향 |
|---|---|
| **사진 종류** | `documentary photo`, `candid shot`, `everyday photo` (NOT `professional studio shot`) |
| **광원** | `natural daylight`, `window light`, `overcast soft light` (NOT `dramatic lighting`) |
| **앵글** | `eye-level`, `slight angle`, `casual framing` (NOT `dramatic low angle`) |
| **배경** | `plain background`, `simple home interior`, `blurred neutral background` |
| **무드** | `unposed`, `natural`, `realistic`, `not staged` |
| **비율** | `1:1 square aspect ratio` (별도 요청 없으면 디폴트) |
| **금지어** | `no text`, `no logo`, `no watermark`, `no captions`, `blank surfaces` |

**좋은 프롬프트 예시:**
```
A candid, documentary-style photo of a woman in her 30s smiling 
softly while looking off-camera. Natural window light from the side, 
eye-level angle, plain beige wall background. Unposed, realistic, 
no makeup styling. 1:1 square aspect ratio. 
No text, no logos, no watermarks anywhere.
```

```
An everyday photo of a small unbranded gift box on a wooden table, 
wrapped in plain kraft paper with a simple twine bow. Natural daylight, 
top-down casual angle, slightly soft focus. 1:1 square aspect ratio.
Blank surfaces only — no text, no logos, no labels, no captions.
```

**나쁜 프롬프트 예시 (피할 것):**
```
❌ Beautiful professional studio portrait with dramatic lighting
❌ Luxury gift box with elegant gold logo and ribbon
❌ Stylish model posing with branded packaging
```

### 📦 서브 가이드: 제품 실사컷 규칙

Special Gift, 제품 소개, 카탈로그 등 **제품이 주인공인 컷**에 적용. 인물 컷과는 다른 별도 규칙.

> **핵심 철학**: 무드 < 정보 전달. 사용자가 "이게 뭔지 / 몇 개인지 / 어떻게 생겼는지" 1초 안에 파악할 수 있어야 함.

#### 1️⃣ 앵글 & 자세

| 항목 | 규칙 | 이유 |
|------|------|------|
| **앵글** | `eye-level angle`, `slightly off-center composition` | 세워진 제품의 입체감·정면이 모두 드러남 |
| ❌ 회피 | `top-down`, `dramatic low angle` | 제품 식별 어려움, 만든 사람 자기과시 느낌 |
| **제품 자세** | `standing upright`, `NOT lying down` | 3D 존재감, 진열대 같은 신뢰감 |
| **박스류** | `tilted slightly toward camera so the inside is visible` | 내용물 노출 → 무엇이 들었는지 즉시 인지 |

#### 2️⃣ 프레이밍

```
✅ fully framed with comfortable margins on all sides
✅ both items entirely within frame
✅ 1:1 square aspect ratio
❌ 가까이 찍어서 가장자리 잘림
```

> ⚠️ 프롬프트에 **"fully framed", "comfortable margins", "entirely within frame"** 명시 — 안 쓰면 AI가 멋부리려고 클로즈업해서 자름

#### 3️⃣ 제품 식별성 (Distinguishability) — 가장 중요

여러 제품이 한 컷에 들어가면 **시각적으로 명확히 구분**되어야 함.

| 함정 | 해결 |
|------|------|
| 둘 다 같은 크라프트지 → 뭐가 뭔지 모름 | 한쪽에 **투명창 / 다른 색 / 다른 형태** 추가 |
| 박스 닫힌 채 → 안에 뭐 들었는지 모름 | **open box, tilted to show inside** |
| 여러 개 펼쳐놓음 → 산만 | **box/tray로 그룹화** |

**예시 — 원두 + 드립백 세트:**
```
LEFT: a coffee bean pouch with a transparent clear plastic front window 
      revealing the dark roasted whole coffee beans inside, kraft back panel
RIGHT: an open plain kraft paper gift box tilted slightly toward camera, 
       containing 5 individually wrapped drip coffee bags arranged neatly 
       side-by-side in a single row inside the box
```
→ 한 번에 "원두 / 드립백 / 5개"가 모두 인지됨.

#### 4️⃣ 광원 (Lighting)

| 톤 | 프롬프트 키워드 | 용도 |
|----|----------------|------|
| **화사·밝음** (CdBd 기본) | `bright, fresh, airy natural daylight from a large window, soft diffused light` | Special Gift, 신제품, 카탈로그 |
| 따뜻·아늑 | `warm afternoon light, golden hour` | 무드 중심 (예: 라이프스타일 컷) |
| ❌ 회피 | `dramatic lighting, moody, dark shadows` | 제품 식별 약화 |

> **"natural daylight"만 쓰면 AI가 어둑한 톤으로 가는 경향** — `bright, fresh, airy` 형용사 3개 명시.

#### 5️⃣ 배경 (Background)

| 등급 | 프롬프트 키워드 | 용도 |
|------|----------------|------|
| **A. 최우선** | `minimal clean uncluttered background, softly blurred plain neutral wall` | 제품에 집중 |
| **B. 허용** | `pale light wood surface, neutral linen tabletop` | 약간의 텍스처 (페일 톤만) |
| **C. 회피** | `cafe atmosphere, plants, mugs, decorative props, patterned fabric` | 산만 |

**부정문 필수 명시:**
```
NO cafe props, NO plants, NO mugs, NO additional objects, 
NO patterned fabrics visible
```

#### 6️⃣ 표면 (Tabletop)

- ✅ `pale light wood`, `neutral linen`, `off-white surface`
- ❌ `dark walnut`, `glossy black`, `rustic weathered wood`
- 어두운 우드는 화사함을 죽임. 페일 톤이 CdBd 모바일 카드 위에 얹혔을 때 안정적.

#### 7️⃣ 제품 실사컷 마스터 프롬프트 템플릿

복제해서 변수만 바꿔 쓰는 베이스 프롬프트:

```
A clean product-focused documentary photo of {제품 카테고리 명사}
standing upright on a pale light wood surface or neutral linen tabletop, 
fully framed with comfortable margins on all sides.

LEFT ITEM: {제품 1의 형태·재질·색상·식별 포인트 (예: 투명창 / 라벨 없는 크라프트 / 알루미늄 캡)}
RIGHT ITEM: {제품 2의 형태·재질·색상·식별 포인트}

Both items standing upright, NOT lying down.
Bright, fresh, airy natural daylight from a large window, soft diffused light, 
eye-level angle, slightly off-center composition.

Minimal clean uncluttered background — softly blurred plain neutral wall, 
NO cafe props, NO plants, NO mugs, NO additional objects, NO patterned fabrics visible.

Realistic product photography, not staged. 
1:1 square aspect ratio with both items entirely within frame.
Absolutely no text, no logos, no labels, no printed letters, no watermarks, 
no barcode anywhere — all surfaces blank.
```

#### 8️⃣ 검수 체크리스트 (생성 후)

- [ ] 1:1 정사각형 + **잘림 없음** (가장자리 여백 충분)
- [ ] 각 제품 **세워져 있음** (누워있지 않음)
- [ ] 제품 간 **시각적 구분 가능** (같은 재질·형태 X)
- [ ] 내용물 / 개수 / 형태 **1초 안에 파악 가능**
- [ ] **화사한 톤** (어둑하지 않음)
- [ ] 배경 **깔끔** (소품 없음)
- [ ] 글자·로고·라벨·바코드 **0개**

### 🏷 서브 가이드: 온라인몰 썸네일컷 규칙

쇼핑몰 제품 썸네일·상세 페이지 메인 컷에 적용. **순수 흰 배경 + 제품만 분리(isolated)**된 스튜디오 컷.

> **핵심 철학**: 무드 X 컨텍스트 X. **제품 = 화면의 전부**.
> 상세 페이지에서 제품 라이브러리 그리드에 얹혔을 때 시각적 노이즈 0.

#### 🆚 '제품 실사컷' vs '온라인몰 썸네일컷' 비교

| 항목 | 📦 제품 실사컷 (lifestyle) | 🏷 온라인몰 썸네일컷 (e-commerce) |
|------|--------------------------|--------------------------------|
| **용도** | Special Gift, 후기, About 섹션 | 상품 그리드, 상세 페이지 메인 컷 |
| **배경** | 페일 우드·리넨 (살짝 텍스처) | **순수 흰색 seamless** (0 텍스처) |
| **표면** | 테이블 톱이 보임 | **표면 없음** — 제품이 흰색 위에 떠 있음 |
| **광원** | 화사한 자연광 (창문 느낌) | **균등한 스튜디오 디퓨즈 라이트** |
| **그림자** | 자연스러운 캐스트 그림자 | **subtle drop shadow** (제품 바로 아래만) |
| **컨텍스트** | 페일 월·블러 배경 약간 | **컨텍스트 0** — 제품만 |
| **앵글** | eye-level + 살짝 옆 | eye-level 정면 또는 살짝 위 3/4 |
| **무드** | 다큐멘터리·캔디드 | 카탈로그·중립 |

#### 1️⃣ 배경 (가장 큰 차이)

```
✅ pure white seamless background
✅ no surface, no table, no shadow context
✅ products isolated on white
✅ only a very subtle soft drop shadow directly underneath
```

> **"on a white background"만 쓰면 약함** — AI가 흰 천이나 흰 책상으로 해석하기도. 위 4줄을 모두 명시.

#### 2️⃣ 광원

```
✅ bright even diffused studio lighting from above and front
✅ no dramatic shadows, no colored tints
```

스튜디오 디퓨즈 = 부드러운 박스 라이트. 자연광 키워드 (window light, daylight)는 피함.

#### 3️⃣ 앵글

| 제품 타입 | 권장 앵글 |
|----------|----------|
| **평면적 (원두·식재료)** | top-down 또는 eye-level 정면 |
| **세워진 패키지 (봉투·박스)** | eye-level frontal |
| **잔·그릇류** | slightly elevated 3/4 angle (잔 모양 + 내용물 모두 보임) |
| **세트 상품** | slightly elevated 3/4 angle (구성품 모두 보임) |

#### 4️⃣ 동일 제품 라인업 (사이즈/메뉴별 모음컷)

여러 변형을 한 컷에 보여줄 때 (예: 용량별, 메뉴별):

```
✅ identical {제품} in {N} distinctly different {variant axis}
✅ arranged in a perfectly aligned single row from left to right
✅ evenly spaced
✅ perfectly aligned at the same height
✅ identical in shape  (variant 축만 다르고 나머지는 통일)
```

> **"identical" 강조 필수** — 안 쓰면 AI가 디자인을 각각 다르게 만들어 산만해짐.

**축 예시:**
- **사이즈 축**: `small 50g, medium 200g, large 500g`
- **메뉴 축**: `classic espresso / con panna / breve / macchiato` (각각 표면 디테일 명시)

#### 5️⃣ 시각적 변별점 강조 (메뉴/맛 컷)

같은 잔에 담긴 다른 음료가 한 컷에 있을 때, **표면 디테일**을 매우 구체적으로 지시:

```
CUP 1: classic single espresso — pure dark brown coffee with thin golden crema
CUP 2: con panna — espresso with generous swirl of pure white whipped cream on top
CUP 3: breve — espresso topped with creamy steamed half-and-half showing 
       visible light caramel and cream layered tones
CUP 4: espresso macchiato — espresso with small dollop of bright white milk foam in center
```

> 색상·층·토핑을 명시해야 AI가 진짜 그 음료처럼 그림. "espresso variations" 같은 두루뭉술은 X.

#### 6️⃣ 세트 상품 컷 (구성품 그룹)

잔+받침+스푼 같은 패키지 세트는:

```
✅ all components in a single composition
✅ cup placed centered on its matching saucer
✅ spoon resting elegantly on saucer beside the cup
✅ slightly elevated 3/4 angle to show all components together
```

빈 잔 (empty cup, no coffee inside) — 음료가 아닌 **세트 자체**가 상품임을 강조.

#### 7️⃣ 온라인몰 썸네일컷 마스터 프롬프트 템플릿

```
A clean e-commerce product thumbnail: {제품 상세 설명 — 형태·재질·색상·내용물·정렬}.

Pure white seamless background, no surface, no shadow context — {제품} isolated 
on white with only a very subtle soft drop shadow directly underneath.

Bright even diffused studio lighting from above and front, 
no dramatic shadows, no colored tints. 
{앵글 선택: eye-level frontal | slightly elevated 3/4 angle | top-down}, 
slightly off-center composition.

Comfortable white margins on all sides. 
Hyperrealistic product photography, not styled, not staged. 
1:1 square aspect ratio.

Absolutely no text, no logos, no labels, no printed letters, no watermarks, 
no barcodes, no menu cards, no fabric, no other props — 
clean isolated product shot.
```

#### 8️⃣ 검수 체크리스트 (생성 후)

- [ ] 배경이 **순수 흰색** (회색·베이지·우드 X)
- [ ] 제품 외 **다른 사물 0개** (소품·테이블·천 X)
- [ ] 그림자가 **subtle** — 제품 바로 아래에만 살짝
- [ ] 광원이 **균등** (드라마틱 명암 X)
- [ ] 여러 변형 컷의 경우 **identical 형태**, 변형 축만 차이
- [ ] 모든 제품 **완전 프레임 내**, 여백 충분
- [ ] 글자·로고·라벨·바코드 **0개**

### ✂️ 서브 가이드: 누끼(배경 제거) 이미지 처리 요청

신제품 소개 / 패키지 / 컬렉션 그리드 등에서 **흰 배경조차 없이 제품만 분리(투명 PNG)**된 누끼 이미지가 필요한 경우.

> **상세 기술 절차**:
> [[../../../cdbd-design-service/룩북/2. 디자인 가이드/2-1. 공통.md|cdbd-design-service/룩북/2. 디자인 가이드/2-1. 공통.md]]
> 의 「로고·누끼 이미지 처리」 섹션 (line 163~238) 동일 패턴 적용.

#### 🆚 썸네일컷 vs 누끼컷

| 항목 | 🏷 온라인몰 썸네일컷 | ✂️ 누끼컷 |
|------|---------------------|-----------|
| **배경** | 순수 흰색 (불투명) | **alpha 투명** (배경 X) |
| **용도** | 상세 페이지 메인 컷 | **카드·그리드 셀에 넣기** (배경색이 셀 컬러 따라감) |
| **파일 형식** | JPG 또는 PNG | **PNG (alpha 채널 필수)** |
| **생성 방법** | `/generate-flow-image` 1단계 | 1단계 + **사용자 가공 요청 1단계** |
| **alpha bbox 크롭** | 불필요 | **필수** (PIL `getbbox()` + `crop()`) |

#### 🎯 두 가지 처리 모드

용도에 따라 분기:

| 모드 | 산출물 | 사용처 |
|------|--------|--------|
| **🅰️ 로컬 누끼** | `~/Downloads/{keyword}-cutout.png` (투명 PNG) | Obsidian 노트 임베드, 로컬 사용 |
| **🅱️ Figma 누끼 + 프레임** | Figma 안 누끼 RECT + 배경색 프레임 | **CdBd 페이지용 디자인 자산 (기본)** |

> ⚠️ **CdBd 페이지 내 사용은 🅱️ 모드 필수**. 배경색을 이미지에 베이크하지 말고 Figma 프레임에 분리해서 적용해야 재사용·수정 가능.

#### 🔄 모드 🅱️ — Figma 누끼 + 프레임 워크플로우 (블록·blocking, 8 단계)

**⚠️ 누끼 가공 전 원본을 최종 셀에 넣지 않는다.** Figma "사례 기획" 페이지의 별도 보드에 업로드, 사용자 가공 완료 신호 후 후속 단계 자동 진행.

```
1️⃣ 베이스 컷 생성
   /generate-flow-image 으로 흰 배경 + 최종 구성 (스푼 X 등 사용자 확정) 생성
   → ~/Downloads/{keyword}.png
   ⚠️ 배경색은 이 단계에서 적지 말 것 — 프레임 단계(8️⃣)에서 적용

2️⃣ Figma 업로드 보드 생성
   사례 기획 페이지 (file=oi8zIHLfy59O5zV8aysqq4, node=1:746)의 빈 공간에
   "누끼 가공 요청 — {프로젝트명}" 보드 생성
   각 이미지마다 카드 (라벨 + placeholder RECT + 파일명 라벨) 추가
   ※ ~/.config/cdbd/credentials.json 의 figma_locations.사례_기획_page 참조

3️⃣ 이미지 업로드
   mcp__claude_ai_Figma__upload_assets (count=1, nodeId=placeholder RECT)
   → 단일 사용 URL → curl POST multipart/form-data
   ⚠️ upload_assets가 nodeId 지정해도 fill 자동 적용 안 됨 → 다음 단계 필요

4️⃣ 수동 fill 적용
   use_figma 스크립트로 받은 imageHash를 RECT.fills로 설정
   rect.fills = [{ type: "IMAGE", imageHash, scaleMode: "FIT" }]

5️⃣ 사용자에게 위치 알림 (정형 메시지)
   ↓ 아래 「요청 메시지 템플릿」 참고

6️⃣ 대기 (BLOCKING)
   사용자가 Figma AI Remove background 적용 후 완료 신호 보낼 때까지

7️⃣ 누끼 추출 + alpha bbox 크롭 (자동)
   Figma REST API 로 RECT를 PNG 렌더 (scale=4)
   → 다운로드 → PIL getbbox() + crop() → ~/Downloads/{keyword}-cutout.png

8️⃣ 최종 프레임 생성 (자동)
   크롭본 재업로드 → use_figma로 새 FRAME 생성
   - 배경색: 색상 라이브러리에서 주제 매칭 (예: 카페 → HappyHues 8 #F8F5F2)
   - 비율: 사용 컨텍스트에 따라 (3:2 가로 패키지 / 1:1 단일 등)
   - 레이아웃: 누끼 RECT를 절대 좌표로 배치 (auto-layout 없이 정밀 정렬)
```

#### 📝 사용자 요청 메시지 템플릿 (모드 🅱️)

업로드 + fill 적용 완료 후 사용자에게 다음 형식으로 알림:

```markdown
🎨 **Figma 누끼 가공 요청 — {프로젝트명}**

| 항목 | 값 |
|------|-----|
| **위치** | [사례 기획 페이지 → "누끼 가공 요청" 보드](Figma URL with node-id) |
| **노드 ID** | 보드: `{board_id}` / 이미지 RECT: `{rect1_id}`, `{rect2_id}` |
| **처리 내용** | 1) 각 RECT 선택 → Figma AI **Remove background** <br> 2) 완료되면 알려주세요 |

**참고 컨텍스트**: {왜 누끼가 필요한지 한 줄}

가공 완료 신호 받으면 자동으로:
1. Figma REST API로 가공본 추출
2. PIL alpha bbox 크롭
3. 크롭본 재업로드
4. 새 패키지 프레임 (배경색 + 정렬) 생성
까지 이어집니다.
```

#### 🐍 추출 + 크롭 자동화 스크립트 (7️⃣ 단계)

```bash
# Figma REST API로 렌더링된 PNG 다운로드
PAT=$(jq -r .figma_pat ~/.config/cdbd/credentials.json)
FILE_KEY=oi8zIHLfy59O5zV8aysqq4
RECT_IDS="276:29,276:33"  # 예시

# 렌더 URL 받기 (scale=4 → 1600x1600 PNG)
RESPONSE=$(curl -sS -H "X-Figma-Token: $PAT" \
  "https://api.figma.com/v1/images/$FILE_KEY?ids=$RECT_IDS&format=png&scale=4")

# URL 두 개 추출 후 다운로드
for id in $(echo "$RESPONSE" | jq -r '.images | keys[]'); do
  url=$(echo "$RESPONSE" | jq -r ".images[\"$id\"]")
  curl -sS -o "/tmp/${id//:/_}-raw.png" "$url"
done
```

```python
    out = src.replace("-raw", "")
    img = Image.open(os.path.expanduser(f"~/Downloads/{src}"))
    if img.mode != "RGBA":
        raise SystemExit(f"❌ {src}: alpha 없음 (모드: {img.mode})")
    bbox = img.getbbox()
    if not bbox:
        raise SystemExit(f"❌ {src}: 전체 투명")
    img.crop(bbox).save(os.path.expanduser(f"~/Downloads/{out}"), "PNG", optimize=True)
```

> ⚠️ **anti-pattern**: 가공 직후 1600×1600 raw PNG를 그대로 다음 단계 RECT에 fill 하면 alpha 여백이 시각 면적 균일성을 깨뜨림. **반드시 PIL 크롭 거친 -cutout.png 만 사용**.

#### 🎨 최종 프레임 생성 (8️⃣ 단계)

**📏 프레임 사이즈 규칙 (CdBd 페이지용)**

| 항목 | 값 |
|------|-----|
| **프레임 가로** | **380px** (CdBd 모바일 페이지 카드 폭) |
| **세로** | 비율에 맞춰 (3:2 → 253, 1:1 → 380, 4:5 → 475 등) |
| **내보내기** | `PNG @ 3×` (retina) → 1140 × {h×3} 실제 출력 |
| **모서리** | 8 (작은 프레임용) ~ 16 (큰 프레임용) |

**📐 다중 아이템 시각 면적 균등화 (룩북 2-1 공통 패턴)**

서로 다른 비율의 두 누끼를 한 프레임에 배치할 때 **시각 면적이 비슷해 보이도록** 사이즈 계산:

```js
const S = 8000; // 목표 면적 (px²) — 프레임 크기에 맞춰 조정
const aspectA = bbox_a_w / bbox_a_h;
const aspectB = bbox_b_w / bbox_b_h;

// 공식: w = √(S × a), h = w / a = √(S / a)
const wA = Math.round(Math.sqrt(S * aspectA));
const hA = Math.round(wA / aspectA);
const wB = Math.round(Math.sqrt(S * aspectB));
const hB = Math.round(wB / aspectB);
```

✅ 결과: 두 아이템 면적이 거의 동일 (±2% 이내), 원본 비율 유지.
❌ 잘못된 방법: 단순히 width 통일 → 비율 다른 아이템들의 면적이 크게 차이남.

**🌬 여백 비율 (작은 프레임용)**

| 영역 | 가이드라인 |
|------|----------|
| 외곽 padding | **프레임 폭의 10% 이상** (380px 프레임 → 40px) |
| + 아이콘 ↔ 제품 | **프레임 폭의 8% 이상** (380px → 30~40px 한쪽 / 60~80 전체 gap) |
| + 아이콘 크기 | **fontSize ≈ 프레임 높이의 5~6%** (253px 프레임 → 14) |

**🎨 use_figma 예시 (380×253 패키지 프레임)**

```javascript
const FRAME_W = 380, FRAME_H = 253;
const frame = figma.createFrame();
frame.resize(FRAME_W, FRAME_H);
frame.fills = [{ type: "SOLID", color: { r: 0xF8/255, g: 0xF5/255, b: 0xF2/255 } }];
frame.cornerRadius = 8;

// 등면적 사이징

const bagAspect = 1404 / 817;  // PIL 크롭본 bbox 비율
const cupAspect = 1139 / 832;
const bagW = Math.round(Math.sqrt(S * bagAspect));   // 117
const bagH = Math.round(bagW / bagAspect);            // 68
const cupW = Math.round(Math.sqrt(S * cupAspect));   // 105
const cupH = Math.round(cupW / cupAspect);            // 77

// 좌측 누끼

frame.appendChild(bag);
bag.x = PAD;
bag.y = Math.round((FRAME_H - bagH) / 2);
bag.fills = [{ type: "IMAGE", imageHash: BAG_HASH, scaleMode: "FIT" }];

// 우측 누끼
const cup = figma.createRectangle();
cup.resize(cupW, cupH);
frame.appendChild(cup);
cup.x = FRAME_W - PAD - cupW;
cup.y = Math.round((FRAME_H - cupH) / 2);

  format: "PNG",
  constraint: { type: "SCALE", value: 3 }
}];
```

#### 🤔 Figma 직접 크롭은 가능한가? (FAQ)

질문: PIL 다운로드 단계 없이 Figma 안에서 alpha bbox 크롭 가능?

**답: 기술적으로는 가능, 실용적으로는 PIL이 더 깔끔.**

```js
// scaleMode: "CROP" + imageTransform 으로 가시 영역만 샘플링
rect.fills = [{
  type: "IMAGE",
  imageHash: BG_REMOVED_HASH,  // 크롭 안 한 원본 누끼
  scaleMode: "CROP",
  imageTransform: [
    [bbox_w / canvas_w, 0, bbox_x / canvas_w],
    [0, bbox_h / canvas_h, bbox_y / canvas_h]
  ]
}];
```

문제: `imageTransform` 행렬을 계산하려면 **alpha bbox 좌표가 필요**한데, Figma Plugin API에는 PNG 디코딩 기능 없음. bbox를 알아내는 방법:

| 방법 | 비용 | 추천도 |
|------|------|--------|
| 🅰️ 외부 PIL | 다운로드 3~5초 | ⭐⭐⭐⭐⭐ (현재 표준) |
| 🅱️ UPNG.js inline 임베드 | use_figma 코드 +40KB | ⭐⭐ (50KB 코드 제한에 근접) |
| 🅲️ 사용자 수동 Figma Crop 툴 | 사용자 클릭 2회 | ⭐⭐⭐ (자동화 깨짐) |

> ⚠️ 빈번한 누끼 작업 (월 100건+) 시 🅱️ 임베드 검토. 일반적인 사용은 🅰️ 그대로.

### ✂️ Figma 노드 투명 배경 PNG export (2026-06-22 기록)

**문제**: 어드민 등록용 아이콘(38×38)·썸네일·feature 프리뷰(360×300) 등 **카드/그리드 셀에 들어가는 자산은 모서리가 투명해야** 하는데, `download_assets`의 `export` URL로 받으면 둥근 모서리 바깥이 **페이지 캔버스 배경색**(예: `템플릿 등록` 페이지 `#f5f5f5` = rgb 154,154,154)으로 채워져 나온다. CdBd 어드민/라이브에서 그 회색 모서리가 그대로 노출됨.

**원인**: `download_assets`의 `export` 필드는 노드를 **페이지 배경과 합성(composite)** 해서 PNG를 만든다. `node.exportAsync()`(노드 단독 렌더, 투명 보존)와 결과가 다르다.

**✅ 해결 — 노드 단독 렌더를 `rawImages` 경로로 회수**:

```js
// 1️⃣ use_figma — exportAsync로 노드 단독 PNG 바이트 → createImage → 임시 RECT에 fill
const targets = [
  { id: "311:544", name: "feature1-icon", scale: 4 },   // 아이콘은 ×4
  { id: "311:549", name: "feature1-preview", scale: 2 }, // 프리뷰·썸네일은 ×2
];
const tempIds = [];
for (const t of targets) {
  const node = await figma.getNodeByIdAsync(t.id);
  const bytes = await node.exportAsync({ format: "PNG", constraint: { type: "SCALE", value: t.scale } });
  const img = figma.createImage(bytes);                  // 노드 단독 = 투명 보존
  const rect = figma.createRectangle();
  rect.resize(100, 100);
  rect.x = -10000 - tempIds.length * 200; rect.y = -10000; // 화면 밖
  rect.fills = [{ type: "IMAGE", scaleMode: "FILL", imageHash: img.hash }];
  figma.currentPage.appendChild(rect);
  tempIds.push(rect.id);
}
return { tempIds };   // 이 RECT id들을 다음 단계에서 download_assets에 넘김
```

```
2️⃣ 각 임시 RECT id로 download_assets 호출 → 응답의 rawImages[0].url 다운로드
   (export.url ❌ — rawImages[].url 이 노드 단독·투명 보존 원본)
   curl -sfo asset.png "https://www.figma.com/api/mcp/asset/{rawImages uuid}"

3️⃣ 검증 (PIL): 네 모서리 alpha = 0 확인
   python3 -c "from PIL import Image; px=Image.open('asset.png').load(); w,h=Image.open('asset.png').size; print(px[0,0], px[w-1,0], px[0,h-1], px[w-1,h-1])"
   → (0,0,0,0) 4개면 투명 OK

4️⃣ 작업 후 임시 RECT 제거 (use_figma: tempIds.forEach → node.remove())
```

> ⚠️ **안티패턴**:
> - ❌ `download_assets` `export.url` 을 그대로 카드 자산으로 사용 → 모서리 회색
> - ❌ 페이지 배경을 투명으로 바꿔서 `download_assets` 재호출 → `export` 경로는 여전히 합성 결과를 캐시할 수 있음 (1회 실측 실패). `rawImages` + 임시 RECT 패턴이 확실
> - ❌ `exportAsync` 바이트를 hex/base64로 받아 shell로 디코딩 → 큰 응답 truncate로 PNG 깨짐. **반드시 createImage → RECT → rawImages URL** 경로
