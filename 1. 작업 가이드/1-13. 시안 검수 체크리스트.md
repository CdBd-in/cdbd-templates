# 시안 검수 체크리스트 (정본) — 결함 26종 + 함정 4종

> **왜 이 문서가 있나** — 이 결함들은 *한 번 고치면 끝나는 실수*가 아니라 **조립(D2)·통일(D3)·무드(D4) 단계에서 매번 다시 생기는 것**들이다. 그리고 **눈으로 한 섹션씩 보면 대부분 못 잡는다.** 완료 보고 전에 **재귀 walk 스크립트로 전수 검사**하는 것이 유일하게 작동한 방법이다.
>
> 📌 **사용법** — 완료 보고 직전 A~G를 순서대로 1회 돌린다. 각 항목의 「탐지」를 그대로 코드로 옮기면 된다. H(자동화 함정)는 작업 *중* 지켜야 하는 것이라 먼저 읽는다.
>
> 🔗 요약판·진입점 = [[../CLAUDE.md]] 「페이지 완성 전 최종 검수」

## A. 구조

### ① 모든 페이지에 「히어로」가 있어야 한다
[[1-12. 조립 레시피 (제안 초안)]] 공통 골격의 **필수★** 항목.

- **판정** — 프레임 자식 중 이름이 `히어로*`인 섹션이 없으면 위반.
- **흔한 원인 2가지**
  - 히어로인데 **이름이 `Frame 48097695`** (프리셋 라이브러리에도 이 이름으로 있음) → **이름만 `히어로-{스타일}`로**.
  - **프로필·명함·포트폴리오·이력서(주제 2-①~2-④)** — 이 유형은 **프로필이 히어로를 겸한다**. 프로필 위에 별도 히어로를 얹지 말고 **그 섹션 자체를 히어로로** 취급하고 이름도 `히어로-{스타일} (프로필형)`.
- ⚠️ **히어로급 스케일 확인** — 3안 사이에서 프로필 이름 크기가 어긋나면(미니멀·볼드 22px인데 에디토리얼만 18px) **형제 안의 값으로 맞춘다**(형제에 실재하는 값이므로 창작 아님).
- 🐛 실측 16건.

### ② 히어로가 최상단 콘텐츠 섹션이어야 한다
- **판정** — 헤더(`헤더*`·`0 헤더`)를 건너뛴 뒤 **첫 섹션이 히어로가 아니면** 위반.
- 🚫 **eyebrow(조직명·주최처)를 히어로 밖의 별도 타이틀 카드(특히 pill)로 빼지 말 것** → 히어로 안 첫 줄로 넣는다.
- 🐛 실측 1건(5-①-볼드: `봉곡상가번영회` pill 타이틀이 히어로 위에 있었음).

### ③ 근거 섹션 없는 CTA 버튼 금지
- **판정** — ⓐ같은 동작을 하는 버튼이 이미 페이지 아래에 있나 ⓑ그 버튼이 가리키는 내용 섹션이 페이지에 있나. 둘 다 아니면 **삭제**.
- 🐛 사례: 개업·오픈 안내에 메뉴·가격 섹션이 없는데 「가격 문의하기」 버튼만 중간에 놓이고, 하단 「전화하기」와 기능이 동일 → 삭제, 안내 문구만 유지.
- ⚠️ 삭제 후 **앞 섹션 마지막 카드에 하단 36 재부여**.

### ④ 주제별 「필수 사실 정보」 누락 검사
페이지의 주제가 요구하는 사실 정보가 **아예 빠져 있는지**를 본다. 디자인이 아무리 깔끔해도 이게 없으면 페이지가 제 일을 못 한다.

| 주제 | 없으면 안 되는 것 |
|---|---|
| 매장·상점(3-①·3-②·1-③) | **영업일시(요일+시간)** · 위치 · 연락처 |
| 행사(1-①·1-②) | 일시 · 장소 · 참석 회신 방법 |
| 예약(1-④) | 회차·시간 · 가격 · 취소 규정 |
| 판매(4-①·4-④) | 가격 · 배송·교환·환불 |
| 모집·접수(5-①·5-②·5-⑤) | 마감일 · 자격 · 제출 방법 |

- 🐛 사례: 3-② 미용실 **가격표 페이지에 영업시간이 아예 없었음**(가격만큼 자주 묻는 정보) → 3안 모두에 「문 여는 시간」 섹션 추가.

## B. 여백

### ⑤ 외부 여백이 내부 여백으로 새어 들어감
- **원칙** — **배경(틴트·솔리드)이나 테두리를 가진 「보이는 박스」는 상하 내부 여백이 대칭(원본값)**, **섹션 하단 36은 그 박스 바깥의 투명 래퍼(또는 투명한 섹션 프레임)** 가 갖는다.
- **원본 근거** — 문의 프리셋 = `버튼 래퍼 8/20/36/20`(투명) > `버튼 16/16/16/16`(채움·pill).
- **탐지** — `보이는 박스 && paddingBottom≥28 && pb−pt≥16`
- **수정** — 박스 pb를 형제 리듬값으로 내리고, 36을 바깥 래퍼(없으면 섹션 프레임)의 `paddingBottom`으로.
- ⚠️ **푸터는 예외** — 푸터 원본은 마지막 카드가 자기 `pb`(24)를 직접 갖는다.
- 🐛 실측 19건(문의 버튼 7·헤더 4·틴트 마지막 카드 8).

### ⑥ 푸터 첫 카드 상단 내부 여백 0
- **원본값** — 투명 푸터 **14** / 배경(틴트·솔리드) 있는 푸터 **20** (첫 카드가 이미지면 **30**) / 2단 카드 단독형 **12**.
- ⚠️ **구분선으로 시작하는 푸터는 구분선이 첫 카드라 정상**(오탐 주의). 중첩 래퍼(`12 푸터 > 푸터`)도 건너뛰고 실제 첫 카드를 봐야 한다.
- 🐛 실측 8건.

### ⑦ 같은 섹션 안 카드들의 좌우 여백 통일
- **판정** — 형제 카드가 20/32인데 **한 카드만 0**이면 형제 최빈값으로.
- **예외** — 풀블리드 이미지·갤러리·지도·구분선, 그리고 **폼(Q&A) 카드 내부의 질문 프레임**(바깥 Q&A 카드가 이미 패딩을 가짐).
- 🐛 실측 14건.

### ⑧ 🅰 카드 안 요소가 FIXED 폭이라 좌우 여백이 무효화됨
> *"여백값은 맞는데 왜 여백이 없어 보이지"* 의 **진짜 원인**인 경우가 많다. 여백을 의심하기 전에 이걸 먼저 본다.

- **증상** — 카드는 좌우 패딩이 있는데 **내부 텍스트가 `FIXED`로 카드 안쪽 폭보다 넓어**(예 카드 안쪽 316인데 텍스트 380) 글자가 패딩을 뚫고 나간다.
- **탐지** — `자식 width > 부모 width − 좌우 패딩`
- **수정** — 내부 텍스트를 **`FILL`**로.
- 🐛 실측 9건.

### ⑨ 섹션 마지막 카드 하단 = 36 고정
32·40으로 들쭉날쭉한 것이 **가장 자주 틀리는 지점**. 카드 삭제·추가 후 반드시 재확인.

## C. 색·채움

### ⑩ 동일 섹션에서 한 카드만 배경색 누락
- **증상** — 연속 틴트 패널을 이루는 섹션에서 **마지막 버튼 카드·갤러리 카드만 채움이 없어** 패널에 구멍이 생김.
- **수정** — 형제와 같은 틴트 적용. ⚠️ 채우는 김에 **⑤ 위반 주의** — 그 카드가 `pb36`을 갖고 있었다면 pb를 형제 리듬값으로 낮추고 36은 바깥 래퍼로.
- ⚠️ **섹션 타이틀 래퍼(`Frame 4809…` 류, 좌우 패딩 0)는 패널 구성원이 아니므로 제외**.
- 🐛 실측 11건.

### ⑪ Outlined 버튼 텍스트 색이 {배경색}
- 채움 버튼 규칙(텍스트={배경색})을 Outlined에 그대로 써서 **글자가 배경에 묻힌다**.
- **정답** — 채움=텍스트`{배경색}` · 틴트=텍스트`{버튼색}` · **Outlined=텍스트`{버튼색}`(=테두리색)**
- ⚠️ 테두리가 `{텍스트색}×20%` 같은 **옅은 선인 「테두리 텍스트 카드」는 버튼이 아니므로 대상 ❌**.
- 🐛 실측 2건.

### ⑫ 외곽선이 래퍼에 중복 적용
- 여백용 투명 래퍼와 실제 버튼이 **둘 다 같은 stroke**를 가져 이중 테두리·전폭 박스가 생김 → **래퍼 stroke 제거**.
- **탐지** — `부모·자식이 같은 색·두께 stroke`
- 🐛 실측 3건.

### ⑬ 무드가 콘텐츠·페르소나에 맞아야 한다
- 🚫 **B2B 제조·가공업에 럭셔리(딥네이비+골드)** → 프로페셔널(그래파이트 `#1E2226` + 스틸블루 `#4E8FA8`)
- 🚫 **동네 상점(미용실·반찬가게)에 페미닌/로맨틱(연핑크+딥로즈+명조)** → 내추럴(세이지 `#E9EDEC` + 틸 `#3F6B66`, 제목 본고딕)
- **판정 질문** — *"이 색·서체를 그 사장님이 자기 가게 간판에 쓸까?"*
- ⚠️ 무드 교체 시 **3안 명도 방향 분산(전부 라이트/전부 다크 ❌)과 액센트 hue 분산을 반드시 재확인**. 대비 2개(텍스트↔배경·버튼↔배경 각 ≥3.6)도 재계산.
- 🐛 실측 2건.

## D. 정렬

### ⑭ 🅰 텍스트 정렬은 「프리셋 원본」보다 「관계」로 정한다
정렬을 프리셋이 갖고 온 값 그대로 두지 말 것. **① 섹션 타이틀과의 관계 ② 섹션의 성격 ③ 위아래 섹션과의 관계**를 보고 결정한다.

- **좌정렬 타이틀(①③⑤⑩) → 본문도 좌정렬.** 🔓 예외 = **⑥ 좌18+「긴 구분선」**(전폭 선이 프레임 역할을 해 중앙 본문도 성립).
- **중앙 타이틀이어도 좌정렬이 맞는 본문이 있다** — **긴 문단 · 양끝정렬 표 행(라벨↔값) · 항목별 설명문**은 읽기가 우선. 중앙정렬은 **짧은 리드 문장·강조 문구**에만.
- **고정 예외(관계와 무관)** — Q&A 제목 = **중앙정렬 고정 스펙** · 버튼/메뉴/예약 텍스트 · 2열 값 셀(RIGHT) · 이모지·번호 셀 · 이미지 placeholder 라벨.
- 🐛 실측 37건.

### ⑮ 푸터 내 카드들의 좌우 정렬 통일
- 푸터 안에서 **SNS 아이콘 행만 중앙, 텍스트는 좌측** 같은 혼용 ❌ → 그 푸터의 **텍스트 정렬에 SNS 행을 맞춘다**(`primaryAxisAlignItems`).
- ⚠️ 로고 이미지 카드 안의 placeholder 라벨 정렬은 판정에서 제외(오탐).
- 🐛 실측 6건.

### ⑯ 2열 카드 = 「좌우 비율」과 「좌우 정렬」을 같이 본다
- **ⓐ 짧은 셀(이모지·번호·아이콘·짧은 라벨)이 FILL로 절반을 차지 ❌** → 짧은 셀 **HUG(또는 FIXED)** + 긴 셀 **FILL** + gap 12~16 · 긴 셀은 좌정렬.
- **ⓑ 양끝정렬 라벨↔값 행은 좌 LEFT + 우 RIGHT** — 값 셀이 LEFT면 가운데에 떠 보인다.
- **ⓒ 양끝정렬 라벨↔값 행의 값은 1행이어야 한다** — 2줄로 접히면 좌우 균형이 깨진다. 해결 = **짧은 셀 HUG로 값 셀 폭 확보**(ⓐ와 동일 처방) → 그래도 접히면 스택형(라벨↵값)으로.
  - ⚠️ **적용 범위 주의** — 이 1행 제한은 **양끝정렬 라벨↔값 행에만** 해당한다. **아이콘·불릿 + 설명문** 형태(`💡` + 긴 안내문)는 **여러 줄이 정상**이므로 대상 ❌. (실측 18건이 전부 이 정상 케이스였다)
- 🐛 실측 7건.

## E. 타이포그래피

### ⑰ 줄바꿈 고아(마지막 줄 1~2글자) 금지 — 자동 탐지법
폰트 원칙 #16의 **실행 가능한 검사법**.

- **탐지** — TEXT를 복제해 **마지막 2글자를 지운 뒤 높이가 줄면 = 마지막 줄이 2글자 이하 = 고아**.
- **교정** — 뒤에서 1~4개 **어절을 통째로** 다음 줄로 내리는 `\n`을 넣고, **전체 높이가 그대로인(줄 수가 안 늘어나는) 첫 후보**를 채택.
- ⚠️ **여백·글자 크기·폭을 바꾼 뒤에는 반드시 다시 돌린다** — 줄바꿈은 폭에 의존하므로 이전 통과가 무효가 된다. (실측: 1차 10건 → 여백·크기 수정 후 19건 재발생)
- ⚠️ 멀티런 텍스트는 `characters` 대입이 아니라 **`insertCharacters`/`deleteCharacters`** 로 고칠 것(H 참조).
- 🐛 실측 누적 30건.

### ⑱ 라벨+값 텍스트의 「런 무결성」
- **증상** — 한 텍스트 카드 안 `라벨 14px + 값 18px` 위계가 **전부 한 크기로 납작**해짐.
- **탐지** — `\n`을 포함하고 **스타일 세그먼트가 1개뿐**이며 첫 줄이 짧고(≤6자) 둘째 줄이 긴 텍스트 → 의심.
- ⚠️ 원인은 대부분 H의 「런 뭉갬」. **안내사항 항목처럼 원래 한 크기인 것도 있으니** 원본 프리셋과 대조 후 판정.
- 🐛 실측 2건.

## F. 콘텐츠

### ⑲ 🏪 매장·시설 운영 정보 = 「요일 + 시간」이 함께
**개업일(문 여는 날)만으로는 부족**하다. 손님이 알아야 하는 건 *"언제부터"* 가 아니라 ***"무슨 요일 몇 시에 가면 열려 있나"*** 다.

- 라벨은 `영업시간`이 아니라 **`영업일시`**, 값은 **`화–일 · 오전 10시 – 오후 8시`** 처럼 **요일 범위 + 시간**.
- ✅ 이미 충족으로 보는 경우 — `평일 08:30~18:00`(요일 포함) · 전시 `관람 시간 + 휴관 매주 월요일`(휴관일로 보완) · 숙박·캠핑 `입실/퇴실`(연중 운영이라 요일 개념 없음).
- 🐛 실측 3건(1-③ 3안).

### ⑳ 휴무일 = 「운영일」의 하위 항목 — 독립 행 ❌
투명도만 낮추는 걸로는 위계가 안 낮아진다. **독립 행에서 빼고 운영시간 값 바로 아래에 붙는 한 줄 부가 텍스트**(13px · {텍스트색}×70% · 라벨 폰트)로 넣는다.

| 원래 구조 | 처리 |
|---|---|
| 라벨+값 **한 카드**형 | 운영시간 카드 텍스트에 **3번째 줄 추가** 후 휴무 카드 삭제 |
| 라벨/값 **분리**형 | 운영시간 **값 카드에 줄 추가** 후 휴무 라벨·값 카드 **둘 다** 삭제 |
| **2단 카드**형 | 좌 셀에 `휴관  매주 월요일`로 통합, 우 셀 삭제, 카드 상단여백 0 |

- ⚠️ **휴무가 페이지 주제인 공지(휴관 안내)는 예외** — 그건 주인공이다.
- 🐛 실측 6건(1-③ 3안 + 6-③ 3안).

### ㉑ 🅷 히어로 헤드라인 = 「카피·제목」이지 「말 걸기」가 아니다
- 🚫 **질문형 ❌** — `오실 수 있으신가요?` · `~하시겠어요?`. 히어로 제목 자리에 물음표가 들어가면 제목이 아니라 대화문이 된다.
- ✅ **문장형이어도 단정형 카피로** — `초대합니다` · `참석해 주세요` · `자리에 초대합니다`
- **탐지** — 히어로에서 **가장 큰 텍스트에 `?`가 있으면 경고**
- 🐛 실측 3건.

### ㉒ 유저가 준 정보는 생략하지 않는다 — 3안 공통 콘텐츠
3안 중 한 안에만 SNS·연락처가 들어가 있으면 *"그 안만 넣기로 했다"*가 아니라 **정보를 받았는데 나머지 안이 빠뜨린 것**이다.

- **받은 정보는 3안 전부에 동일 반영** — 푸터 SNS 행 자체가 없으면 **행을 만들어 추가**.
- **탐지** — 주제별로 `SNS Icon` 인스턴스의 variant(`Type=`) 집합과 문의 버튼의 채널 집합을 3안 비교.
- ✅ **허용되는 차이** — 가로 2단 버튼의 압축 표기(`Call`·`Kakao`·`Email`) · **프리셋을 다르게 쓰는 것**(같은 내용이 「나열」과 「문의」 프리셋에 각각 담겨도 정상) · 폭이 좁아 문구를 줄인 경우.
- **통일 대상은 「어떤 정보가 있는가」**이지 라벨·프리셋 선택이 아니다.
- 🐛 실측 3주제 + 1주제(SNS 행 신설).

## G. CdBd 재현성

### ㉓ 갤러리 인디케이터 = CdBd 실제 디자인만
- **8px 원형 닷 · gap 8 · 중앙정렬 · 첫 닷 {버튼색} 100% / 나머지 10%**
- 🚫 **FILL로 늘어난 「막대(progress bar)」형 ❌** — CdBd에 없는 UI = 4단계 재현 불가.
- 🐛 실측 3건(폭 77~105px 막대).

### ㉔ pill 타이틀 ✕ 원형 버튼 나열 = 금지
- pill 섹션 타이틀(⑧) **바로 아래**가 원형(pill) 버튼 나열 섹션이면 타이틀이 버튼처럼 보여 위계가 무너진다 → **타이틀을 지우고 「구분선」 카드로 대체**(문의 섹션은 대개 최하단이라 「최하단 영역 경계선」 예외에 해당).
- **구분선 스펙** — `구분선 프레임 pad 10/20/10/20` + `1px 라인`, 색 = **{버튼색}×40%(밝은 배경) / ×50%(다크)**, **배경 채움은 형제 섹션 카드와 동일하게**.
- ⚠️ 판정은 **바로 다음 형제**로 — 원형 프로필 이미지·지도 버튼 1개는 해당 ❌.
- 🐛 실측 3건.

### ㉕ 구분선 있는 섹션 타이틀 + 본문 구분선 = 중복
- 타이틀 프리셋이 이미 선을 갖고 있으면(⑤⑥⑦⑨) **본문 섹션의 구분선 카드는 생략**(선 언어가 두 번).
- 제거 시 **마지막 구분선이 갖고 있던 하단 36은 앞 카드로 이관**.
- ⚠️ 타이틀 안 구분선 노드 이름이 `Rectangle 1`이 아닐 수 있으니 **`구분선` 이름으로 탐지** · **중첩 그룹(`N 이름`) 안까지 재귀**.
- 🐛 실측 5건.

### ㉖ 원페이지 시안에 헤더 우측 「메뉴 아이콘」 ❌
- 헤더 2단 카드의 우측 햄버거/메뉴 아이콘은 **멀티페이지에서 목차로 이동하는 장치**다. 원페이지엔 갈 곳이 없다.
- **수정** — 아이콘 노드 삭제(좌측 브랜드/로고 셀이 FILL이라 그대로 채워짐).
- 🐛 실측 21건.

## H. 🧨 Figma 자동화 함정 — 실제로 밟은 것

> 이 셋은 **검수가 아니라 작업 중 지켜야 하는 것**이다. 셋 다 조용히(에러 없이) 산출물을 망가뜨린다.

### ㉗ 멀티런 텍스트에 `characters`를 통째로 대입하면 런 스타일이 전멸한다
```js
t.characters = t.characters + '\n' + 추가문구   // ❌ 라벨14+값18 → 전부 14px
```
- ✅ **줄 추가는 `insertCharacters(index, text)`** (주변 스타일 보존)
- ✅ 또는 **세그먼트를 미리 덤프해두고 대입 후 `setRangeFontName/FontSize/Fills/LineHeight`로 전 구간 재적용**
- 🐛 사례: 1-③ 미니멀·볼드의 `영업시간` 값이 18→14px로 뭉개진 걸 나중에야 발견.

### ㉘ 측정용 복제본을 「원본과 같은 오토레이아웃 부모」에 붙이면 원본 폭이 바뀐다
- 가로(HORIZONTAL) 부모에 자식을 하나 더 넣으면 `FILL` 자식들의 폭이 재분배되어 **원본 높이·줄바꿈이 달라지고 측정이 전부 틀린다.**
- ✅ 복제본은 **페이지에 붙이고 화면 밖(예 `-9000,-9000`)으로 보낸 뒤** `textAutoResize='HEIGHT'` + `resize(원본폭, h)`로 **격리 측정**. 측정 후 **반드시 제거**(잔존 복제본 스윕 포함).

### ㉙ `figma.group()` + `ungroup()`으로 스크린샷 찍지 말 것
- 오토레이아웃 안에서 앞쪽 카드 몇 개를 임시 그룹으로 묶었다 풀면 **그 카드들이 맨 뒤로 밀려** 헤더·히어로가 페이지 하단으로 간다.
- ✅ 부분 확인이 필요하면 **해당 섹션 노드 자체에 `await node.screenshot()`** (그룹 금지).
- 🐛 사례: 3-①·3-②-에디토리얼 두 시안의 섹션 순서가 통째로 뒤집힘.

### ㉚ `use_figma`는 트랜잭션이다 — 중간에 throw하면 **전부 롤백**
- 폰트 미로드로 마지막 줄에서 실패하면 **앞의 성공한 수정도 전부 사라진다.** 실패 후에는 **적용 여부를 반드시 재확인**하고 다시 돌린다.
- 예방 = 텍스트 관련 mutate 전에 **그 노드의 현재 폰트를 전부 `loadFontAsync`** (`getStyledTextSegments(['fontName'])` 순회).
