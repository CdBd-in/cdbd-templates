## 🎯 카드 매칭 핵심 결정 원칙

콘텐츠 의도를 카드에 매핑하기 전, 다음 3가지 질문으로 후보를 좁힌다.

1. **카드의 default 기능이 그 의도와 일치하는가?** (지도 → 위치 안내, 영상 → 유튜브, 예약 슬롯 → 예약, 폼 입력 → Q&A) — 일치하면 그 카드. 디자인으로 흉내내지 말 것.
2. **편집 단위가 얼마인가?** — 텍스트 한 줄이면 텍스트 1장, 사진 여러 장을 묶음으로 보여주려면 갤러리.
3. **사용자가 같은 패턴을 반복 복제할 가능성이 있는가?** — 있다면 텍스트 카드 한 줄 = 한 속성 원칙 (작업 원칙 #2).

> ⚠️ **카드 라벨 ≠ 카드 타입**. 라벨은 자유텍스트, 타입은 고정(기본 14종 + 2열 6종). 동일 라벨이 여러 타입에 걸칠 수 있고 (예: 라벨 "이미지" → 갤러리·이미지·프로필 카드 어디든), 동일 콘텐츠 의도라도 디자인 의도에 따라 선택지가 달라짐.

### 🚫 카드 default 기능 — 디자인에서 다시 만들지 말 것

위 원칙 #1의 적용 기준. 아래 항목들은 카드의 기본 기능이지 디자이너의 시각 선택이 아님. **시안·에디터에서 별도로 그리거나 강조 장치로 추가하지 말 것** (사용자가 받는 가치 = "카드 그대로 갖다 쓰면 동작함"). 신규 템플릿 노트의 "반복되는 디자인 요소"에도 적지 말 것.

| 카드 종류 | default 기능 (재현 ❌) |
|---|---|
| **유튜브** | 영상 임베드, 플레이 버튼, 썸네일 |
| **위치 안내** | 지도 임베드, 핀 마커 |
| **Q&A** | 필수 별표, placeholder, 체크박스/라디오 모양 |
| **예약** | 예약 위젯 UI, 캘린더, 옵션 선택기 |
| **갤러리** | 기본 그리드 자체 (단, 그리드 vs 캐러셀 vs 나열 선택은 디자인) |
| **SNS** | SNS 아이콘 세트 |
| **메뉴** | 탭 네비 구조 |
| **프로필 카드** | 사진+이름+소개 기본 구조 (단, 원형/풀블리드 등 모양 선택은 디자인) |
| **멀티페이지** | 페이지 인디케이터 도트 |
| **CTA 버튼 반복 자체** | 비즈니스 페이지는 버튼이 여러 개 반복되는 게 당연. "반복" 자체는 디자인 통일성이 아님 |

**반대로 = 실제 디자인 선택** (여기서 결정): 컬러 / 모서리 / 보더 / 그라데이션 · 풀블리드·박스·강조 색면으로 감싸기 · 사진 후처리 통일(B&W·빛바램, 교체 이미지 전제) · 타이포 페어링 · 갤러리 표현(그리드/캐러셀/나열) · 프로필·이미지 모양(원형/풀블리드).

> ⛔ **편집 불가 장식(팬텀) 배제** — 점선·골드 라인·노치·형광펜·다이아몬드 마커 같은 사용자가 못 바꾸는 장식 ❌ (작업 원칙 #5). 강조는 헤드라인 포인트 컬러(`{버튼색}`)·섹션 강조 배경(`{버튼색}×N%`)·텍스트 위계로. 단 로고/프로필처럼 **교체 가능 이미지는 OK**.

> 🚫 **이미지 그라데이션·이미지 위 텍스트 오버레이 = CdBd 불가 (필수, 2026-07-23 이선호 지시)** — 위 「그라데이션」은 **카드 배경/색면**에 한한 얘기이고, **이미지 카드에는 ① 그라데이션(스크림) 오버레이를 입힐 수 없고 ② 이미지 위 특정 영역에 텍스트를 얹을 수 없다**(이미지는 독립 카드, 텍스트는 별도 카드). 그래서 **풀블리드 히어로/상품컷 위에 제목·가격·카피를 겹치는 시안 ❌** → **이미지 카드 + 아래(또는 위) 별도 텍스트 카드 스택**으로 재현. 스크림은 겹친 글자 가독성용이라 오버레이를 없애면 **불필요**(삭제). 어두운 이미지 위에서만 읽히던 밝은 글자색은 **아래 페이지 배경에서도 대비 ≥3.6:1**인지 재확인. 사례: C①-볼드 구매 시안(히어로+상품 3컷) 스크림+오버레이 → 이미지+아래 텍스트로 전면 교체. 정본: [[../CLAUDE.md]] 🧩 생성 시안 ⑦.

### 🔲 둥근 모서리 카드 — 1 카드 = 1 콘텐츠 타입

**핵심**: 카드에 둥근 모서리 배경을 적용한 순간, **이 카드 하나로 의미가 완결되는 단일 콘텐츠**가 되어야 한다. 둥근 배경은 시각적으로 "닫힌 영역"을 만들기 때문.

#### ❌ 위배 케이스 (둥근 카드 안에 여러 콘텐츠 타입 혼합)
- 한 둥근 배경 안에 **이미지 + 텍스트** (예: 로고 + 워드마크)
- 한 둥근 배경 안에 **텍스트 + 버튼** (예: 출석 등록 안내 + 출석 등록 버튼)
- 한 둥근 배경 안의 **별도 내부 박스가 다른 padding**으로 풀-블리드 (예: 지도 박스가 카드 padding 무시)

#### ✅ 올바른 처리

| 의도 | 처리 방법 |
|---|---|
| **한 섹션의 여러 카드를 묶어 보이게** (예: 출석 등록 = 안내 텍스트 + 등록 버튼) | 관련 카드들의 **배경을 모두 비움**(`fills: []`). 카드 간 간격만으로 자연스러운 그룹 형성 |
| **다음 섹션과 분리해 보이게** (예: 출석 등록 vs 주최측 문의) | 섹션 마지막 액션 카드 또는 분리할 카드 한 쪽에 **배경/외곽선 적용**, 또는 사이에 **구분선/여백 카드** 삽입 |
| **카드 안에 보조 영역**(지도·이미지 박스 등) | 카드의 padding 안에 둠 (`layoutSizingHorizontal: FILL`). 풀-블리드 ❌ |

#### 🔄 각진 모서리(0px)의 예외
각진 모서리는 시각적으로 "열린" 형태 → 인접 카드와 **이어진 것처럼** 표현 가능. 텍스트 + 버튼을 시각적으로 한 덩어리로 보여주고 싶을 때는 둘 다 각진 0px로.

#### 🧭 판단 흐름
> "이 카드 안의 모든 요소가 같은 콘텐츠 타입인가?" → No → **둥근 배경 ❌** (배경 빼거나 카드 분리)

## 🔲 Outlined 버튼 만들기 (CdBd 전용 패턴, 2026-06-19 기록)

> **CdBd 버튼 디자인에는 outlined/ghost 옵션이 없다.** Outlined 효과는 **카드 디자인**으로만 만든다.

### 핵심 룰
1. **버튼 색상 = 페이지 배경색** (커스텀 컬러 픽커에서 hex 입력) → 버튼 fill이 페이지에 묻혀 transparent처럼 보임
2. **버튼 텍스트 색 = 카드 테두리 색** (예: 페이지 텍스트 색 `#FFFFFE`)
3. **카드 디자인 > 테두리** — **색상 + 두께 슬라이더 모두 설정** (두께 0이면 invisible. 보통 1~2px)

### 크기 조절 (outlined 버튼 전용)
| 방향 | 조정 위치 | 비고 |
|---|---|---|
| **세로** | 버튼 디자인 > 세로 (1=4px 각 측) | 내부여백 0으로 두고 버튼 세로만으로 조정. 예: Figma py-14 → 버튼 세로 = 3 (= 12px) |
| **가로** | 카드 디자인 > **좌우 외부여백** | 버튼 가로 ❌ (가로를 줄이면 테두리는 그대로고 버튼만 작아져 어색) |
| **내부여백** | **0** 유지 | outlined에서 내부여백은 card border ↔ button 공간을 만들어 어색함. button이 card에 꽉 차야 outline = button 가장자리 정합 |

**Figma는 페이지 자체에 `px-N` 적용** (오토레이아웃 wrapper). **CdBd 페이지에는 default padding이 없음** → 각 카드의 **좌우 외부여백**으로 같은 효과 만들어야 함.

예: Figma 페이지 `px-[20px]` → CdBd 각 카드 `외부여백 좌=20, 우=20`

### 종합 매핑 (Figma 오토레이아웃 → CdBd 외부여백)

### Spacer 카드 — Figma `h-[16px]` 빈 공간 매핑 (2026-06-19 추가)
Figma "여백 — 섹션 구분" 같은 `h-[16px]` 빈 div는 그룹간 시각 분리용. CdBd에서는 **구분선 카드 두께 0 + 내부여백** 으로 구현.

**구현** (2026-06-19 사용자 검증):
1. + 카드 추가하기 → 구분선 카드 선택
2. 우측 패널 두께(첫 슬라이더) → **0** (보이지 않는 선)
3. 구분선 옵션 **상하여백 → 0** (단위가 큼: 1=10px 각 측, max 4=80px)
4. 카드 디자인 **내부여백 → N** (1=1px 각 측, Figma h-16이면 8 = 8px 각 측 = 총 16px)

**CdBd 구분선 카드 슬라이더 단위 (2026-06-19 사용자 정정)**:
- **두께**: 1 = 1px (선 굵기)
- **상하여백** (구분선 옵션): **1 = 10px 각 측** ⚠️ — max 4 = 80px 각 측 (매우 큼!)
- **카드 내부여백**: 1 = 1px 각 측 (보통 사용)
- **카드 외부여백**: 1 = 1px 각 측

권장: spacer 카드 만들 때 **상하여백 0** + **내부여백으로 미세 조정**.

**dnd-kit 자동화로 추가 후 위치 이동 가능** (1-4-1 dnd-kit 패턴 참조).

### ⚠️ 비다크 카드 (배경/테두리 없음)의 내부여백 = 0 권장 (2026-06-19 사용자 룰)
**배경/테두리 없는 카드는 내부여백이 시각적으로 의미 없음** — 외부여백과 합산되어 padding 중복.

| 카드 종류 | 내부여백 | 외부여백 |
|---|---|---|
| 다크 (배경 #222226) | 사용 (24/20 등) — 카드 내부 콘텐츠 여유 | wrap padding (8/20 등) |
| 비다크 (배경 없음) | **0** — 외부여백만으로 시각 위치 결정 | 페이지 padding 직접 매핑 |
| Outlined 버튼 (테두리 있음) | **0** — 카드 = 버튼 frame | 외부여백으로 가로 조정 |

**중복 사례**: 비다크 카드의 외부여백 좌우 40 + 내부여백 좌우 20 → 텍스트가 페이지 edge에서 60px 떨어짐 (Figma 40px 예상). 내부여백 0으로 reset 필요.

### 종합 매핑 (Figma 카드 내부 → CdBd 내부여백)
Figma 카드의 `px-N py-M` → CdBd 카드 디자인 > 내부여백 아코디언 분리 후 직접 매핑.

| Figma 표기 | CdBd 내부여백 |
|---|---|
| `px-20 py-24` | 상=24, 하=24, 좌=20, 우=20 |
| `p-20` | 상=20, 하=20, 좌=20, 우=20 (단일값으로도 OK) |
| `px-16 py-12` | 상=12, 하=12, 좌=16, 우=16 |

### Filled vs Outlined 매트릭스
| 속성 | Filled | Outlined |
|---|---|---|
| 배경 fill | 색상 swatch | 커스텀 픽커 = `{배경색}` |
| 테두리 | 없음 | 카드 디자인 > 테두리 (색 + 두께) |
| 텍스트 색 | `{텍스트색}` default | 테두리 색과 동일 |
| 가로 크기 | 버튼 디자인 > 가로 | 카드 외부여백 |
| 세로 크기 | 버튼 디자인 > 세로 | 버튼 세로 + 카드 외부여백 |

### Outlined ↔ Filled 버튼 가로 통일 룰 (2026-06-19 추가)
**페이지 안에 outlined + filled 버튼 섞일 때 visible width를 같게 매칭**:
- Filled 버튼(다크 카드 안): width ≈ 페이지 너비 - 외부여백 좌우 - 다크 카드 내부여백 좌우 - 버튼 내부 padding × 2
- Outlined 버튼 카드(단독): width ≈ 페이지 너비 - 외부여백 좌우
- 두 width 같게 하려면 outlined 카드의 **외부여백 좌우 = 다른 카드의 외부여백 + 내부여백** 합산값
- 예: 다른 카드 외부여백 20 + 내부여백 20 → outlined 외부여백 좌우 **40**
- T-NEW1 사례: 신청하기 284px, 출석 등록 284px → 인사팀 outlined 외부여백 좌우 59~60 으로 매칭

### 예약(reservation) 카드 — 내재 padding 주의 (2026-06-19 추가)
**예약 카드는 inherent inner padding이 있음** — 카드 외부여백 좌우 + **카드 내부여백** 둘 다 적용되면 button width 작아짐.

**🥇 권장 패턴: 한쪽 여백만 사용** (2026-06-19 사용자 룰)
- 배경/테두리 없는 카드 (예약 카드 포함)는 **내부여백 = 0** 으로 통일
- **외부여백 좌우만으로** button width 조정 (인사팀 outlined 패턴과 동일)
- 인사팀과 예약 둘 다 같은 방식 = 일관성 ↑

**T-NEW1 검증 (이중여백 → 단일여백 정리)**:
- Before: 외부여백 40/40 + 내부여백 20 → button width 244 (작음)
- After: 외부여백 40/40 + **내부여백 0** → button width 284 ✓ (다른 버튼과 매칭)

**룰**: 외부여백 좌우 = 다른 버튼 카드의 외부여백 좌우와 **같은 값**으로 통일 (내부여백 0 전제).

### 색상은 **테마 변수 그대로** 사용
- 피그마 `#FFFFFE @ opacity-N%` 같은 표기 → **opacity 무시하고 `{텍스트색}` (예: `#FFFFFE`) 그대로 입력**
- 이유: CdBd는 사용자가 테마를 한 번에 교체할 수 있어야 하는 템플릿. opacity-blended effective color(`#DCDCDC` 등)를 적으면 **테마 교체 시 따라오지 않음**. 시안 단계에서 미세한 톤 매칭을 위해 hex를 적는 것은 **편집 용이성 원칙 위배**.

### 보조 텍스트 투명도 — CdBd Alpha 채널 활용 (2026-06-19 추가)
**Figma의 `#FFFFFE @ opacity-N%` 표기를 CdBd로 정확 매칭**:
- 카드별 텍스트 색상은 page theme `{텍스트색}` 변수를 그대로 쓰는 게 default
- 보조/캡션 텍스트는 hex `#FFFFFE`(테마 텍스트색) 유지 + **Alpha 슬라이더(0-100)로 투명도 적용**
- 테마 교체 시 색상은 따라오지 않지만, 시각적 weight 차별화가 design intent이면 alpha는 OK
- 색상 픽커 dialog 안에서 **hex + alpha 둘 다 명시 입력** (alpha만 변경 시 hex가 default로 reset되는 버그 — 1-4-1 함정 19 참조)

| 피그마 표기 | CdBd 입력 |
|---|---|
| `#FFFFFE` 단순 | hex `FFFFFE` + alpha `100` |
| `#FFFFFE @ opacity-85` | hex `FFFFFE` + alpha `85` (예: 본문 강조) |
| `#FFFFFE @ opacity-75` | hex `FFFFFE` + alpha `75` (예: 안내 캡션) |
| `#FFFFFE @ opacity-50` | hex `FFFFFE` + alpha `50` (예: 보조 슬로건) |

### 자동화 시퀀스 (검증됨)
```js
// 1. 버튼 카드 선택 (label-value 매칭)
// 2. 버튼 디자인 > 색상 > 6번째 swatch (커스텀 픽커 — 체크무늬 ring 모양 div) 클릭
// 3. z-9999 dialog의 첫 input(=hex) 찾고 fill
const picker = document.querySelector("div.z-\\[9999\\]");
const hex = picker.querySelectorAll("input")[0];
hex.id = "__hex_temp";
// $B click "#__picker_outer"  (cursor-pointer DIV에 id 부여 후 $B click — JS click은 React 이벤트 미발화)
// $B fill "#__hex_temp" "16161A"
hex.dispatchEvent(new Event("input", {bubbles: true}));
hex.dispatchEvent(new Event("change", {bubbles: true}));

// 4. 테두리 두께 slider native setter로 0 → 1
const slider = [...document.querySelectorAll("input[type=range]")].find(i => /* 테두리 라벨 근처 y */);
Object.getOwnPropertyDescriptor(HTMLInputElement.prototype, "value").set.call(slider, "1");
slider.dispatchEvent(new Event("input", {bubbles: true}));
slider.dispatchEvent(new Event("change", {bubbles: true}));
```

### 함정
- 색상 swatch 6번째는 **커스텀 컬러 픽커**(체크무늬 ring 모양)이지 outlined 토글 아님. CdBd에는 outlined 토글 자체가 없음.
- 테두리 두께가 0이면 색만 바꿔도 안 보임. **두께 슬라이더 필수**.
- 픽커 다이얼로그 열기는 `el.click()` 만으론 안 됨 — `$B click` (Playwright native) 필요. 1회만 id 부여 후 click.

- CdBd는 Bold ON(700) / OFF(400) 토글만 지원
- 피그마 SemiBold/Bold → Bold ON
- 피그마 Regular/Light → Bold OFF

## 📐 Figma ↔ CdBd 여백·Auto Layout 정합 (2026-07-10 이관)

> [[1-1. 워크플로우]] 3단계(Figma 반입·수정)에서 시안을 CdBd-legal로 만들 때 적용.
> **출처**: 옛 `1-0. 템플릿 기획 워크플로우` 2단계 (파일 삭제 시 살려온 규칙 · [[../CLAUDE.md]] "Figma↔CdBd 정합(여백·평탄화)은 1-6-2" 지시에 따름).
> ⚠️ 옛 문서의 "피그마 수작업 스켈레톤" 절차 자체는 폐기됨 — **여백·구조 매핑 규칙만** 유효.

#### 📐 Auto Layout 구조 규칙 (필수) — CdBd 카드 내부/외부 여백과 1:1 매핑

피그마 시안을 CdBd로 쉽게 옮기기 위해, **피그마 Auto Layout 속성이 CdBd 카드 옵션과 동일하게** 작동하도록 구조를 잡는다.

##### 페이지·카드 구조

| 레이어 | Auto Layout 설정 | 매핑 |
|---|---|---|
| **페이지 프레임** | `vertical` · `gap=0` · `padding=0` | CdBd는 페이지 자체에 패딩·gap 옵션 없음 |
| **카드 (페이지 직접 자식)** | `vertical`로 페이지에 쌓임 · 카드 간 gap=0 | CdBd 카드 보드 배치와 동일 |
| **카드 내부 여백** | 카드 프레임 자체에 `padding` 추가 | = CdBd 「카드 내부여백」 슬라이더 (0~40, 2단위) |
| **카드 외부 여백** | 카드를 **부모 Auto Layout 프레임으로 한 번 더 감싸고** 부모 프레임에 `padding` 추가 | = CdBd 「카드 외부여백」 슬라이더 (0~40, 2단위) |

##### 카드 간 여백 처리

- **상하 여백 조정** — 인접 카드의 외부여백 padding을 조정
- **여백 카드 삽입** — 빈 프레임(혹은 구분선 카드 두께 0) 사용
- ❌ **페이지 gap 사용 금지** — CdBd는 페이지 gap 옵션이 없으므로 4단계에서 재현 불가
- ❌ **카드 사이 임의 spacer 컴포넌트 금지**

##### 금지 사항

| ❌ 하지 말 것 | 이유 |
|---|---|
| 카드 자체에 margin 추가 (피그마는 margin 개념 없음, gap으로 흉내) | CdBd 외부여백과 매핑 안 됨 → wrapper 프레임 padding 방식만 사용 |
| 페이지 프레임에 padding 적용 | CdBd 페이지 자체에 padding 옵션 없음 |
| 페이지 프레임 gap 사용 (예: gap=16) | CdBd 페이지 gap 없음 → 카드별 외부여백으로 분산 표현 |
| 카드 외부에 절대 위치 요소 | CdBd는 absolute positioning 불가 |
| 한 카드 안에 자식 frame을 manual position | 모든 카드 내부 구조도 Auto Layout |

#### 예시

```
✅ 올바른 구조
페이지 프레임 (vertical, gap=0, padding=0)
├─ 카드1 wrapper (padding 16 = 외부여백 16)
│  └─ 카드1 (padding 20 = 내부여백 20)  ← 텍스트 카드
├─ 카드2 wrapper (padding 0 = 외부여백 0)
│  └─ 카드2 (padding 24 = 내부여백 24)  ← 이미지 카드
└─ 여백 카드 (높이 32, 빈 프레임)
   └─ 카드3 wrapper (padding 16)
      └─ 카드3 (padding 20)
```

> **목적**: 4단계 CdBd 에디터로 옮길 때, 피그마 frame padding 값을 그대로 CdBd 카드 내부/외부 여백 슬라이더에 입력하면 1:1 재현됨.

#### 🎯 단일 depth 예외 — 배경·테두리 없는 카드 (필수)

**배경(fill)도 테두리(stroke)도 없는 카드는 wrapper를 만들지 말 것.** 카드 자체 단일 depth에만 padding을 부여하고, **CdBd 에디터에서는 "카드 내부여백" 슬라이더 1개로 관리**한다 (외부여백 0).

#### 이유

- 배경·테두리가 없으면 시각적으로 "카드 안과 밖"의 경계가 보이지 않음 → 내부여백과 외부여백이 시각적으로 구분 불가
- 사용자가 두 군데(외부+내부)에서 같은 시각 효과를 위해 여백을 조정해야 한다면 의미 없는 작업 → 단일 슬라이더로 통합 관리
- 5대 원칙 #1(범용성·편집 용이성)에 직결

#### 적용 매트릭스

| 카드 유형 | 피그마 구조 | CdBd 매핑 |
|---|---|---|
| **배경/테두리 없음** (대부분의 텍스트·이미지·버튼 카드) | 카드(단일 depth) — `padding`만 | "카드 내부여백" 슬라이더 1개 |
| **배경 또는 테두리 있음** (카드 배경 색 / outlined 카드 등) | wrapper(외부) → 카드(내부) — 두 depth | "외부여백" + "내부여백" 2개 슬라이더 |

#### 합쳐진 padding이 슬라이더 max를 초과할 때

- CdBd 슬라이더는 0~40px 범위 (2단위) → 합친 padding이 40을 초과하면 **40으로 cap**
- 시각적으로 더 큰 여백이 필요하면 **여백 카드(빈 프레임)** 를 인접에 삽입해서 분산
- 예: 첫 카드 padding-top 60 → 카드 padding-top 40 + 위에 높이 20 빈 프레임 카드 추가

#### 변환 예시 (배경 없는 카드 collapse)

```
변환 전 (두 depth):
페이지 (gap=0, padding=0)
├─ wrapper (padding-top=8, bottom=8, l=20, r=20)
│  └─ 텍스트 카드 (padding-top=12, bottom=12, l=20, r=20, bg❌)

변환 후 (단일 depth):
페이지 (gap=0, padding=0)
└─ 텍스트 카드 (padding-top=20, bottom=20, l=40, r=40, bg❌)
   ↑ wrapper padding + card padding 합산, max 40 cap
```

> **목적**: 사용자가 CdBd 에디터에서 한 슬라이더만 만지면 되도록 — 시각적으로 의미 없는 외부/내부 구분을 강제하지 않음.

#### 📐 여백 우선순위 규칙 (필수) — 카드 padding 우선, 여백 카드는 예외

**여백을 설정할 때는 우선순위에 따라 결정**:

1. **1순위 — 4면 비슷한 padding** (top≈bottom≈left≈right)
   - 카드 padding을 4면 모두 비슷한 값으로 설정 (예: (24, 24, 20, 20) · (14, 14, 20, 20) · (8, 8, 12, 12))
   - 인접 카드와의 시각 간격은 **두 카드의 인접 padding 합**으로 자연스럽게 형성
   - 별도 spacer 카드 ❌

2. **2순위 — top=bottom symmetric** (4면 비슷이 불가능할 때)
   - 4면을 똑같이 못 맞춰도 **상/하만큼은 동일하게** (예: (8, 8, 20, 20))
   - 이유: 카드 삭제 시 시각 균형 유지 (텍스트 카드 분리의 목적은 사용자가 필요 없는 카드를 **삭제**해서 템플릿을 쓸 수 있게 하기 위함)
   - 비대칭 사례 (top=20, bottom=4 같이) — 그 카드를 삭제하면 시각 균형 깨짐

3. **3순위 — 여백 카드 (예외)**
   - 위 두 가지로 표현 불가능할 때만 사용
   - 주된 용도: **intra-section tight spacing** (분할된 텍스트 카드 사이 4~8px) — padding 합으론 표현하기 어려운 미세 간격
   - 페이지 단위 큰 간격을 굳이 여백 카드로 표현 ❌ → 1순위로 해결

#### 「여백 카드」 정의 — 구분선 카드 두께 0

- **CdBd 에디터에서**: **구분선 카드**를 추가하고 **두께 0**으로 설정. 카드는 보이지 않지만 카드 외부여백만큼의 공간 확보. 카드 외부여백 슬라이더를 사용해 원하는 높이 조정.
- **피그마 시안에서**: 빈 Auto Layout 프레임 (`fills=[]`, padding=0, 고정 height) 사용. 네이밍 `여백 — {용도}` (예: `여백 — 분할 카드 사이`)
- **표준 height 권장값** (intra-section 용도, CdBd 외부여백 슬라이더 0~40 범위 내):
  - 분할 텍스트 카드 사이: **4~8**
  - 그룹 내 미세 분리: **8**

#### 🟢 예외 — 페이지 최상단·최하단 카드는 asymmetric 허용

**페이지의 첫 카드와 마지막 카드는 4면 비슷 규칙의 예외**. 이 위치엔 삭제될 인접 카드가 없어 균형이 깨질 위험이 없기 때문.

- **첫 카드(페이지 최상단)**: `padding-top`을 크게 줘도 됨. 페이지 상단 여백을 이 카드의 top padding으로 흡수 (별도 spacer 불필요).
- **마지막 카드(페이지 최하단)**: `padding-bottom`을 크게 줘도 됨. 페이지 하단 여백을 이 카드의 bottom padding으로 흡수.
- **표준 권장값**:
  - 첫 카드 padding-top: **24~40**
  - 마지막 카드 padding-bottom: **24~40**
- 중간 카드는 무조건 **1순위(4면 비슷) → 2순위(상/하 symmetric)** 우선 — 이 예외를 일반화하지 말 것.

```
✅ 1순위 (4면 비슷) 권장 패턴 — 모든 카드 padding으로 간격 해결, spacer 없음
페이지
├─ 프로필 카드 (padding 24/24/20/20)       ← top=24 페이지 상단 흡수 + bottom=24 인접 간격 흡수
├─ 일시 카드 (padding 14/14/20/20)         ← 4면 비슷 (14+14=28 → 이전 카드와 합쳐 38 시각 간격)
├─ 장소 카드 (padding 14/14/20/20)
├─ 갤러리 카드 (padding 14/14/20/20)
├─ ...
├─ 마지막 버튼 (padding 14/36/20/20)        ← bottom=36 페이지 하단 흡수
```

```
✅ 3순위 (여백 카드) 적용 예 — intra-section tight spacing
페이지
├─ ...
├─ 일시 카드 (padding 14/14/20/20)
├─ 여백 — 분할 카드 사이 (height 4)         ← intra-section 미세 분리만 spacer
├─ 장소 카드 (padding 14/14/20/20)
├─ ...
```

#### 변환 예시 (구버전 symmetric+spacer → 신버전 4면 비슷)

```
❌ 구버전 (spacer 남용)
페이지
├─ 프로필 카드 (padding 24/4/20/20)        ← bottom=4 (인접 spacer 의존)
├─ 여백 — 섹션 구분 (height 20)             ← 불필요한 spacer
├─ 일시 카드 (padding 4/4/20/20)            ← top/bottom=4 (spacer 의존)

✅ 신버전 (padding으로 흡수)
페이지
├─ 프로필 카드 (padding 24/24/20/20)       ← bottom=24 (spacer 흡수)
├─ 일시 카드 (padding 14/14/20/20)         ← 4면 비슷
```

> **이유 재강조**: 카드 단위 복제·삭제·재배치가 자유로워야 한다는 본 워크플로우의 5대 원칙 #1(범용성)에 직결. 카드는 항상 "자체로 시각 균형이 잡힌 단위" 여야 함. 4면 비슷 padding은 균형이 가장 잘 유지되는 패턴.

이유:
- 색·폰트 선정과 구조 검토를 **분리** → 스켈레톤 게이트에서는 "콘텐츠 흐름·카드 구성"에만 집중
- 디폴트 테마는 모든 무드에 중립 → 구조 평가 시 색이 판단 흐릴 일 없음
- 3단계에서 무드별 색·폰트 입혔을 때 디폴트 대비 변화량을 한눈에 확인 가능
