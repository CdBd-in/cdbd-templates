# 템플릿 상세 페이지 콘텐츠

사용자가 `/templates/{slug}` 상세 페이지에서 보게 될 정보 = **카탈로그 메타데이터**. 사용자가 "템플릿 사용하기" 버튼을 누르기 전에 마주하는 첫 인상.

> 실제 페이지 제작(에디터 작업)은 [[1-4. 에디터 페이지]] 참조.

## ✍️ 작성 원칙

### 카테고리 선택
- 5종 카탈로그 중 1개. 템플릿의 **주요 사용처**에 따라 결정.
- 두 카테고리 사이에서 망설인다면 → 사용자가 검색 시 어떤 키워드로 들어올지 기준으로 판단.

### 🆔 슬러그 명명 규칙

어드민 등록 시 슬러그는 **어드민 URL**에 그대로 노출됨.

- ✅ **영문 소문자 + 하이픈(-)만 사용**
- ❌ 한글·언더바(_)·점(.)·대문자·공백 모두 불가
  - 단, 기존 등록 슬러그(`buttery_moment`·`oak_table` 등)는 **그대로 유지** (호환성)
- ✅ 캠페인 의도를 **영문 직역**으로 짧게
  - 예: `attendance-full`, `recruit-rsvp`, `corporate-sales`
- 신규 등록 시 충돌 가능성 있으면 카테고리 약어를 prefix로 (선택)

> 출처: qna 카드 dossier §4 URL 정보 편집 페이지 제약과 정합.

### 제목 작성
- "**무엇을 위해, 무엇을 하는, 무엇이다**" 구조로 압축.
- 예: "프로모션 노출과 상담 신청으로 전환을 만드는 영업용 명함"
  - 무엇을 위해 = 프로모션 노출 + 상담 신청
  - 무엇을 하는 = 전환을 만드는
  - 무엇이다 = 영업용 명함

### 사용 성과
- **수치 포함** 권장 (예: 전환율 40%↑, 예약률 2배, 조회수 1.5만+).
- 추상적 표현 ❌ → "고객 만족도 상승" 대신 "재방문 의향 88%"

### 추천 대상 (2가지)
- 구체적인 페르소나로 작성. 직군/업종/상황 명시.
- 예: "오프라인 영업 빈도가 높은 보험설계사", "신규 고객 응대가 잦은 1인 살롱 원장님"

### 주요 기능 (2가지)
- 템플릿이 가진 **차별점**에 집중. "프로필이 있어요" 같은 당연한 기능 ❌
- 예: "QR 명함 저장으로 한 번 만나도 잊히지 않기", "프로모션 배너로 본업 상품 자연 노출하기"

## 🎨 썸네일 배경색 산정 룰 (정착 2026-06-18 / T01)

**썸네일(thumb)의 배경색은 페이지의 포인트 색상(보통 = 버튼색)에 dim 15%를 별도 색상 레이어로 얹어 만든다.** Dim 방향은 베이스 색상의 명도에 따라 결정:

| 베이스 HSL Lightness | Dim 방향 |
|---|---|
| **L ≥ 50** (밝음) | **Black dim 15%** → 약간 어둡게 |
| **L < 50** (어두움) | **White dim 15%** → 약간 밝게 |

**구현 (Figma)**:
```js
thumb.fills = [
  { type: 'SOLID', color: BASE },                                  // 베이스 (페이지 버튼색)
  { type: 'SOLID', color: { r: 0, g: 0, b: 0 }, opacity: 0.15 },   // dim (밝은 베이스면 black, 어두우면 white)
]
```

⚠️ **단일 SOLID로 pre-multiplied 값을 박지 말 것** — Figma 인스펙터에서 dim 레이어 존재가 보여야 사용자가 시각으로 검수 가능.

## 🃏 주요기능 아이콘 정책 (정착 2026-06-18 / T01)

**스타일**: **다크 라운드 컨테이너 (`rgb(0.12, 0.12, 0.13)`, radius 8) + WHITE 글리프** — 기존 템플릿(신제품 소개 [node 235:10965](https://www.figma.com/design/oi8zIHLfy59O5zV8aysqq4/CdBd-%ED%85%9C%ED%94%8C%EB%A6%BF-%EB%93%B1%EB%A1%9D?node-id=235-10965))과 동일.

### 우선순위
1. **1순위 — 카드 배지 (Block Icon)** ([Design System 13271:33703](https://www.figma.com/design/9GM1FagjqiyrQHyHLBGoFj/CdBd-Design-System?node-id=13271-33703)) — 22종(Profile/Image/QnA/Video/Map/Phone/Email/SNS/Gallery/Columns/Group/Star/Link/Code/Date/Reservation/Divider/Text/Text Title/Product/List/Image Title). 카드 타입에 정확히 1:1 대응될 때.

## 📐 주요기능 메인 이미지 디자인 가이드 (정착 2026-06-18 / T01)

단순 화면 캡처 ❌. 다음 3요소 조합 권장:

1. **모바일 mockup** — 핵심 카드 영역. 캡처 source의 aspect에 맞춰 자연스럽게:
   - 세로 긴 source (예: Q&A form 340×848): 180×290으로 FILL crop, 중요 영역이 가운데
   - 가로 짧은 source (예: 출석 등록 안내 340×196): 180×104로 FIT (= 정확히 source aspect → empty space 0)
   - **부모 프레임 height도 캡처 자식 + 패딩에 맞춰 줄임** — 일관성을 위해 360 너비 유지
   - Drop shadow + radius 14
2. **마커 (Marker)** — 핵심 액션(CTA 버튼·체크박스 그룹) 둘러싸기
   - 색상: **`#59A7FF`** (CdBd brand blue marker)
   - dashed stroke 2, dash pattern [5, 4]
   - 사각형(체크박스 그룹) 또는 pill(버튼) 모양 — 강조 대상 모양에 맞춤
3. **Floating callout 카드** — 흰색 카드(radius 12, drop shadow 12px blur)
   - 부가 설명, 알림 미리보기, 통계 표시 등
   - Connector line으로 마커와 연결 (#59A7FF dashed)
   - **실제 결과물 패턴 재현 권장** — 카톡 알림이면 KakaoTalk 알림톡 스타일(노란 헤더 `알림톡 도착` + 본문 + 회색 버튼), 데이터 시각화면 차트 미리보기 등. 실제 사용자가 받게 될 화면을 그대로 보여줄 것

### 캡처 dark base 레이어 (모던/시크 무드 등)
모바일 mockup의 source가 transparent fills를 가지면(페이지 bg에 의존) FILL/FIT에서 빈 영역이 보임. 해결:
```js
phone.fills = [
  { type: 'SOLID', color: { r: 0.086, g: 0.086, b: 0.102 } },  // 페이지 bg 색 (다크 무드)
  { type: 'IMAGE', scaleMode: 'FILL', imageHash: '...' },        // 캡처 이미지 위에 얹음
]
```
1순위: source 노드 자체에 임시 SOLID 추가 후 export → 복원 (1회용)
2순위: 위처럼 캡처 rect에 SOLID + IMAGE 두 레이어 (영구, 사용자가 인스펙터에서 검수 가능)

## 🗣 카피 톤 가이드 (정착 2026-06-18 / T01)

상세 페이지의 **사용 성과·본문·추천 대상은 리뷰 형식의 구어체**로 작성.

| 슬롯 | 톤 |
|---|---|
| 사용 성과 | "...됐어요 / ...줄었고요" 같은 1인 사용자 후기 톤 |
| 본문 | "...였어요 / ...하고 있어요" 사용자가 자신의 경험을 회상하듯 |
| 추천 대상 | 기호(·) 대신 자연어로 풀어 쓸 것. "...이라면 잘 맞아요" / "...에게 추천해요" |

❌ 영업 멘트 톤 ("...로 해소합니다", "...한 페이지에 묶어")
✅ 사용자 후기 톤 ("...만 되면 늘 야근이었어요", "...로 바꾸고 나서는...")
