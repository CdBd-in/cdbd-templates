## 2부 — 줄간격 정상화 (T-NEW1 + T-NEW2)

### 2-1. 문제
- CdBd 텍스트 카드의 줄간격 옵션은 **100% 시작, 10% 단위, 최대값 없음** (구버전 가이드의 `1.2/1.4/1.6/1.8/2.0` 기재는 오류).
- 피그마 텍스트 노드들은 `AUTO` 또는 `PERCENT 175%` 같은 10% 비배수 값을 가지고 있어 4단계 에디터에서 그대로 재현 불가.

### 2-2. 정규화 코드 (재사용 가능)
```js
// Figma plugin
const ratio = node.height / node.fontSize;
const target = Math.max(100, Math.round(ratio * 10) * 10);  // 10% 단위 snap, 최솟값 100
await figma.loadFontAsync(node.fontName);
node.lineHeight = { unit: 'PERCENT', value: target };
```

### 2-3. 결과
- T-NEW1(298:23) + T-NEW2(362:23) 합산 **209/209 텍스트** 줄간격 정합 (100, 110, 120…).
- 정정 대상: 26 `AUTO` + 3 `PERCENT 175%` = 29건.
- 카드 height 변화 미미 (<1%) → 카드 간 여백 추가 조정 불필요.

### 2-4. 가이드 정정
- [[../CLAUDE.md]]: `줄간격 (1.2/1.4/1.6/1.8/2.0)` → `**줄간격 (100·110·120·130·... %, 10% 단위, 최대값 없음)**`
- [[1-0. 템플릿 기획 워크플로우]] 옵션 표 row: `100·110·120·130·140·150·**160**(default 권장)·170·180·190·200·... %`

## 3부 — 여백 우선순위 원칙 진화

### 3-1. 결정 흐름 (라운드)
1. **R1 (이전 세션 정립)**: "상/하 symmetric 우선, 어쩔 수 없으면 spacer 카드". 그래서 프로필↔일시 간격 20을 (24,4,20,20) + spacer 20 + (4,4,20,20) 형태로 작성.
2. **R2 (이번 세션 사용자 피드백)**: "프로필↔일시 간격은 프로필 하단 여백으로 옮겨도 될 것 같아. **앞으로 여백 설정은 상하좌우 비슷하게 주되, 불가능한 경우만 예외적으로 구분선(여백) 카드 사용**"
3. **R3 (룰 진화)**: 3순위 규칙으로 재구성
   - **1순위 — 4면 비슷한 padding** (top≈bottom≈left≈right). 인접 카드 padding 합이 시각 간격 형성. spacer 카드 없음.
   - **2순위 — top=bottom symmetric** (4면 비슷이 불가능할 때만).
   - **3순위 — 여백 카드 (예외)**: intra-section 미세 분리(4~8) 같이 padding으론 표현 어려운 경우만.
   - **🟢 페이지 최상단/최하단 카드는 비대칭 padding OK** (인접 삭제 위험 없음 → page-top/bottom 흡수).

### 3-2. 변환 예시 (구버전 → 신버전)
| 케이스 | ❌ 구버전 (symmetric+spacer) | ✅ 신버전 (4면 비슷) |
|---|---|---|
| 프로필↔일시 (섹션 간 20 간격) | 프로필 (24,4,20,20) + spacer 20 + 일시 (4,4,20,20) | 프로필 (24,**24**,20,20) + 일시 (4,4,20,20) — spacer 제거, 프로필 bottom 흡수 |
| 페이지 첫 카드 (로고) | 페이지 top spacer 40 + 카드 (8,16,40,40) | 카드 (**40**,16,40,40) — 카드 top으로 흡수 |
| 페이지 마지막 카드 (버튼) | 카드 (12,8,40,40) + page bottom spacer 36 | 카드 (12,**36**,40,40) — 카드 bottom으로 흡수 |
| 분할 텍스트 카드 사이 (intra-section 4~8) | 카드1 (8,4,20,20) + 카드2 (4,8,20,20) ❌ 비대칭 | 카드1 (4,4,20,20) + **여백 카드 4** + 카드2 (4,4,20,20) — 예외적으로 spacer 허용 |

### 4-2. 카드 padding setter
```js
function setCardPadding(card, t, b, l, r) {
  card.paddingTop = t; card.paddingBottom = b;
  card.paddingLeft = l; card.paddingRight = r;
  card.itemSpacing = 0;
}
```

### 4-3. 여백 카드(spacer) — Figma 표현
```js
function makeSpacer(name, h, w) {
  const sp = figma.createFrame();
  sp.name = name;                  // e.g. "여백 — 섹션 구분"
  sp.fills = [];
  sp.layoutMode = 'VERTICAL';
  sp.paddingTop = sp.paddingBottom = sp.paddingLeft = sp.paddingRight = 0;
  sp.itemSpacing = 0;
  sp.primaryAxisSizingMode = 'FIXED';
  sp.counterAxisSizingMode = 'FIXED';
  sp.resize(w, h);
  return sp;
}
```

### 4-4. 텍스트 카드 split (한 카드 → 속성별 N개)

## 5부 — 3단계 진입 · 이미지 채움 · OpenAI gpt-image-1 자동화 영구 정착

### 5-1. 작업 흐름 (요약)
1. **3단계 룰 추가**: 시안 3종 작성 시 **2단계 스켈레톤 frame은 남기고 복제해서 작업** → 룰을 [[1-0. 템플릿 기획 워크플로우]]에 추가.
2. **무드 색·폰트 적용** (3단계 본격 진입): 시안 A 페미닌·B 드리미·C 럭셔리에 팔레트 + 한·영 폰트 페어링 적용 (3시안 색·폰트 차이 명확).
3. **이미지 소싱**: `/generate-flow-image` Playwright 스킬은 본 세션 환경에 미설치. 검증 사이클:
   - Figma Plugin API (`createImageAsync`, `fetch`, `atob`) → ❌ 모두 sandbox 제약
   - `upload_assets` nodeId 자동 fill → ❌ auto-layout FRAME에선 fill 자동 적용 안 됨. **RECTANGLE 자식 추가 후 RECTANGLE nodeId 지정**해야 동작 (영구 룰).
   - 🅲️ Unsplash + curl → 한국인 웨딩 stock 부족 → 외부에 의존하지 않는 생성으로 전환
   - 🅳️ **OpenAI gpt-image-1** → 표준 흐름 정착.

### 5-2. OpenAI 자동화 환경 정착 (영구 자산)
- **키 저장 위치**: `~/.config/cdbd/credentials.json` 의 `openai_api_key` 필드 (chmod 600). vault 내 평문 저장 ❌.
- **사용 모델**: `gpt-image-1`, `quality: medium`, `1024×1024` → 1056 output tokens / ~$0.042/장
- **표준 4단계 흐름**: (1) curl로 생성 → b64 응답 → (2) Python base64 디코딩으로 PNG 저장 → (3) Figma `upload_assets` × N → 단일 사용 submitUrl × N → curl POST multipart 병렬 → imageHash 회수 → (4) `use_figma` 한 호출에서 RECTANGLE 노드 fills 직접 설정.
- **dedup 활용**: 동일 bytes → Figma 서버 동일 hash 반환 → **1회 업로드로 3시안 RECTANGLE 모두에 fill 가능**.
