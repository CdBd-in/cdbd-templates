## 검증 스크립트 메모 (재사용)

다음 세션에서 새 팔레트 추가 시 사용할 WCAG 대비 계산 스크립트.

### Python — WCAG 2.1 Contrast Ratio
```python
def relative_luminance(hex_color):
    """WCAG 2.1 relative luminance from hex color."""
    hex_color = hex_color.lstrip('#')
    r, g, b = (int(hex_color[i:i+2], 16) / 255.0 for i in (0, 2, 4))
    def transform(c):
        return c / 12.92 if c <= 0.03928 else ((c + 0.055) / 1.055) ** 2.4
    R, G, B = transform(r), transform(g), transform(b)
    return 0.2126 * R + 0.7152 * G + 0.0722 * B

def contrast_ratio(bg_hex, fg_hex):
    L1 = relative_luminance(bg_hex)
    L2 = relative_luminance(fg_hex)
    lighter, darker = max(L1, L2), min(L1, L2)
    return (lighter + 0.05) / (darker + 0.05)

def grade(ratio):
    if ratio >= 7: return "AAA"
    if ratio >= 4.5: return "AA"
    if ratio >= 3: return "AA-Large"
    return "FAIL"

# 예시
print(contrast_ratio("#F8F5F2", "#232323"))  # 14.47 AAA
```

### 임계값 정책
- **유지**: ≥ 3.6 (CdBd 비즈니스 모바일 임계값)
- **AAA**: ≥ 7 — 모든 텍스트 안전
- **AA**: 4.5 ~ 7 — 본문 14pt 이상 권장
- **AA-Large**: 3.6 ~ 4.5 — 헤드라인·CTA 위주, 본문 18pt 이상

### K. CSS computed style 검증 절차 정착 ✅

스크린샷 시각 분석의 한계를 발견하고, 다음 JS 코드를 표준화:

**페이지 root 배경색 추출** (모바일 프리뷰 내 가장 큰 면적 색):
```javascript
const preview = document.querySelector('.max-w-1\\/2.transform.origin-top');
const all = preview.querySelectorAll('*');
const bgCounts = {};
all.forEach(el => {
  const bg = getComputedStyle(el).backgroundColor;
  const rect = el.getBoundingClientRect();
  const area = rect.width * rect.height;
  if (bg !== 'rgba(0, 0, 0, 0)' && area > 10000) {
    bgCounts[bg] = (bgCounts[bg] || 0) + area;
  }
});
Object.entries(bgCounts).sort((a,b) => b[1] - a[1]).slice(0, 8)
```

**텍스트 컬러 + 버튼 컬러** 추출 코드도 표준화 → `05. 디자인 특성 분석 절차.md`에 수록.

## 핵심 인사이트 (2부)

- **스크린샷 시각 판단만으로는 부족하다**: 다크 카드/풀블리드 사진이 빽빽이 쌓이면 그게 페이지 배경처럼 보임. **CSS computed style 추출이 필수 보정 절차**.
- **카드 default UI ≠ 디자인 선택**: 유튜브 플레이 버튼·Q&A 별표·지도 임베드 등은 카드 자체 기능. 디자인 특성에 적으면 잘못.
- **"비즈니스 페이지는 버튼이 반복되는게 당연"** → CTA 반복 자체는 디자인 통일성이 아님. 디자인 면에서 반복되는 시각 장치만 기재.
- **모서리는 3가지 옵션뿐**: 픽셀값 적지 말고 각진/둥근/원형. 예외는 "둥근 (단, X는 각진)" 형식.
- **팬텀 디자인 흔한 사례**: "골드 라인", "점선 디바이더", "형광펜 강조", "노치 컷" — 시각적으로 비슷한 인상의 요소를 잘못 본 것. **반드시 CSS로 검증** (`borderStyle`, `clipPath`, `backgroundColor`, `backgroundImage`).

## 핵심 설계 결정사항 (3부)

- **무드 체계는 색상 팔레트와 통일** — 한 페이지의 색상과 폰트를 **같은 무드로** 짝지을 수 있도록 의도적으로 일치시킴. 무드가 결정되면 색·폰트 동시 선정 가능.
- **국문 페이지 본문 한글 의무화** — 영문 폰트의 한글 fallback 렌더링 문제를 원천 차단. 헤드라인만 영문 폰트 허용.
- **중복 등장 = 정상**: 범용 폴백 폰트(프리텐다드·본명조·KoPub바탕·Lato·EB Garamond 등)는 여러 무드에 동시 등장. 한 폰트가 다용도로 쓰여도 OK.
- **Tier ≠ 무드** (직교 분류): 무드는 시각적 인상(가로축), Tier는 사용 범위(세로축). 페이지 배치 시 두 축 모두 만족해야 함.
- **🆑 헤드라인 전용 폰트는 본문 ❌**: 한글 12종·영문 7종은 디스플레이 전용. 본문 후보는 한글 14종 + 영문 11종에서만 선택.
- **디스플레이 폰트가 많은 무드(🔥 비비드)의 본문은 다른 무드에서 차용** — 본문 폰트가 0개인 무드는 🌑/💼에서 끌어옴.

---

## 핵심 인사이트 (3부)

- **폰트 선택의 결정적 변수는 "본문 가독성"** — 헤드라인 폰트는 무드 폭이 넓지만 본문은 가독성이라는 단일 기준에 수렴. 그래서 🆑 헤드라인 전용이 19종으로 가장 많음.
- **한글 본문 후보 14종 중 절반이 명조** (본명조, KoPub바탕, 나눔명조, 부크크명조, 고운바탕, 조선일보명조, 학교안심 돋보기) — 무드에 따라 명조/돋움 선택 가능.
- **프리텐다드는 모든 무드의 폴백**: 명시적으로 4개 무드(💼/🌑/🌿/🎉)에 배치했지만 사실상 어디든 안전. "망설여질 때 = 프리텐다드 단일 폰트"가 검증된 답.
- **영문 본문 = Lato·EB Garamond·Libre Baskerville 3강**: 각각 산세리프/올드세리프/에디토리얼 세리프로 영역 분담. 나머지는 보조.
- **무드 간 인접성 활용**: ✨ 럭셔리 + 🎨 빈티지, 🌑 모던 + 💼 프로페셔널, 🌸 페미닌 + 🌙 드리미는 인접 무드라 조합 가능.
