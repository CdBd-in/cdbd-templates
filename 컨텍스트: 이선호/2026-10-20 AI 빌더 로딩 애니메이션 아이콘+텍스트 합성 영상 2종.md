## 핵심 설계 결정사항

- **영상 합성이 아니라 HTML 원본에 텍스트를 넣어 재렌더**: 기존 아이콘 영상 위에 텍스트를 얹는 게 아니라, 아이콘 모션 HTML에 텍스트·스피너를 추가해 Playwright로 프레임 렌더 → 싱크가 코드로 보장됨.
- **고정 배율 2.0 (텍스트 fit ❌)**: 시리즈로 여러 벌 만들 때 아이콘 크기가 영상마다 같아야 함 (이선호 지시). 최장 문구 대비 좌우 ~55px 여유, +25% 긴 문구까지 수용.
- **모바일 전용판 안 만듦**: 피그마 모바일 시안이 데스크톱과 같은 비율 체계라 표시 크기만 조절(§E).
- **새 세트 제작법**: ②-C HTML에서 `src` 3개 + `MSG` 배열 3개만 교체 → Playwright 270프레임 렌더 → imageio-ffmpeg로 인코딩.

## 재사용 파이프라인 (렌더·인코딩 레시피)

- **ffmpeg 없음** → `python3 -c "import imageio_ffmpeg; print(imageio_ffmpeg.get_ffmpeg_exe())"` 의 번들 바이너리 사용 (libx264·libvpx-vp9 포함).
- **렌더**: python `playwright.sync_api` → chromium, viewport 1200×920, `__seek(k/30)` 후 screenshot ×270. HTML은 `window.__ready`(폰트 로드 후 true) 대기.
- **인코딩**: MP4 `-c:v libx264 -pix_fmt yuv420p -crf 18 -movflags +faststart` · WebM `-c:v libvpx-vp9 -b:v 0 -crf 32` · GIF palettegen(128색)+paletteuse 2-pass.
- **검증**: ① seamless = `diff(f269,f000)`이 인접 프레임 diff 범위 내인지 ② MP4를 cv2로 열어 1.2/4.5/7.5초 프레임에서 아이콘↔텍스트 싱크 눈 확인.
- **함정**: `#inner`에 `transform:scale(2)`을 쓰므로 텍스트 폭 측정 `getBoundingClientRect().width`를 **SCALE로 나눠야** 함 (HTML 내 `SCALE=2` 상수로 처리됨).
