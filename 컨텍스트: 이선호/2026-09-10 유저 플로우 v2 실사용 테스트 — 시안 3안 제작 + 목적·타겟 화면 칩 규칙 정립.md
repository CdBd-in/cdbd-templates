**결정 흐름 (뒤집힌 것 포함)**

| 라운드 | 결론 |
|---|---|
| ① | 필수 골격(행사 알리기·위치·문의)은 **칩에서 뺀다** |
| ② | → 「무엇을 하고 싶나요?」에 답이 없어짐 → **「더」 추가 + 부제로 되살리기** 제안 |
| ③ | 🔄 **이선호: 필수를 입력 필드에 그냥 포함하는 게 제일 쉽다** → ①② 폐기 |
| ④ | AI가 다 켜고 「빼세요」(opt-out)로 뒤집기 제안 |
| ⑤ | 🔄 **이선호: 읽을 게 너무 많다** → ④ 폐기, 필드는 짧게 유지 |
| ⑥ | 🔄 **이선호: 목적 칩이 「섹션」에 가깝다. P1~P6와 가까워야 하지 않나** → **칩=섹션 13칸이 맞고, 화면 이름이 틀렸던 것**으로 정리 |
| ⑦ | 최종: **필드 = 목적 한 문장**(`~에 초대하기`) · **태그 = 아직 모르는 것 5개** |

**필드가 「한 문장」이 되면서 얻은 것** — 앞서 비판했던 B안(토글 방식, `6691:10153`)의 「필드와 태그가 같은 걸 두 번 보여준다」 문제가 사라짐. 필드=무엇을 하려는지 / 태그=무슨 내용을 담을지로 역할이 완전히 갈림.

**태그 5개 (북토크 · 레시피 자동 포함분 제외 · AI가 자료로 알 수 없는 것)**

| 태그 | 왜 모르나 | 종류 |
|---|---|---|
| 참석 신청 받기 | 무료·예약 없음이어도 인원 파악은 가능 | 목적 ＋P3 |
| 정원 안내하기 | `예약 없이 오세요`인데 자리가 20석이면 헛걸음 | 내용 |
| 사인회 안내하기 | 출간 기념의 반쯤 관행인데 자료에 없음 | 내용 |
| 현장 판매 안내하기 | 서점 주최라 팔 확률 높으나 확신 불가 | 목적 ＋P5 |

## 오늘 확정된 규칙 (문서 미반영 — 다음 세션 최우선)

### 칩 — 무엇을 올리나

- **필드 = 목적 한 문장** (`~에 초대하기` · 수정 가능) · **태그 = 아직 모르는 것**
- **태그에서 뺄 것** = ① 주제가 정한 **필수 골격** ② **레시피 기본**(위치·문의) ③ 자료가 **부정한 것** ④ 자료에 **답이 이미 있는 것**
- **태그 출처 2가지** — ① 자료에 **이름은 있는데 내용이 없는 것**(강한 근거·앞 배치) ② **이 주제에 흔한데 자료에 없는 것**(약한 근거·뒤 배치). ①만으론 보통 2~3개밖에 안 나옴
- **같은 정보를 두 번 쓰지 않는다** — 같은 **정보** 반복 ❌(`@bookshop_orae`=문의 → 소식 채널 ❌) / 같은 **대상의 다른 정보**는 ⭕️(책방 오래=주소 → 공간 소개 ⭕️)
- **필수 항목은 추천 태그에 ❌** — 판별법 = **✕로 빼면 페이지가 성립하나?**
- **추천 5개** · 선택 개수는 자유
- 목적/내용 태그는 **한 줄에** 두고 **순서로만** 구분

### 칩 — 표기

- **목적 칩 = `~하기` 동사형** · **주어는 언제나 「이 페이지」** — 읽는 쪽 시점(`소식 받아보기`) ❌ → `소식 채널 알려주기`
- **타겟 칩 = `~사람`** · **`~분` 금지** · 예외 = 신분·역할 명사(`주민`·`직원`·`독자`·`단골`·`회원`)
- **필수 칩 이름은 목적 분류(P)에서** — P1 `~ 알리기` / P2 `~에 초대하기` / P3 `~ 신청받기` / P4 `~ 보여주기` / P5 `~ 팔기` / P6 `~ 소개하기`
  > 🚩 지금까지 쓰던 `행사 알리기`는 **P1(알림형) 어휘**인데 이 북토크는 **P2 초대형**이라 어긋났음

### 문구

- **🆕 화면 문구에 「AI」를 주어로 쓰지 않는다** — 말하는 주체가 곧 AI. 주어 생략(`정리했어요`·`찾았어요`·`적어봤어요`·`골라뒀어요`)
  - 위반 2곳: 3번 `자료를 보고 **AI가** 먼저 적어뒀어요` · 8번 `실제 정보라 **AI가** 임의로 채우지 않았어요`
  - ⚠️ ✦ 라벨(`AI가 정리한 내용`)은 **콘텐츠 꼬리표**라 성격이 달라 별도 판단
- **두 경로를 다 덮는 말은 「주신 내용」** — `자료를 보고`는 2-B(직접 설명)에서 거짓, `적어주신 내용`은 2(파일·URL)에서 거짓
- **기대효과는 「보는 사람에게 생기는 일」로** — `페이지가 풍성해져요` ❌ → `처음 듣는 사람도 관심이 생겨요` ⭕️
- **경고 대신 이득으로** — `많이 고를수록 무난해져요` ❌ → `한두 사람만 골라도 충분해요`
- **주어·목적어 없는 절 금지** — `좁을수록 또렷해져요` ❌ (무엇이 좁고 무엇이 또렷한지 없음) → 절을 **삭제**
- **「군데」는 고유어 수사와** — `1군데` ❌ → **`한 군데`**. UI 권장 = **1~4는 고유어, 5 이상은 숫자**
- **조사 자동 처리 필요** — `#내용#을(를)` 병기 ❌ → 받침 판정으로 `을/를`·`이/가`·`은/는` 선택
- **말끝 통일 필요** — 현재 `~나요`(3) · `~세요`(1) · `~시나요`(1) · `~인가요`(1) → 최다인 **`~나요`**로

### 화면 간 일관성

- **3번에서 안 켠 것은 8번에서 안 묻고 9번에도 안 띄운다** — 세 화면이 한 목록 공유
- **다시 권하는 건** ① 새 근거가 생겼고 ② 아직 안 보여준 것(추천 5개 밖)일 때만
- **9번에서는 새로 권하지 않는다** — 끝내는 화면에 새 할 일 ❌. 늦게 권할 자리는 **8번 도중**이나 **에디터**
- **안심 문구는 두 형태** — 자료에 답 **있으면** `오시는 길·문의는 **이미 담았어요**` / **없으면** `기본으로 담고, **뒤에서 여쭤볼게요**`

### 목적 분류(P) 파생

- **결정 요인 2개** — ① **받는 기능이 있나**(유저가 켠 칩) ② **반복 아이템이 몇 개인가**(자료·입력). 둘 다 이미 받는 정보라 별도 질문 불필요
- **＋는 누적, →는 대체** — `＋P3`·`＋P4` 둘 다 걸리면 `P2＋P3＋P4`
- **🆕 `＋P4` 임계값 = 3개 이상** *(문서에 숫자가 없었음)*. 근거 = 나열 프리셋이 3행 고정 · 안토 2행 시간표는 나열이 아니라 안내사항으로 갔음. **2개 이하는 `[핵심정보]`·`[안내사항]`에 흡수**
- **구멍 2**: `＋P3`는 자료가 부정하면 칩이 안 떠서 **영영 못 켬** → 3번에 **「직접 입력」** 필요 *(§16엔 「추천 4 + 직접 입력」으로 설계돼 있으나 시안엔 없음)*
- **구멍 3**: `＋P4`는 개수를 **8번에서야** 아는데 **5번에서 이미 원/멀티를 통보**하고 6번에서 시안을 만듦 → 자료 빈약 경로는 **재생성이 아니라 「나열 섹션만 추가」**로 처리

지금 파이프라인(40~60분)은 **제품 속도의 참고치가 못 됨**. 시간의 대부분이 피그마 조립·픽셀 측정이고, 제품에선 카드가 JSON이라 통일·검수 단계 자체가 없음.

## 핵심 설계 결정사항

- **필드에 목적 「한 문장」을 두기로 한 이유** — 칩 여러 개를 두면 「필드=담긴 것 / 태그=더 담을 것」 역할 분리가 무너지고 읽을 양이 늘어남. 문장 하나면 **필드=무엇을 하려는지 / 태그=무슨 내용을 담을지**로 완전히 갈리고, 토글 UI(`6691:10153`)의 중복 문제도 동시에 해소됨.
- **AI가 다 켜는 opt-out을 폐기한 이유** — 「읽을 내용이 너무 많아진다」(이선호). 대신 **AI는 자료에 근거가 있는 것만** 켜고, 근거 없는 것은 태그로.
- **목적/내용 태그를 한 줄에 둔 이유** — `＋P3`/`＋P5` 구분은 **내부 로직**이고, [[4-3. 목적·주제별 분류]] §16이 「카테고리 이름을 문구에 쓰지 않는다」로 확정. 라벨 2개는 읽을 양 2배 + 목적 태그 0개일 때 레이아웃 흔들림.
- **8번을 「질문」에서 「확인」으로 바꾼 이유** — 대부분이 이미 AI가 채운 상태라, 빠진 것만 묻는 구조는 **채워진 것을 검토할 기회를 없앰**. 페이지 상단부터 차례로 확인받는 편이 실제 상태와 맞음.
- **9번에서 새 추천을 안 하는 이유** — 끝내는 화면에 새 할 일이 생기면 「돌아가서 채우기」를 눌러 이탈. 9번은 **「내가 켠 것 중 채운 것/안 채운 것」** 한 기준으로만.

## 완료한 작업 (2026-09-10 재개 세션)

> 주제 = **「내용 채우기」 단계 화면 문구 전면 설계**. 플로우 개편(유형 → 1안 → 내용 → 3안 → 무드 → 에디터)에 맞춰 안내 문구·인디케이터·응원 UX를 정하고, **주제 25개 전체 문구표**를 만들었다.

### I. 플로우 개편 — 시안 선택이 「내용 채우기 뒤」로 이동 ✅

| 이전 | 개편 |
|---|---|
| 유형 → **3안 제시** → 선택 → 수정 | 유형 → **1안 먼저** → 내용 채우기 → **3안(1안 포함)** → 선택 → **무드** → 에디터 |

- **1안 제작 예상 시간 = 3~5초** (LLM 카피 생성 없이 프리셋 샘플 문구 그대로 쓸 때). AI가 주제 맞춤 카피까지 쓰면 12~20초 → **첫 화면에서 시간을 쓰지 말 것**
- 2·3안 추가 생성 = **20~40초** · 무드 교체 = **1~2초**(값 치환)
- ⚠️ **1안도 AI 추론 무드를 입혀서** 보여줄 것 — 기본 회색+보라로 띄우면 첫인상을 잃는다(핵심 원칙 7 = 정해서 보여주고 바꿀 수 있게)

**시안 제작 실시간 연출 = 7단계 · 총 6~8초**
`뼈대 잡기 → 섹션 모양 고르기 → 글 넣기 → 사진 넣기 → 색·글씨체 입히기 → 정리 → 완성`
- 실제 계산은 3~5초지만 **일부러 나눠 보여준다**(한꺼번에 끝나면 무슨 일이 있었는지 이해가 안 됨)
- 항상 **위 → 아래** · **색 입히기를 뒤쪽에**(변화 폭이 가장 커 클라이맥스) · **10초 넘기지 말 것**
- 2·3안 생성(20~40초)은 **3열 동시 진행**으로 표시

### J. 인디케이터 — 3막 구조 + 마일스톤 ✅

| 막 | 구간 | 형태 | 완성 순간 |
|---|---|---|---|
| **1막 준비** | 종류 → 목적 → 대상 → 형태 | 점 4개 | **"준비 완료!"** → 시안 제작 연출로 이어짐 |
| **2막 채우기** | 내용 채우기 | 게이지 + 섹션 목록 | → 3안 제작 |
| **3막 고르기** | 시안 → 무드 | **진행바 ❌** · "마지막 단계" | 에디터 |

- **2막 게이지는 0%가 아니라 35%에서 시작** — 앞 답변으로 1안을 이미 만들었으므로 사실이고, 「35→100」이 「0→100」보다 훨씬 잘 끝난다
- **「이건 없어요」도 진척 +1** — 아니면 원래 없는 항목 때문에 영영 100%가 안 됨
- 응원은 **5번만**: 첫 입력 직후 · 섹션 1개 완성 · 절반 · 마지막 하나 · 전부 완성(여기만 크게)
- **남은 양이 아니라 채운 양을 셀 것** — `6개 채웠어요` ⭕ / `8개 남았어요` ❌

**컨셉 인디케이터 추천** — 「페이지가 완성되어 가는 것」 자체를 진행바로
1막 = 네 질문이 **페이지 틀 네 변**을 그림 → 2막 = 그 틀 **안쪽이 위에서부터 물듦**(미니맵 = 진행률+목차+현재 위치) → 3막 = **틀 셋이 나란히**

### P. 시안 3안 선택 화면 · 「추가 시안 2개」 화면 — 문구 지적 (미반영)

**시안 선택 화면** — `원하는 시안을 고르면 다음 단계에서 수정할 수 있어요.` = **옛 플로우 전제**
→ ✅ `세 시안 모두 내용은 같아요. 구성이 마음에 드는 걸 고르면, 다음에서 색과 글씨체를 정해요.`
→ 💡 **시안 B에 「지금까지 보던 시안」 라벨** 추가 권장(흐름 연결)

**「추가 시안 2개를 확인하시겠어요?」** (`7010:24105`) — 제목은 *지금 보여줄까*인데 설명은 *다 채워지면 보여주겠다*로 **앞뒤가 안 맞음**
→ ⚠️ **버튼 위계가 뒤집힘** — 강조(보라)가 `지금 시안으로 충분해요`에 있어 **그만두기를 권하는 모양**. 3안 비교가 핵심 가치인데 손해
→ 라벨 짝 맞추기: `2개 더 볼게요` / `지금 시안으로 할게요`
→ **이 화면이 언제 뜨는지(완료 후 제안 vs 미완 이탈 시)** 미확정 → 이선호 확인 필요
