## 왜 멀티페이지 · 점프형인가
[[4-4. 조립 레시피]] P4 멀티는 두 모드로 갈리는데, 본 건은 **점프형**이다.
- **넘겨보기형**(룩북·도록) = 순서대로 읽음 → 목차 만들면 안 됨(뷰어가 직접 그림)
- **점프형**(메뉴판·품목집·디렉토리) = **원하는 항목으로 건너뜀 → 목차 필요** ✅
- 담당자는 카탈로그를 처음부터 읽지 않는다. **자기 현장에 맞는 라인업 하나만** 본다 → 점프형 확정.
- ⚠️ 실패 사례 인용: 서초 프로그램북은 **목차를 이미지로** 만들어 `link.href:""` = **죽은 목차**가 됐다 → 목차는 메뉴/버튼 카드로.

## 근거가 된 실사용 관찰 (제공)
- 미팅 후 남기는 **PDF 카탈로그는 열리지 않는다** — 무겁고 메일에 묻힘.
- **상품 라인업별 카드 링크**를 남기면 담당자가 필요한 것만 클릭.
- 한 **B2B 산업재 제조사(LED·디스플레이 계열)** 가 **6~7종 라인업을 각각 카드로** 제작해 세일즈에 활용.
- **4개월간 5회 반복 결제** → 상품별 카드 발행이 축적된 익명 패턴.

🔑 **이 관찰이 설계에 주는 요구 = 「라인업 한 장을 복제해 계속 늘리는 구조」**
→ 라인업 장 6개는 **완전히 동일한 틀**이어야 하고, 시안에서도 **6장 전부** 그려 확인한다(1장만 그리고 생략 ❌).
→ 이중 용도: **① 전체 카탈로그 1벌**(미팅 후 전달) **② 라인업 장을 복제해 개별 발행**(반복 결제 패턴의 실체).

## 브리프 (Part B — 생성 전달본)

### 기본
- **무드 방향**: 💼 프로페셔널 (2순위 🌑 모던) — 산업재 제조사의 기술 신뢰감. **서체는 산세리프**(명조 ❌).
- **타겟**: B2B 산업재 제조사의 영업팀·마케팅 담당자 · 총판·대리점 영업 · 전시회 팔로업 담당 / **받는 사람**: 고객사 구매·설비 담당자, 시공사·설계사, 대리점
- **페이지 목적**: 세일즈 미팅 뒤 **PDF 대신 남기는 링크 한 줄**로, 담당자가 **필요한 상품 라인업만 골라 열어보고** 그 자리에서 사양서·견적을 요청하게 한다.
- 색·폰트 = 🔓 개방 (3토큰 모델 · WCAG 3.6:1 · 폰트 1~2개 · 국문 본문 = 한글 산세리프 안에서 자유 탐색)

### 콘텐츠 인벤토리 (반드시 전부 포함)

**① 표지 (P1)**
1. 회사 로고 + 회사명
2. 카탈로그 제목 + 발행 정보(개정 월 · Rev.)
3. 한 줄 소개
4. 대표 비주얼 (제품 설치 전경)
5. **라인업 목차 6항목** — 각 항목 = 번호 + 라인업 이름 (+ 한 줄 용도)
6. 「필요한 라인업만 골라 보셔도 됩니다」 안내 한 줄
7. 대표 문의 (전화 · 이메일)

**② 라인업 장 (P2~P7 · 6장 모두 동일 구성)**
8. 상단 고정 헤더 — 브랜드명 + 「목차」 복귀
9. 라인업 이름 + **한 줄 용도 설명**
10. 대표 제품 이미지
11. **핵심 스펙 4~5행** (라벨 + 값) — 예: 픽셀 피치 · 밝기(nit) · 방수 등급(IP) · 설치 방식 · 보증 기간
12. **적용 사례 2~3건** (설치 장소 + 규모 한 줄)
13. 적용 사례 사진 (여러 컷)
14. **이 라인업 문의 CTA** — 「사양서 받기」 · 「담당자에게 문의」

**③ 마무리 장 (P8)**
15. 회사 개요 — 설립 연도 · 생산 능력 · 인증(KS·CE 등) · 주요 납품 실적
16. **자료 요청 폼** — 회사명 · 담당자명 · 연락처 · 관심 라인업(복수) · 문의 내용
17. 문의 버튼 — 전화 · 이메일 · **연락처 저장(명함)**
18. 본사·공장 위치 (지도)
19. 푸터 — 회사명 · 주소 · 사업자 정보

### 기능상 고정 카드 (정보 → 카드 매핑만 · 레이아웃은 개방)
- 라인업 목차(5) → **메뉴 카드**(페이지 이동) 또는 버튼 카드 — 🚫 **이미지 목차 ❌**
- 서브페이지 복귀 헤더(8) → **2열 카드**(좌 브랜드 텍스트 + 우 목차/홈) · 상단 고정
- 적용 사례 사진(13) → **갤러리 카드**
- 자료 요청 폼(16) → **Q&A 카드** — 제목 중앙정렬 국문 · 제출 버튼은 카드 하단 내장
- 위치(18) → **위치 안내 카드** — 지도+주소+버튼 한 단위 · 주소 중앙정렬 단일 텍스트 · 버튼 채움
- 문의(17) → **버튼 카드**(전화 · 이메일 · 연락처 저장)
- 제품 소개 영상이 있으면 → **유튜브 카드** (선택)
- 🚫 상품 카드 ❌ (견적·문의형 B2B) · 🚫 코드 카드 ❌

### 구성 개방 — 시안마다 크게 갈릴 지점
- ⓐ **표지 목차** — 번호 리스트형 vs 큰 버튼 6개 vs 썸네일 + 이름 2열
- ⓑ **스펙 표현** — 라벨/값 2열 나열 vs 스택형(라벨 위·값 아래) vs 큰 숫자 강조
- ⓒ **적용 사례** — 사진 갤러리 중심 vs 텍스트 리스트 중심
- ⓓ **라인업 장의 도입** — 풀블리드 제품컷 몰입형 vs 타이포(라인업명) 중심형
- ⓔ **CTA 위치** — 라인업 장마다 하단 1회 vs 상·하단 2회
- ⚠️ **라인업 장 6개는 한 시안 안에서 서로 완전히 같은 구성** (복제해 늘리는 구조) · 시안에선 6장 전부 그려 확인(1장만 그리고 생략 ❌)

### 이미지 노트 (자리와 톤만)
| 슬롯 | 톤 |
|---|---|
| 표지 대표 비주얼 | LED 설치 전경(로비·옥외 사이니지) · 과장된 CG ❌ |
| 라인업 대표컷 ×6 | 제품 단독 또는 설치 상태 · 각 라인업이 한눈에 구분되게 |
| 적용 사례 사진 | 실제 설치 현장 스냅 톤 |
| 로고 | 텍스트 워드마크 · 배경과 대비되는 밝기로 |
| 지도 | 위치 안내 카드의 지도 자리(플레이스홀더) |
- ⚠️ 이미지 안에 **글자·로고가 보이는 컷은 배제**(AI 텍스트 렌더링 부정확).

## 카드 선택에서 주의할 점
- 🚫 **상품 카드 ❌** — 「구매 링크가 있을 때만 권장」. B2B는 **견적·문의형**이라 페이지 안에서 결제가 끝나지 않는다 → 이미지+텍스트+버튼으로.
- 목차 = **메뉴 카드**(`linkButton.type: page`)가 본래 용도.
- 자료 요청 = Q&A 카드(관심 라인업 복수선택).
- 문의에 **연락처 저장(vCard)** 포함 — 영업 담당자 명함 역할.

1차 업로드는 **44/44 `success:true`인데 fill이 하나도 안 붙었다.** 원인 추정 = 업로드 커밋 직후 **다른 `use_figma` 쓰기**(라벨 숨김)가 들어가면서, 그 스냅샷이 업로드 이전 상태라 **덮어써짐**.
✅ **안전한 절차**: 업로드 응답의 **`imageHash`를 받아 두고** → `use_figma` 한 호출에서 `n.fills=[{type:'IMAGE',imageHash,scaleMode:'FILL'}]`로 **직접 적용**(+ 같은 호출에서 라벨 숨김). 자동 배치에 의존하지 말 것.
