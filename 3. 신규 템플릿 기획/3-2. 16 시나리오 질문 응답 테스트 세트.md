# 16 시나리오 — 질문 응답 테스트 세트

> **왜 만드나**: [[1-9. AI 유저 플로우 (제품 설계도)]]의 ③ 추가 정보 입력 질문이 **정말 페이지를 만들기에 충분한지** 검증한다.
> **방법**: 각 세부 카테고리마다 가상의 유저를 세우고 **질문에 전부 답한다** → **그 답만 보고** 템플릿을 제작한다 → **만들다 막힌 곳 = 빠진 질문.**
>
> ⚠️ **아래 답변 외의 정보는 제작 시 쓰지 않는다.** "당연히 이것도 있겠지"로 채우면 테스트가 무의미해진다. 없으면 **없는 채로** 만들고, 무엇이 없어서 곤란했는지 적는다.
> 🔓 실제 제품에선 전 문항이 선택이지만, **이 테스트는 최대 정보 조건**(🟡 선택 문항까지 전부 채움)이다. 최대 정보로도 부족하면 그건 **질문 자체가 빠진 것**.

---

## 🧪 테스트 진행 방법

1. 시나리오 1개를 고른다.
2. **그 답변만** 들고 [[1-2. 기획 문서 템플릿]] Part B(콘텐츠 인벤토리)를 채운다.
3. 채우다 **빈칸이 생기면 즉시 기록** — 그게 후보 질문.
4. [[1-8. 섹션 프리셋 라이브러리]] 조립 레시피로 섹션을 배열한다.
5. 레시피가 요구하는데 **답변에 재료가 없는 섹션**을 기록한다.
6. 아래 「📋 관찰 기록표」에 남긴다.

### 무엇이 "빠진 질문"인가
- ❌ **답이 없어 섹션을 못 채움** → 질문 추가 대상
- ❌ **답은 있는데 형태가 안 맞음**(예: 통짜 문단인데 카드는 항목 반복 필요) → 질문 **형식** 수정 대상
- ⭕ **AI가 예시로 채워도 무방**(인사말·안내 문구 등) → 질문 불필요
