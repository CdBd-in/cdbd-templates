# 디자인 특성 분석 절차

기존 CdBd 템플릿(`cdbd 템플릿 현황/0X.*.md`)의 디자인 특성을 분석할 때 사용. 17개 템플릿 일괄 분석 과정에서 발견한 **흔한 오류 3가지**를 차단하기 위한 검증 절차.

---

## ⚠️ 자주 발생하는 오류 3가지

| 오류 유형 | 예시 | 원인 |
|---|---|---|
| **페이지 배경 ↔ 카드 혼동** | "다크 네이비 풀배경"이라 적었지만 실제는 화이트 배경 + 다크 네이비 CTA 카드들 | 다크 컬러 카드/풀블리드 사진이 빽빽이 쌓이면 그게 페이지 배경처럼 보임 |
| **카드 기본 기능을 디자인 요소로 적시** | "유튜브 플레이 버튼 일러스트 아이콘", "지도 임베드 카드", "Q&A 필수 별표" | 카드의 default UI를 디자이너의 시각 선택으로 오인 |
| **팬텀 디자인 (존재하지 않는 요소)** | "형광펜 스타일 강조", "골드 라인", "점선 디바이더", "노치 컷" | 스크린샷 시각 해석에서 비슷한 인상의 요소로 잘못 본 것 |

---

## 🔍 검증 절차 (4단계)

### 1단계: 페이지 테마 — CSS computed style로 추출

스크린샷 시각 판단은 **반드시** CSS 검사로 보정. 페이지 테마는 (배경 / 텍스트 / 버튼) 3-튜플로 표기.

#### 1-1. 페이지 root 배경색

```javascript
// browse JS — 모바일 프리뷰의 우세 배경색 (면적 합산 1위)
const preview = document.querySelector('.max-w-1\\/2.transform.origin-top');
const all = preview.querySelectorAll('*');
const bgCounts = {};
all.forEach(el => {
  const bg = getComputedStyle(el).backgroundColor;
  const rect = el.getBoundingClientRect();
  const area = rect.width * rect.height;
  if (bg !== 'rgba(0, 0, 0, 0)' && area > 10000) {
    bgCounts[bg] = (bgCounts[bg] || 0) + area;
  }
});
Object.entries(bgCounts).sort((a,b) => b[1] - a[1]).slice(0, 8)
```

가장 큰 면적의 색상이 **페이지 배경**. 그 다음 큰 색상들이 카드/CTA/액센트.

#### 1-2. 텍스트 컬러

```javascript
const ps = document.querySelectorAll('p, span, strong');
const colors = {};
ps.forEach(p => {
  const c = getComputedStyle(p).color;
  if (p.offsetParent && p.textContent.trim().length > 3) {
    colors[c] = (colors[c] || 0) + 1;
  }
});
Object.entries(colors).sort((a,b) => b[1] - a[1]).slice(0, 5)
```

가장 많이 등장하는 텍스트 색이 **본문 텍스트색**.

#### 1-3. 버튼 컬러

페이지 내 명확한 CTA 버튼(예: "제출하기", "신청하기", "예약하기")의 배경색을 직접 추적:

```javascript
const target = Array.from(document.querySelectorAll('*')).find(el => 
  el.children.length === 0 && el.textContent.trim() === '제출하기'
);
let el = target;
for (let i = 0; i < 8; i++) {
  if (!el) break;
  const bg = getComputedStyle(el).backgroundColor;
  if (bg !== 'rgba(0, 0, 0, 0)') {
    console.log({ tag: el.tagName, bg, w: el.offsetWidth, h: el.offsetHeight });
    break;
  }
  el = el.parentElement;
}
```

### 2단계: 카드 기본 기능 제외

**아래 항목들은 "반복되는 디자인 요소"에 적지 말 것** — 카드의 default 기능이지 디자이너의 시각 선택이 아님.

| 카드 종류 | 제외 대상 (default 기능) |
|---|---|
| **유튜브** | 영상 임베드, 플레이 버튼, 썸네일 |
| **위치 안내** | 지도 임베드, 핀 마커 |
| **Q&A** | 필수 별표, placeholder, 체크박스/라디오 모양 |
| **예약** | 예약 위젯 UI, 캘린더, 옵션 선택기 |
| **갤러리** | 기본 그리드 자체 (단, 그리드 vs 캐러셀 vs 나열 선택은 디자인) |
| **SNS** | SNS 아이콘 세트 |
| **메뉴** | 탭 네비 구조 |
| **프로필 카드** | 사진+이름+소개 기본 구조 (단, 원형/풀블리드 등 모양 선택은 디자인) |
| **멀티페이지** | 페이지 인디케이터 도트 |
| **CTA 버튼 반복 자체** | 비즈니스 페이지는 버튼이 여러 개 반복되는 게 당연. "반복" 자체는 디자인 통일성이 아님 |

**유지 대상 (실제 디자인 선택):**
- 컬러 / 모서리 / 보더 / 그라데이션 처리
- 풀블리드·박스·강조 색면으로 감싸기
- 장식 추가 (점선·도트 마커·골드 라인·일러스트 등)
- 카드 후처리 (B&W, 빛바램 톤 등 사진 보정 통일)
- 타이포 페어링 (영문 디스플레이 + 한글 부제)

### 3단계: 팬텀 디자인 — 시각 표현은 CSS로 검증

스크린샷에서 "있는 것 같다"고 느낀 요소는 **반드시** 다음 CSS 검사를 통과해야 기재.

| 시각 표현 | 검증 방법 |
|---|---|
| **점선/대시 디바이더** | `getComputedStyle(el).borderStyle === 'dashed' \|\| 'dotted'` 카운트 |
| **노치/스티커 모양** | 4개 모서리 border-radius가 비대칭이거나 `clipPath !== 'none'` |
| **그라데이션** | `getComputedStyle(el).backgroundImage`에 `linear-gradient(` 포함 |
| **형광펜 하이라이트** | 텍스트 element의 `backgroundColor`에 노란/형광색 존재 |
| **글자색 강조 (옐로우/골드 등)** | 텍스트 element의 `color` 값 확인 — 강조하려는 색이 실제 적용됐는지 |
| **SVG 라인 아이콘** | `document.querySelectorAll('svg').length` |
| **다이아몬드 마커** | `transform: rotate(45deg)` 또는 SVG, 또는 Unicode 문자 확인 |
| **도트 디바이더** | `border-radius: 50%`인 작은(≤8px) 요소 카운트 — 단, SVG/이미지로 구현된 경우는 시각 확인 필요 |
| **흑백/저채도 사진** | 이미지 자체 확인 (`<img src>` 또는 캡처로 시각 검증) |
| **손그림 일러스트** | 이미지 자체 확인 (벡터·핸드드로잉 스타일인지) |

CSS 검사가 0건이면 **명시적으로 삭제**하고, 시각적으로 의심되는 보조 표현(예: "장식 마커")으로 대체.

### 4단계: 작성 후 키워드 점검 (선택)

새 분석 노트 저장 전, 다음 키워드가 들어가 있다면 다시 검증:
- "골드 / Gold" — 실제로 골드 톤 hex가 추출됐는가?
- "형광펜 / 하이라이트" — 실제 배경 highlight인가, 단순 글자색인가?
- "노치 / 스티커" — 실제로 비대칭 모서리인가?
- "점선 / dashed" — 실제 `borderStyle: dashed`인가?
- "흑백" — 실제 채도 0인가?
- "그라데이션" — 실제 `linear-gradient`인가?
- "마스코트 / 캐릭터" — 디자인 패턴인가, 단순 업로드 콘텐츠인가?

## 📐 "## 디자인 특성" 섹션 표준 포맷

각 템플릿 노트 하단에 다음 구조로 추가:

```markdown
## 디자인 특성

- **전체 인상**: <한 줄 — 무드 키워드 2-3개 + 이유>
- **페이지 테마**: 배경 [이름 + hex] / 텍스트 [이름 + hex] / 버튼 [이름 + hex]
- **포인트 컬러**: <페이지 테마 밖의 보조 액센트만 — 강조 박스 배경, 장식 라인 등>
- **컬러 대비**: <강/중/약> — <근거 한 줄>
- **모서리 처리**: <각진 / 둥근 / 원형> — <전반 처리 한 줄>
- **카드 배경**: <페이지 배경 위에 카드들이 어떻게 배치되는지>
- **텍스트 사이즈 대비**: <큼/보통/작음> — <헤딩-본문 위계>
- **반복되는 디자인 요소**:
  - <시각적 통일성을 만드는 장치 3-4개. 카드 default 기능 제외>
- **레이아웃 특징**: <섹션 흐름, 정렬, 간격>
```

### 페이지 테마 표기 규칙
- **배경/텍스트/버튼**은 CDBD 페이지 테마 시스템의 3-튜플 ([[1-1. 색상 팔레트 라이브러리]] 참조)
- 색상은 **이름 + hex** 둘 다 (예: "다크 네이비 #1F2B5A")
- 멀티페이지 템플릿은 모든 페이지 공통 적용되는 1세트

### 모서리 처리 표기 규칙
- 디자인 보드 옵션이 **각진 / 둥근 / 원형** 3가지뿐이므로 픽셀값 적지 말 것
- 예외 (다른 모양 섞임)은 "둥근 (단, X는 각진)" 형식으로 솔직히 표기

## 🚦 분석 흐름 요약

```
1. 라이브 URL 방문 (https://www.cdbd.in/templates/{slug})
2. 모바일 프리뷰 스크린샷 캡처
3. CSS computed style 추출 → 페이지 테마 확정
4. 스크린샷에서 의심되는 시각 요소 → CSS 검사로 검증
5. 카드 기본 기능은 제외하고 "반복 디자인 요소" 3-4개 추리기
6. 표준 포맷대로 노트 작성
7. 키워드 점검으로 팬텀 표현 한 번 더 거르기
```

## 📚 참조 사례

이 절차는 17개 템플릿 일괄 분석 과정에서 발견한 오류 패턴을 토대로 만들어짐. 라운드별 정정 흔적:

- **1라운드** — 스크린샷 시각만으로 17개 분석 → 페이지 테마 8개 오류, 버튼 컬러 5개 오류, 골드 멘션 3건 등 다수 오류
- **2라운드** — CSS computed style 추출로 15개 정정
- **3라운드** — CSS + 시각으로 팬텀 디자인(점선·노치·도트 등) 5개 추가 정정

새 템플릿 분석할 때 처음부터 이 절차를 따르면 라운드 반복 없이 1회로 정확한 분석 가능.
