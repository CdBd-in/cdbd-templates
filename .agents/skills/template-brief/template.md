## 0. 이 작업의 본질 (가장 먼저 이해할 것)

우리는 **"모바일 원페이지 빌더" 서비스의 템플릿**을 만든다. 최종 사용자는 **비디자이너·비개발자**로, 완성된 템플릿을 가져다 **텍스트·이미지·색만 갈아끼워** 바로 쓴다.

> 📱 **이건 "모바일 웹 페이지"이지 네이티브 앱이 아니다 (필수).** 사용자는 브라우저에서 **링크(URL)로 열어** 세로로 스크롤하며 본다. 따라서 앱 UI 요소를 **절대 그리지 마라**:
> - ❌ 상단 상태바(시계·배터리·신호), 앱바/헤더바(뒤로가기 화살표·페이지 타이틀바)
> - ❌ 하단 탭 내비게이션 바(홈·검색·마이페이지·장바구니 등 아이콘 탭)
> - ❌ 플로팅 액션 버튼(FAB)·햄버거 메뉴·앱 스플래시 등 네이티브 크롬
> - ✅ 페이지는 **위→아래로 쌓인 카드 스택이 전부**다. 화면 폭을 꽉 채우는 콘텐츠 카드만 있고, 고정된 상/하단 바는 없다.

그래서 결과물은 "멋진 일회성 아트워크"가 아니라 **"편집·복사·교체가 쉬운 템플릿"** 이어야 한다. 아래 5대 원칙은 **디자인을 아무리 자유롭게 해도 반드시 지켜라** — 이걸 어기면 사용자가 편집할 수 없어 템플릿으로서 실패한다.

1. **범용성** — 페이지 전체뿐 아니라 **각 카드(블록)도 개별 복제·삭제·재사용** 가능해야 한다. 카드는 항상 "그 자체로 시각 균형이 잡힌 단위"여야 한다.
2. **텍스트 카드 = 1속성** — 한 텍스트 블록 안에 서로 다른 속성(크기·굵기·정렬·색·줄간격)을 섞지 마라. "제목 + 본문"은 **반드시 2개 블록으로 분리**. "본문 + 보조설명"도 2개 블록.
3. **보조 텍스트는 투명도로** — 회색 hex를 따로 쓰지 말고 `{텍스트색}`의 불투명도 N%(예: 60%)로 표현. 테마 색을 바꿔도 따라오게.
4. **테마 변수 3개로 색을 조직** — 페이지 색은 `{배경색}`·`{텍스트색}`·`{버튼색}` 3개 역할 변수로 구성한다. **색 자체는 네가 자유롭게 고르되**, 카드마다 제각각 무관한 색을 흩뿌리지 말고 이 3개 역할 체계 안에서 운용하라. (액센트가 꼭 필요하면 1개까지 추가 허용 — 남용 금지.)
5. **편집 불가 장식 그래픽 배제** — 사용자가 못 바꾸는 장식용 도형·라인·패턴·일러스트를 카드에 붙이지 마라. 색·여백·타이포·이미지 배치만으로 무드를 만들어라. 단, 로고·프로필·헤더 사진처럼 **교체 가능한 이미지**는 OK.

## 2. 디자인 방향 — **자유. 단, 이유가 있어야 한다.**

색·폰트·모서리·여백·크기·정렬·간격은 **전부 네가 정한다.** 라이브러리나 정해진 후보 목록은 없다. 대신 아래를 요구한다.

- **주제·타겟·통증에서 출발한 디자인 결정**을 하라. "{{NAME}}"의 사용자와 상황에 어울리는 무드를 **네가 정의**하고, 그 무드가 색·폰트·레이아웃에 일관되게 흐르게 하라.
- **시안마다 방향을 다르게** — 같은 필수 요소로 **뚜렷이 구별되는 3개 시안**을 내라. 색만 바꾼 게 아니라 **무드·타이포·질감·구성의 방향 자체가 다른** 3개여야 한다. (예: ①차분한 미니멀 ②따뜻한 감성 ③대담한 하이컨트라스트 — 예시일 뿐, 주제에 맞게 네가 골라라.)
- **가독성 하한선(유일한 강제 규칙)**: 본문 텍스트와 배경의 WCAG 대비 **3.6:1 이상**. CdBd는 비즈니스 모바일 페이지라 햇빛·작은 화면에서 읽혀야 한다. 각 시안에 실제 대비값을 명시하라.
- **색 역할 매핑**: 어떤 색을 고르든 `{배경색}` / `{텍스트색}` / `{버튼색}` 역할로 정리해 제시하라. **버튼 텍스트 색 = `{배경색}`** 으로 둔다(버튼은 `배경=버튼색·글자=배경색`으로 렌더된다). 보조/캡션은 `{텍스트색}` 불투명도 50~70%.
- **폰트**: 자유. 단 (a) 한 페이지 **1~2개**만, (b) **국문 본문은 반드시 한글 폰트**(영문 폰트의 한글 fallback은 깨진다), (c) 헤드라인 전용 장식체를 본문에 쓰지 마라. 웹폰트라면 폰트명을 명시하라.

> 핵심: **디자인은 자유, 편집 용이성(0장 5대 원칙)과 가독성(3.6:1)은 불가침.**

## 4. 포함 요소 — **이 정보들은 반드시 담아라. 순서·구성·카드 선택은 자유.**

아래는 이 페이지가 **반드시 담아야 할 정보 요소**다. **무엇을 담을지는 고정, 어떻게 담을지는 개방**이다.

- 이 요소들을 **어떤 순서로 배치할지**, **어떤 걸 한 카드에 묶고 어떤 걸 나눌지**, **각각을 아래 카드 중 무엇으로 표현할지** 는 전부 네가 정한다.
- 목적·타겟·통증(1장)에 가장 잘 맞는 흐름을 스스로 설계하라. 요소를 빠뜨리지만 마라. **주제상 자연스러우면 요소를 추가**해도 좋다(단, 5대 원칙·규격 준수).
- 텍스트는 5대 원칙 #2(1속성=1블록)에 따라 필요하면 여러 블록으로 나눠라.
- **3개 시안은 구성(순서·그룹핑·카드 선택)까지 서로 달라도 좋다** — 오히려 다른 구성을 보여주면 우리가 고를 폭이 넓어진다.

## 5. 결과물 (Deliverables)

아래를 모두 제출하라.

1. **카드별 최종 카피** — 카드 각각의 확정 문구(한국어). 가상의 브랜드/행사명을 정하되 네가 정한 무드 톤을 유지. 텍스트 카드는 5대 원칙 #2대로 속성 단위로 분리해 표기.
2. **모바일 목업 3종 (HTML/CSS, 폭 380px 고정)** — **구성과 디자인 방향이 서로 뚜렷이 다른** 시안 A·B·C. 4장 필수 요소는 3종 모두 빠짐없이 담되, **요소의 순서·그룹핑·카드 선택(구성)과 색·폰트·모서리·여백·크기·정렬·질감(디자인)은 3종이 확연히 다르게.**
   - 각 시안 상단에 `시안 A — {무드 이름} · {대표색 hex} · {폰트명}` 형식 라벨 + 한 줄 컨셉(구성 아이디어 포함).
   - 각 시안마다 **카드 구성 리스트**(위→아래 카드 타입·역할 순서)를 목업 앞에 짧게 명시.
   - 이미지 자리는 톤에 맞는 색 박스 placeholder + 주석("헤더: …")으로 표시.
3. **이미지 생성 프롬프트** — 페이지에 쓰일 각 이미지의 생성용 영문 프롬프트. (인물이면 인종·연령·분위기 명시, 실사 다큐멘터리 톤)
4. **OG 썸네일 컨셉** — 800×400 단색 배경 + 가상 브랜드 로고 배치안(로고 면적 9~10% 규칙 준수).
5. **디자인 근거 요약** — 시안별로 무드·색·폰트를 **왜 그렇게 정했는지**(주제·타겟·통증과 연결) 3~5줄. 각 시안 WCAG 본문 대비값 명시.
