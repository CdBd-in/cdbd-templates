# MD-03. 추가 항목 제안

> 📍 **화면**: v2 · 3 목적 선택 — 목적 문장 input **아래 보조 칩** 「있으면 더 좋은 것들」 · [피그마에서 보기](https://www.figma.com/design/24O01lprp5i2ufl7CbZXXx/AI-%EC%84%B9%EC%85%98-%ED%94%84%EB%A6%AC%EC%85%8B?node-id=6919-13797)
> 🗒 **출처**: 피그마 코멘트 (2026-09-10, codeisneverodd)
> 🚧 **상태**: 골격만 — 본문 지침 작성 대기

## 1. 무엇을 정하는 MD인가

**「이것도 담을까요?」 제안 칩 N개**를 만든다.

⚠️ **이름은 「목적 선택지」였지만 실제 성격은 목적이 아니라 「담을 내용·기능」이다** (2026-09-11 이선호 정정).
유저는 바로 위 input에서 **목적을 이미 말했다.** 이 칩은 그 목적을 **다시 고르게 하는 게 아니라**, 그 목적이라면 **함께 있으면 좋을 섹션을 추가로 권하는 것**이다.
→ 칩 하나 = **페이지에 섹션 하나 추가**.

## 2. 입력

- MD-02가 만든 **목적 문장**
- 확정된 **주제 분류**(25개 중 1개)와 그 주제의 **조립 레시피 = 이미 들어갈 섹션 목록**
- 자료(파일·URL)에서 파악된 내용

## 3. 출력

칩 N개. 칩 하나 = `{ 화면에 보일 문구, 추가할 섹션 목적, 들어갈 자리 }`

## 4. 규칙

- 🔴 **필수 섹션은 칩으로 올리지 않는다** — 레시피에 **이미 들어가는 섹션**을 제안하면 유저는 「이미 되는 걸 또 고르는」 셈이 된다. 칩 후보 = **레시피 필수 섹션을 뺀 나머지**.
- 🔴 **조건 1** — 칩마다 **어떤 「섹션 목적」을 쓸지 미리 정해져 있어야 한다**
- 🔴 **조건 2** — 섹션 목적 용어는 **어드민 프리셋 편집기와 반드시 일치**
- 🗣 **칩 문구는 유저 말로** — 섹션 목적 용어를 그대로 노출하지 않는다 (`폼` ❌ → `참석 신청받기`)
- 예시 매핑: 참석 신청받기 = **폼** / 정원 안내하기 = **소개** / 문의사항 = **문의**
- 🔀 **갈림 질문 흡수** — AI가 주제 분류 둘 사이에서 갈리면, **둘을 가르는 섹션을 칩으로 올려** 유저 선택으로 결정한다 (별도 질문 화면 ❌ · [[4-3. 목적·주제별 분류]] §16)
- ❓ **미결** — 칩 개수 N (화면 시안 기준 확인 필요)

> 🚧 여기에 실제 생성 지침(프롬프트 수준의 규칙·예시·금지 사항)을 채운다.

## 5. 볼트 근거

- [[4-5. 섹션 라이브러리]] 섹션 목적 13칸
- [[4-4. 조립 레시피]] §3 섹션 부품 목록 · 주제별 레시피(= 필수 섹션)

## 6. 원본 코멘트

```
input 아래 보조 선택지로 제시할 문장 N개.
조건1) 이 선택지들은 어떤 섹션 목적을 사용할 것인지 미리 정해져 있어야함.
조건2) 섹션 목적은 어드민의 프리셋 편집기와 용어를 반드시 통일해야함
```

## 7. MD-02와 합치지 말 것 (2026-09-11)

같은 화면에 있지만 **하는 일이 다르다.**

| | [[MD-02. 목적 문장]] | 이 문서 |
|---|---|---|
| 만드는 것 | 목적 **문장 1개** | 담을 내용 **칩 N개** |
| 성격 | 유저가 하려는 일을 **요약** | 페이지에 **섹션 추가** |
| 입력 | 앞 단계 설명 글 | 목적 문장 + **레시피 필수 섹션 목록** |
| 출력이 바꾸는 것 | 화면 문구 | **페이지 구조** |

→ 한 문서로 합치면 「문장 다듬는 규칙」과 「섹션 고르는 규칙」이 섞여 둘 다 흐려진다.
