# MD-00. 단계별 누적 정보 (전 MD 공통 입력 계약)

> 🚫 **이 문서는 어드민에 등록하지 않는다** — 우리끼리 보는 **전체 지도**다. 각 MD는 **혼자서도 읽히도록** 자기 입력을 직접 풀어 쓴다.
> 📌 각 MD가 입력을 적을 땐 **여기 있는 이름 그대로** 쓴다(줄임 기호·화면 번호 ❌).

ℹ️ **왼쪽 패널 제목 문구**(`○○을 추가하면 좋아요`)는 AI가 짓지 않고 **미리 등록해 둔 문구를 고른다** — 문구 정본은 [[4-7. 입력 단계 안내 문구]]. **반응 문구는 AI가 패턴으로 만든다**([[MD-09-3. 내용 채우기: 반응 문구]]).

⚠️ **주제 코드·목적 분류는 화면에 절대 나오지 않는다** (각 MD의 「내부 분류 이름 노출 ❌」 규칙).

## 모든 MD 공통 작성 규칙 ① — 🤖 「AI가 실행할 수 있는 규칙」 7가지 점검

> 🔑 **개발 피드백 34건을 역산한 상시 체크.** MD를 새로 쓰거나 고칠 때마다 한 줄씩 대조한다 — 어기면 그 규칙은 **실행되지 않거나(AI가 못 씀) 무시된다.**

1. **역할 분리 — MD에는 AI가 하는 일만** 적는다: 판정 · 거르기 · 문구/값 생성. **랜덤 선택 · 앞 안 제외 · 시드/기록 · 화면 생김새·동작**(포커스 · 접힘 · 사라지는 시간 · 색 · 연결선) · **고정 문구**는 시스템(개발) 구현이다 → MD에 쓰지 않는다. 경계를 알려야 하면 **「~는 시스템이 한다」 한 줄**로.
2. **출력 계약 완결** — 규칙이 AI더러 정하라고 한 값은 **반드시 §2 출력에 자리가 있어야** 한다(스위치 동작 · 대표 칸 · 선택지별 플레이스홀더 …). `있음|없음`처럼 **대상을 못 집는 출력 ❌** — 섹션에 버튼이 여러 개면 「어느 버튼인지」까지 출력에 넣는다.
3. **멈춤 금지 — 모든 규칙에 폴백** — AI는 「멈추고 검토 요청」을 못 하고, 그 사실을 적을 출력도 없다. 예외 상황마다 **대신 무엇을 할지**를 적는다(가장 가까운 인풋으로 받기 · 2단으로 접기 …).
4. **판정 재료는 §1 입력에** — 규칙이 요구하는 판정(무거운 소식 · 브랜드 색)의 재료가 입력에 없으면 그 규칙은 공회전한다. **입력에 추가하거나 규칙을 뺀다.**
5. **그 단계에서 쓰는 규칙만** — 다른 단계 몫의 규칙(레이아웃 문서 속 무드 제외 등)은 무시된다 → **그 단계의 MD로 옮긴다.** 일부 단계에만 해당하는 규칙도 **공통 문서가 아니라 그 단계의 MD 안에** 둔다.
6. **데이터는 MD(또는 분류 DB) 안에** — *「조건은 그 주제의 레시피에 적혀 있다」* 처럼 **AI가 못 보는 외부 문서로 미루지 ❌** — 표로 그 MD 안에 넣는다. 다른 MD를 가리킬 땐 문서 이름으로만(옛 번호 ❌).
7. **경우의 수를 다 받기** — 상태표·분기표는 **섞인 상태 · 복수 대상**(빈 칸＋채운 칸 혼합 · 타겟 2개 · 한 섹션 여러 단계)까지 한 줄씩 적는다. 두 상태만 적으면 세 번째 상태에서 AI가 임의 판단한다.

➕ **화면·플로우는 실물과 대조** — 없는 화면 이름(`추가 2안을 볼까요?`) · 틀린 순서(`바로 다음 화면`)를 적지 않는다. 🚧 **미결 표시는 작성 중에만** — **어드민 활성화 전에 해소**한다(결정해서 적거나 뺀다 · 🚧인 채 활성화하면 AI는 초안대로 실행해 버린다).

## 모든 MD 공통 작성 규칙 ② — 🚫 모호한 표현 금지 · 🚫 히스토리 표기 금지

🚫 **히스토리 표기 금지** — MD에는 **현재 규칙만** 적는다. 결정 날짜·결정자 이름·`옛 X 대체`·`폐기`·개정 경위 같은 **변경 이력은 쓰지 않는다**(AI가 참고할 기준이 아니라 소음). 이력이 필요하면 vault 내부 문서(CLAUDE.md·세션 컨텍스트)에만 남긴다.

🚫 **판단 근거 표기 금지** — **「왜 이 규칙을 만들었나」·「어느 규칙과 충돌해서」·「무엇을 재서 나온 수치인가」** 같은 설명은 쓰지 않는다. MD에 적는 것은 **ⓐ지킬 규칙 ⓑ판정 기준 ⓒ예시** 셋뿐이다. 근거가 필요하면 vault 내부 문서에만 남긴다. (예: `기본이 없으면 위 🔴와 충돌한다` ❌ → `기본을 반드시 함께 낸다` ✅ / `CdBd 가로는 380 고정이라` ❌ → `360px에서 계산한다` ✅)

🔤 **UI 용어는 표준 명칭 그대로 쓴다** — `드롭다운` · `토글` · `탭` · `칩` · `아코디언` 같은 **디자인 표준 용어**를 그대로 적는다. 쉬운 말로 풀어쓰면(`켜기·끄기` · `고르기`) 같은 부품을 문서마다 다르게 불러 **무엇을 가리키는지 흐려진다** — 부품 이름 정본 = [[4-12. 입력 유형 카탈로그]].
 - 🚫 **단, 유저 화면에 나가는 말은 예외** — 칸 라벨 · 왼쪽 패널 제목 · 버튼 문구는 **쉬운 국문**이다(`EYEBROW`·`CTA`·`label` ❌). 문서에서 부품을 부르는 말과, 화면에 찍히는 말은 **다른 층**이다([[MD-09-1. 내용 채우기: 질문 구성]] §3-0-B·§3-4).

> 🔑 **MD는 사람에게 읽히는 설명서가 아니라 AI가 매번 같은 결과를 내게 하는 기준이다.** *「구체적으로」·「적절히」·「흔한 것」* 처럼 **읽는 사람마다 답이 갈리는 말**을 쓰면, 같은 입력에도 결과가 매번 달라진다. 문서 하나만 보고도 **일관되고 품질 좋은 결과**가 나오게 쓴다.

**🚫 쓰지 않는 말** — `적절히` · `자연스럽게` · `구체적으로` · `간결하게` · `흔한` · `일반적인` · `필요하면` · `가능한 한` · `잘` · `적당히` · `대체로`

**✅ 대신 쓰는 것 4가지** (하나 이상)

| 방법 | 무엇 | 예 |
|---|---|---|
| **① 목록으로** | 고를 것을 다 적는다 | `구체적으로` → **관계 / 속성** 2축 표 |
| **② 금지어로** | 안 되는 말을 나열 | `분류 용어 ❌` → `타겟`·`세그먼트`·`F&B`·`B2B` … |
| **③ 숫자로** | 세거나 잴 수 있게 | `짧게` → **12자 이내** · **5개 고정** |
| **④ 판정 문장으로** | **예/아니오로 답이 갈리는 한 문장** | `겹치지 않게` → *"한 사람이 두 칩에 동시에 해당되면 겹친 것"* |

**🧪 다 쓴 뒤 자가 점검 2개**
- **다른 사람 둘이 이 줄만 읽고 각자 만들면 같은 게 나오나?** — 아니면 ①~④로 다시 쓴다
- **실행 시점에 확인할 수 없는 근거를 깔지 않았나** — *"그 주제 페이지 10개 중 절반"* 처럼 **세어 볼 데이터가 없는 기준** ❌. 손에 있는 입력(첫 입력 글·자료·주제 코드)만으로 답이 나와야 한다

⚠️ **예외 = 판단을 사람에게 넘기는 자리** — 🚧 표시를 달고 *「검토 필요」*라고 적는다(애매한 채로 두되 **애매하다는 걸 드러낸다**). 단 **어드민 활성화 전에는 해소**한다(규칙 ① ➕ — 🚧인 채 활성화하면 AI는 초안대로 실행한다).

## 모든 MD 공통 작성 규칙 ③ — 📄 무엇을 넣고 · 어떻게 고치나

- 📄 **넣는 것 = AI가 그 단계에서 실제로 참고할 근거만** — 문구 · 시안을 만들 때 **의사결정이 필요한 부분의 근거**만 적는다. 🚫 **내부 논의 · 플로우 판단 근거**(왜 이런 플로우인지)는 넣지 않는다 — vault 내부 문서의 몫이다.
- 🧱 **틀 = `## 0. 반드시 지킬 것` → `## 1. 입력` → `## 2. 출력` → `## 3. 규칙`**(3-A · 3-B로 나눠도 된다) — 입력 → 출력 → 규칙 세 칸으로 **혼자서도 읽히게** 쓴다 · 화면 이름 · 피그마 링크 ❌.
- 🔝 **0절 = 자주 뚫리는 절대 규칙 6~8줄 요약** (어드민 등록 MD 14개 공통 · **본문이 정본**) — 새 규칙이 절대 규칙급이면 **본문에 반영하고 0절에도 한 줄** 넣는다. 상세 · 예외는 본문에만, 0절은 한 줄 요약만.
- ✍️ **짧고 세게** — 새 규칙은 문서 **맨 뒤에 붙이지 않는다** → **관련 있는 영역에 끼워 넣고**, 기존 규칙과 **중복 없이 최대한 간결하게** 쓴다(시간이 걸려도 이 방식).
- 📤 **MD 수정 = 어드민 업로드 · 활성화까지가 한 작업** — 새 버전으로 저장만 하면 예전 버전이 계속 쓰인다 → **`활성화`까지** 눌러야 반영된다.

## 📤 어드민 업로드 절차 (우리 참고용 · 어드민에 올리지 않는 절)

> **MD를 고치면 어드민에 올려 활성화할 때까지가 한 작업이다.** 아래는 실측으로 확인한 절차·함정. 화면 = `https://cdbd-client-git-ai-makevu-s-team.vercel.app/admin/ai/assembly-docs` (상단 탭 「가이드 MD」 · 계정 = `account@emka.group`).

### 한 슬롯 올리는 순서

1. **슬롯 버튼 클릭** → 본문 `textarea` 1개가 그 슬롯의 **활성본**으로 채워진다
2. **올리기 전 안전 확인** — 지금 활성본이 **우리 볼트의 과거 판인지** 대조한다(아래 🔒). 볼트 이력에 없는 내용이면 **다른 세션/사람이 어드민에서 직접 고친 것** → 덮어쓰지 말고 멈춰 확인
3. **본문 주입** — `textarea`에 **native setter → `input` 이벤트** (React가 값 변경을 인식하는 유일한 경로)
4. **`새 버전으로 저장`** → 목록 맨 위에 **`draft` 행**이 생긴다(저장만 하면 예전 버전이 계속 쓰인다)
5. **그 draft 행의 `활성화`** 클릭 → 행이 `active`로 바뀌고 이전 활성본은 `archived`로 내려간다
6. **검증** — 슬롯을 다시 열어 본문 **글자수·해시를 볼트 파일과 대조**

### 🔒 안전 확인 = 「기존 활성본이 볼트 이력에 있나」

업로드 전 활성본의 길이·해시를 떠 두고, `git log`로 그 파일의 과거 판을 훑어 **같은 값이 나오는 판을 찾는다**. 찾으면 「우리가 전에 올린 판」이므로 덮어써도 된다. 못 찾으면 외부 수정이다.

### ⚠️ 함정 6가지 (전부 실측)

- **로그인 버튼이 셀렉터로 안 눌린다** — 같은 글자의 버튼이 여러 개라 `click`이 실패한다 → **JS로 `disabled`가 아닌 버튼을 찾아 `.click()`**
- **글자수 표시는 본문 길이 + 1** (끝 줄바꿈 포함) — `5,537자` ↔ 본문 5,536
- **JS `charCodeAt`은 UTF-16 코드 유닛** — 이모지(🚫·🖼)가 2로 세어진다. 파이썬에서 같은 해시를 내려면 **UTF-16-LE 코드 유닛**으로 비교할 것(코드포인트로 세면 길이가 어긋난다)
- **`textarea`는 화면에 1개** — 슬롯을 바꾸면 그 안의 내용만 교체된다
- **draft 행 식별** = 행 텍스트가 `draft`로 시작 ＋ 오늘 날짜 · 활성 행에는 `활성화` 버튼이 없다(`불러오기`·`삭제`만)
- 🔐 **작업 중 로그인이 풀린다** — 어드민·빌더는 **같은 계정을 사람과 자동화가 동시에 쓰면 서로 밀어낸다**(로그인 쿠키가 httpOnly라 토큰을 갱신하는 쪽이 상대 세션을 무효화). 긴 업로드 작업 전에 **그 계정으로 빌더를 쓰고 있는 사람이 있는지 확인**하고, 작업 중 `/login`으로 튕기면 **다시 로그인한 뒤 활성화 상태를 눈으로 확인**한다(활성화를 눌러도 목록이 안 바뀌면 그 사이 세션이 끊긴 것)
- **긴 본문은 CLI 인자로 넘기지 말 것** — 20~40KB라 잘린다 → **JS 파일에 JSON 문자열로 적어 `eval` 로 실행**
