# MD-05. 페이지 유형 판정

## 1. 입력

- **설명 글** — 유저가 확인·수정을 끝낸 페이지 설명 1개
- **목적** — 유저가 확정한 목적 문구 1개
- **추가 항목** — 유저가 **켠 칩만** (문구 · 추가할 섹션 목적 · 들어갈 자리)
- **타겟** — 타겟 문구 1개 ＋ 유저가 고른 라벨
- **주제 코드** — 앞 단계에서 자동 판정한 주제(25개 중 1개 · **화면 노출 ❌**) → 그 주제의 **조립 레시피**를 펼친다
- **조립 레시피** — 그 주제의 섹션 목록. **관문 1(반복 항목)·관문 2(카드 수)를 재는 자**다

## 2. 출력

페이지 유형 1개 (원페이지 / 멀티페이지)

## 3. 규칙

- 유저에게는 **통보형** — 고르게 하지 않고 정해서 보여준 뒤 `바꾸기`만 둔다
- **애매하면 원페이지** — 멀티로 나누면 표지·목차·페이지마다 반복되는 헤더 때문에 **카드가 오히려 늘어난다**

### 3-A. 3관문 — 앞에서 걸리면 거기서 끝

| | 묻는 것 | 판정 |
|---|---|---|
| **0** | 목적이 **알림 · 초대 · 접수**이고, **알리는 대상이 1건**인가 | 둘 다 ✅ → **원페이지 확정 (끝)** |
| **1** | 같은 항목이 **3개 이상** 반복되고, **항목 하나가 카드 3장 이상**인가 | ✅ → **멀티 확정 (끝)** |
| **2** | 카드가 **35장 이상**인가 | ✅ → 멀티 / ❌ → 원페이지 |

### 3-B. 관문별 판정 기준

- **관문 0 · 「대상이 1건」** — 행사 1건짜리 초대장·예약 페이지는 페이지를 넘기게 하면 신청이 샌다 → 원페이지.
  ⚠️ **단 대상이 여러 건이면 여기서 끝내지 말고 다음 관문으로 넘긴다** — 행사 19건이 묶인 안내 책자, 매장 20곳 목록, 품목 50종 카탈로그는 목적이 「알림」이어도 원페이지가 아니다. **세는 것 = 행사 수 · 매장 수 · 품목 수 · 모집 건수.**
- **관문 1 · 「크게 반복되는 항목」** — 룩북·포트폴리오·도록·신제품·매거진(기사별)이 여기 걸린다. **둘 다 만족할 때 ✅**:
  1. **같은 형식의 항목이 3개 이상** 반복된다 (룩 1·2·3 / 프로젝트 1·2·3 / 기사 1·2·3)
  2. **항목 하나가 카드 3장 이상**이다 — 항목 하나가 화면 한 장을 채운다는 뜻
  - 🔑 **가르는 건 「이미지냐 글이냐」가 아니라 「항목 하나가 얼마나 큰가」다** — 사진 없는 소식지·매거진도 **기사 한 편이 한 장 분량**이면 멀티다
  - ❌ **반례** — 메뉴판·품목표·지점 목록: 항목은 반복되지만 **하나가 1~2카드**(이름·가격 한 줄)라 나열이다 → 여기서 끝내지 말고 관문 2로
  - **전체 카드 수가 적어도 멀티**다 (룩북은 한 장에 4~5장뿐)
- **관문 2 · 「35장」** — 조립 레시피를 펼쳐 **카드 수를 세어** 판정한다.
