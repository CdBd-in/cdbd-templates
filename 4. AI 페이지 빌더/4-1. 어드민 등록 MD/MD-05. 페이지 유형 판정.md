# MD-05. 페이지 유형 판정

## 1. 입력

- **설명 글** — 유저가 확인·수정을 끝낸 페이지 설명 1개
- **목적** — 유저가 확정한 목적 문구 1개
- **추가 항목** — 유저가 **켠 칩만** (문구 · 추가할 섹션 목적)
- **타겟** — 타겟 문구 1개 ＋ 유저가 고른 라벨
- **주제 코드** — 앞 단계에서 자동 판정한 주제(25개 중 1개 · **화면 노출 ❌**) → 그 주제의 **조립 레시피**를 펼친다
- **조립 레시피** — 그 주제의 섹션 목록. **관문 2(나열 항목 수)·관문 3(카드 수)을 재는 자**다

## 2. 출력

페이지 유형 1개 (원페이지 / 멀티페이지)

## 3. 규칙

- 유저에게는 **통보형** — 고르게 하지 않고 정해서 보여준 뒤 `바꾸기`만 둔다
- **애매하면 원페이지** — 멀티로 나누면 표지·목차·페이지마다 반복되는 헤더 때문에 **카드가 오히려 늘어난다**

### 3-A. 3관문 — 앞에서 걸리면 거기서 끝

| | 묻는 것 | 판정 |
|---|---|---|
| **1** | 목적이 **알림 · 초대 · 접수**이고, **알리는 대상이 1건**인가 | 둘 다 ✅ → **원페이지 확정 (끝)** |
| **2** | **나열 항목이 4개 이상**인가 *(반복되는 대상 — 제품 · 룩 · 기사 · 지점 · 회차)* | ✅ → **멀티 확정 (끝)** |
| **3** | 카드가 **35장 이상**인가 | ✅ → 멀티 / ❌ → 원페이지 |

### 3-B. 관문별 판정 기준

> 🔑 **세 관문이 세는 단위 = 「대상」 한 건** — 이 페이지가 보여주려는 것 하나다. **행사 1건 · 제품 1종 · 룩 1벌 · 프로젝트 1건 · 기사 1편 · 매장 1곳.**
> **관문 1·2가 세는 건 「대상 건수」 하나다** — **1건이면 원페이지** · **4건 이상이면 멀티** · **2~3건이면 관문 3(분량)으로** 넘긴다.

- **관문 1 · 「대상이 1건」** — 행사 1건짜리 초대장·예약 페이지는 페이지를 넘기게 하면 신청이 샌다 → 원페이지.
  ⚠️ **단 대상이 여러 건이면 여기서 끝내지 말고 다음 관문으로 넘긴다** — 행사 19건이 묶인 안내 책자, 매장 20곳 목록, 품목 50종 카탈로그는 목적이 「알림」이어도 원페이지가 아니다. **세는 것 = 대상 건수**(행사 수 · 매장 수 · 품목 수 · 모집 건수).
- **관문 2 · 「나열 항목 4개 이상」** — 레시피에서 **같은 형식으로 반복되는 대상**이 **4건 이상**이면 **페이지로 나눈다**(제품 · 룩 · 기사 · 프로젝트 · 지점 · 회차).
  - 🔎 **세는 법** — 그 **나열의 항목 수**를 센다. **3건 이하는 한 화면에 무리 없이 들어간다** → 관문 3으로
  - 🧩 **한 페이지에 몇 건씩 담을지**는 여기서 정하지 않는다 → [[MD-06. 페이지 구성]]
  - **전체 카드 수가 적어도 멀티**다 (룩북은 한 장에 4~5장뿐)
- **관문 3 · 「35장」** — 조립 레시피를 펼쳐 **카드 수를 세어** 판정한다.
