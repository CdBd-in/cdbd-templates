# MD-06. 페이지 구성

## 1. 입력

- **설명 글** · **목적** · **타겟** — 유저가 확정한 문구들
- **추가 항목** — 유저가 **켠 칩만** (문구 · 추가할 섹션 목적) — **어느 자리에 넣을지는 이 문서가 정한다**(3-B)
- **주제 코드** — 앞 단계에서 자동 판정한 주제(25개 중 1개) → 그 주제의 **조립 레시피**를 펼친다
- **조립 레시피** — 그 주제에 **어떤 섹션을 어떤 순서로** 넣는지 미리 정해 둔 목록. 이 문서의 **주 재료**
- **페이지 유형** — `원페이지` 또는 `멀티페이지`
- **목적 분류** — 앞 단계에서 주제로부터 자동 파생한 6종(알림 · 초대 · 접수 · 진열 · 전환 · 인물) → 멀티일 때 **어느 덩어리를 어느 장에** 놓을지의 기준(3-C)

## 2. 출력

`[페이지1: 섹션 a → b → c] [페이지2: …]` 형태의 구성표

## 3. 규칙

### 3-A. 섹션 고르기·순서

- **공통 골격**(히어로 → … → 문의)을 먼저 깔고 **그 주제의 레시피가 정한 섹션**으로 채운다
- **최상단은 반드시 히어로** — 작은 소개 카드로 페이지를 열지 않는다
- 📥 **첫 입력 글·자료에 재료가 있는 섹션은 칩과 무관하게 넣는다** — 주소가 있으면 위치 안내, 가격표가 있으면 구매·나열. **유저가 준 내용은 물어보지 않고 쓴다**
- **추가 항목 칩**([[MD-03. 추가 항목]])에서 켜진 것을 **3-B가 정한 자리**에 끼운다 — 칩은 **재료가 아직 없는 섹션**만 올라온다
- 🎲 **어떤 섹션 목적을 넣을지 정했으면, 그 서랍에서 실제 섹션은 「거른 뒤 랜덤」으로 뽑는다** — 내용에 맞는 것만 먼저 추리고, 그중 **랜덤**으로 (절차는 아래)
- 🖼 **이미지가 없으면 이미지 칸이 적은 섹션을 고른다** — 스타일을 바꾸는 게 아니라 **여기서** 해결한다

### 3-B. 추가 항목 자리·순서

> 유저가 **켠 칩**([[MD-03. 추가 항목]])을 페이지 어디에 넣나. **03은 「무엇을 더할지」까지만 정하고, 자리는 여기서 정한다.**

**① 기본 자리**

|  순  | 섹션 목적     | 들어갈 자리 (기본값)                  |
| :-: | --------- | ----------------------------- |
|  1  | **프로모션**  | 히어로 직후 — 혜택은 위에서 끌어당긴다        |
|  2  | **소개**    | 히어로 바로 아래(도입)                 |
|  3  | **스토리**   | 도입 · 전환이 목적인 페이지는 **결정 섹션 뒤** |
|  4  | **핵심 정보** | 도입 다음                         |
|  5  | **나열**    | 결정 섹션 다음                      |
|  6  | **자료**    | 결정 섹션 다음                      |
|  7  | **구매**    | 보여준 다음                        |
|  8  | **예약**    | 보여준 다음                        |
|  9  | **안내사항**  | **폼·예약 바로 위** — 신청 전에 읽어야 한다  |
| 10  | **폼**     | 문의 앞                          |
| 11  | **위치 안내** | 문의 앞                          |

- 🧭 **자리는 「그 내용이 페이지에서 하는 역할」로 정한다** — 같은 목적이어도 자리가 다르다. **제품 사진**은 구매 바로 위(사기 전에 본다), **고객 후기**는 신청·구매 직전(마음을 정하는 자리) → **나란히 붙일 이유가 없다**
- 표의 자리는 **기본값**이다. 내용이 뚜렷한 역할을 가지면 **그 역할이 자리를 정한다** · 역할이 애매하면 기본값 그대로 (그때그때 흩뜨리지 않는다)

**② 여러 개를 켰을 때 순서**

- 📐 **표의 위→아래가 곧 페이지의 위→아래** — 여러 칩이 켜지면 **이 번호 순서대로 쌓는다**
- 🚫 **유저가 켠 순서는 뜻이 없다** — 화면에 나열된 순서로 눌렀을 뿐이다. 켠 순서로 배치하지 않는다
- 🧭 **순서의 뜻 = 끌고 → 알리고 → 보여주고 → 받는다** — `프로모션` → `소개·스토리·핵심 정보` → `나열·자료` → `구매·예약·폼`. **행동을 요구하는 섹션일수록 뒤**(위에 두면 아직 판단이 안 선 사람에게 결정을 요구하게 된다)
- 🔗 **붙어 다니는 짝은 떼지 않는다 — 번호보다 우선** — `안내사항`은 **폼·예약 바로 위** · `고객 후기`는 **구매·신청 직전**. 짝이 성립하면 번호 순서를 건너뛴다
- 같은 번호 안에서 둘이면(자료 2개 등) **역할로 가르고**(①), 역할이 애매하면 **재료가 많은 쪽을 앞으로**

### 3-C. 멀티페이지 분할

> 원/멀티 판정은 [[MD-05. 페이지 유형 판정]]가 이미 끝냈다. 여기서는 **몇 장으로 · 무엇을 어느 장에** 나눌지 정한다.
> 🔒 **멀티는 4페이지 이상일 때만 성립한다** — 나눠 봐서 **3장 이하면 원페이지로 되돌린다**(05 관문 3과 같은 선). 표지·목차도 1장으로 센다.
> 📈 **4장은 하한이지 상한이 아니다** — 내용이 많으면 **5장·10장·50장도 만든다**(멀티 상품이 「4페이지 최소 400크레딧」이라 장이 늘면 크레딧도 는다). 장수를 4장에 맞추려고 내용을 구겨 넣지 않는다.

**① 나누는 축 — 왜 멀티가 됐는지에 따라 다르다**

| 멀티가 된 이유 | 자르는 축 |
|---|---|
| **나열 항목이 무겁다** (4건 이상 · 항목마다 사진·설명·스펙) | **대상 하나 = 한 장** (제품 · 룩 · 기사 · 프로젝트 · 지점 · 회차) |
| **분량이 많다** (카드 35장 이상) | **목적 덩어리로** 자른다 (②) |

- 🔑 **대상 「건수」가 아니라 「하나의 무게」로 나눈다** — 한 줄로 끝나는 목록(이름＋가격 메뉴판 · 전화번호만 있는 매장 목록)은 **50건이어도 나누지 않는다**. 그런 페이지는 05 관문 2에서 이미 원페이지로 걸러진다
- **대상이 많고 하나하나가 무거우면 장이 그만큼 늘어난다** — 품목 50종에 사진·설명·스펙이 다 붙으면 **50장이 정상**이다. 장수를 줄이려고 억지로 묶지 않는다

**② 목적별 기본 분할 — 4장 기준**

> 목적 분류는 **내부 이름**이다(화면 노출 ❌). 아래는 **기본값**이고, 내용이 더 많으면 같은 순서로 장을 늘린다.

| 목적 | P1 | P2 | P3 | P4 |
|---|---|---|---|---|
| **알림** | 표지 ＋ 목차 | 대상별 상세 *(건수만큼 반복)* | 〃 | 공통 안내 · 문의 |
| **초대** | 표지 · 초대의 말 | 프로그램 · 일정 | 안내 사항 · 준비물 | 회신 · 위치 · 문의 |
| **접수** | 표지 · 왜 신청하나 | 모집 내용 · 조건 | 안내 사항 · 마감 | 폼 · 문의 |
| **진열** | 표지 ＋ 목차 | 아이템 내지 *(1건 = 1장)* | 〃 | 마무리 · 문의 |
| **전환** | 히어로 · 가격 · 구매 | 상세 · 스펙 | 근거(후기 · 프로모션) | 안내 사항 · 구매 재노출 |
| **인물** | 프로필 ＋ 주요 채널 | 이력 · 경력 | 작업 · 자료 | 연락처 · 문의 |

- **알림 · 진열**은 가운데 장이 **대상 수만큼 반복**된다(표의 P2·P3은 대표 표기)
- **초대 · 접수 · 전환 · 인물**은 대상이 1건이라 **4장이 상한에 가깝다** — 내용이 4장을 못 채우면 **원페이지**다

**③ 공통 규칙**

- 🔀 **목차 자리는 고정이 아니다** — **표지 안에 목차를 넣어도** 되고, **표지 다음 장을 목차 페이지로** 두어도 된다. 항목이 적으면 표지 안, 항목이 많아 표지가 빽빽해지면 별도 장으로
- 서브페이지엔 **상단 고정 헤더**를 두어 목차·표지로 돌아갈 수 있게 한다 (**메뉴 카드**)
- **한 페이지에 목적이 둘 이상 섞이지 않게**
- 🚫 **신청·구매는 쪼개지 않는다** — 폼·구매는 **한 장 안에서 끝나야** 중간에 샌다
- **장수는 최소로** — 페이지마다 헤더·브랜드가 반복돼 **카드가 오히려 늘어난다**(실측 21카드 = 전체의 24.7%)

### 🎲 섹션 뽑는 절차 — 「거른 뒤 랜덤」

```
섹션 자리마다:
  후보 = 그 서랍에서 「이 페이지 내용에 맞는 것」만 추림      ← ① 품질이 먼저
  후보가 3개 이하면 → 그대로 쓴다 (다양성 면제)             ← ② 얇은 서랍
  아니면          → 랜덤으로 뽑되 「앞 안이 쓴 것」은 제외    ← ③ 비복원
끝나면 기록한다: 시드 · 쓴 섹션 id · 레이아웃 유형 · 팔레트
```

- 🔴 **거르는 조건은 칸 「개수」가 아니라 「역할」이다** — 개수만 맞추면 연혁용 섹션(연도·회사명·역할)에 링크 목록이 들어가 글자 크기가 제각각이 된다. 볼 것 = ⓐ 텍스트 덩어리 수 ⓑ 칸의 역할(`YYYY` · `hh:mm` · 버튼 · 아이콘) ⓒ 이미지 역할(로고 / 프로필 / 지도 / 메인) ⓓ 칸 폭 대비 글자량(폭이 좁은 칸에 긴 글 ❌)
- **장식용 기호 칸(`——` · `"` · `★★★★★`)은 내용 칸이 아니다** — 본문을 넣지 않는다
- **남는 칸을 잘라내지 않는다** — 마지막 행을 지우면 그 행이 들고 있던 **섹션 하단 여백(36)** 이 함께 사라진다
- **멀티페이지 내비게이션은 「메뉴 카드」로** — 메뉴 카드의 본래 용도가 **페이지 이동 · 같은 페이지 카드로 점프 · 외부 링크**다

## 4. 부록 — 섹션 목적 13칸 (용어 정본)

> 🔒 **이 이름 그대로 쓴다 — 새 이름을 지어내지 않는다.** 섹션 라이브러리의 서랍 이름이자 어드민 프리셋 편집기의 분류와 같은 말이다.

| 섹션 목적 | 무엇을 담나 |
|---|---|
| **히어로** | 페이지 첫 화면 — 제목·한 줄 소개 (최상단 **필수**) |
| **소개** | 우리가 누구·무엇을 하는지 |
| **핵심 정보** | 일시·장소·가격 같은 **라벨 + 값** |
| **스토리** | 배경·취지·이야기 (긴 글) |
| **안내사항** | 유의사항·준비물·주의 |
| **나열** | 같은 모양 항목의 반복 (프로그램·메뉴·목록) |
| **자료** | 이미지·후기·자료 모음 |
| **예약** | 회차 선택 (버튼 1개 = 회차 1개) |
| **폼** | 신청·설문·문의 입력 받기 |
| **구매** | 상품 + 가격 + 구매 버튼 |
| **프로모션** | 할인·쿠폰·이벤트 |
| **위치 안내** | 지도 + 주소 + 길찾기 |
| **문의** | 전화·카톡·이메일 버튼 |

**구조 뼈대 2종**(목적 13칸 **밖** · 선택) — **헤더** · **푸터**

⚠️ 띄어쓰기까지 그대로 — `핵심 정보` · `위치 안내`(붙여 쓰지 않는다)
