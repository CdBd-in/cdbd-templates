# MD-06. 페이지 유형 판정

> 📍 **화면**: 6 · 페이지 유형 · [피그마에서 보기](https://www.figma.com/design/24O01lprp5i2ufl7CbZXXx/AI-%EC%84%B9%EC%85%98-%ED%94%84%EB%A6%AC%EC%85%8B?node-id=6919-10907)
> 🗒 **출처**: 피그마 코멘트 (2026-09-10, codeisneverodd)

## 1. 무엇을 정하는 MD인가

**원페이지 / 멀티페이지** 중 하나를 판정한다.

> 📌 **근거 한 줄은 AI가 짓지 않는다 (2026-09-11 이선호)** — 유형(원/멀티)마다 **미리 써 둔 문구**를 그대로 내보낸다. 이 MD는 **유형만 판정**하고, 문구는 **어드민에 등록해 둔 두 줄**(원페이지용·멀티페이지용) 중 하나를 부른다. → [[MD-01. UX 라이팅]] 적용 대상 아님.

## 2. 입력

**설명 글** · **목적** · **추가 항목**(켠 것) · **타겟** · **내부 판정 주제코드**

> 📥 칸 정의 = [[MD-01. UX 라이팅]] 「부록 — 단계별 누적 정보」

## 3. 출력

페이지 유형 1개 (화면에 나가는 근거 한 줄 = 미리 써 둔 문구를 그대로)

## 4. 규칙

- ⚠️ 판정 기준 **미확정** — 아래 「4관문」을 검토 중이다
  (0.목적 P1·P2·P3 = 원페이지 확정 → 1.챕터 ≥3 → 2.장면형 → 3.카드 ≥35)
- 유저에게는 **통보형** — 「○○페이지로 만들어 드릴게요」 + 근거 한 줄(어드민에 등록해 둔 유형별 고정 문구) + `바꾸기`
- 크레딧이 다르므로(원 120C / 멀티 400C) **근거가 납득되어야 한다** — 다만 문구는 고정이라 **판정만 틀리지 않으면 된다**

> 🚧 여기에 실제 생성 지침(프롬프트 수준의 규칙·예시·금지 사항)을 채운다.

## 5. 함께 지키는 것

- **4관문(검토 중)** — 뒤로 갈수록 멀티페이지 쪽이다
  ① 목적이 **알림·초대·접수**면 → **원페이지 확정**(여기서 끝) → ② 성격이 다른 **챕터가 3개 이상**인가 → ③ **한 장면씩 넘겨 보는** 구성인가 → ④ 카드가 **35장을 넘는가**
- **유저가 유형을 고르게 하지 않는다** — 앞 단계에서 이미 충분히 말했으므로 **정해서 보여주고 `바꾸기`만** 둔다
- **근거 한 줄은 AI가 짓지 않는다** — 유형마다 어드민에 등록해 둔 고정 문구를 그대로 부른다

## 6. 원본 코멘트

```
앞선 3단계 내용 기반으로 어떤 페이지 유형을 사용할지. 원페이지, 멀티페이지
```
