# MD-03. 추가 항목

## 1. 입력

- **설명 글** — 유저가 확인·수정을 끝낸 페이지 설명 1개
- **목적** — 유저가 확정한 목적 문구 1개
- **주제 코드** — 앞 단계에서 자동 판정한 주제(25개 중 1개 · **화면 노출 ❌**) → 그 주제의 **조립 레시피 = 이미 들어갈 섹션 목록**(= 제외 대상)

## 2. 출력

칩 **5개** + **나열 순서**. 칩 하나 = `{ 화면에 보일 문구, 추가할 섹션 목적, 들어갈 자리 }`

## 3. 규칙

⚠️ **성격은 「목적」이 아니라 「담을 내용·기능」이다**.
유저는 바로 위 입력창에서 **목적을 이미 말했다.** 이 칩은 그 목적을 다시 고르게 하는 게 아니라, **함께 있으면 좋을 섹션을 추가로 권하는 것**이다. → **칩 하나 = 페이지에 섹션 하나 추가.**

- 🔴 **필수 섹션은 칩으로 올리지 않는다** — 레시피에 **이미 들어가는 섹션**을 제안하면 유저는 「이미 되는 걸 또 고르는」 셈이 된다. 후보 = **레시피 필수 섹션을 뺀 나머지**
- 🔴 **칩마다 「섹션 목적」과 「들어갈 자리」가 미리 정해져 있어야 한다** — 무엇을 무엇에 붙이나 = **§4**
- 🗣 **칩 문구는 유저 말로** — 섹션 목적 용어를 그대로 노출하지 않는다 (`폼` ❌ → `참석 신청받기`)
  - 단 **`모집`·`접수`·`예약` 같은 업무 용어는 그대로 쓴다** — 쉬운 말로 풀어쓰라는 게 아니라 **우리 분류어를 감추라는 것**
- **칩 라벨은 명사구** — 문장도 질문형도 ❌ (`참석 신청받기` ✅ · `참석 신청을 받으시겠어요?` ❌). 묻는 일은 화면 제목(고정 문구)이 한다
- **개수 5개 고정** · 칩 문구 **12자 이내**(칩 1줄)
- 📋 **나열 순서 = 근거가 센 것부터** ① **첫 입력 글·자료에 실제로 나온 것** → ② 그 주제에서 흔한 것 → ③ 일반적인 것
- **칩끼리 겹치지 않게** — 포함 관계 ❌ (`문의` ↔ `상담 문의`)

## 4. 칩 ↔ 섹션 목적 매핑

> 🔑 **방향은 「섹션 목적 → 문구」다.** 유저 말에서 거꾸로 올라가면 13칸 밖 이름이 생긴다 → **후보 섹션 목적을 먼저 고르고, 그다음 유저 말로 문구를 붙인다.**
> 목적 이름 정본 = [[MD-06. 페이지 구성]] 「부록 — 섹션 목적 13칸」. 그 목록 밖의 이름을 지어내지 않는다.

- **1칩 = 섹션 목적 1개** — 한 칩이 섹션 둘을 더하지 않는다
- **한 목적당 칩 1개까지** — `후기 싣기`·`사진 보여주기`가 둘 다 「자료」면 **하나만** (= *칩끼리 겹치지 않게*의 구체판)
- **들어갈 자리도 목적마다 이미 정해져 있다** — AI가 그때그때 정하지 않는다

| 섹션 목적 | 칩 문구 예 (12자 이내) | 들어갈 자리 |
|---|---|---|
| **소개** | `어떤 곳인지 알리기` | 히어로 바로 아래(도입) |
| **스토리** | `시작한 이야기` | 히어로 바로 아래(도입) · 전환이 목적인 페이지는 **결정 섹션 뒤** |
| **핵심 정보** | `일시·장소 안내` | 도입 다음 |
| **프로모션** | `할인 안내하기` | 히어로 직후 (혜택은 위에) |
| **나열** | `프로그램 소개` | 결정 섹션 다음 |
| **자료** | `사진 보여주기` | 결정 섹션 다음 |
| **구매** | `바로 구매받기` | 결정 섹션 다음 |
| **예약** | `시간 골라 예약받기` | 결정 섹션 다음 |
| **안내사항** | `준비물 알리기` | **폼·예약 바로 위** (신청하기 전에 읽어야 하므로) |
| **폼** | `참석 신청받기` | 문의 바로 위 |
| **위치 안내** | `오시는 길 넣기` | 문의 바로 위 |

🚫 **칩이 될 수 없는 2칸** — **히어로**(항상 필수) · **문의**(사실상 필수라 이미 들어 있다). **골격이 이미 갖고 있는 자리는 칩으로 올리지 않는다.**
