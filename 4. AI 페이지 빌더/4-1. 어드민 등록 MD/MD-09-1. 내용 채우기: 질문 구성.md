# MD-09-1. 내용 채우기: 질문 구성

## 0. 반드시 지킬 것

> 가장 어기기 쉬운 절대 규칙만 모았다. **출력을 내기 전에 한 줄씩 대조한다.** 상세 기준·예외·예시는 아래 본문이 정본이다.

1. **인풋은 12종 밖 창작 ❌ · 반복은 2단까지** — 12종 밖이 필요해 보이면 **가장 가까운 종류(대개 텍스트)로** 받는다 · 3단이 필요해 보이면 **가장 안쪽 반복을 텍스트 칸 줄 나열로** · **같은 꼴 묶음 2벌 이상 = 반드시 반복으로**(칸 1개짜리·딱 2벌이어도 · 칸을 평평하게 펼쳐 나열 ❌ · 꼴 비교는 안내 문구·버튼을 떼고) · **한 행의 칸들(2열 카드의 셀) = 반복 한 벌** — 셀마다 따로 반복 항목으로 펼치지 ❌ · 단 **행 안에서 같은 꼴 쌍이 또 반복되면(표형 4칸 = 라벨＋값 쌍×2) 벌 = 그 쌍** · **바깥 반복 한 벌 = 견본 항목 하나 전체**(사진부터 마지막 행까지) — 항목 안의 같은 꼴 행(스펙 행)은 그 항목의 **안쪽 반복** · 남는 행을 새 바깥 항목으로 꺼내지 ❌ · **바깥 항목은 전부 같은 칸 구성**
2. **인풋 종류는 「받는 값」이 정한다** — 날짜·시각 = 피커 · **지도에 쓰일 주소 = 검색 · 글자로만 보이는 장소 이름 = 제목 텍스트** · URL = 링크 · 가격·정원 = **단위를 포함한 한 줄 값**(`제목 텍스트` — `35,000원`·`20명` · 별도 단위 UI 없음) (일시를 자유 텍스트 칸으로 ❌) · **연락·채널 버튼(문의 섹션의 전화·카카오·이메일·홈페이지 단위) = `유형`(드롭다운) ＋ `버튼 문구` ＋ `연락처` 세 칸 한 벌**(값 칸을 빼지 ❌ — 번호가 글자로 노출된다 · 전 항목 같은 칸 라벨)
3. **입력칸 안 만드는 것 = 섹션 제목 · 사실 행의 고정 라벨(`일시`·`장소`) · 아이콘 그림 자리(고른 유형을 따라가는 그림) · 넘버링 표식(`01`·`02` — 묻지 않고 출력에 「그 번호가 들어갈 자리의 이름」만 적어 주면 항목 순서는 **시스템**이 넣는다)** — 고정 라벨은 표기만 하고 **값 칸만** 받는다 · **eyebrow는 입력칸을 주되 라벨 = 「제목 위 문구」 고정**(견본 글자 라벨 ❌) · **항목 왼쪽 이모지 칸은 입력칸을 준다 — 그 행의 글과 한 벌 `[아이콘 ＋ 내용]`** · `채움=AI` 칸은 입력칸을 준다
4. **라벨: 고정 8개 우선 · 영어/제작 용어(`EYEBROW`·`CTA`·`label`·`히어로`) ❌ · 국문 「~ 라벨」·「~ 값」도 ❌ · 한 단계에 같은 라벨 두 개 ❌** — 같아지면 앞에 구분어(2단 반복의 안쪽 라벨＋값 줄 = `항목`·`내용`) · **칸 하나뿐인 단계는 주어 = 칸 라벨과 같은 말** · **고른 유형 따라 바뀌는 라벨 ❌**(범용어로 — `연락처` ✅ `전화` ❌)
5. **같은 역할의 이미지 자리 여럿 = 「복수 이미지」 인풋 하나** — 역할이 다른 것(메인·로고·프로필)만 각각 인풋 ＋ 예외 라벨 · **한 섹션(반복이면 한 항목)에 함께 놓인 같은 대상의 사진 = 같은 역할**(슬롯 이름 `이미지`·`서브 이미지`·`갤러리` · 크기·배치가 달라도) · **`메인 이미지` 라벨은 히어로 단계 전용**
6. **방문자가 받아 갈 문서 = 「파일」 인풋** — 이미지 인풋과 별개 · 페이지의 다운로드 버튼에 연결
7. **필수/선택 = 「비면 그 섹션이 성립하는가」** — AI가 채운 칸도 찬 것 · **`이건 없어요` = 그 질문만 건너뛴다**(같은 단계의 채워진 다른 값 삭제 ❌) · **상품·메뉴의 가격은 선택**(비면 가격 칸만 빠지고 항목은 남는다)
8. **단계 순서 = 페이지 섹션 순서 · 칸 순서 = 섹션에서 보이는 순서 · 한 섹션을 쪼갠 단계들의 순서도 = 보이는 순서**(히어로 문구가 이미지보다 위에 보이면 문구 단계가 먼저) · **반복 항목 안의 칸 순서도 = 보이는 순서**(사진이 이름 위에 보이면 `이미지` 칸이 먼저 · 대표 칸 `제목`이라고 맨 앞으로 옮기지 ❌) · **라벨로 나뉜 영역(`일시`·`장소`·`참가비`)은 반복 항목이 아니면 영역마다 따로 묻는다**(한 단계에 묶지 ❌ · 주어 = 그 라벨)
9. **한 섹션 = 기본 한 단계** — 나누는 건 칸 5개↑·히어로·라벨 영역(반복 아닐 때)뿐 · 같은 섹션의 글＋이미지 쪼개기 ❌(히어로 전용 규칙의 일반화 ❌)
10. **칸 ↔ 슬롯 양방향 1:1** — 칸 = 실존 슬롯만(이름 연상 칸 ❌) · 편집 슬롯엔 전부 받는 칸(예외 = 제외 넷) · **모든 칸에 플레이스홀더**(안내 문구·버튼 문구 칸 포함 · 못 짓겠으면 지시형)

> 🔑 **케이스마다 화면을 미리 그려 두지 않는다.** 인풋은 **종류 12개와 반복 여부**만 정해져 있고, **채택한 섹션의 정보 구조를 보고 그때그때 조합**한다.

## 1. 입력

| 값 | 내용 |
|---|---|
| **구성** | `{섹션 목적, 섹션 id, 순서, 페이지 번호}` 배열 |
| **섹션 슬롯** | 각 섹션이 가진 빈칸의 이름·개수·반복 구조 |
| **시안 텍스트** | 각 섹션에 이미 들어간 글 |
| **설명 글 · 자료** | 유저가 쓴 설명과 첨부한 파일·URL |

## 2. 출력

**질문 단계 배열.** 단계 하나는 이렇게 생겼다.

```
{
  주어        : 왼쪽 제목에 들어갈 섹션 이름표
  한 번만 받는 칸 : [{ 칸 }, ...] — 항목마다 반복되지 않고 섹션에 한 번만 있는 칸(제목 위 문구 · 리드 설명) · 없으면 빈 배열
  칸 배열     : [{ 라벨, 인풋 종류, 필수/선택, 플레이스홀더, 들어갈 자리, 스위치 동작 }, ...]
                반복이면 이 배열 = 묶음 「한 벌」의 칸 (항목마다 통째로 복제된다)
  반복        : 없음 | 1단 | 2단
                반복이면 → { 묶음 라벨(칸 라벨을 생략할 때만), 대표 칸, 안쪽 추가 버튼 이름(2단일 때만), 넘버링 자리 }
  안내 문구   : [{ 플레이스홀더 }, ...] — 반복 「바깥」 안내 자리 수만큼(대개 0~1개) · 배열 순서 = 그 섹션에서 보이는 순서
  버튼 문구 칸 : [{ 플레이스홀더 }, ...] — 버튼 수만큼 · 배열 순서 = 그 섹션에서 버튼이 보이는 순서
}
```

- 🧢 **「한 번만 받는 칸」 = 반복 섹션에서 항목에 딸리지 않고 섹션 맨 위에 한 번만 있는 칸** — 반복 섹션은 글 자리가 두 갈래다: ⓐ **항목마다 반복되는 칸**(사진·이름·설명) ⓑ **섹션 전체에 한 번만 있는 칸**(`제목 위 문구` · 섹션을 여는 리드 설명 한 줄). ⓑ를 이 배열에 낸다
 - **예** — 섹션이 `제목 위 문구 → 리드 설명 → [사진＋이름＋설명] ×3` 꼴이면 → **한 번만 받는 칸** = `제목 위 문구`·`리드 설명` · **칸 배열**(묶음 한 벌) = `이미지`·`제목`·`내용`
 - 🚫 **ⓑ를 칸 배열에 섞지 ❌ — 항목마다 복제된다**
 - **반복이 없는 단계는 이 배열을 쓰지 않는다** — 칸이 전부 한 번만 받는 칸이라 **칸 배열에 그대로 둔다**(빈 배열)
- 📍 **들어갈 자리 = 그 값이 실리는 섹션 슬롯** — 칸마다 적는다(3-3 🧩 「칸↔슬롯 대조」를 출력으로 낸 것). **두 칸이 한 슬롯에 합쳐 들어가면 합치는 형식까지** 적는다(`일시 텍스트 ← 시작~종료` · `가격 텍스트 ← 정상가/할인가`). 🚫 **자리를 못 적는 칸은 섹션에 슬롯이 없는 칸**이니 칸 자체를 다시 의심한다 — 받은 값이 **그대로 버려진다**
- 🔢 **넘버링 자리** — 반복 항목에 `01`·`02`·`No.`가 찍히는 자리가 있으면 **그 자리의 이름**을 적는다(`넘버링 자리: 번호 텍스트`) · 그런 자리가 없으면 `없음`. 입력칸은 만들지 않고(3-0-B) **항목 순서를 시스템이 그 자리에 넣는다**(추가·삭제·이동하면 다시 매긴다). 🚫 **자리를 안 적으면 아무도 안 채워 빈칸으로 남는다**
- **스위치 동작** — `토글` 칸에만. 켜면 **어느 칸을 숨기는지/드러내는지/잠그는지, 라벨이 어떻게 바뀌는지**를 적는다 (3-8)
- **연락·채널 버튼은 세 칸 한 벌로 받는다 — `유형` ＋ `버튼 문구` ＋ `연락처`** — 문의 섹션의 전화·카카오·이메일·홈페이지 같은 **아이콘＋글자 단위는 전부 링크 버튼**이다. 항목마다 ⓐ**유형** 칸 = 드롭다운(전화·문자·이메일·카카오·홈페이지 — 고른 유형이 아이콘과 동작을 정한다) ⓑ**버튼 문구** 칸 = 방문자에게 보일 행동·채널 이름(`전화 문의`·`카톡 상담` — 채움 = AI) ⓒ**연락처** 칸 = 전화번호·채널 링크·이메일·홈페이지 주소(고른 유형에 맞는 인풋 · 채움 = 사실 — 자료에 있을 때만). 🚫 **세 칸 중 하나를 빼지 ❌** — 유형이 빠지면 동작이 미정이고, 연락처 칸이 빠지면 번호가 글자로 노출된다. 🚫 같은 위계의 채널 항목들인데 칸 라벨이 서로 다르면 ❌ — **전 항목 같은 칸 라벨**(`유형`/`버튼 문구`/`연락처`) · 라벨에 `값` 같은 내부 필드명 ❌(규칙 4). 행동 라벨이 디자인에 박힌 섹션(`CALL`·`MESSAGE`형)도 버튼 문구 칸은 둔다
- **대표 칸** — 다 채운 반복 항목이 접힐 때 보일 **한 줄 요약 칸(들)**. 정하는 법·예외 = **3-2 🏷** (`제목` 칸 → 없으면 맨 앞 필수 입력행 전부 · 연락·채널 버튼 묶음은 `유형` 칸만 · SNS 채널 묶음은 `채널` 칸만)
- **버튼 문구 칸 = 버튼 수만큼의 배열, 순서로 매칭한다** — `있음` 하나만 내지 ❌ — 어느 버튼에 넣을지 못 정한다. **배열 순서 = 섹션에서 버튼이 보이는 순서**: 세로로는 **위 → 아래**, 한 줄에 **2단 이상 나란한 버튼은 좌 → 우**(왼쪽 줄을 다 센 뒤 다음 줄로 · 3-7의 칸 순서 규칙과 같은 약속). **반복 항목 안의 버튼은 전 항목이 같은 문구**라 **칸 1개만** 둔다
- **안내 문구도 버튼과 같은 순서 매칭이다** — 섹션의 **반복 바깥** 안내 자리(슬롯) 수만큼 배열로 내고, **순서 = 섹션에서 보이는 순서**(항목 블록 「안」에 있는 안내 자리는 이 배열이 아니라 **묶음 칸**으로 받는다 — 3-3). 「무엇에 대한 안내인지」는 따로 적지 않는다 — **자리가 곧 소속**이다(폼 아래 슬롯 = 폼 안내). 한 섹션이 여러 단계로 나뉘면 **그 단계가 받는 칸들 바로 아래 놓인 안내 자리**가 그 단계 몫이다
- **플레이스홀더** — 값 1개 · **칸 배열의 칸뿐 아니라 안내 문구·버튼 문구 칸에도 하나씩** 낸다(`예: 주차는 건물 뒤편을 이용해 주세요` · `예: 예약하기`). 단 **드롭다운에 딸린 값 칸은 선택지별 목록** `{ 선택지: 플레이스홀더 }` (3-6)

## 3. 규칙

### 3-0. 질문 문구 (왼쪽 패널 제목)

단계마다 왼쪽 맨 위에 **한 줄**이 붙는다. 이 줄이 「무엇을 채우는 단계인지」를 말한다.

| 칸 상태 | 문구 |
|---|---|
| 비어 있다 | **`{주어}{을/를} 추가하면 좋아요`** |
| AI가 미리 채웠다 | **`{주어}{을/를} 미리 채워뒀어요`** |
| 빈 칸과 채운 칸이 섞여 있다 | **`{주어}{을/를} 마저 채우면 좋아요`** — 「미리 채워뒀어요」는 **그 단계의 모든 칸이 채워져 있을 때만**, 「추가하면 좋아요」는 **모든 칸이 비어 있을 때만** 쓴다 |

**주어 = 그 단계가 채우는 섹션의 이름표.** 아래 순서로 찾는다 — **0번이 가장 먼저다.**

0. **히어로 단계면 → 그 단계가 받는 칸의 고정 이름** (`메인 이미지` · `로고 이미지` · `프로필 이미지` · `메인 문구`) — 🚫 섹션 이름(`히어로`)이나 `히어로 문구`를 주어로 ❌
0-2. **라벨 영역 하나를 떼어 묻는 단계면(3-3 🔪) → 그 라벨** (`일시` · `장소` · `참가비`) — 섹션 제목(`클래스 정보`)을 주어로 ❌ — 어느 영역인지 안 보인다
1. 섹션 제목이 **두 줄(작은 라벨 ＋ 제목)**이면 → **라벨 줄**
2. 한 줄이면 → **그 제목**
3. 신청 폼이면 → **폼 제목** (`참가 신청서`)
4. 제목이 문장이면 → **그 섹션에 지어 둔 명사형 이름표**

**지킬 것**

- 🚫 **칸 라벨을 주어로 쓰지 않는다** — `이미지를 추가하면 좋아요` ❌ (무슨 섹션인지 알 수 없다)
- 🚫 **라벨 줄의 말이 제목에 그대로 들어 있으면 라벨을 주어로 쓰지 않는다** — `안내` ＋ `가격과 발송 안내` 같은 겹침은 **제목 줄**을 쓴다
- **조사** — 주어 마지막 글자에 **받침이 있으면 `을`, 없으면 `를`**
- 🪞 **주어와 칸 라벨의 말을 맞춘다** — **칸이 하나뿐인 단계는 주어 = 그 칸의 라벨과 같은 말** (주어 `메인 문구` ＋ 라벨 `한 줄 카피` 같은 어긋남 ❌ — 유저는 둘이 다른 것인 줄 안다). 칸이 여럿인 단계만 주어 = 묶음 이름, 칸 라벨은 각자

### 3-0-B. 입력칸을 만들지 않는 칸 · 칸 라벨 말

- ✅ **eyebrow(제목 위 작은 꾸밈 글)는 입력칸을 만든다 — 라벨은 무조건 「제목 위 문구」 고정** — 섹션마다 견본 글자(`EYEBROW` · `한 줄 카피` · `부가 설명 텍스트`)가 달라도 라벨은 항상 이 하나다(견본 글자를 라벨로 ❌ · `작은 소개` · `상단 문구` 같은 별칭 ❌). 판정은 라벨이 아니라 **그 값이 제목 위 작은 글로 렌더되는가**로
- 🚫 **섹션 제목은 입력칸을 만들지 않는다** — 섹션에 그 칸이 있어도 질문 화면에서 뺀다
- 🚫 **역할이 정해진 사실 행의 라벨(`일시` · `장소` · `가격` · `연락처`)도 입력칸으로 묻지 않는다** — 라벨은 화면에 **고정 표기**하고 **값 칸만** 받는다. 라벨 입력칸을 두는 건 **유저가 항목을 자유로 늘리는 라벨＋값 표**뿐이다
- 🚫 **아이콘 그림 자리(문의 · 핵심 정보 · SNS · 헤더 메뉴의 작은 그림)는 입력칸을 만들지 않는다** · **유형을 고르는 칸이 있으면 아이콘은 고른 유형을 따라간다**(전화를 고르면 전화 아이콘)
- ✅ **항목 왼쪽 이모지 칸(안내 사항·나열 항목의 한 글자 칸)은 입력칸을 준다 — 그 행의 글과 한 벌로** — 반복 한 벌 = `[아이콘 ＋ 내용]`(`아이콘` = 제목 텍스트 · 이모지 1개 · 선택 / `내용` = 필수) · 칸 순서 = 행에서 보이는 순서(왼쪽 → 오른쪽) · 🚫 **이모지와 글을 각각 따로 반복 항목으로 펼치지 ❌**(이모지 항목과 문장 항목이 섞인다) · 이모지 값은 AI가 미리 채우고, 유저가 글을 바꾸면 「반응 문구」 호출이 새 내용에 맞는 이모지로 갱신한다
- 🚫 **전 행이 같은 구분점·표식(`●`·`•`·`✓`·`-`)은 입력칸을 주지 않는다 (필수)** — 바로 위 이모지 칸과 가르는 기준 = **행마다 글자가 다른가**. 행마다 다른 그림(`🧘`·`⏰`)은 **그 행의 뜻**이라 칸을 주고, **전 행이 똑같은 글자**면 목록 **장식**이라 값이 아니다 — 칸을 주면 **접힌 항목 이름이 `●`로** 뜬다(잘못된 예: 「주요 프로그램」)
- 🚫 **넘버링·순번 표식(`01` · `02` · `No.`)은 입력칸을 만들지 않는다 — 번호는 유저도 AI도 쓰지 않고 「시스템」이 항목 순서대로 자동으로 넣는다**
 - **하는 일** = 섹션에 `01`·`02`가 찍히는 자리가 있으면 **그 자리의 이름을 출력에 적는다** — `넘버링 자리: 번호 텍스트` · 그런 자리가 없으면 `넘버링 자리: 없음` (§2)
 - **왜 적나** = 안 적으면 그 표식은 **끝까지 빈칸으로 남는다**
 - 🚫 **AI가 `01`을 글로 써 넣거나 유저에게 묻지 ❌** · `번호`라는 칸 라벨이 생겼다면 표식 자리를 입력칸으로 연 것 — 항목 이름은 넘버 자리가 아니라 **제목 슬롯**이 받는다
- ℹ️ 반대로 **`채움 = AI`인 칸(히어로 제목·설명 · eyebrow 등)은 입력칸을 준다** — 질문 화면에서 빼는 건 **섹션 제목 · 사실 행의 고정 라벨 · 아이콘 그림 자리 · 넘버링 표식** 넷뿐이다
- 🚫 **칸 라벨에 영어·제작 용어를 쓰지 않는다** — 라벨은 전부 쉬운 국문으로 (`페이지 제목` · `한 줄 카피` · `이미지`). `EYEBROW` · `CTA` · `label` · `섹션` · **`히어로`** 같은 **만드는 쪽 용어**를 유저에게 그대로 보여주지 ❌ — 주어(왼쪽 제목)에도 똑같이 적용된다 — **섹션 슬롯 이름(`label`·`LABEL`)이 화면에 그대로 새어 나오면 안 된다**(고정 라벨 8개나 역할 이름으로 바꿔 단다)
 - **국문이라도 「~ 라벨」·「~ 값」은 같은 제작 용어다** — `원재료명 라벨` · `규격 값` 같은 칸 라벨 ❌. 라벨＋값 표는 **반복 묶음**으로 받고 칸 라벨 = 고정 라벨 **`제목`·`내용`** (행 이름이 자료에 이미 있으면 미리 채워 둔 `제목` 칸의 값일 뿐, 칸 라벨에 붙이는 말이 아니다) · **단 2단 반복의 안쪽 줄(상품 항목 안의 스펙 줄)이면 `항목`·`내용`** — 바깥 항목의 이름 칸이 이미 `제목`이라, 안쪽도 `제목`이면 같은 라벨이 둘이 되고 요약에 두 값이 이어 붙는다(`Vintage Tailoring 소재`)

### 3-1. 인풋 종류 12가지 — 이 밖의 입력 UI는 만들지 않는다

| 종류 | 받는 것 |
|---|---|
| **일반 텍스트** | 문장·설명 (여러 줄) |
| **제목 텍스트** | 이름·제목처럼 **한 줄로 끝나는 말** |
| **날짜** | 날짜 (피커) |
| **시간** | 시각 (피커) |
| **단일 이미지** | 사진 1장 |
| **복수 이미지** | 사진 여러 장 |
| **파일** | 방문자가 **받아 갈 문서** 1개 (카탈로그 · 메뉴판 · 브로슈어 PDF) — **이미지 인풋과 별개.** 올린 파일은 페이지에서 **다운로드 버튼**에 연결된다. 유저가 처음에 첨부한 파일이 이 용도면 **그 파일을 미리 채워 둔다** |
| **링크(URL)** | 주소 |
| **주소** | 장소 (검색 결과에서 고름 ＋ 상세 주소) |
| **드롭다운** | 정해진 것 중 하나 — 후보가 많아 접어 둔다 |
| **토글(스위치)** | 켜고 끄기 (값을 받지 않는다) |
| **선택 버튼** | 정해진 것 중 하나 — 후보 2~3개를 전부 드러낸다(받는 값은 드롭다운과 같다) |

- 🗺 **`주소`(검색) 인풋은 그 값이 「지도」에 들어갈 때만 쓴다** — **지도 없이 글자로만 보이는 장소 이름**(행사 정보의 장소 행 등)은 `제목 텍스트`로 받는다(검색이 안 되는 장소 — 온라인 · `본관 2층 세미나실` — 도 적을 수 있어야 한다). **장소 이름과 지도용 주소는 다른 정보** — 한 칸에 묶지 않고 각자의 섹션 단계에서 따로 묻는다
- 🔘 **드롭다운·선택 버튼에는 「빈 상태」가 없다 — 항상 하나가 선택된 채로 시작한다** — 드롭다운은 **첫 선택지**가 선택된 채로, 선택 버튼(신청 폼의 질문 유형)은 **질문을 추가할 때 정한 유형**이 선택된 채로 시작한다. 🚫 `선택 안 함`·`유형을 골라 주세요` 같은 **빈 선택지를 만들지 ❌**
- 🔀 **드롭다운 ↔ 선택 버튼 — 받는 값은 같다. 생김새는 이 기준으로 고른다**
 - **선택 버튼** = 후보가 **2~3개**이고 **고른 값에 따라 뒤 칸 구성이 바뀔 때**(신청 폼의 질문 유형 — 객관식이면 `선택지` 칸, 주관식이면 답변 유도 문구 칸)
 - **드롭다운** = 그 밖에 전부 — 후보 **4개 이상** · 고른 값이 **값 칸의 플레이스홀더만** 바꿀 때(연락처 유형 · SNS 채널 · 별점 · 요일) · 선택지 글자가 길 때
- **토글은 값을 받지 않는다.** 하는 일은 넷 — ⓐ **다른 칸을 숨기거나 드러낸다**(드러날 때 라벨이 바뀔 수 있다 — `종료일 추가`를 켜면 `날짜`가 `시작 날짜`로) ⓑ **칸을 잠근다**(`인원 제한 없음`) ⓒ **표시를 끈다**(`할인율 표시`) ⓓ **그 항목의 속성을 켠다**(`필수` · `복수 선택`). **스위치마다 무엇을 하는지를 칸 배열의 「스위치 동작」으로 출력**한다 (자주 쓰는 예 = 3-8)
- 위 12가지로 만들 수 없는 입력이 나오면 **가장 가까운 종류로 받는다**(대개 `일반 텍스트`·`제목 텍스트`) — 캘린더 그리드 · 슬라이더 · 태그 입력 · 서식 있는 글 편집기 같은 **새 입력 UI를 창작하지 ❌**
- 🔑 **인풋 종류는 섹션 칸의 생김새가 아니라 「받는 값」이 정한다** — 섹션 칸이 자유 텍스트(라벨＋값 행)여도, 값이 **날짜·시각이면 `날짜`·`시간`(피커)** · 지도에 쓰일 주소면 `주소`(검색) · URL이면 `링크` · 가격·정원이면 **단위를 포함한 한 줄 값**(`제목 텍스트` · 플레이스홀더가 형식을 보여준다 — `예: 35,000원`). **일시를 텍스트 칸으로 받지 ❌** — 일시 = `날짜`＋`시간` 가로 한 줄(종료 시간은 토글로). 화면에 찍히는 형식(`2026. 10. 16 (금) 09:00 - 17:00`)은 받은 값으로 조합한다
 - 🔪 **역할이 정해진 사실 행(일시·장소)은 라벨＋값 표 하나로 묶지 않는다** — 라벨마다 단계를 나누고(3-3), 인풋 종류는 그 단계 안에서 값 유형대로 정한다(일시 = 피커 · 장소 = 제목 텍스트)

### 3-2. 반복 여부 판정

| 판정 | 조건 | 결과 |
|---|---|---|
| **반복 없음** | 그 섹션이 그 정보를 **한 벌만** 담는다 | 칸을 그대로 나열 |
| **1단 반복** | **같은 꼴의 칸 묶음이 2벌 이상** 들어간다 — **벌 = 칸 1개여도 · 딱 2벌이어도 반복**(견본이 2개뿐이라고 고정 2칸 쌍으로 펼치지 ❌) | 묶음 한 벌 ＋ `항목 추가` |
| **2단 반복** | 반복되는 항목 **안에** 또 반복되는 칸이 있다 | 바깥 ＋ 안쪽 각각 추가 버튼 |

- 🪜 **한 덩어리로 적힌 슬롯이라도 위계가 다른 줄이 섞여 있으면 칸을 나눠 받는다** — 슬롯이 `LABEL ● 안내 사항 ● 안내 사항`처럼 한 줄로 적혀 있어도, 그 안에 **큰 글자 제목 줄**과 **작은 글자 항목 줄**이 섞여 있으면 질문은 **`제목` 1칸 ＋ 항목 반복**으로 나눈다. 🧪 판정 = **그 덩어리 안에서 글자 크기·굵기가 바뀌는 자리가 있나** · 🔑 **카드가 한 장인 것과 묻는 칸이 한 개인 것은 다른 얘기다**(색 박스라 카드를 쪼갤 수 없어도 칸은 나눈다) — 한 칸에 받으면 유저가 제목만 고치거나 항목 하나만 더할 수 없다
- 🔖 **섹션 슬롯 이름에 되풀이 표식(`×3`·`x4`·`(리스트)`)이 있으면 그것만으로 반복 확정** — `상품명|가격 ×3` 같은 표기는 **같은 묶음이 3벌 들어간다는 뜻**이다. 벌 = 그 표식이 걸린 묶음(`상품명`＋`가격`) · 자료에 2건뿐이어도 **고정 칸으로 펼치지 ❌**. 🧪 흔한 위반 = 요금표를 `과정명·강습비·과정명·강습비`로 평평하게 펴기(자료 건수에 맞춰 칸을 깔면 유저가 항목을 더할 수 없다)
- ✂️ **꼴 비교 전에 「반복 바깥 요소」를 떼어 놓는다** — 섹션 제목 · 안내 문구(부가 설명) · 버튼은 항목이 아니다. 이것들을 떼고 **남은 슬롯끼리** 같은 꼴인지 비교한다. 끝의 안내 문구 하나가 꼴을 깨 보인다고 전체를 고정 칸 나열로 펼치지 ❌ — 사례: 슬롯 `[안내 사항, 안내 사항, 부가 설명]`을 **슬롯 개수·이름 그대로 베껴** 고정 3칸(`안내 사항`·`안내 사항`·`안내 문구`)으로 펼침(❌) → 정답 = 부가 설명을 떼면 `안내 사항` 2벌 = **`내용` 1칸 반복 ＋ `항목 추가`**, 안내 문구는 반복 바깥 1칸. **섹션 슬롯 나열을 그대로 복사하는 것이 이 판정의 전형적 위반**이다(슬롯 이름을 라벨로 베끼면 같은 라벨이 두 번 생긴다 — 아래 자기 점검)
- **반복은 2단까지만.** 3단이 필요해 보이면 **「여러 줄 텍스트 칸 1개」로 받는다**(한 줄 = 한 항목) — 예: 세미나 프로그램의 `세션 〉 연사 〉 연사별 주요 경력`은 세션(1단)·연사(2단)까지만 반복으로 하고, 경력은 연사 묶음 안 `경력` 텍스트 칸에 `○○대 교수` `△△학회 이사`를 줄바꿈으로 나열 (⚠️ 분류·카테고리처럼 **항목을 묶는 축은 반복 단이 아니라 「분류 탭」으로 빠진다**(아래 🗂)이니 단수에 세지 않는다)
- 🧪 **자기 점검 = 칸 배열에 같은 라벨이 두 번 나오면 반복 판정을 놓친 것** — `[항목, 내용, 항목, 내용]` 같은 쌍 패턴만이 아니라 `[안내 사항, 안내 사항]`처럼 **칸 1개짜리 중복도 같다**. 같은 꼴을 평평하게 펼치지 ❌ → **묶음 한 벌(`항목`·`내용`) ＋ 반복**으로 바꾼다 (펼친 채 두면 줄이 어긋난다)
- 🧪 **반대 방향 점검 = 한 반복 목록에 성격이 다른 값(이모지 한 글자와 문장)이 섞여 있으면 한 행의 칸을 쪼갠 것** — 2열 카드 한 행의 셀들(이모지＋글 · 이름＋가격)은 **묶음 한 벌**이다 → 행 하나 = 한 벌로 다시 묶는다(칸 순서 = 셀 순서 · 왼쪽 → 오른쪽)
- ✂️ **반복 단위 자르기 — 바깥 반복 한 벌 = 견본 항목 하나 전체** — 반복 섹션의 슬롯에는 견본 항목이 2벌 이상 들어 있다. **같은 꼴이 다시 시작하는 지점**(둘째 항목의 첫 슬롯 — 대개 사진이나 넘버링)에서 자르고, 그 앞까지가 **한 벌 전체**다(사진 · 이름 · 설명 · 구분선 아래 행까지)
 - **한 벌 안에 같은 꼴 행이 여러 개면**(스펙 행 `소재`·`컬러`·`사이즈` · 라벨＋값 행) **그 항목의 안쪽 반복(2단)**이다 — 행 하나만 칸으로 두고 나머지 행을 바깥 목록의 새 항목으로 꺼내지 ❌ (바깥 목록에 상품 항목과 스펙 항목이 섞인다)
 - **반대로 「한 행」을 통째로 한 벌로 자르지도 ❌ — 행 안에서 같은 꼴이 또 반복되면 벌 = 그 작은 단위다** — 「한 행 = 한 벌」은 행의 칸들이 **서로 다른 역할**(이모지＋글 · 이름＋가격)일 때고, 표형처럼 **한 행에 라벨＋값 쌍이 2개 나란**하면 벌 = 쌍(`제목`＋`내용`)이다(행 = 쌍 2개의 배치일 뿐). 사례: 인증 표의 4칸 행 `[인증명, 세부, 인증명, 세부]`를 한 벌 `[제목, 내용, 내용, 내용]`으로 자름(❌ — 라벨 `내용`이 3번 중복) → **쌍 2벌**. 🧪 점검 = **한 벌 안에 같은 라벨이 두 번 이상 나오면 벌을 너무 크게 자른 것**
 - 견본 항목끼리 견본 글자가 달라도(`설명 문구` / `세부 정보`) **슬롯 종류와 순서가 같으면 같은 꼴**이다
 - 🧪 **점검 = 바깥 반복의 항목이 전부 같은 칸 구성인가** — 항목마다 칸 구성이 다르거나, **대표 칸 값이 라벨 이름을 이어 붙인 말(`컬러 사이즈`)**로 읽히면 단위를 잘못 자른 것 → 견본 항목 하나 전체를 한 벌로 다시 묶는다
- 🔀 **반복 = 「칸 구조」의 반복이지 「값」의 반복이 아니다** — 신청 폼의 질문처럼 묶음 안에 `유형`(객관식/주관식) 선택 버튼이 있으면 **유형은 항목마다 각각 고른다**. 객관식과 주관식이 한 폼에 섞이는 게 정상이다(한 번 고른 유형을 전 항목에 적용 ❌)
- 🗂 **바깥 단이 「분류」뿐이면 세로 2단이 아니라 「분류 탭」으로 받는다** — 바깥 항목이 **분류 이름 하나만** 갖고 그 아래 같은 꼴 항목이 반복되면(메뉴판의 커피·차·에이드 · 카탈로그 분류) **탭으로 펼친다**: 탭 이름 = 유저가 치는 값(✏️ 수정) · `+`로 분류 추가 · **고른 탭의 항목만** 아래에 보인다(4-12 조합 장치). ✅ **이때만 추가 버튼이 두 곳**(탭 `+` ＋ `항목 추가`)인 것이 정상 — 아래 「추가는 한 곳」의 유일한 예외다
- 🚫 **바깥 묶음에 자기 칸이 하나도 없으면 2단이 아니다 — 1단으로 받는다 (필수)** — 바깥 항목이 **안쪽 반복만** 품고 있으면 그 바깥은 **껍데기**다. 그러면 「항목 추가」와 「○○ 추가」가 **동시에 뜬다**. 🧪 판정 = **바깥 항목에 안쪽 반복 말고 자기 칸(`제목`·`설명`·이미지 등)이 있나** — 없으면 안쪽 칸 하나짜리 **1단 반복**으로 바꾸고 **추가 버튼도 한 곳**만 둔다. 잘못된 예: 「주요 프로그램」(= 프로그램 이름만 나열하는 1단 목록)을 바깥 항목 3개 × 안쪽 `프로그램` 반복으로 만들어 「항목 추가」＋「프로그램 추가」가 같이 떴다
- **2단일 때 안쪽 추가 버튼**은 무엇이 늘어나는지 드러나는 이름을 지어 출력한다(`옵션 추가` · `메뉴 추가`) — 바깥과 같은 이름 ❌ — 어느 단계인지 알 수 없다
- 🏷 **대표 칸을 정해 출력한다** — 다 채운 항목이 접힐 때 보일 **한 줄 요약** (묶음의 칸 값을 전부 이어 붙이지 ❌ — 아래 둘 중 하나만) · **바깥 묶음의 칸에서만 고른다**(2단이면 안쪽 반복의 칸 ❌). 순서대로 대조해 처음 맞는 것:
 - **① 라벨이 `제목`인 칸** (고정 라벨 규칙상 이름 칸은 항상 `제목`이다) — 칸 1개
 - **② 없으면 묶음 맨 앞의 필수 입력행** — 텍스트 칸만이 아니라 **드롭다운·날짜/시간 피커 칸도 포함**한다(값을 글자로 바꿔 표시). 그 행에 칸이 여럿이면 **그 행의 칸 전부**를 순서대로 출력하고, 표시할 때 **값 사이 공백 1자**를 둔다 (예: 폼 질문 묶음 = `질문` · 예약 회차 = `날짜`＋`시간`＋`정원` → `2026.10.16 14:00 20명` · 별점 후기 = `별점`＋`리뷰 내용` → `★★★★★ 또 가고 싶어요`)
 - ⚠️ **예외 = 연락처가 들어가는 묶음 — 연락처 값은 요약에 보이지 않게 한다** (접힌 줄에 번호가 노출된다)
  - **연락·채널 버튼 묶음**(`유형` ＋ `버튼 문구` ＋ `연락처` · §2) → **`유형` 칸만** 대표 (요약 = `전화`)
  - **SNS 채널 묶음**(보이는 글자 없이 아이콘만 · `채널` 드롭다운 ＋ `주소`) → **`채널` 칸만** 대표 (요약 = `인스타그램`)

### 3-3. 한 단계의 뼈대

```
[한 번만 받는 칸]  반복 섹션에서 항목에 딸리지 않는 칸(제목 위 문구 · 리드 설명) — 있을 때만
[주 입력 묶음]   칸 1~4개
   └ 반복이면 이 묶음이 통째로 늘어난다
[안내 문구]      반복 「바깥」 안내 자리가 있을 때만 · 자리 수만큼(대개 0~1개)
[버튼 문구]    그 섹션에 버튼이 있을 때만 · 버튼 수만큼
```

- 🧩 **칸 ↔ 슬롯은 양방향으로 맞아야 한다** — ⓐ **칸 = 그 섹션에 실제 있는 슬롯만**: 칸마다 *「이 값이 들어갈 슬롯이 있는가」*를 대조하고 없으면 만들지 ❌. 섹션 **이름에서 연상한 칸**(`메뉴 종류`라고 링크·유형 칸 — 라벨＋값 행엔 링크 슬롯이 없다)이 전형적 위반 — 슬롯 없는 칸은 유저 입력을 버린다. ⓑ **편집 가능한 슬롯은 전부 받는 칸이 있어야 한다**: 미리보기에 보이는 값(제품명·설명 반복)을 받는 칸이 없으면 질문이 덜 짜인 것 — 같은 꼴 여러 벌은 반복으로(3-2). 예외 = 입력칸 제외 넷(3-0-B)
- 🧱 **한 섹션 = 기본 한 단계다** — 나누는 경우는 아래 셋**뿐**: ⓐ 칸 5개 이상 ⓑ 히어로(고정 이름 단위) ⓒ 라벨로 나뉜 영역(반복 항목이 아닐 때 — 아래 🔪). 그 밖엔 같은 섹션의 **글 ＋ 그 글에 딸린 이미지를 한 단계에 묶는다**(쪼개면 같은 섹션을 두 번 오간다). ⚠️ 아래 히어로의 「이미지·문구 분리」는 **히어로 전용** — 다른 섹션에 일반화 ❌
- 🔁 **멀티페이지에서 장마다 반복되는 같은 헤더는 한 번만 묻는다** — 값(로고·페이지 제목)은 그 헤더가 놓인 모든 장에 함께 들어간다 · 단계 위치 = 헤더가 처음 나오는 자리 · 같은 로고를 히어로 등 다른 단계에서 이미 받으면 다시 묻지 않는다 · 메뉴 아이콘은 입력칸 ❌(아이콘 그림 자리)
- **칸이 5개 이상이면 두 단계로 나눈다**
- 🦸 **히어로는 고정 이름 단위로 단계를 나눈다** — `메인 이미지` / `로고 이미지` / `프로필 이미지` / `메인 문구`(페이지 제목＋설명) 각각 **한 단계씩**. 이미지와 제목·문구를 한 단계에 묶지 ❌ — 주어가 하나로 안 떨어진다. ⚠️ 이 나열은 이름 목록이지 **묻는 순서가 아니다** — 순서 = 3-7(섹션에서 보이는 순서)
- 🔪 **라벨로 나뉜 영역은 반복 항목이 아니면 영역마다 따로 묻는다** — 섹션 안에서 작은 라벨(`일시`·`장소`·`대상`·`참가비`)로 영역이 나뉘어 있거나, 서로 다른 질문(언제·어디·누구·얼마)에 답하는 정보면 **칸이 적어도 영역마다 한 단계**다(`일시` 단계 = 날짜＋시간 · `장소` 단계 = 장소 칸 · 주어 = 그 라벨 — 3-0의 0-2). **한 단계 = 한 가지 질문** — 왼쪽 제목의 주어가 한 가지로 떨어져야 한다
 - ✅ **예외 = 반복 항목** — 같은 꼴의 행을 유저가 하나 더 늘릴 수 있는 표(제품 스펙 · 계좌 · 요일별 운영시간)는 라벨이 달라도 **반복 한 벌로 한 단계**에 받는다. 판정 = **그 행을 하나 더 추가하는 게 자연스러운가** — 일시·장소처럼 행마다 역할이 정해져 있으면 따로 묻는다
- **안내 문구는 반복 바깥**에 둔다 — 항목마다 늘어나지 않는다
 - ✅ **예외 = 안내 자리가 「항목 블록 안」에 있는 섹션** — 항목마다 작은 보충 글 자리가 딸린 나열 섹션이면, 그 안내는 **묶음 한 벌의 칸**으로 받는다(라벨 `안내 문구` · 선택 · 칸 순서 맨 끝). 🧪 판정 = **안내 자리가 항목 안에 있나(= 묶음 칸) · 묶음 전체 바깥 맨 아래에 있나(= §2 「안내 문구」 배열)** — 둘 다 있는 섹션은 양쪽 모두 받는다(§2의 안내 배열은 **바깥 자리 수만큼**만 센다)
- 🖼 **같은 역할의 이미지 자리 여러 개 = 「복수 이미지」 인풋 하나로 묶는다** — 섹션에 이미지 자리가 3개 있어도 역할이 같으면(갤러리·시설 사진) **인풋 1개 ＋ `항목 추가`**. 자리 수만큼 이미지 인풋을 벌리지 ❌ — 같은 라벨 `이미지`가 반복된다. **역할이 다른 이미지**(로고·메인·프로필)만 각각 인풋 ＋ 예외 라벨로 나눈다
 - **같은 역할 판정 = 「같은 대상을 보여 주는가」** — 한 섹션(반복이면 한 항목)에 함께 놓인 사진들이 같은 상품·공간·행사·작품을 보여 주면 같은 역할이다. **슬롯 이름(`이미지`·`서브 이미지`·`갤러리`)·크기·배치(큰 1장＋작은 2장)·슬롯 수가 달라도 같은 역할** — 슬롯 이름의 `메인`·`서브`는 배치 이름이지 올릴 사진이 다르다는 뜻이 아니다. 다른 역할 = **로고 · 인물(프로필) 사진**처럼 다른 대상을 보여 주는 자리뿐
 - **`메인 이미지` 라벨은 히어로 단계 전용** — 히어로 밖 섹션의 큰 사진 자리에 `메인 이미지`를 달지 ❌(라벨 = `이미지`) · 한 단계에 `이미지` 인풋이 둘 이상 생겼다면 사진 묶음을 쪼갠 것이다
 - **복수 이미지 인풋이 채우는 자리 순서 = 섹션에서 보이는 순서**(위 → 아래 · 한 줄 안은 왼쪽 → 오른쪽) — 첫 장이 맨 위(큰) 자리에 들어간다
- ✍️ **같은 역할의 「글」 자리 여러 개도 똑같이 반복으로 묶는다** — 섹션에 같은 역할의 텍스트 자리가 여럿이면(특징 3줄 · 한 줄 소개 4개) **칸 하나짜리여도 묶음 한 벌 ＋ `항목 추가`(반복)** 로 받는다. 하나만 묻고 나머지 자리를 비워 두지 ❌
 - 🚫 **여러 줄 텍스트 한 칸(줄바꿈 문단)으로 받지 ❌** — 항목 단위 삭제·순서 변경·이모지 갱신이 안 된다. 판정 = **섹션의 자리가 슬롯 1개(문단)면 텍스트 한 칸 · 슬롯 여러 개면 반복**

| `날짜`     | 날짜 칸                                                                                                                |
| `시간`     | 시간 칸                                                                                                                |
| `안내 문구`  | 단계 맨 아래 부가 한 줄 — **페이지에 실리는 섹션 하단의 작은 보충 글**(조건·유의 · 예: `부가세 포함` · `주차는 건물 뒤편`). 본문(소개·설명)은 ❌ — 그건 주 입력 묶음의 텍스트 칸이다 |
| `버튼 문구` | 버튼에 들어갈 말                                                                                                           |

**그 밖의 라벨을 지을 때 5가지**

1. **명사로 끝낸다** — `가격` ✅ / `가격 입력` ❌
2. **2~6자**
3. **그 칸 하나가 받는 것만** 가리킨다 — 두 가지를 묶은 라벨 ❌
4. **주제어를 넣지 않는다** — `프로그램 제목` ❌ → `제목`. 무엇에 대한 칸인지는 **왼쪽 패널 제목**이 이미 말하고 있다
5. **한 단계 안에 같은 라벨 두 개 ❌** — 앞에 구분어를 붙인다(`시작 날짜`·`종료 날짜` / `정상가`·`할인가`)

**예외 3가지**

| 예외 | 라벨 |
|---|---|
| 히어로의 사진 | `메인 이미지` · `로고 이미지` · `프로필 이미지` — 역할마다 다른 라벨 · **같은 라벨의 이미지 인풋을 한 단계에 두 번 ❌** |
| 링크 칸 | 용도를 앞에 붙인다 — `유튜브 URL` · `링크` |
| 고르는 칸(드롭다운·선택 버튼) | 무엇을 고르는지 — `유형` · `별점` |

**칸 라벨 대신 「묶음 라벨」 하나만 내는 경우 — 하나뿐이다** — 칸 라벨을 생략해도 되는 조건 = **옆 드롭다운이 그 값 칸이 무엇인지 말해 줄 때**(고른 유형에 따라 값 칸의 플레이스홀더가 바뀐다 · 3-6). 그 밖에는 **칸마다 라벨을 적는다** — 🚫 **텍스트·날짜 칸은 라벨 없이 두지 ❌**(플레이스홀더만으론 무엇을 넣을 칸인지 알 수 없다 · `작성자` 칸을 라벨 없이 두면 이름인지 상품명인지 모른다)
 | 조건 | 예 |
 |---|---|
 | 첫 칸이 **드롭다운**이고, **고른 값이 곧 그 항목의 이름**이 될 때 (칸 2개까지) — 🚫 **연락·채널 버튼은 여기 해당 ❌**(칸이 3개라 `유형`·`버튼 문구`·`연락처` 칸 라벨을 적는다 · §2) | SNS 채널 묶음 — 아이콘만 보이는 자리라 드롭다운에서 `인스타그램`·`유튜브`를 고르고 옆 칸에 주소를 친다 → 묶음 라벨 = **`SNS 채널`** |

- 🚫 **입력칸이 딸리지 않은 라벨을 내지 않는다 (필수)** — **칠 곳 없는 라벨만 뜬다**. 묶음 라벨은 **칸 라벨을 생략하고 그 자리를 대신할 때만**(위 조건) 쓴다 — **묶음 라벨과 칸 라벨을 둘 다 내지 ❌**(잘못된 예: 안쪽 반복 위에 `스펙`만 덩그러니 떠 있고 그 아래 `항목`·`내용` 칸 라벨이 또 있음). 안쪽 반복을 구분해 보여 줘야 하면 **묶음 이름 대신 「안쪽 추가 버튼 이름」**(`항목 추가`)으로 드러낸다
- 🚫 **라벨은 고른 유형을 따라 바뀌지 않는다** — 묶음 라벨이든 칸 라벨이든 **어느 유형을 골라도 포괄하는 범용어**로 짓는다 (`연락처` ✅ / `전화`·`인스타그램` ❌ — 그건 라벨이 아니라 드롭다운의 **고른 값**이다). 유형 따라 바뀌는 건 **플레이스홀더뿐**(선택지별 목록 · 3-6)

### 3-5. 필수와 선택

| 분류 | 판정 |
|---|---|
| **필수** | 이 칸이 비면 **그 섹션이 성립하지 않는다** — 항목의 이름·제목, 일시 |
| **선택** | 비어도 섹션이 성립한다 — 설명 문구 · 안내 문구 · 부가 정보 · **상품·메뉴의 가격** |

- **칸이 하나뿐인 단계는 무조건 필수**
- **AI가 미리 채운 칸도 찬 것으로 센다**
- **`이건 없어요` = 그 질문 하나만 건너뛴다** — 같은 단계의 채워진 다른 값은 그대로 둔다. 건너뛴 자리는 `추가하기` 표시로 접혀 남아, 되돌아와 채울 수 있다
- **반복 항목은 항목 안에서도 나뉜다** — 항목은 **필수 칸이 다 차야 완성**. 선택 칸만 빈 항목은 그 부분만 빼고 만든다

**자주 쓰는 묶음의 필수 · 선택**

| 묶음 | 필수 | 선택 |
|---|---|---|
| 날짜 ＋ 시간 | 날짜 | 시간 · 종료 일시 |
| 주소 | 주소 (**검색 결과를 고른 상태**여야 찬 것으로 센다) | 상세 주소 |
| 가격 (가격을 받는 묶음 안에서) | 판매가 | 정상가 · 할인율 |
| 상품·메뉴 반복 (이름 ＋ 가격) | 이름 | **가격** — 비면 가격 칸만 빼고 이름은 남긴다 |
| 제목 ＋ 내용 반복 | 제목 · 내용 | — |
| 이미지 ＋ 글 반복 | 이미지 · 제목 | 설명 |
| 상품·작품 상세 반복 (사진 묶음 ＋ 이름 ＋ 설명 ＋ 스펙 행) — 칸 순서 = 보이는 순서 · 스펙 행 = 그 항목의 안쪽 반복 | 이미지 · 제목 | 설명 · 스펙 행(**채운 행만** 센다) |
| 버튼 이름 ＋ 링크 반복 (`유형` ＋ `버튼 문구` ＋ `링크`) | **셋 다** (하나만 빠져도 버튼이 동작하지 않는다) | — |
| 연락·채널 버튼 반복 (`유형` ＋ `버튼 문구` ＋ `연락처`) | **셋 다** — 하나라도 비면 동작이 미정이거나 번호가 글자로 노출된다 | — |
| SNS 채널 반복 (`채널` ＋ `주소`) | **둘 다** | — |
| 예약 회차 | 날짜 · 시간(시작) | **종료 시간** · 정원 |
| 후기 | 내용 | 별점 · 작성자 · 날짜 · 상품 옵션 |
| 신청 폼의 질문 | 유형 · 질문 · **객관식이면 선택지 2개 이상**(단 **동의 질문**(개인정보 수집·이용 동의 등)은 선택지 「동의합니다」 **1개**로 찬 것으로 센다 · 필수) — 유형은 **항목마다 각각**(한 폼에 객관식·주관식 섞임이 정상) | 주관식 답변 유도 문구 |
| 라벨 ＋ 값 표 (행을 늘리는 표 — 스펙 · 계좌 · 요일별 운영시간) | 라벨 · 값 쌍 (**채운 행만** 센다 · 빈 행은 지운다) — `일시`·`장소`처럼 **역할이 정해진 사실 행은 이 표가 아니라 라벨마다 따로 묻는다**(3-3 🔪) · 라벨이 항목 이름(상품명)이면 위 「상품·메뉴 반복」을 따른다 | — |
| 아이콘 ＋ 내용 반복 (항목 왼쪽 이모지 칸) | 내용 | 아이콘 |

- 🙈 **자료·첫 입력 글이 「익명」 응답을 명시하면 폼에 이름·연락처 칸을 만들지 않는다** — 페이지가 스스로 모순된다
- 🎟 **예약 섹션이 있으면 「호스트 이름·연락처」를 받는 질문을 넣는다** — 없으면 페이지를 완성할 수 없다. 자료·프로필에 이미 있으면 그 값으로 미리 채우고 묻지 않는다
- ⏱ **시각 칸은 「시작·종료」 한 쌍이되, 종료 칸은 `종료일 추가` 토글로 접어 둔다 (기본 꺼짐 = 선택 · 3-1의 「종료 시간은 토글로」와 같은 약속)** — 유저·자료가 종료 시각을 줬으면 스위치를 켜고 채운다(버리지 ❌). 예약 카드처럼 **저장 필드가 시작뿐인 기능**이어도 종료 값은 받는다 — 종료 칸의 **「들어갈 자리」 = 시작 값과 같은 일시 텍스트 슬롯**이고 합치는 형식은 `시작~종료`다(§2 · `일시 텍스트 ← 시작~종료`). 🚫 **들어갈 자리를 안 적으면 종료 값이 그대로 버려진다**

### 3-6. 플레이스홀더

**왼쪽 입력칸의 빈칸 안내에만 해당한다.** 오른쪽 미리보기에 들어가는 글에는 `예: `를 쓰지 않는다 — 미리보기는 완성된 페이지처럼 보여야 한다.

- 🔴 **모든 입력칸은 플레이스홀더를 가진다 — 빈 플레이스홀더 ❌** — 어떤 값을 적을 칸인지 알려줄 예시를 못 짓겠으면 지시형(`~을/를 입력해 주세요.`)이라도 반드시 넣는다. 플레이스홀더가 안 지어지는 칸은 대개 **그 섹션에 슬롯이 없는 칸**(위 🧩)이라는 신호다 — 칸 자체를 다시 의심할 것

| 대상 | 형식 | 예 |
|---|---|---|
| 기본 | **`예: ` ＋ 그 칸에 들어갈 법한 값** | `예: 아메리카노` · `예: 4,500원` |
| **날짜 · 시간 · 주소 · 연락처 · 링크** | **지시형** — 입력 방식이 형식을 강제하므로 예시가 필요 없다 | `날짜를 선택해 주세요.` · `링크 URL을 입력해 주세요.` |
| 계좌 · 가격 · 정원 · 작성자 이름 | **예시형** — 어떤 형태로 적을지를 예시가 알려준다 | `예: 국민은행 123456-78-901234` · `예: 20명` |
| 반복 항목 **2번째부터** | 지시형 | `내용을 입력해 주세요.` |

- 지시형 어미는 **`~해 주세요.`** 로 통일한다(마침표 포함)
- **드롭다운에 딸린 값 칸의 플레이스홀더는 「선택지별 목록」으로 낸다** — 드롭다운은 **첫 선택지가 선택된 채로 시작**하므로(3-1) 처음 보이는 플레이스홀더는 **첫 선택지 것**이고, 유저가 유형을 바꾸면 그 선택지 것으로 바뀐다. 예: `{ 전화: "전화번호를 입력해 주세요.", 이메일: "이메일을 입력해 주세요.", 인스타그램: "계정 주소를 입력해 주세요." }`

### 3-7. 순서

- **단계 순서 = 페이지에서 섹션이 놓인 순서**
- **단계 안의 칸 순서 = 그 섹션에서 정보가 보이는 순서**
- **한 섹션이 여러 단계로 나뉘면(히어로 등) 단계끼리의 순서도 = 그 정보가 섹션에서 보이는 순서**(위→아래) — 고정 이름 목록(3-3)의 나열 순서를 묻는 순서로 쓰지 ❌. 히어로가 `제목 위 문구 → 제목 → 설명 → 메인 이미지`로 보이면 **첫 질문 = 메인 문구, 그다음 = 메인 이미지**다
- **반복 항목 안의 칸 순서도 = 그 항목에서 보이는 순서**(위 → 아래 · 한 줄 안은 왼쪽 → 오른쪽) — 항목이 `사진 → 이름 → 설명 → 스펙 행`으로 보이면 칸도 `이미지 → 제목 → 설명 → 안쪽 반복(스펙)` 순서다. **대표 칸(`제목`)은 접힌 줄에 보일 값을 고르는 것이지 칸 순서가 아니다** — 대표 칸이라고 맨 앞으로 옮기지 ❌ (미리보기와 순서가 어긋난다)

### 3-8. 스위치 동작 출력

**토글 칸마다 「스위치 동작」을 출력한다** — 켜면 **어느 칸**을 숨기는지/드러내는지/잠그는지, 라벨이 어떻게 바뀌는지. 자주 쓰는 예:

| 스위치 | 켜면 (스위치 동작에 적을 내용) |
|---|---|
| `하루종일` | `시간` 칸을 숨긴다 (종료 시간까지) |
| `종료일 추가` | 종료 `날짜`·`시간` 칸이 생기고, 원래 라벨이 `시작 날짜`·`시작 시간`으로 바뀐다 |
| `인원 제한 없음` | `정원` 칸을 잠근다 |
| `할인율 표시` | 끄면 할인율 표시를 숨긴다 |

### 3-9. 미리보기에 넣을 수 없는 것

아래는 **입력을 받아도 페이지에 표시할 방법이 없다.** 칸을 만들지 않는다.

- **남은 자리 · 잔여 수량** — 예약이 들어올 때마다 바뀌는 숫자
- **D-DAY · 남은 날짜** — 시간이 지나면 바뀌는 표시

정원은 **`회차당 정원 8명`** 처럼 **바뀌지 않는 문장**으로만 보여준다.
