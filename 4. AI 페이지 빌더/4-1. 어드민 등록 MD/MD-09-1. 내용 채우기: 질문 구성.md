# MD-09-1. 내용 채우기: 질문 구성

## 0. 반드시 지킬 것

> 가장 어기기 쉬운 절대 규칙만 모았다. **출력을 내기 전에 한 줄씩 대조한다.** 상세 기준·예외·예시는 아래 본문이 정본이다.

1. **인풋은 12종 밖 창작 ❌ · 반복은 2단까지** — 12종 밖이 필요해 보이면 **가장 가까운 종류(대개 텍스트)로** 받는다 · 3단이 필요해 보이면 **안쪽 두 단을 합쳐 2단으로** · **같은 꼴 묶음 2벌 이상 = 반드시 반복으로**(칸을 평평하게 펼쳐 나열 ❌)
2. **인풋 종류는 「받는 값」이 정한다** — 날짜·시각 = 피커 · **지도에 쓰일 주소 = 검색 · 글자로만 보이는 장소 이름 = 제목 텍스트** · URL = 링크 · 가격·정원 = **단위를 포함한 한 줄 값**(`제목 텍스트` — `35,000원`·`20명` · 별도 단위 UI 없음) (일시를 자유 텍스트 칸으로 ❌)
3. **입력칸 안 만드는 것 = eyebrow(별칭 `작은 소개` 류도 ❌) · 섹션 제목 · 사실 행의 고정 라벨(`일시`·`장소`)** — 고정 라벨은 표기만 하고 **값 칸만** 받는다 · `채움=AI` 칸은 입력칸을 준다 · **히어로는 고정 이름 단위로 단계 분리**
4. **라벨: 고정 7개 우선 · 영어/제작 용어(`EYEBROW`·`CTA`·`label`·`히어로`) ❌ · 한 단계에 같은 라벨 두 개 ❌** — 같아지면 앞에 구분어 · **칸 하나뿐인 단계는 주어 = 칸 라벨과 같은 말**
5. **같은 역할의 이미지 자리 여럿 = 「복수 이미지」 인풋 하나** — 역할이 다른 것(메인·로고·프로필)만 각각 인풋 ＋ 예외 라벨
6. **방문자가 받아 갈 문서 = 「파일」 인풋** — 이미지 인풋과 별개 · 페이지의 다운로드 버튼에 연결
7. **필수/선택 = 「비면 그 섹션이 성립하는가」** — AI가 채운 칸도 찬 것 · **`이건 없어요` = 그 질문만 건너뛴다**(같은 단계의 채워진 다른 값 삭제 ❌)
8. **단계 순서 = 페이지 섹션 순서 · 칸 순서 = 섹션에서 보이는 순서** · 성격이 다른 사실 덩어리(일시/장소)는 한 단계에 묶지 ❌

> 🔑 **케이스마다 화면을 미리 그려 두지 않는다.** 인풋은 **종류 12개와 반복 여부**만 정해져 있고, **채택한 섹션의 정보 구조를 보고 그때그때 조합**한다.

## 1. 입력

| 값 | 내용 |
|---|---|
| **구성** | `{섹션 목적, 섹션 id, 순서, 페이지 번호}` 배열 |
| **섹션 슬롯** | 각 섹션이 가진 빈칸의 이름·개수·반복 구조 |
| **시안 텍스트** | 각 섹션에 이미 들어간 글 |
| **설명 글 · 자료** | 유저가 쓴 설명과 첨부한 파일·URL |

## 2. 출력

**질문 단계 배열.** 단계 하나는 이렇게 생겼다.

```
{
  주어        : 왼쪽 제목에 들어갈 섹션 이름표
  칸 배열     : [{ 라벨, 인풋 종류, 필수/선택, 플레이스홀더, 스위치 동작 }, ...]
  반복        : 없음 | 1단 | 2단
                반복이면 → { 묶음 라벨(칸 라벨을 생략할 때만), 대표 칸, 안쪽 추가 버튼 이름(2단일 때만) }
  안내 문구   : [ 안내 1, ... ] — 안내 자리 수만큼(대개 0~1개) · 배열 순서 = 그 섹션에서 보이는 순서
  버튼 텍스트 칸 : [ 버튼 1, 버튼 2, ... ] — 버튼 수만큼 · 배열 순서 = 그 섹션에서 버튼이 보이는 순서
}
```

- **스위치 동작** — `켜기·끄기` 칸에만. 켜면 **어느 칸을 숨기는지/드러내는지/잠그는지, 라벨이 어떻게 바뀌는지**를 적는다 (3-8)
- **대표 칸** — 다 채운 반복 항목이 접힐 때 **한 줄 요약으로 보일 칸**. 그 묶음의 **제목·이름 역할 칸**, 없으면 **첫 필수 텍스트 칸**
- **버튼 텍스트 칸 = 버튼 수만큼의 배열, 순서로 매칭한다** — `있음` 하나만 내면 버튼이 여러 개일 때 유저가 친 글을 어느 버튼에 넣을지 정할 수 없다. **배열 순서 = 섹션에서 버튼이 보이는 순서**: 세로로는 **위 → 아래**, 한 줄에 **2단 이상 나란한 버튼은 좌 → 우**(왼쪽 줄을 다 센 뒤 다음 줄로 · 3-7의 칸 순서 규칙과 같은 약속). **반복 항목 안의 버튼은 전 항목이 같은 문구**(반복 = 한 행의 복제)라 **칸 1개만** 둔다
- **안내 문구도 버튼과 같은 순서 매칭이다** — 섹션의 안내 자리(슬롯) 수만큼 배열로 내고, **순서 = 섹션에서 보이는 순서**. 「무엇에 대한 안내인지」는 따로 적지 않는다 — **자리가 곧 소속**이다(폼 아래 슬롯 = 폼 안내). 한 섹션이 여러 단계로 나뉘면 **그 단계가 받는 칸들 바로 아래 놓인 안내 자리**가 그 단계 몫이다
- **플레이스홀더** — 값 1개. 단 **고르기에 딸린 값 칸은 선택지별 목록** `{ 선택지: 플레이스홀더 }` (3-6)

## 3. 규칙

### 3-0. 질문 문구 (왼쪽 패널 제목)

단계마다 왼쪽 맨 위에 **한 줄**이 붙는다. 이 줄이 「무엇을 채우는 단계인지」를 말한다.

| 칸 상태 | 문구 |
|---|---|
| 비어 있다 | **`{주어}{을/를} 추가하면 좋아요`** |
| AI가 미리 채웠다 | **`{주어}{을/를} 미리 채워뒀어요`** |
| 빈 칸과 채운 칸이 섞여 있다 | **`추가하면 좋아요`** — 「미리 채워뒀어요」는 **그 단계의 모든 칸이 채워져 있을 때만** 쓴다 |

**주어 = 그 단계가 채우는 섹션의 이름표.** 아래 순서로 찾는다 — **0번이 가장 먼저다.**

0. **히어로 단계면 → 그 단계가 받는 칸의 고정 이름** (`메인 이미지` · `로고 이미지` · `프로필 이미지` · `메인 문구`) — 🚫 섹션 이름(`히어로`)이나 `히어로 문구`를 주어로 ❌ (「히어로」는 만드는 쪽 용어라 화면에 못 나간다)
1. 섹션 제목이 **두 줄(작은 라벨 ＋ 제목)**이면 → **라벨 줄**
2. 한 줄이면 → **그 제목**
3. 신청 폼이면 → **폼 제목** (`참가 신청서`)
4. 제목이 문장이면 → **그 섹션에 지어 둔 명사형 이름표**

**지킬 것**

- 🚫 **칸 라벨을 주어로 쓰지 않는다** — `이미지를 추가하면 좋아요` ❌ (무슨 섹션인지 알 수 없다)
- 🚫 **라벨 줄의 말이 제목에 그대로 들어 있으면 라벨을 주어로 쓰지 않는다** — `안내` ＋ `가격과 발송 안내` 같은 겹침은 **제목 줄**을 쓴다
- **조사** — 주어 마지막 글자에 **받침이 있으면 `을`, 없으면 `를`**
- 🪞 **주어와 칸 라벨의 말을 맞춘다** — **칸이 하나뿐인 단계는 주어 = 그 칸의 라벨과 같은 말** (주어 `메인 문구` ＋ 라벨 `한 줄 카피` 같은 어긋남 ❌ — 유저는 둘이 다른 것인 줄 안다). 칸이 여럿인 단계만 주어 = 묶음 이름, 칸 라벨은 각자

### 3-0-B. 입력칸을 만들지 않는 칸 · 칸 라벨 말

- 🚫 **eyebrow(제목 위 작은 꾸밈 글)와 섹션 제목은 입력칸을 만들지 않는다** — 이 둘은 시안이 정하는 꾸밈·이름표 요소라 유저 편집 대상이 아니다. 섹션에 그 칸이 있어도 질문 화면에서 뺀다. **이름을 바꿔 달아도 똑같이 ❌** — `작은 소개` · `상단 문구` 같은 별칭으로 eyebrow 입력칸을 만들지 않는다 (판정은 라벨이 아니라 **그 값이 제목 위 작은 글로 렌더되는가**로)
- 🚫 **역할이 정해진 사실 행의 라벨(`일시` · `장소` · `가격` · `연락처`)도 입력칸으로 묻지 않는다** — 라벨은 화면에 **고정 표기**하고 **값 칸만** 받는다. 라벨 입력칸을 두는 건 **유저가 항목을 자유로 늘리는 라벨＋값 표**뿐이다
- 🚫 **아이콘 자리(문의 · 핵심 정보 · SNS · 헤더 메뉴의 작은 그림)도 입력칸을 만들지 않는다** — 섹션에 딸린 그림이지 유저 이미지를 받는 자리가 아니다. 채우는 쪽은 둘로 갈린다:
 - **유형을 고르는 칸이 있으면** → 아이콘은 **고른 유형을 따라간다** (전화를 고르면 전화 아이콘)
 - **유형 없이 내용에 딸린 이모지 자리**(안내 사항·나열 항목 왼쪽의 한 글자 칸)는 → **유저가 그 항목의 텍스트를 바꾸거나 항목을 추가할 때 AI가 새 내용에 맞는 이모지로 갱신**한다(「반응 문구」 호출이 함께 출력 — 그 규칙 참조). 바뀐 글 옆에 안 맞는 이모지를 그대로 두지 ❌
- ℹ️ 반대로 **`채움 = AI`인 칸(히어로 제목·설명 등)은 입력칸을 준다** — 질문 화면에서 빼는 건 위 셋뿐이다
- 🚫 **칸 라벨에 영어·제작 용어를 쓰지 않는다** — 라벨은 전부 쉬운 국문으로 (`페이지 제목` · `한 줄 카피` · `이미지`). `EYEBROW` · `CTA` · `label` · `섹션` · **`히어로`** 같은 **만드는 쪽 용어**를 유저에게 그대로 보여주지 ❌ — 주어(왼쪽 제목)에도 똑같이 적용된다 — **섹션 슬롯 이름(`label`·`LABEL`)이 화면에 그대로 새어 나오면 안 된다**(고정 라벨 7개나 역할 이름으로 바꿔 단다)

### 3-1. 인풋 종류 12가지 — 이 밖의 입력 UI는 만들지 않는다

| 종류 | 받는 것 |
|---|---|
| **일반 텍스트** | 문장·설명 (여러 줄) |
| **제목 텍스트** | 이름·제목처럼 **한 줄로 끝나는 말** |
| **날짜** | 날짜 (피커) |
| **시간** | 시각 (피커) |
| **단일 이미지** | 사진 1장 |
| **복수 이미지** | 사진 여러 장 |
| **파일** | 방문자가 **받아 갈 문서** 1개 (카탈로그 · 메뉴판 · 브로슈어 PDF) — **이미지 인풋과 별개.** 올린 파일은 페이지에서 **다운로드 버튼**에 연결된다. 유저가 처음에 첨부한 파일이 이 용도면 **그 파일을 미리 채워 둔다** |
| **링크(URL)** | 주소 |
| **주소** | 장소 (검색 결과에서 고름 ＋ 상세 주소) |
| **고르기** | 정해진 것 중 하나 |
| **켜기·끄기** | 켜고 끄기 (값을 받지 않는다) |
| **갈래 선택** | 유형 · 선택지 |

- 🗺 **`주소`(검색) 인풋은 그 값이 「지도」에 들어갈 때만 쓴다** — 검색에서 결과를 골라야 지도·길찾기가 동작하기 때문이다. **지도 없이 글자로만 보이는 장소 이름**(행사 정보의 장소 행 등)은 `제목 텍스트`로 받는다(검색이 안 되는 장소 — 온라인 · `본관 2층 세미나실` — 도 적을 수 있어야 한다). **장소 이름과 지도용 주소는 다른 정보** — 한 칸에 묶지 않고 각자의 섹션 단계에서 따로 묻는다
- **켜기·끄기는 값을 받지 않는다.** 하는 일은 넷 — ⓐ **다른 칸을 숨기거나 드러낸다**(드러날 때 라벨이 바뀔 수 있다 — `종료일 추가`를 켜면 `날짜`가 `시작 날짜`로) ⓑ **칸을 잠근다**(`인원 제한 없음`) ⓒ **표시를 끈다**(`할인율 표시`) ⓓ **그 항목의 속성을 켠다**(`필수` · `복수 선택`). **스위치마다 무엇을 하는지를 칸 배열의 「스위치 동작」으로 출력**한다 (자주 쓰는 예 = 3-8)
- 위 12가지로 만들 수 없는 입력이 나오면 **가장 가까운 종류로 받는다**(대개 `일반 텍스트`·`제목 텍스트`) — 캘린더 그리드 · 슬라이더 · 태그 입력 · 서식 있는 글 편집기 같은 **새 입력 UI를 창작하지 ❌**
- 🔑 **인풋 종류는 섹션 칸의 생김새가 아니라 「받는 값」이 정한다** — 섹션 칸이 자유 텍스트(라벨＋값 행)여도, 값이 **날짜·시각이면 `날짜`·`시간`(피커)** · 지도에 쓰일 주소면 `주소`(검색) · URL이면 `링크` · 가격·정원이면 **단위를 포함한 한 줄 값**(`제목 텍스트` · 플레이스홀더가 형식을 보여준다 — `예: 35,000원`). **일시를 텍스트 칸으로 받지 ❌** — 일시 = `날짜`＋`시간` 가로 한 줄(종료 시간은 켜기·끄기로). 화면에 찍히는 형식(`2026. 10. 16 (금) 09:00 - 17:00`)은 받은 값으로 조합한다
 - 이때 **반복 묶음의 「같은 꼴」보다 값 유형이 우선** — 라벨＋값 표에서 행마다 값 인풋이 달라도 된다(일시 행 = 피커 · 장소 행 = 텍스트)

### 3-2. 반복 여부 판정

| 판정 | 조건 | 결과 |
|---|---|---|
| **반복 없음** | 그 섹션이 그 정보를 **한 벌만** 담는다 | 칸을 그대로 나열 |
| **1단 반복** | **같은 꼴의 칸 묶음이 2벌 이상** 들어간다 | 묶음 한 벌 ＋ `항목 추가` |
| **2단 반복** | 반복되는 항목 **안에** 또 반복되는 칸이 있다 | 바깥 ＋ 안쪽 각각 추가 버튼 |

- **반복은 2단까지만.** 3단이 필요해 보이면 **안쪽 두 단을 합쳐 2단으로 받는다**(가장 안쪽 반복을 한 칸 안의 줄 나열로)
- 🧪 **자기 점검 = 칸 배열에 같은 라벨이 두 번 나오면 반복 판정을 놓친 것** — `[항목, 내용, 항목, 내용]`처럼 같은 꼴을 평평하게 펼치지 ❌ → **묶음 한 벌(`항목`·`내용`) ＋ 반복**으로 바꾼다 (펼친 채 두면 배치 규칙이 4칸 한 묶음으로 오해해 줄이 어긋난다)
- 🔀 **반복 = 「칸 구조」의 반복이지 「값」의 반복이 아니다** — 신청 폼의 질문처럼 묶음 안에 `유형`(객관식/주관식) 고르기가 있으면 **유형은 항목마다 각각 고른다**. 객관식과 주관식이 한 폼에 섞이는 게 정상이다(한 번 고른 유형을 전 항목에 적용 ❌)
- **2단일 때 안쪽 추가 버튼**은 무엇이 늘어나는지 드러나는 이름을 지어 출력한다(`옵션 추가` · `메뉴 추가`) — 바깥과 같은 이름이면 어느 단계가 늘어나는지 알 수 없다
- 🏷 **대표 칸을 정해 출력한다** — 다 채운 항목이 접힐 때 보일 **한 줄 요약 칸**. 그 묶음의 **제목·이름 역할 칸**, 없으면 **첫 필수 텍스트 칸** (칸 값을 전부 이어 붙이지 ❌)

### 3-3. 한 단계의 뼈대

```
[주 입력 묶음]   칸 1~4개
   └ 반복이면 이 묶음이 통째로 늘어난다
[안내 문구]      그 섹션(단계 몫)에 안내 자리가 있을 때만 · 자리 수만큼(대개 0~1개)
[버튼 텍스트]    그 섹션에 버튼이 있을 때만 · 버튼 수만큼
```

- **칸이 5개 이상이면 두 단계로 나눈다**
- 🦸 **히어로는 고정 이름 단위로 단계를 나눈다** — `메인 이미지` / `로고 이미지` / `프로필 이미지` / `메인 문구`(페이지 제목＋설명) 각각 **한 단계씩**. 이미지와 제목·문구를 한 단계에 묶지 ❌ — 묶으면 주어가 하나로 떨어지지 않는다
- 🔪 **성격이 다른 사실 덩어리는 칸이 적어도 단계를 나눈다** — 일시(날짜·시간)와 장소(주소·상세 주소)를 한 단계에 묶지 ❌. **한 단계 = 한 가지 질문** — 왼쪽 제목의 주어가 한 가지로 떨어져야 반응 문구·미리보기 연결선도 그 하나를 가리킨다 (같은 섹션의 행들이라도 단계는 나뉜다)
- **안내 문구는 반복 바깥**에 둔다 — 항목마다 늘어나지 않는다
- 🖼 **같은 역할의 이미지 자리 여러 개 = 「복수 이미지」 인풋 하나로 묶는다** — 섹션에 이미지 자리가 3개 있어도 역할이 같으면(갤러리·시설 사진) **인풋 1개 ＋ `항목 추가`**. 자리 수만큼 이미지 인풋을 벌리면 같은 라벨 `이미지`가 반복돼 **무엇을 올리라는지 알 수 없다**(한 단계에 이미지 인풋이 하나여야 왼쪽 제목의 주어가 그걸 말해 준다). **역할이 다른 이미지**(로고·메인·프로필)만 각각 인풋 ＋ 예외 라벨로 나눈다
- ✍️ **같은 역할의 「글」 자리 여러 개도 똑같이 반복으로 묶는다** — 섹션에 같은 역할의 텍스트 자리가 여럿이면(특징 3줄 · 한 줄 소개 4개) **칸 하나짜리여도 묶음 한 벌 ＋ `항목 추가`(반복)** 로 받는다. 하나만 묻고 나머지 자리를 비워 두지 ❌

### 3-4. 라벨 정하기

**고정 라벨 7개** — 아래 뜻에 해당하면 **항상 이 말**을 쓴다.

| 라벨 | 언제 |
|---|---|
| `이미지` | 모든 사진 칸 |
| `제목` | 반복 항목의 이름 칸 |
| `내용` | 반복 항목의 본문 칸 |
| `날짜` | 날짜 칸 |
| `시간` | 시각 칸 |
| `안내 문구` | 단계 맨 아래 부가 한 줄 — **페이지에 실리는 섹션 하단의 작은 보충 글**(조건·유의 · 예: `부가세 포함` · `주차는 건물 뒤편`). 본문(소개·설명)은 ❌ — 그건 주 입력 묶음의 텍스트 칸이다 |
| `버튼 텍스트` | 버튼에 들어갈 말 |

**그 밖의 라벨을 지을 때 5가지**

1. **명사로 끝낸다** — `가격` ✅ / `가격 입력` ❌
2. **2~6자**
3. **그 칸 하나가 받는 것만** 가리킨다 — 두 가지를 묶은 라벨 ❌
4. **주제어를 넣지 않는다** — `프로그램 제목` ❌ → `제목`. 무엇에 대한 칸인지는 **왼쪽 패널 제목**이 이미 말하고 있다
5. **한 단계 안에 같은 라벨 두 개 ❌** — 앞에 구분어를 붙인다(`시작 날짜`·`종료 날짜` / `정상가`·`할인가`)

**예외 3가지**

| 예외 | 라벨 |
|---|---|
| 히어로의 사진 | `메인 이미지` · `로고 이미지` · `프로필 이미지` — 역할마다 다른 라벨 · **같은 라벨의 이미지 인풋을 한 단계에 두 번 ❌** |
| 링크 칸 | 용도를 앞에 붙인다 — `유튜브 URL` · `링크` |
| 고르기 칸 | 무엇을 고르는지 — `유형` · `별점` |

**칸 라벨 대신 「묶음 라벨」 하나만 내는 경우 2가지** — 이때는 칸 라벨을 생략하고 **묶음 라벨**(`문의 연락처` · `후기`)을 출력한다
 | 조건 | 예 |
 |---|---|
 | 첫 칸이 **고르기**이고, **고른 값이 곧 그 항목의 이름**이 될 때 | `전화` ＋ 전화번호 칸 · `인스타그램` ＋ 주소 칸 |
 | 한 줄의 칸이 **전부 선택 칸**일 때 | 별점 ＋ 작성자 ＋ 날짜 |

### 3-5. 필수와 선택

| 분류 | 판정 |
|---|---|
| **필수** | 이 칸이 비면 **그 섹션이 성립하지 않는다** — 항목의 이름·제목, 일시, 가격 |
| **선택** | 비어도 섹션이 성립한다 — 설명 문구 · 안내 문구 · 부가 정보 |

- **칸이 하나뿐인 단계는 무조건 필수**
- **AI가 미리 채운 칸도 찬 것으로 센다**
- **`이건 없어요` = 그 질문 하나만 건너뛴다** — 같은 단계의 채워진 다른 값은 그대로 둔다. 건너뛴 자리는 `추가하기` 표시로 접혀 남아, 되돌아와 채울 수 있다
- **반복 항목은 항목 안에서도 나뉜다** — 항목은 **필수 칸이 다 차야 완성**. 선택 칸만 빈 항목은 그 부분만 빼고 만든다

**자주 쓰는 묶음의 필수 · 선택**

| 묶음 | 필수 | 선택 |
|---|---|---|
| 날짜 ＋ 시간 | 날짜 | 시간 · 종료 일시 |
| 주소 | 주소 (**검색 결과를 고른 상태**여야 찬 것으로 센다) | 상세 주소 |
| 가격 | 판매가 | 정상가 · 할인율 |
| 제목 ＋ 내용 반복 | 제목 · 내용 | — |
| 이미지 ＋ 글 반복 | 이미지 · 제목 | 설명 |
| 이름 ＋ 링크 반복 | **이름 · 링크 둘 다** (하나만으론 버튼이 동작하지 않는다) | — |
| 연락처 반복 | 유형 · 값 | — |
| 예약 회차 | 날짜 · 시간 | 정원 |
| 후기 | 내용 | 별점 · 작성자 · 날짜 · 상품 옵션 |
| 신청 폼의 질문 | 유형 · 질문 · **객관식이면 선택지 2개 이상** — 유형은 **항목마다 각각**(한 폼에 객관식·주관식 섞임이 정상) | 주관식 답변 유도 문구 |
| 라벨 ＋ 값 표 | 라벨 · 값 쌍 (**채운 행만** 센다 · 빈 행은 지운다) | — |

### 3-6. 플레이스홀더

**왼쪽 입력칸의 빈칸 안내에만 해당한다.** 오른쪽 미리보기에 들어가는 글에는 `예: `를 쓰지 않는다 — 미리보기는 완성된 페이지처럼 보여야 한다.

| 대상 | 형식 | 예 |
|---|---|---|
| 기본 | **`예: ` ＋ 그 칸에 들어갈 법한 값** | `예: 아메리카노` · `예: 4,500원` |
| **날짜 · 시간 · 주소 · 연락처 · 링크** | **지시형** — 입력 방식이 형식을 강제하므로 예시가 필요 없다 | `날짜를 선택해 주세요.` · `링크 URL을 입력해 주세요.` |
| 계좌 · 가격 · 정원 · 작성자 이름 | **예시형** — 어떤 형태로 적을지를 예시가 알려준다 | `예: 국민은행 123456-78-901234` · `예: 20명` |
| 반복 항목 **2번째부터** | 지시형 | `내용을 입력해 주세요.` |

- 지시형 어미는 **`~해 주세요.`** 로 통일한다(마침표 포함)
- **고르기에 딸린 값 칸의 플레이스홀더는 「선택지별 목록」으로 출력한다** — 하나만 내면 유형을 바꿔도 플레이스홀더가 안 바뀐다. 예: `{ 전화: "전화번호를 입력해 주세요.", 이메일: "이메일을 입력해 주세요.", 인스타그램: "계정 주소를 입력해 주세요." }`

### 3-7. 순서

- **단계 순서 = 페이지에서 섹션이 놓인 순서**
- **단계 안의 칸 순서 = 그 섹션에서 정보가 보이는 순서**

### 3-8. 스위치 동작 출력

**켜기·끄기 칸마다 「스위치 동작」을 출력한다** — 켜면 **어느 칸**을 숨기는지/드러내는지/잠그는지, 라벨이 어떻게 바뀌는지. 자주 쓰는 예:

| 스위치 | 켜면 (스위치 동작에 적을 내용) |
|---|---|
| `하루종일` | `시간` 칸을 숨긴다 (종료 시간까지) |
| `종료일 추가` | 종료 `날짜`·`시간` 칸이 생기고, 원래 라벨이 `시작 날짜`·`시작 시간`으로 바뀐다 |
| `인원 제한 없음` | `정원` 칸을 잠근다 |
| `할인율 표시` | 끄면 할인율 표시를 숨긴다 |

### 3-9. 미리보기에 넣을 수 없는 것

아래는 **입력을 받아도 페이지에 표시할 방법이 없다.** 칸을 만들지 않는다.

- **남은 자리 · 잔여 수량** — 예약이 들어올 때마다 바뀌는 숫자
- **D-DAY · 남은 날짜** — 시간이 지나면 바뀌는 표시

정원은 **`회차당 정원 8명`** 처럼 **바뀌지 않는 문장**으로만 보여준다.
