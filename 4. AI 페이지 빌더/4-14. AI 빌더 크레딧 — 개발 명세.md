# AI 빌더 크레딧 — 개발 명세

> **정본 시안**: [크레딧 모달 섹션 8028-46058](https://www.figma.com/design/24O01lprp5i2ufl7CbZXXx/AI-%EC%84%B9%EC%85%98-%ED%94%84%EB%A6%AC%EC%85%8B?node-id=8028-46058) · [잔여 크레딧 표시 섹션 8028-45687](https://www.figma.com/design/24O01lprp5i2ufl7CbZXXx/AI-%EC%84%B9%EC%85%98-%ED%94%84%EB%A6%AC%EC%85%8B?node-id=8028-45687) (`*Sketch` 페이지)

## 1. 크레딧 정책 (수치 확정)

### 지급

| 시점 | 지급량 | 횟수 |
|---|---|---|
| 가입 시 | **50 C** | 1회 |
| 가입 30일 후 | **50 C 추가** | 1회 |

### 차감 (AI 빌더)

| 동작 | 차감 | 비고 |
|---|---|---|
| **첫 시안(1안) 생성** | **−20 C** | ⑥ 단계 진입 시 |
| 추가 2안(B·C) 생성 | **0 C** | ⑨ 「네, 보여주세요」 — 차감 없음 |
| **3안 재생성** | **−20 C** | ⑩ 3안 비교 화면의 「3안 재생성」 버튼 |
| 내용 채우기·무드 변경·에디터 전환 | 0 C | 차감 없음 |

- 가입 혜택만으로 가능한 사용량: **첫 생성 1회 + 재생성 2회** (50 = 20+20+10 남음), 30일 후 +50으로 동일 사이클 1회 더.
- 기존 과금(발행 120 C/1개월, 예약 7 C 등)과 **같은 크레딧 풀**을 쓴다.

### 차감 UX 원칙

- **차감 확인 모달 없음** — 차감은 조용히. 동의·학습은 ⓐ 버튼에 비용 병기 ⓑ M1 웰컴 모달이 대신한다.
- **유일한 차감 관련 모달 = M3 크레딧 부족** (잔액 < 20 C 상태에서 차감 동작 시도 시에만).
- 잔액 임박 경고(배지 색 변화·토스트) **없음**.

## 2. 잔액 표시 UI

| 요소 | 스펙 |
|---|---|
| **잔액 배지** | 빌더 전 화면 **우상단 플로팅 필** `내 크레딧 {잔액} C` · 차감 즉시 실시간 갱신 |
| **비용 병기 버튼** | 차감이 걸린 버튼에만 비용 표기: `✦ 3안 재생성 · 20 C` |

- 시안의 `30 C`는 예시 수치(가입 50 − 첫 생성 20 시점). `{잔액}`은 실값 바인딩.
- 첫 생성 버튼(⑤→⑥ 진입)에도 같은 패턴으로 `· 20 C` 병기 — 시안에는 ⑩ 재생성 버튼만 예시로 있음.

## 3. 모달 명세 (4종)

모두 기존 디자인 시스템 컴포넌트의 **인스턴스 + 오버라이드** — 새 컴포넌트 없음.

### M1 · 웰컴 크레딧 지급

- **컴포넌트**: `Modal/Confirm/First URL` (DS `9GM1FagjqiyrQHyHLBGoFj` · `15211:19837`) — 이미지만 💎 젬스톤으로 교체
- **트리거**: 가입 직후 1회
- **시안**: Desktop [8104-45664](https://www.figma.com/design/24O01lprp5i2ufl7CbZXXx/AI-%EC%84%B9%EC%85%98-%ED%94%84%EB%A6%AC%EC%85%8B?node-id=8104-45664) · Mobile `8104:45698`

| 요소 | 값 |
|---|---|
| 제목 | `가입 선물로 50크레딧을 드려요!` |

### M3 · 크레딧 부족

- **컴포넌트**: 기존 공용 `Modal/Confirm/Text` — **기존 제품 문구 그대로 재사용** (전용 문구 없음)
- **트리거**: 잔액 < 20 C 상태에서 차감 동작(첫 생성·3안 재생성) 시도 시
- **시안**: Desktop `8028:46063` · Mobile `8028:46064`

| 요소 | 값 |
|---|---|
| 제목 | `크레딧이 부족합니다` |
| 본문 | `보유한 크레딧이 부족합니다. 크레딧을 충전할까요?` |
| 보조 버튼 | `취소하기` → 모달 닫기 (만든 시안·진행 상태는 그대로 유지) |
| 주 버튼 | `충전하기` → 기존 충전 모달 `Modal/Billing/Charge Credit`(`15219:31272`) 연결 |

### M6 · 진행본 복귀

- **컴포넌트**: 공용 `Modal/Confirm/Text` + 문구 오버라이드
- **트리거**: AI 빌더 진입 시 저장된 진행본이 있을 때 (진입 경로 무관)
- **시안**: Desktop `8028:46066` · Mobile `8028:46067`

| 요소 | 값 |
|---|---|
| 제목 | `작업하던 페이지가 있어요` |

## 4. 진행본(이어 만들기) 규칙

| 항목 | 규칙 |
|---|---|
| 저장 단위 | **계정당 최신 1개** |
| 저장 시작 | **⑥ 첫 시안 생성 이후** (①~⑤ 입력만 하다 이탈하면 저장 안 함 — 크레딧이 쓰인 작업물부터 저장) |
| 소멸 | **⑫ 에디터 전환 완료 시** 슬롯 비움 |
| 크레딧 관계 | 진행본 복원은 차감 없음. 「삭제하고 새로 만들기」 후 새 첫 시안 생성은 **다시 20 C 차감** |

## 5. 상태 흐름 예 (가입 유저 1명)

```
가입            +50  → 잔액 50   (M1 노출)
첫 시안 생성     −20  → 잔액 30   (배지 30 C · 추가 2안은 무료)
3안 재생성       −20  → 잔액 10
3안 재생성 시도   잔액 10 < 20 → M3 노출 (차감 없음 · 시안 유지)
가입 30일 후     +50  → 잔액 60   (다음 접속 시 M1-B 노출)
```

## 6. 🚧 개발 착수 전 결정 필요

| # | 항목 | 내용 |
|---|---|---|
| 1 | **차감 시점** | 생성 「시작 시」 차감 vs 「완료 시」 차감. 시작 시 차감이면 **생성 실패 시 자동 환급** 필요 (실측: PDF 첨부 시 3안 생성 실패 재현 — [[4-9-6. AI 빌더 API 비용 측정]] §2) |
| 2 | **포인트 폴백** | 기존 과금은 P → C 순서 차감. AI 생성 차감도 포인트 잔액을 쓸 수 있는지, 크레딧 전용인지 |
| 3 | **M3 모바일 버튼** | 시안의 Mobile 주 버튼이 `확인하기`로 남아 있음(Desktop은 `충전하기`) — `충전하기`로 통일 권장 |
| 4 | **무료 지급분 만료** | 가입 50 C·30일 50 C에 만료 기한을 둘지 (현 명세는 무기한) |
| 5 | **재생성 반복 차감** | 「3안 재생성」은 누를 때마다 매번 20 C 차감으로 명세 — 상한 없음 확인 |
