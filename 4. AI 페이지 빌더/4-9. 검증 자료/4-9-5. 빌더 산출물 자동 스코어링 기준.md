## 1. 판정 원칙 — 전부 기계가 채점할 수 있어야 한다

1. **모든 체크 = ID ＋ 대상 산출물 ＋ 판정식 ＋ 심각도.** 판정식은 다음 넷 중 하나만 허용:
   - **패턴**: 정규식 매칭 (금지어·형식·종결어)
   - **집합**: 토큰·id가 허용 목록(⊆)에 드는가 / 입력에 실재(⊆ IN)하는가
   - **수치**: 개수·길이·값 비교 (연속 항목 ≤6 · 여백 ≥20)
   - **재계산**: 같은 규칙을 스크립트로 다시 계산해 출력과 대조 (대표 칸·네 구역·무드 후보)
2. 🚫 **주관어 금지** — 체크 문장에 `어색하다`·`자연스럽다`·`적절하다`·`예쁘다`·`무드에 맞다`가 들어가면 그 체크는 무효. 전부 위 넷으로 바꿔 적는다.
3. **⚙ 표시 = 보정 가능한 임계값** — 숫자 자체는 가설이고, 오탐·미탐이 쌓이면 §7 절차로 고친다. 임계값을 고쳐도 체크 ID는 유지.
4. **심각도 3단계**
   | 급 | 뜻 | 채점 |
   |---|---|---|
   | **C 치명** | 사실 지어냄 · 유저 값 유실 · 내부 용어 노출 · 실존하지 않는 id | **케이스 즉시 FAIL** (점수와 별개 플래그) |
   | **M 주요** | 규칙 위반 — 유저가 알아챌 결함 | **−4점** |
   | **m 경미** | 형식·표기 어긋남 | **−1점** |
5. **점수 = max(0, 100 − 4×M건수 − 1×m건수)** · **통과 = FAIL 0 ＆ 점수 ≥90** ⚙. 스위트 지표 = 케이스 통과율 ＋ **체크별 발생률**(어느 체크가 자주 깨지는지 = 다음 MD 보강 대상).

## 2. 스코어러 입력 패키지 — 채점에 쓰는 텍스트 전부

### 2-A. 케이스 입력 (IN)

| 키 | 내용 |
|---|---|
| `IN.text` | 첫 입력 글 (원문) |
| `IN.mat` | 자료의 파싱 텍스트 전부 (PDF 추출문 · URL 본문) |
| `IN.files` | 첨부 파일명 목록 (`logo.webp` 등) |
| `IN.url_ok` | URL별 수집 성공 여부 (불리언) |
| `IN.filled` | 내용 채우기에서 유저가 친 값 로그 `{칸, 값, 순서}` |
| `IN.gold` | **골든 라벨** — 케이스 작성자가 미리 적는 정답: 주제 코드 · 목적 분류 · 페이지 유형 · 무거운 소식 여부 (§5) |

### 2-C. 사실 토큰 추출기 — 환각 판정의 공통 부품

산출물과 입력 양쪽에서 아래 패턴을 뽑아 **집합 비교**한다. `OUT 토큰 ⊆ IN 토큰`이 아니면 = **지어낸 사실**.

| 토큰 | 패턴 |
|---|---|
| 날짜 | `\d{1,2}월 ?\d{1,2}일` · `\d{4}[.\-/] ?\d{1,2}[.\-/] ?\d{1,2}` |
| 시각 | `\d{1,2}:\d{2}` · `(오전|오후) ?\d{1,2}시` |
| 금액 | `[\d,]+ ?원` · `₩[\d,]+` |
| 전화 | `0\d{1,2}-\d{3,4}-\d{4}` |
| 계좌 | `\d{2,6}-\d{2,6}-\d{2,6}` (전화 패턴 제외) |
| 이메일 · URL | 표준 패턴 |
| 수량·정원 | `\d+ ?(명|석|개|팀|부)` |

⚠️ 비교는 **정규화 후** (공백·구두점 제거, `11월15일`=`11월 15일`). 날짜는 연도 생략형↔완전형을 같은 값으로 접는다.
🆕 **TC50 런 보정 (2026-10-13 · `.data/tc50/`)** — ① 날짜·시각은 **숫자 단위로 접는다**(`12월 5일`=`2026-12-05`=`12/5` · 선행 0 제거 · 월 1~12·일 1~31 검증 — 자릿수 차이로 오탐 다발) ② ISO 날짜(`2026-11-05`)는 계좌 패턴에서 제외 ③ **입력(IN) 쪽은 관대 추출** — `원` 없는 콤마 가격(`35,000→28,000원`의 앞 값)·맨 `N시`(오전/오후 양쪽 후보)도 토큰으로(자료 표기가 헐거워 산출물만 엄격 추출하면 환각 오탐) ④ **수량(`N개`) 토큰은 C급 환각 판정에서 제외** — 항목 수에서 파생 가능(`구성 3개`)이라 지어냄이 아니다.

## 5. 테스트 케이스 포맷 — 골든 라벨까지가 케이스다

```json
{
  "id": "TC-031",
  "text": "다음 달 성수동에서 ... (첫 입력 글 원문)",
  "materials": [{"type":"url","value":"https://...","fetched":true},{"type":"file","name":"logo.webp"}],
  "fill_scenario": [
    {"step":"일시","action":"fill","value":"2026-11-15 14:00"},
    {"step":"연락처","action":"skip"},
    {"step":"작업물 2","action":"fill_partial","fields":{"제목":"리브랜딩","이미지":null}}
  ],
  "gold": {"topic":"1-①","purpose":{"base":"P2","extra":["P3"]},"type":"원페이지","heavy":false}
```

- **골든 라벨은 케이스 작성 시 사람이 1회 확정** — 이후 채점은 전부 기계.
- `fill_scenario`에 **일부러 구멍을 설계**한다(건너뛰기 · 이미지 없는 항목 · URL 수집 실패) — S6·S10의 삭제·보존 체크가 이 구멍으로 작동한다.
- 케이스 축 = 주제 25 × 자료 양(Lv0~4 · [[4-9-4. 빌더 실기 테스트 8사례]]) × 구멍 패턴(3종⚙) — 조합에서 추출.

## 6. 재런 판별 프로토콜 — 결함의 책임 소재 3갈래

같은 케이스를 **3회 재런** ⚙하고 체크 결과를 겹쳐 본다 (10-13 판별 프레임의 자동화):

| 패턴 | 판정 | 다음 행동 |
|---|---|---|
| 3/3 실패 ＋ 값 자체가 산출물에 없음 | 🔴 **개발 문제** (배관 누락) | 개발 전달 목록에 체크 ID로 기록 |
| 3/3 실패 ＋ 값은 있는데 규칙 위반 | 📘 **MD 규칙 공백/모순** | MD 보강 → 재업로드 → 재런 |
| 1~2/3 실패 (간헐) | 🌀 **AI가 흘림** | MD 0절 승격 또는 출력 자리 보강 검토 |

- 판별 1순위 재료 = **프롬프트 로그** (개발 요청 중 — 확보 전까지는 위 재런 패턴으로 추정).
- MD 수정 후엔 **같은 케이스 재런으로 "잡힘 확인"을 남겨야 종결** (10-13 B표 방식).

## 7. 기준 고도화 루프 — 결함은 반드시 체크가 된다

1. **새 결함 1건 = 신규 체크 ≥1개** — 판정식(§1의 넷 중 하나) 없이는 등재 불가. 주관어가 들어가면 반려.
2. **체크 ID는 불변** — 판정식·임계값만 고친다. 폐기 시 삭제 대신 `~~취소선~~`＋사유 (발생률 통계의 연속성).
3. **오탐 2회 = 판정식 보정** — ⚙ 임계값 변경은 이 절에 날짜·변경 전후 값을 1줄 기록.
4. **발생률 상위 체크 = 다음 MD 보강 대상** — 스위트 리포트는 체크별 실패율 내림차순으로 출력.
