## 2-B. 🚫 AI 이미지 생성 요금 — 측정 불가 (2026-10-22 · 기능 미배포)

내용 채우기 「단일 이미지」의 **「✦ AI 이미지 생성」 버튼([Figma 7113-32930](https://www.figma.com/design/24O01lprp5i2ufl7CbZXXx/AI-%EC%84%B9%EC%85%98-%ED%94%84%EB%A6%AC%EC%85%8B?node-id=7113-32930))은 시안에만 있고 프리뷰 빌드엔 아직 없다.** 동일 5사례 × 3회 생성 측정을 시도했으나 2런 검증 후 중단.

- **검증 방법 3중**: ① 메인 이미지 질문 화면 실측 — 파일 업로드 영역만 있음(클릭해도 모달·AI 탭 없음) ② 화면 DOM 전체에 「AI」 문자열 0건 ③ **Next.js 번들 40청크 전수 검색 — 「AI 이미지」·`generateImage`·`generate-image`·`image_generation` 전부 0건**(「이미지 생성 중」 1건은 내보내기 i18n 문자열 — 오탐). 숨김 플래그가 아니라 **코드 자체가 미배포**.
- **부수 발견**: ⓐ **이미지 질문 유무는 시안 구성에 달렸다** — 요가 사례(Y1) 시안 A는 히어로·클래스 정보·이용 안내·예약·문의 구성이라 **이미지 질문이 플로우에 아예 없음**(11화면 전수 통과) · 채용 사례(P1)는 Q4에 「메인 이미지」 질문 있음(22화면 중). 배포 후 측정 시 **이미지 질문이 나오는 시안인지 먼저 확인**할 것. ⓑ 1안 비용 재확인: 요가 $0.47 (620원) · 채용 PDF $0.47 (620원) — 채용이 §1($0.70~0.72 · 930~960원)보다 낮은 건 **원본 PDF가 이 기기에 없어 같은 내용을 텍스트 기반 2쪽으로 재구성**했기 때문(`아카이브/2026-10-22/credit/wanted-383387-recreated.pdf` · 원티드 원본은 403 차단). 검증 지출 합계 $0.94 (약 1,250원 · 잔액 $180.79→$179.85 = 약 239,730원→238,480원).
- **기기 메모**: 콘솔 쿠키는 **콘솔 로그인이 있는 크롬 프로필**에서 가져온다 — 프로필 번호는 기기마다 다름(10-21 leesunho 기기 = Profile 11 / 10-22 designer 기기 = **Profile 7** · sessionKey 만료 10-27). `credit-run.sh`·`usage-read.sh`의 아카이브 경로가 `/Users/leesunho/…`로 하드코딩돼 있어 designer 기기에선 그대로 못 쓴다.

## 3. 측정 방법 (재사용)

**원리**: Anthropic 콘솔(`platform.claude.com`)의 ① **크레딧 잔액**(실시간 · `/api/organizations/{org}/prepaid/credits`) ② **내부 사용량 API**(`/v1/organizations/analytics/usage` · 1분 버킷 · 모델별 · 반영 지연 수 시간)를 헤드리스 브라우저 세션으로 읽는다. 이 세션(Claudian)은 claude.ai 구독으로 동작하므로 콘솔 크레딧에는 섞이지 않는다.

**전제**
- 콘솔 계정 `.env` `ANTHROPIC_CONSOLE_EMAIL`(개인 조직 → Admin API 없음 · 로그인은 **이메일 코드 방식이라 자동화 브라우저에서 완료 불가**) → 대신 **크롬 Profile 11의 콘솔 쿠키를 가져온다**: `browse cookie-import-browser chrome --profile "Profile 11" --all` (`--domain`으로는 세션이 안 붙음 · 키체인 「항상 허용」 1회 필요 · 쿠키 만료 10-28 → 그 뒤엔 크롬에서 다시 로그인)
- 빌더는 `account@emka.group`로 프리뷰 도메인 로그인 · **같은 계정 동시 사용 ❌(409)** · 측정 중 다른 호출이 섞이면 잔액이 오염됨(10-21 22:08~22:11 미확인 18회 $0.59가 실제로 섞였음)
- 헤드리스 브라우저 서버는 **유휴 몇 분이면 재시작**돼 탭·쿠키가 날아간다 → 파이프라인 대기 중 30초마다 `browse url`로 깨우고, 시작 시 로그인 복구부터 한다.

**스크립트** (`4-13. 데일리 퀄리티 루프/스크립트/`)
| 파일 | 역할 |
|---|---|
| `usage-read.sh <tag> [window_start]` | 잔액 + 1분 버킷 모델별 사용량 → `아카이브/{날짜}/credit/{usage,credits}-{tag}.json` |
| `credit-run.sh` (`STAGE=1|2|3` · `ATTACH=` · `FILL=1`) | 1=설명→1안 완료 정지 · 2=채우기→3안 정지 · 3=무드→에디터. `ATTACH`로 파일 첨부, `FILL=1`이면 빈 칸 자동 입력(🚧 칸 이름 오인식 — 미완) |
| `credit-pipeline2.sh` | 즉시 실행 전체: 로그인 복구 → L4r → L1c → 단계마다 잔액 |
| `credit-pipeline.sh` (`START=HHMM`) | 지정 시각 대기 후 동일 실행 |

**측정 지점** ① 시작 전 ② 1안 완료(「시작하기」 등장) ③ 3안 완료(「3안 재생성」 등장) ④ 에디터 URL 도착 — 지점마다 잔액을 읽고, 토큰 상세는 몇 시간 뒤 같은 창으로 다시 읽어 분 단위로 가른다.
