# 4-12. 입력 유형 카탈로그

> **무엇** — 유저가 내용을 채우는 화면에서 쓰는 **입력 부품 23종**과, 그 부품을 **어느 섹션 슬롯에 끼우는지**를 잇는 규칙.
> **왜** — 섹션은 355개이고 슬롯 구성은 **198가지**다. 변형마다 인풋 셋을 만들면 198벌이 된다. **부품을 조립**해야 한다.

---

## 0. 세 줄 요약

1. **문항은 「슬롯」이 아니라 「재료」를 묻는다** — 히어로 슬롯 구성은 29가지지만 물어야 할 재료는 **6가지**뿐이다.
2. **질문 셋은 주제 고정**([[4-7. 입력 단계 안내 문구]]), **섹션은 그 재료로 빈칸 없이 채워지는 것만** 뽑는다.
3. **`채움 = AI`인 칸도 입력칸을 준다** — 편집 제외는 **eyebrow · 섹션 타이틀 둘뿐**.

## 2. 입력 부품 23종

**상태 4가지는 부품마다 전부 필요하다.**

| 상태 | 언제 | 화면 |
|:--:|---|---|
| ① 비어있음 | 사실 칸, 아직 안 채움 | `○○을 추가하면 좋아요` ＋ 빈칸 |
| ② **AI가 채워둠** | `채움 = AI`인 칸 55개 | `미리 채워뒀어요` ＋ **값이 들어간 채로 편집 가능** |
| ③ 사실인데 못 채움 | 자료에 없음 | 흐린 플레이스홀더 · 끝까지 안 채우면 자동 삭제([[4-11. 실패·예외 처리]] F5) |
| ④ 유저가 채움 | 직접 입력 | 반응 말풍선 2초 (**AI 칸은 고쳐도 반응 없음**) |

### 2-0. 필수/선택 칸 ＋ 하단 버튼 전환 (필수)

각 단계(질문)의 칸은 **필수 / 선택** 둘 중 하나로 분류한다.

| 분류 | 무엇 | 예 (프로그램 단계) |
|---|---|---|
| **필수** | 그 단계(섹션)가 **성립하는 데 없어서는 안 되는 칸** — 항목의 이름·제목, 일시, 가격 등 | 날짜·시간(AI가 미리 채워둠) · **프로그램 제목** |
| **선택** | 비어 있어도 섹션이 성립하는 **부가 칸** — 설명 문구·서브 텍스트. 색인의 **`*` 옵션 슬롯**(§4)이 이 부류 | 프로그램 설명 |

- **하단 버튼은 한 자리 · 필수 충족 여부로 바뀐다**:
 | 상태 | 버튼 |
 |---|---|
 | 필수 칸이 하나라도 비어 있음 | **`이건 없어요`** (건너뛰기) |
 | 필수 칸이 전부 참 | **`다음`** |
- 필수 충족 판정에 **누가 채웠는지는 무관** — 유저 입력·AI가 채워둠·자료 추출 전부 「참」으로 센다(예시의 날짜·시간처럼 미리 채워져 있으면 제목만 채워도 `다음`이 뜬다).
- 🧲 **자료 조건부 칸 = 필수 ** — 스펙·실측처럼 **자료에 그 내용이 있을 때만 해당 슬롯 섹션이 뽑히는** 칸(§4 거르기)은 **빈 채로 나타나는 경우가 없다** → 필수로 분류해도 버튼을 막을 일이 없다.
- 📍 **주소 검색 칸의 「채워짐」 = 검색 결과에서 1개 「선택 완료」 ** — 입력칸에 **타이핑만 한 상태는 미충족**이다(글자가 있어도 버튼은 `이건 없어요` 유지). 검색 목록에서 골라야 좌표가 생겨 지도·길찾기가 동작하기 때문 — 타이핑만 받으면 「채워졌는데 지도가 안 열리는」 페이지가 된다. 상세주소(선택)는 일반 텍스트 판정 그대로.
- **반복 부품**(반복 아코디언 등)은 **항목 안에서도 같은 분류** — 항목은 필수 하위 칸이 다 차야 완성으로 센다.
- `이건 없어요` = 그 단계를 건너뜀 → 남은 빈 자리는 **⑧ 마지막 확인**에서 일괄 삭제 안내([[4-11. 실패·예외 처리]] F5). ⑦의 버튼과 ⑧의 일괄 처리는 **역할을 나누는 두 겹**이다.
- 📋 **칸별 필수/선택 분류의 정본 = [[4-7. 입력 단계 안내 문구]] 표** — ✅ **「필수」 열 반영 완료 (2026-09-17 히어로 설명 정정 후 279칸 = 필수 256 · 선택 23 · 판정 5규칙 = 4-7 「작성 메모 › 필수/선택 판정」 — ⑤ 별도 인풋 칸 = 필수: 히어로 제목/설명은 각각 별도 인풋이라 둘 다 필수)**. 이 문서는 분류 **기준**과 아래 **부품 내부 필드**를 정한다.

**⏎ 키보드 동작 규칙 (2026-09-17 이선호 확정)** — **엔터로는 단계가 안 넘어간다.** 단계 이동은 하단 버튼 또는 Cmd/Ctrl+엔터만. 조합·반복 화면에서 습관적 엔터로 넘어가는 사고를 원천 차단.

| 키 | 동작 (모든 화면 공통) |
|---|---|
| **Cmd/Ctrl+엔터** | **다음 단계** = 하단 버튼 누르기와 동일 (필수 미충족이면 반응 없음 · 맥/윈도우 양쪽 키 다 받아줌) |
| **엔터 · 탭** | **다음 필드로 포커스 이동** · 마지막(또는 유일한) 필드면 **포커스 해제만** (⚠️ 단계 이동 ❌ · 항목 추가 ❌ — 추가는 `＋ 추가` 버튼만) |
| 여러 줄 텍스트 입력 안의 엔터 | **줄바꿈** (기존 확정 그대로 · 필드 이동은 탭으로) |

- **힌트 표기 = OS 감지해 하나만** — 맥 `⌘+엔터로 다음` / 윈도우·기타 `Ctrl+엔터로 다음`(폴백=Ctrl) · **모바일은 힌트 숨김**(조합키 없음 → 하단 버튼만). 여러 줄 텍스트는 `엔터로 줄을 나눌 수 있어요`(4-7 공통 안내) 유지.

**🖼 이미지 칸 라벨 = 「이미지」로 통일 (2026-09-17 이선호 확정)** — 왼쪽 질문 영역의 이미지 입력칸 라벨은 **전부 `이미지`** 한 가지로 쓴다. **예외 둘뿐 = 히어로의 `메인 이미지` · `로고 이미지`**. `사진`·`제품 사진`·`대표컷`·`프로필 사진` 같은 수식형 라벨 ❌ — 무엇을 올릴지의 맥락은 라벨이 아니라 **왼쪽 패널 제목**([[4-7. 입력 단계 안내 문구]])이 전담한다. (오른쪽 시안 목업 안 플레이스홀더 슬롯 이름은 별개 — 목업 표현 규칙 그대로.)

**💬 부가 안내 줄 입력칸 라벨 = 「안내 문구」로 통일 (2026-09-17 이선호 확정)** — 색인의 `*부가 설명 텍스트` 옵션 슬롯(별표 각주 · 예 `*기부금 영수증을 보내 드립니다`)의 입력칸 라벨은 **`안내 문구`** 한 가지로 쓴다(`부가 설명`·`참고 문구` ❌). **선택 칸** · 플레이스홀더 = `예: 기부금 영수증을 보내 드립니다` · 맨 앞 `*`와 회색 스타일은 **섹션이 붙인다**(유저 입력 ❌).

**복합 부품의 내부 필드 필수/선택** — 반복 항목·묶음 부품은 항목 안에서도 나뉜다. 항목은 **필수 필드가 다 차야 완성**, 선택 필드가 빈 항목·행은 그 부분만 지운다.

#### 「표」는 쓰임이 둘 — 섹션 표 / 항목 표 (질문)

입력 UI(`라벨 ｜ 값 ｜ ✕` ＋ `항목 추가`)는 같지만 **어디에 붙느냐가 다르다.**

| | 부품 | 쓰임 | 예 |
|---|---|---|---|
| **섹션 표** | 라벨 ＋ 값 표 | **섹션 하나에 표 하나** | 안내 사항 · 핵심 정보 · 배송 안내 |
| **항목 표** | **작품 정보 표** · **제품 스펙 표** | **항목(작품·제품)마다 표가 반복** → 표가 **아코디언 안**으로 들어간다 | 도록 작품(제목·작가·재료·크기) · 상품 상세(소재·크기·무게) |

- **작품 정보 표**는 아코디언 안에 **작품 이미지 ＋ 제목 ＋ 표**가 함께 들어간다(도록은 이미지와 캡션이 한 묶음).
- **제품 스펙 표**는 표만 있다 — 제품 이름·가격·사진은 **제품 상세 반복**이 이미 받으므로 다시 묻지 않는다.


#### 신청 폼 — 질문은 아코디언

- **질문 하나 = 아코디언 한 장.** 펼치면 **유형(객관식/주관식) ＋ 질문**이 나오고, 그 아래가 **유형에 따라 갈린다**:
 - **객관식** → `선택지` 입력칸 여러 개 ＋ `선택지 추가`
 - **주관식** → `플레이스홀더` 입력칸 1개
- 한 화면에 둘 다 펼치면 세로가 넘쳐서 **화면을 3장**으로 뒀다 — `비어있음`(유형 미선택) · `객관식 펼침` · `주관식 펼침`.
- 🚫 **`받을 항목` 토글은 따로 두지 않는다 ** — **이름·연락처도 질문 목록 안의 한 질문**이다. 토글을 따로 두면 같은 것을 두 군데서 묻게 된다.
- ✅ **질문 목록 순서 = 목업 폼 순서** — 목록 맨 위 `이름`·`연락처`가 목업 폼에서도 맨 위 칸이다. (목록이 길면 왼쪽 패널은 스크롤되므로 화면에 다 안 보여도 된다)

**CdBd에 실시간 잔여 수량을 보여 주는 기능이 없다.** 예약이 들어올 때마다 숫자가 줄어드는 표시는 **만들 수 없다.**

|---|---|
| 🚫 안 되는 것 | `남은 자리 3석` · `잔여 5명` · `마감 임박` — **예약 수에 따라 바뀌어야 하는 모든 표기** |
| ✅ 되는 것 | **정적 문장** — `회차당 정원 8명` · `선착순 마감` 처럼 **예약이 들어와도 안 바뀌는 말**. 자리는 그 섹션의 **`안내 문구` 슬롯**에 적는다 |
| **잔여 관리** | 실제 마감은 **4단계 예약 카드**가 정원대로 처리한다 — 페이지에 숫자로 보여 주지 않을 뿐 **기능이 없는 게 아니다** |

#### ➕ 반복 항목의 추가 버튼 = 항상 `항목 추가` (필수, 2026-09-18 이선호)

「＋ 추가」 버튼 텍스트를 부품마다 다르게 쓰지 않는다 — **전부 `항목 추가`** 한 가지.

| | |
|---|---|
| **왜** | `버튼 추가`·`회차 추가`·`품목 추가`처럼 **부품마다 다른 말**을 쓰면, 유저는 화면이 바뀔 때마다 **같은 기능을 다른 버튼으로** 인식한다. 문구를 하나로 고정하면 **누르는 법을 한 번만 배우면 된다** |
| **적용** | 반복 부품의 **주 추가 버튼 전부** — 갤러리·버튼＋링크·반복 아코디언·한 줄 항목·이미지＋글·후기·FAQ·라벨＋값 표·제품 상세·카탈로그·예약 회차·신청 폼 |
| **예외 = 2단(중첩) 부품의 「하위」 추가 버튼** | 한 화면에 추가 버튼이 **두 개**면 **주 반복 = `항목 추가`**, 그 안에 딸린 하위 추가는 **무엇이 늘어나는지 드러나는 이름**을 그대로 쓴다(신청 폼 = `항목 추가`(질문) ＋ `옵션 추가`(선택지)). 둘 다 `항목 추가`면 **어느 단계가 늘어나는지 알 수 없다** |
| 🚫 아님 | **`AI 이미지 생성`**은 같은 버튼 컴포넌트(`Button/Editor/Add`)를 쓰지만 **반복 추가가 아니다** · 날짜＋시간 부품의 **`종료일 추가`는 토글 라벨** |

#### 🔢 열 수를 넘는 반복항목 = 「카드 추가」 (필수, 2026-09-18 이선호)

2열 카드는 **최대 4단**이라 한 카드에 항목을 무한히 못 담는다. 넘치면 **열을 늘리지 않고 카드를 한 장 더 쌓는다.**

| | |
|---|---|
| **그 페이지의 최대 열 수** | **처음 제시한 시안의 열 개수** — 시안이 2열로 나갔으면 그 페이지는 계속 **2열**, 3열이면 3열. 유저가 항목을 늘려도 **열 수는 안 바뀐다**(항목이 늘었다고 2열→4열로 조이지 않는다) |
| **넘칠 때** | **그 카드를 통째로 복제해 바로 아래에 붙인다** — 원본 여백·테두리·정렬 그대로. 예: 2열인데 항목 3개 → `[①②]` ＋ `[③]` |
| **덜 찬 마지막 카드** | 셀이 **FILL**이라 남은 항목이 **자동으로 폭을 나눠 가진다**(1개면 전폭·중앙). **빈 셀을 남기지 않고**, 3+2처럼 **재배분도 하지 않는다** |
| **카드 사이 간격** | 복제본이라 **앞 카드 하단여백 ＋ 뒤 카드 상단여백** 그대로(실측 12＋8=20). **섹션 하단 36은 맨 마지막 요소에만** |
| **세로 나열로 갈아끼우지 않는다** | 항목이 많아졌다고 **다른 섹션으로 교체 ❌** — 유저가 보던 시안이 중간에 딴 모양으로 바뀌면 안 된다 |

> ⚠️ **[[4-8. 시안 검수 체크리스트]] 「항목 1개면 2열 카드 ❌ → 스택형」의 예외** — 그 규칙은 **항목이 원래 1개인 섹션을 고를 때** 얘기다. **넘침으로 생긴 마지막 카드**가 1개인 것은 정상이다.

#### ⓒ 한 단계(질문)의 뼈대

```
[주 입력 묶음]  (원자 1~4개를 가로 또는 세로로)
   └ 반복이면 위 묶음이 통째로 늘어난다 (＋ 항목 추가)
```

#### ⓔ 새 질문을 만들 때

1. **무엇을 받는지 원자로 쪼갠다** — 글자? 고르기? 일시? 이미지? 켜고 끄기?
2. **반복인가** — 같은 꼴이 여러 개면 반복, 한 벌이면 조합형
3. **이미 있는 부품과 조합이 같으면 그 부품을 그대로 쓴다** — 이름만 다른 부품을 새로 만들지 않는다(→ 「🚫 전용 조합 부품을 새로 만들지 않는다」)
4. **원자에 없는 입력이 필요해 보이면 멈추고 확인한다** — 캘린더 그리드·슬라이더·태그 입력·리치 텍스트 등은 **아직 없는 것**이라, 만들려면 부품이 아니라 **원자를 늘리는 결정**이다

> ⚠️ **겹쳐 보이는 조합 3쌍** — 조합이 같아 합칠 여지가 있다: ① `드롭다운 ＋ 값 반복` ↔ `검색형 드롭다운 ＋ 주소` ↔ `버튼 이름 ＋ 링크`(전부 드롭다운＋텍스트 반복) ② `FAQ` ↔ `제품 스펙 표` ↔ `라벨 ＋ 값 표`(전부 텍스트 2칸 반복) ③ `이미지 ＋ 글 묶음` ↔ `카탈로그 품목`. **화면이 이미 따로 있어 지금은 유지**하되, 합칠지는 별도 판단.

### 2-3. 입력 동작 규칙 (화면 주석 정리 · 2026-09-18)

> 지금까지 **Figma 화면의 메모로만** 있던 동작 규칙을 옮긴 것. 개발에 넘길 때 이 표가 근거다.

#### 포커스

| 규칙 | 내용 |
|---|---|
| **첫 텍스트 필드에 자동 Focus** | 단계에 들어가면 **첫 「텍스트」 칸**에 커서가 놓인다 |
| **드롭다운은 건너뛴다** | 첫 칸이 드롭다운이면 그 다음 **텍스트 칸**에 Focus (문의 연락처·링크) |
| **첫 칸이 이미지면 Focus 없음** | 업로드 박스에는 커서를 두지 않는다 |
| **항목을 추가하면 새 항목 첫 필드로** | `항목 추가`를 누르면 **늘어난 항목의 첫 칸**에 자동 Focus |

#### 반복 항목

| 규칙 | 내용 |
|---|---|
| **✕(삭제)는 2개 이상일 때만** | 항목이 하나뿐이면 삭제 버튼을 감춘다(마지막 하나를 지울 수 없게) |
| **드래그 핸들은 항상 보인다** | 개수와 무관 — 1개여도 표시(자리가 흔들리지 않게) · **순서 변경 가능** |
| **1자 이상 입력해야 다음 항목 ON** | 빈 항목을 쌓지 못하게 `항목 추가`를 잠근다 |
| **2번째 항목부터 지시형 플레이스홀더** | 1번째는 `예: 값`, 2번째부터 `~을 입력해 주세요.` (사실 정보 칸은 **첫 항목부터 지시형**) |

| **두 번째 칸의 성격도 바뀐다** | URL=링크 · 전화=번호 · 문자=번호 |
