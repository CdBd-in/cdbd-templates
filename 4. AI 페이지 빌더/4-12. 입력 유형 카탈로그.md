# 4-12. 입력 유형 카탈로그

> **무엇** — 유저가 내용을 채우는 화면에서 쓰는 **입력 부품 27종**과, 그 부품을 **어느 섹션 슬롯에 끼우는지**를 잇는 규칙.
> **왜** — 섹션은 355개이고 슬롯 구성은 **198가지**다. 변형마다 인풋 셋을 만들면 198벌이 된다. **부품을 조립**해야 한다.

---

## 0. 세 줄 요약

1. **문항은 「슬롯」이 아니라 「재료」를 묻는다** — 히어로 슬롯 구성은 29가지지만 물어야 할 재료는 **6가지**뿐이다.
2. **질문 셋은 주제 고정**([[4-7. 입력 단계 안내 문구]]), **섹션은 그 재료로 빈칸 없이 채워지는 것만** 뽑는다.
3. **`채움 = AI`인 칸도 입력칸을 준다** — 편집 제외는 **eyebrow · 섹션 타이틀 둘뿐**.

---

## 1. 3층 — 무엇이 무엇을 정하나

| 층 | 무엇 | 정본 | 개수 |
|:--:|---|---|:--:|
| ① **부품** | 화면에 놓이는 입력 UI | **이 문서 §2** | 27종 |
| ② **문항** | 주제마다 무엇을 묻나 | [[4-7. 입력 단계 안내 문구]] | 25주제 · 279칸 |
| ③ **슬롯** | 섹션이 요구하는 자리 | `.data/preset-index/preset-index.json` `slots` | 355섹션 · 1,046슬롯 |

> 🔑 **②는 ③에 종속되지 않는다.** 종속시키면 ⑨에서 추가 시안(B·C)을 만들 때 **섹션이 바뀌어 A에서 채운 값이 옮겨가지 못한다.**

## 2. 입력 부품 27종

**상태 4가지는 부품마다 전부 필요하다.**

| 상태 | 언제 | 화면 |
|:--:|---|---|
| ① 비어있음 | 사실 칸, 아직 안 채움 | `○○을 추가하면 좋아요` ＋ 빈칸 |
| ② **AI가 채워둠** | `채움 = AI`인 칸 55개 | `미리 채워뒀어요` ＋ **값이 들어간 채로 편집 가능** |
| ③ 사실인데 못 채움 | 자료에 없음 | 흐린 플레이스홀더 · 끝까지 안 채우면 자동 삭제([[4-11. 실패·예외 처리]] F5) |
| ④ 유저가 채움 | 직접 입력 | 반응 말풍선 2초 (**AI 칸은 고쳐도 반응 없음**) |

### 2-0. 필수/선택 칸 ＋ 하단 버튼 전환 (필수)

각 단계(질문)의 칸은 **필수 / 선택** 둘 중 하나로 분류한다.

| 분류 | 무엇 | 예 (프로그램 단계) |
|---|---|---|
| **필수** | 그 단계(섹션)가 **성립하는 데 없어서는 안 되는 칸** — 항목의 이름·제목, 일시, 가격 등 | 날짜·시간(AI가 미리 채워둠) · **프로그램 제목** |
| **선택** | 비어 있어도 섹션이 성립하는 **부가 칸** — 설명 문구·서브 텍스트. 색인의 **`*` 옵션 슬롯**(§4)이 이 부류 | 프로그램 설명 |

- **하단 버튼은 한 자리 · 필수 충족 여부로 바뀐다**:
 | 상태 | 버튼 |
 |---|---|
 | 필수 칸이 하나라도 비어 있음 | **`이건 없어요`** (건너뛰기) |
 | 필수 칸이 전부 참 | **`다음`** |
- 필수 충족 판정에 **누가 채웠는지는 무관** — 유저 입력·AI가 채워둠·자료 추출 전부 「참」으로 센다(예시의 날짜·시간처럼 미리 채워져 있으면 제목만 채워도 `다음`이 뜬다).
- 🧲 **자료 조건부 칸 = 필수 ** — 스펙·실측처럼 **자료에 그 내용이 있을 때만 해당 슬롯 섹션이 뽑히는** 칸(§4 거르기)은 **빈 채로 나타나는 경우가 없다** → 필수로 분류해도 버튼을 막을 일이 없다.
- 📍 **주소 검색 칸의 「채워짐」 = 검색 결과에서 1개 「선택 완료」 ** — 입력칸에 **타이핑만 한 상태는 미충족**이다(글자가 있어도 버튼은 `이건 없어요` 유지). 검색 목록에서 골라야 좌표가 생겨 지도·길찾기가 동작하기 때문 — 타이핑만 받으면 「채워졌는데 지도가 안 열리는」 페이지가 된다. 상세주소(선택)는 일반 텍스트 판정 그대로.
- **반복 부품**(반복 아코디언 등)은 **항목 안에서도 같은 분류** — 항목은 필수 하위 칸이 다 차야 완성으로 센다.
- `이건 없어요` = 그 단계를 건너뜀 → 남은 빈 자리는 **⑧ 마지막 확인**에서 일괄 삭제 안내([[4-11. 실패·예외 처리]] F5). ⑦의 버튼과 ⑧의 일괄 처리는 **역할을 나누는 두 겹**이다.
- 📋 **칸별 필수/선택 분류의 정본 = [[4-7. 입력 단계 안내 문구]] 표** — ✅ **「필수」 열 반영 완료 (2026-09-17 히어로 설명 정정 후 279칸 = 필수 256 · 선택 23 · 판정 5규칙 = 4-7 「작성 메모 › 필수/선택 판정」 — ⑤ 별도 인풋 칸 = 필수: 히어로 제목/설명은 각각 별도 인풋이라 둘 다 필수)**. 이 문서는 분류 **기준**과 아래 **부품 내부 필드**를 정한다.

**⏎ 키보드 동작 규칙 (2026-09-17 이선호 확정)** — **엔터로는 단계가 안 넘어간다.** 단계 이동은 하단 버튼 또는 Cmd/Ctrl+엔터만. 조합·반복 화면에서 습관적 엔터로 넘어가는 사고를 원천 차단.

| 키 | 동작 (모든 화면 공통) |
|---|---|
| **Cmd/Ctrl+엔터** | **다음 단계** = 하단 버튼 누르기와 동일 (필수 미충족이면 반응 없음 · 맥/윈도우 양쪽 키 다 받아줌) |
| **엔터 · 탭** | **다음 필드로 포커스 이동** · 마지막(또는 유일한) 필드면 **포커스 해제만** (⚠️ 단계 이동 ❌ · 항목 추가 ❌ — 추가는 `＋ 추가` 버튼만) |
| 여러 줄 텍스트 입력 안의 엔터 | **줄바꿈** (기존 확정 그대로 · 필드 이동은 탭으로) |

- **힌트 표기 = OS 감지해 하나만** — 맥 `⌘+엔터로 다음` / 윈도우·기타 `Ctrl+엔터로 다음`(폴백=Ctrl) · **모바일은 힌트 숨김**(조합키 없음 → 하단 버튼만). 여러 줄 텍스트는 `엔터로 줄을 나눌 수 있어요`(4-7 공통 안내) 유지.

**🖼 이미지 칸 라벨 = 「이미지」로 통일 (2026-09-17 이선호 확정)** — 왼쪽 질문 영역의 이미지 입력칸 라벨은 **전부 `이미지`** 한 가지로 쓴다. **예외 둘뿐 = 히어로의 `메인 이미지` · `로고 이미지`**. `사진`·`제품 사진`·`대표컷`·`프로필 사진` 같은 수식형 라벨 ❌ — 무엇을 올릴지의 맥락은 라벨이 아니라 **왼쪽 패널 제목**([[4-7. 입력 단계 안내 문구]])이 전담한다. (오른쪽 시안 목업 안 플레이스홀더 슬롯 이름은 별개 — 목업 표현 규칙 그대로.)

**복합 부품의 내부 필드 필수/선택** — 반복 항목·묶음 부품은 항목 안에서도 나뉜다. 항목은 **필수 필드가 다 차야 완성**, 선택 필드가 빈 항목·행은 그 부분만 지운다.

|---|---|---|
| 날짜＋시간 | 날짜 | 시간(`하루종일` 토글) · 종료일 |
| 주소 | 주소 검색 — ⚠️ **충족 = 검색 결과 「선택 완료」**(타이핑만 = 미충족) | 상세주소 |

#### 「표」는 쓰임이 둘 — 섹션 표 / 항목 표 (질문)

입력 UI(`라벨 ｜ 값 ｜ ✕` ＋ `항목 추가`)는 같지만 **어디에 붙느냐가 다르다.**

| | 부품 | 쓰임 | 예 |
|---|---|---|---|
| **섹션 표** | 라벨 ＋ 값 표 | **섹션 하나에 표 하나** | 안내 사항 · 핵심 정보 · 배송 안내 |
| **항목 표** | **작품 정보 표** · **제품 스펙 표** | **항목(작품·제품)마다 표가 반복** → 표가 **아코디언 안**으로 들어간다 | 도록 작품(제목·작가·재료·크기) · 상품 상세(소재·크기·무게) |

- **작품 정보 표**는 아코디언 안에 **작품 이미지 ＋ 제목 ＋ 표**가 함께 들어간다(도록은 이미지와 캡션이 한 묶음).
- **제품 스펙 표**는 표만 있다 — 제품 이름·가격·사진은 **제품 상세 반복**이 이미 받으므로 다시 묻지 않는다.


#### 신청 폼 — 질문은 아코디언

- **질문 하나 = 아코디언 한 장.** 펼치면 **유형(객관식/주관식) ＋ 질문**이 나오고, 그 아래가 **유형에 따라 갈린다**:
 - **객관식** → `선택지` 입력칸 여러 개 ＋ `선택지 추가`
 - **주관식** → `플레이스홀더` 입력칸 1개
- 한 화면에 둘 다 펼치면 세로가 넘쳐서 **화면을 3장**으로 뒀다 — `비어있음`(유형 미선택) · `객관식 펼침` · `주관식 펼침`.
- 🚫 **`받을 항목` 토글은 따로 두지 않는다 ** — **이름·연락처도 질문 목록 안의 한 질문**이다. 토글을 따로 두면 같은 것을 두 군데서 묻게 된다.
- ✅ **질문 목록 순서 = 목업 폼 순서** — 목록 맨 위 `이름`·`연락처`가 목업 폼에서도 맨 위 칸이다. (목록이 길면 왼쪽 패널은 스크롤되므로 화면에 다 안 보여도 된다)

#### 목업 표현 규칙

> ⚠️ **섹션 프리셋을 복제해 쓸 때 오토레이아웃 속성을 건드리지 말 것** — 카탈로그(`purchase-editorial-02`)의 `상품` 래퍼는 **GRID 레이아웃**인데 이걸 `VERTICAL`로 바꿨다가 셀이 전부 잘렸다. 플레이스홀더를 손볼 땐 **`이미지` 텍스트를 직접 가진 프레임만** 골라야 한다(`Badge` 이름으로 고르면 프리셋의 `Badge/Editor/Pointer` 래퍼까지 잡힌다).
