# 입력 단계 안내 문구 — 주제 25개

> **무엇** — 유저가 시안을 보며 내용을 채우는 화면의 **모든 문구**.
> **어디서 나왔나** — 단계 구성은 [[4-4. 조립 레시피]] 5절 레시피 카드, 문구 규칙은 `.data/tips/_SPEC.md`(정본).
> **검수** — 전수 자동 검사 통과(열 수 · 주제 내 중복 · 금지표현).

## 화면 구조 — 문구가 놓이는 자리 3곳

```
┌ 왼쪽 입력 패널 ─────────┐ ┌ 오른쪽 미리보기 ───────┐
│ ① 제목 │ │ ╭──────────╮ │
│ [ 입력칸 ] │ │ │ ② 말풍선 │ │
│ │ │ ╰───╮╭─────╯ │
│ │ │ ━━━━━━━━🚗────────── │
│ │ │ 진행 바 ＋ 자동차 │
│ │ │ ┌────────────────────┐ │
│ │ │ │ 시안 │ │
└─────────────────────────┘ └─┴────────────────────┴─┘
```

🚗 **진행 인디케이터** ([Figma 7010-23500](https://www.figma.com/design/24O01lprp5i2ufl7CbZXXx/AI-%EC%84%B9%EC%85%98-%ED%94%84%EB%A6%AC%EC%85%8B?node-id=7010-23500))
— 진행 바 위를 **자동차가 달려** 진행률을 보여주고, 자동차 위 **말풍선**에 메시지가 뜬다. 숫자(`3/8`)를 대신한다.

| 자리 | 단위 | 언제 |
| ---------------- | --- | ----------------- |
| **① 제목** | 단계 | 항상 |
| **② 말풍선 — 반응** | 칸 | 칸 **「완료」 직후 2초** — 완료 시점 판정 = 「⏱ 리액션 표시 시점」 |
| **② 말풍선 — 마일스톤** | 단계 | 절반 · 하나 남음 · 마지막 |

우선순위 `반응 > 마일스톤` — **겹치면 순차 노출 (2026-09-17 이선호 확정)**: [다음] 클릭으로 트리거되는 리액션은 단계 완료와 동시라 **마일스톤과 겹칠 수 있다** → **리액션 먼저 2초 → 사라진 뒤 마일스톤 ON**(마일스톤을 버리지 않는다)

- 🫥 **평소엔 말풍선을 숨긴다** — 반응·마일스톤이 뜨는 순간에만 나타나고, 그 밖엔 **자동차만** 보인다.
- 채울 때의 안내는 **왼쪽 패널의 제목이 전담**한다 — 왼쪽 패널 = **제목 ＋ 입력칸**.

### 🔒 확정 화면과의 대조 (Figma [7024-7692](https://www.figma.com/design/24O01lprp5i2ufl7CbZXXx/AI-%EC%84%B9%EC%85%98-%ED%94%84%EB%A6%AC%EC%85%8B?node-id=7024-7692))

플로우가 확정되면서 이 문서의 구조가 **화면과 1:1로 맞는 것이 확인**됐다 → 플로우 전체 = [[4-2. AI 유저 플로우#7. 내용 채우기 — 1/8 ~ 8/8 (🟢 단계 필수 / 🟡 칸 선택) — `v2 · 8 내용 채우기`]].

| 확정 화면의 이름 | 이 문서의 자리 | 확인된 것 |
|---|---|---|
| `비어있음` | ① 제목(비어 있을 때) | *"메인 이미지를 추가하면 좋아요"* |
| `AI가 채워둠` | ① 제목(다 찼을 때) | *"○○을 미리 채워뒀어요"* — **런타임 상태가 제목을 고른다** · 제목 한 줄만 |
| `유저가 채움 (리액션・2초)` | ② 말풍선 — 반응 | **2초 노출** 확정 |
| `마일스톤` | ② 말풍선 — 마일스톤 | 화면 라벨 `격려`가 **유형 이름**이고, 그 아래 **절반 · 2단계 남음 · 마지막** 3종이 실제 문구다 |
| 진행 바＋자동차 | — | 숫자 없이 **진행 바＋자동차**가 진행률을 보여준다 |

- 🔄 **8/8 마일스톤은 「다 채우면 다른 시안도 보여드릴게요 🎉」 삭제 → 「드디어 마지막 단계예요 👏」로 교체 (2026-09-17 이선호)** — 완료(예고형) 문구를 없애고 마지막 단계 격려로. 추가 시안 안내는 ⑨ 화면이 전담한다.
- ✅ **「격려」는 별개 유형이 아니다** — **마일스톤 메시지가 곧 격려 메시지**다. 화면의 `격려`는 묶음 이름이고 종류는 **절반 · 하나 남음 · 마지막 3종**뿐이다.
- ℹ️ 화면의 문구(*"벌써 절반이나 왔어요! 🙌"* · *"거의 다 왔어요! 💪"*)는 **북토크 예시용 샘플**이다. **주제별 정본은 이 문서의 표** — 이모지 사용 여부도 여기서 정한다.

## 🔒 이 문구는 「고정 문구」다 — AI가 짓지 않고 **고른다**

| | |
|---|---|
| **AI가 받는 것** | 칸과 그 칸이 속한 **섹션 목적** · 유저가 **채운 칸 / 비어 있는 칸** |
| **AI가 하는 일** | 아래 272행에서 **그 칸에 맞는 문구를 고른다** · 마땅치 않으면 **비워 둔다** |
| **AI가 하지 않는 일** | **문구를 새로 짓는 것** |

⚠️ **[[MD-08-3. 시안: 텍스트 구성]]과 다른 글이다** — 07-3은 **페이지에 들어갈 글**(손님이 읽음), 이 문서는 **입력 화면에서 유저에게 주는 안내**(유저만 봄).

## 규칙 요약 (풀버전 = `.data/tips/_SPEC.md`)

**채움 열 — AI / 사실**
- **AI** = 문장을 지어서 미리 채워둠 (인사말·소개글·스토리·카피)
- **사실** = 자료에 있으면 뽑아 채우고 **없으면 비워둠. 지어내기 절대 ❌** (이름·일시·장소·가격·계좌·연락처·정원·마감일·스펙·경력·작품 정보·통계·후기·이미지)
- 왜 — 표현은 틀려도 고치면 그만이지만 **사실은 틀리면 사고**

**제목 — 런타임 상태가 정한다**
- 그 단계에 **한 칸이라도 비어 있으면** `{항목}을 추가하면 좋아요`
- **전부 채워져 있으면** `{항목}을 미리 채워뒀어요`
- 표에는 **비어 있을 때 버전만** 적는다

**🟣 제목의 주어 = 명사형 섹션 타이틀 ** — `{주어}를 추가하면 좋아요`의 주어 자리 규칙 5개.
1. **주어 = 그 단계가 채우는 섹션의 「명사형 섹션 타이틀」(AI 생성) 그대로** — 화면에서 **포인트(primary) 색**으로 표시하고, 오른쪽 미리보기의 그 섹션 타이틀 영역과 **연결선**으로 잇는다. (표의 「단계 / 칸」 이름은 자리 표시 — 런타임에 실제 타이틀로 치환)
2. **조사 을/를** — 타이틀 **마지막 글자에 받침이 있으면 `을`, 없으면 `를`**(`프로그램을` · `행사 정보를`). 숫자·영문으로 끝나면 **읽는 소리** 기준(`LOOK 1을`·`FAQ를`).
3. **여러 줄 타이틀 — 라벨 줄이 있으면 「라벨」이 주어** (2026-09-17 이선호 변경 · 옛 「명사형 제목 줄」 규칙 대체) · 카피는 주어 후보에서 제외:
 | 타이틀 형태 | 주어 | 예 |
 |---|---|---|
 | 명사형 한 줄 | 그대로 | `프로그램` |
 | **라벨 ＋ 명사형 제목** | **라벨 줄** (제목 줄 ❌) | `가격`＋`봄 첫물차 할인` → **`가격`** · `이용 안내`＋`문 여는 시간` → **`이용 안내`** |
 | 명사형 제목 ＋ 문장 카피 | 제목 (카피 ❌) | |
 | 문장형 (아래 5) | AI 내부 명사형 이름표 | |
 - 왜 라벨 — 라벨은 섹션에 딸린 **고정 이름**이라 제목 문구를 미리 등록해 둘 수 있고, 명사형 제목 줄은 **AI가 짓는 카피성 이름**(`봄 첫물차 할인`)이라 주어로 쓰면 제목이 길어지고 페이지마다 달라진다.
 - ⚠️ **단 아래 중복 규칙이 먼저다** — `안내`＋`가격과 발송 안내`처럼 **라벨 단어가 제목에 들어 있으면** 애초에 2줄 구성을 쓰지 않으므로 라벨이 주어가 될 일이 없다(→ 한 줄 `가격과 발송 안내`가 주어).
 - 🚫 **라벨·제목 의미 중복 구성 ❌ (2026-09-17 이선호)** — 라벨 단어가 제목에 그대로 포함되면(`후원`＋`후원하는 방법` · `신청`＋`참가 신청` · `메뉴`＋`오늘의 메뉴`) 2줄 구성을 쓰지 말고 **라벨 없는 한 줄 타이틀**로 만든다(이때 주어 = 명사형 제목 줄). 라벨＋제목 2줄은 **서로 다른 정보를 더할 때만**(`가격`＋`봄 첫물차 할인` · `이용 안내`＋`문 여는 시간` ✅).
4. **히어로 3단계(메인 이미지·로고·히어로 텍스트) = 고정 이름 유지** — 히어로엔 섹션 타이틀이 없다(eyebrow뿐 · 편집 제외).
5. **문장형 타이틀 섹션**(⑨ 상하선·em대시 계열 — 예 `주문하시면 2일 안에 / 문 앞에 도착합니다`)도 **AI가 명사형 이름표를 함께 생성**해 두고 주어는 그것을 쓴다(예 → `가격과 발송 안내를 추가하면 좋아요`). 화면에 그 명사가 안 보여도 무방 — 연결선이 위치를 가리킨다. 이름표 작법 = 섹션 타이틀 「이름표」 규칙(명사＋역할어 · [[4-8. 시안 검수 체크리스트]] 75번).
6. **폼(Q&A) 섹션 = 「폼 제목」이 곧 섹션 타이틀** — 폼 카드는 **제목을 카드 안에 내장**하므로 그 위에 **섹션 타이틀 카드를 따로 두지 않는다**(두면 `참가 신청`＋`참가 신청서`처럼 같은 말이 두 번 = 중복 타이틀). 따라서 **주어 = 폼 제목 그대로**.
 - 🏷 **폼 제목은 「명사형」으로 짓는다** — `참가 신청서`·`상담 신청서`·`지원서`·`문의 신청서` ✅ / **동사형 ❌** (`신청하기`·`문의 남기기` → 주어에 넣으면 `신청하기를 미리 채워뒀어요`처럼 어색). 제출 버튼은 동사형(`신청하기`)이 정상 — **제목만** 명사형.
 - 예: 폼 제목 `참가 신청서` → 헤딩 `참가 신청서를 미리 채워뒀어요` (Figma [7356-101437](https://www.figma.com/design/24O01lprp5i2ufl7CbZXXx/AI-%EC%84%B9%EC%85%98-%ED%94%84%EB%A6%AC%EC%85%8B?node-id=7356-101437))
→ 주어 우선순위 = **라벨 줄 → 명사형 제목 줄 → (폼이면) 폼 제목 → (문장형이면) AI 생성 이름표**. 예외는 히어로뿐.

**📍 장소 ≠ 찾아오시는 길 ** — 둘은 **받는 방식이 달라 단계가 따로**다.
| | **장소** | **찾아오시는 길** |
|---|---|---|
| 섹션 | 핵심 정보 | 위치 안내 (지도) |
| 입력 | **단순 텍스트** 한 줄 | **주소 검색** ＋ **상세주소**(텍스트) = **칸 2개** |
| 예 | `그랜드 하얏트 서울 그랜드볼룸` | `서울 강남구 테헤란로 521` ＋ `3층 그랜드볼룸` |
- 🔑 주소는 **검색 목록에서 골라야** 지도·길찾기가 열린다(타이핑만 하면 안 열림). 층·호수는 검색에 안 잡히니 **상세주소로 따로** 받아 **지도 아래 주소 옆에** 붙인다. 📍 **그래서 필수 충족 판정도 「선택 완료」 기준 ** — 타이핑만 한 상태는 「채워짐」으로 안 치고, 검색 결과에서 1개를 고른 순간에만 충족(버튼 `다음` 전환이 이 시점). ℹ️ 리액션은 별도 — 주소 검색은 항상 상세주소와 함께 쓰이는 **조합 항목**이라 **[다음] 클릭 시점**에 뜬다(「⏱ 리액션 표시 시점」).
- 단계 자리 = **문의 바로 앞** · 찾아올 곳이 없는 주제(온라인 전용·고객 집 방문·오프라인 매장 없음)는 **단계째 건너뜀**.

**반응** — **따뜻한 한마디 ＋ 이모지 1개**(`멋진 메인 이미지네요 👀` · `브랜드가 확실해졌어요 ✨`) · 이모지는 **칸 종류별 고정 10종** · **채움이 `AI`인 칸은 반응 없음(`—`)** · 🔁 **복수 항목 칸(「＋ 추가」로 늘리는 리스트·갤러리·반복 묶음)은 「첫 항목 완료」 때 1회만**(항목마다 ❌ · `N개가 됐어요` 개수 리액션 ❌) · 🚫 **칸 라벨을 그대로 주어로 쓰는 효과형 ❌**(`이름` 칸 → `이름이 또렷해졌어요`는 무의미) → **방문자의 질문이 풀리는 의문사형**(`누구인지 분명해졌어요`·`어디인지 확실해졌어요`) · 🕯 **무거운 소식(6-① 공지·알림)만 예외 — 이모지·감탄 ❌**

**⏱ 리액션 표시 시점 (2026-09-17 이선호 확정)** — 리액션은 그 칸의 **「완료」 순간**에 뜬다. 「완료」 판정은 입력 부품이 정한다:

| 입력                                      | 표시 시점                                                              |
| --------------------------------------- | ------------------------------------------------------------------ |
| **이미지 업로드**                             | **업로드 완료** 시점 (파일 선택 시점 ❌)                                         |
| **date · time picker**                  | picker 안 **마지막 항목 선택** 시점 (예: 날짜 = 연/월/일 중 「일」까지 선택 완료)            |

🚫 **편집 범위에서 빼는 것은 딱 둘 — 「eyebrow(제목 위 문구)」와 「섹션 타이틀」** (eyebrow 규칙을 섹션 타이틀까지 확장) — 이 둘은 AI가 넣고 유저는 건드리지 않는다. **단계·칸에 등장하지 않는다.** 둘 다 **섹션 디자인에 딸린 표현**이라(eyebrow = 히어로 21개 섹션의 2단 타이틀 윗줄 · 섹션 타이틀 = 공용 팔레트 8유형) 유저가 고치면 레이아웃 언어가 깨진다. ℹ️ 값의 이름표인 **필드 라벨**(`일시`·`장소`)도 문항이 아니다 — 유저는 **값만** 고친다. ℹ️ 4단계(에디터)로 넘어간 뒤에는 이 셋도 당연히 편집 가능하다 — 제외되는 건 **빌더의 「내용 채우기」 화면**뿐.

두 갈래만:

## 작성 메모 (검수용 · 화면에 안 보임)

### 필수/선택 판정 (2026-09-17 히어로 설명 정정 후 279칸 = 필수 256 · 선택 23)

기준 = [[4-12. 입력 유형 카탈로그]] §2-0. 세 규칙으로 판정했다.

1. **단계에 칸이 하나뿐이면 무조건 「필수」** — 그 칸이 곧 그 단계의 건너뛰기 판단이다. 선택으로 두면 버튼이 처음부터 `다음`이 되어 `이건 없어요`(원래 없음 표시)가 영영 안 뜬다. → 소개·SNS·쿠폰·진행 중 이벤트처럼 **내용상 부가여도 단독 단계면 필수**.
2. **복수 칸 단계 = 본체 필수 · 부가 선택** — 본체(이미지·제목·이름·핵심 값·링크 주소)가 차면 `다음`이 뜨고, 부가는 안 채워도 넘어간다.
3. **AI 칸도 같은 기준** — AI가 채우면 자동 「참」이라 실질 영향 없음. 자료 빈약으로 못 채운 경우([[4-11. 실패·예외 처리]])를 대비해 분류는 해 둔다.
4. 🆕 **자료 조건부 칸 = 필수 ** — 스펙·실측처럼 **자료에 그 내용이 있을 때만 해당 슬롯 섹션이 뽑히는** 칸([[4-12. 입력 유형 카탈로그]] §4 거르기 조건)은 **빈 채로 화면에 나타나는 경우가 없다** → 필수로 분류(「값 없으면 행 삭제」 걱정은 애초에 적용될 일이 없음).
5. 🆕 **별도 인풋으로 그려지는 칸 = 필수 (2026-09-17 이선호 · 옛 「히어로 설명 = 선택」 정정)** — 필수/선택 분류의 목적은 **조합형 인풋 안에서 `이건 없어요`→`다음` 버튼 전환 시점을 정하는 것**이다. 히어로 제목/설명처럼 **화면에 각각 별도 인풋으로 그려지는 칸**은 내용상 부가여도 **둘 다 필수** — 「선택」은 **한 부품 안의 부가 필드**(상세주소·종료일·제품 부가 행)에만 쓴다. (AI가 채우는 설명은 자동 「참」이라 실질 부담 없음 · 히어로 · 설명 20곳 전부 필수로 정정)

> 📌 **「사실」 = 「시안에서 그 자리가 빈다」는 뜻이 아니다** — 시안에는 **형식이 보이는 플레이스홀더**(예 `2026. 3. 15 (토) 오후 2시`)가 다른 글과 똑같이 들어가고, **이 화면에서만 흐리게 + 입력칸 비어 있음**으로 보인다. 끝까지 안 채우면 **자동 삭제**된다([[MD-08-3. 시안: 텍스트 구성]]).

- 🆕 **히어로 · 제목/설명 = 항상 「AI」 (2026-09-17 이선호)** — 히어로 카피는 ① 페이지 설명에 재료(이름·주제)가 반드시 있어 AI가 항상 지어 채울 수 있다 → **25주제 전부 채움 = AI** · AI 칸 규칙대로 **반응 = `—`**. 단 제목 안의 사실 조각(할인율·전시명·발행일)은 페이지 설명·자료에서 온 값만 쓰고 **지어내지 않는다**.
- **지어내면 사고인 칸은 전부 「사실」** — 모집 정원·기간·대상 · **자격 요건·처우**(5-② 5·6·7) · 참가 자격·접수 기간·**참가비**·시상 내역(5-⑤ 6·7) · **사용처 항목별 숫자·계좌·예금주**(5-⑥ 5·7) · 정기 후원 금액 구간(5-⑥ 8) · 회신 시간·운영시간(5-④ 8) · 모든 연락처·이미지
- **AI로 둔 칸은 「표현」만** — 취지·스토리·소개글·히어로 카피·폼 질문 문구. 숫자·기간·금액을 품은 칸은 AI로 두지 않았음
- **히어로 설명 칸의 채움은 주제마다 갈린다** — 5-⑤는 접수 마감(사실)이 문장의 본체라 「사실」, 5-②·5-④·5-⑥은 카피라 「AI」. 5-②는 원래 마감을 히어로 설명에 넣는 안이었으나 **AI가 날짜를 지어낼 위험**이 있어 마감은 「모집 정보」(사실) 단계로 옮기고 히어로 설명은 순수 카피로 바꿈

### 왼쪽 패널 제목 판정 (단계 단위)
- **「미리 채워뒀어요」는 단계 전체가 AI일 때만** — 5-④ 히어로(전 칸 AI)는 미리 채운 형, 5-②·5-⑤ 히어로는 사실 칸이 있어 「추가하면 좋아요」 형
- `히어로 · 제목 위 문구`(eyebrow)는 **편집 범위에서 제외**(섹션 타이틀도 함께) — 따라서 **5-⑥ 히어로는 전 칸 AI**, 제목은 「히어로 문구를 미리 채워뒀어요」 형

### 반응(방금 채움) 톤
- **AI 칸은 전부 `—`** — 유저가 채우는 행위가 없어 반응 없음. 4주제 반응 대상 = **사실 칸 30개**(AI 12칸은 빈칸)
- 후원·기부(5-⑥)와 공지·알림(6-①)은 감동·호소 없이 **반영 사실 위주**(계좌 정보가 채워졌어요)
