## 1. 모델 — 3층

### 1-1. 세 층

기존 16개 레시피를 전수 분해해 보니 **예외 없이 같은 골격**이었다. 주제마다 다른 것은 **세 가지뿐**이다.

| 층 | 무엇 | 개수 | 바뀌는가 |
|---|---|:--:|---|
| **① 공통 골격** | 여는 부분 · 닫는 부분 | **1** | 주제 25개 전부 동일 |
| **② 목적 분류** | 본체 순서 규칙 + 멀티 분할 | **6** | 주제마다 하나 지정 |
| **③ 주제별 카드** | ★결정 섹션 · 보조 섹션 · 조건부 | **25** | 주제의 정체 |

🔑 **이 구조를 쓰는 이유** — *"문의 섹션은 3안 모두 다른 섹션"* 같은 **공통 규칙이 바뀌면 골격 한 곳만** 고친다. 구버전은 같은 규칙이 16군데 흩어져 있어 한 곳을 고치면 나머지가 낡았다.

### 1-2. 왜 층을 나누나 — 순서를 25번 쓰지 않기 위해

**주제와 배치는 서로를 결정하지 못한다.** 증거가 두 방향으로 있다.

| 방향 | 증거 |
|---|---|
| **주제가 같은데 배치가 다르다** | `4-① 상세`와 `4-④ 판매`는 둘 다 「물건」이고 재료도 같은데 배치가 정반대다 — 구매 버튼이 중간 한 번 ↔ **최상단＋최하단** · 스토리가 히어로 직후 ↔ **맨 뒤** |
| **배치가 같은데 주제가 다르다** | `4-② 룩북`(옷) · `3-② 메뉴판`(음식) · `6-③ 도록`(작품) · `6-② 매거진`(글) — 재료가 전혀 다른데 배치는 **완전히 같다**(`히어로 → 스토리 → 아이템 반복 → 문의`) |

**그래서 층을 나눈다. 이득은 중복 제거다.**

```
한 층일 때 :  25 × (순서 + 내용)    = 순서를 25번 기술
두 층일 때 :   6 × 순서 + 25 × 내용  = 순서를 6번 기술
                                       ↑ 중복 19번 제거
```

> 🔴 **가정이 아니라 실제로 벌어진 일이다.** 구버전 16개 레시피가 정확히 이 상태였다 — *"문의 섹션은 3안 모두 다른 섹션"* 같은 규칙이 16군데 흩어져, 한 곳을 고치면 나머지 15개가 낡았다.
> ⚠️ **단 「대등한 두 입력」은 아니다** — 진짜 독립 입력은 **주제 25개 하나**이고 목적 분류는 거기서 **파생**된다(★가 폼이면 P3 · 구매 CTA면 P5 · 반복 아이템이면 P4). 8개 주제가 같은 순서를 공유하므로 **별도 층으로 뽑는 것이 이득**일 뿐이다.
> 🔴 **구조를 재검토한다면 이 지점** — **P4·P6는 나머지 넷과 층위가 다를 수 있다.** P1·P2·P3·P5는 *독자 행동*(읽고 끝/온다/제출/산다)인데 **P4는 「★의 형태」, P6는 「★의 정체」**다. 그래서 P4가 거의 모든 주제에 스며든다. → 6절.

### 1-3. 누가 무엇을 정하나 — 결정 주체 셋


| 무엇 | 정하는 주체 |
|---|---|
| 섹션 **큰 덩어리 순서** | **목적 분류** (여는 → 도입 → ★ → 보조 → 닫는) |
| **특징적 배치** | **목적 분류** — P5의 CTA 2회 · P6의 프로필 최상단 · P2의 위치 필수 / P1의 위치·폼 배제 |
| **★의 자리** (몇 번째 · 몇 회 · 반복인지) | **목적 분류** |
| **★의 정체·정보 구조** | **주제** — 식순인지 회차 버튼인지 링크 목록인지 |
| **원페이지 / 멀티페이지 선택** | **유저** — AI 추천(목적 분류 선호 + 자료량) → 유저 확인 |
| **멀티일 때 분할 방식** (몇 장 · 무엇을 어디로) | **목적 분류** |
| 반복 단위의 **정보 구조** | **주제** |
| **보조 섹션 후보 목록** | **주제** — 그 주제에 성립 안 하는 건 후보에서 뺀다(`6-①` 공지에 `[구매]` ❌) |
| **보조 섹션 내용** | **주제** — 같은 `[안내 사항]`이 `1-①`=좌석·주차·복장 / `4-①`=배송·교환·환불 / `5-⑤`=규정·저작권 |
| **보조 섹션끼리의 세부 순서** | **주제** |
| **톤(보이스)** | 목적 분류(기본값) → **주제가 덮어쓰기**(`1-③` 개업·오픈은 P2인데 말투는 「알리고」) |
| **기능 유무**(참석·예약·결제) | **유저** — 목적 문장(3-3 아래 콜아웃) |
| 그 외 보조 섹션 유무 | **유저** — 플레이스홀더 채우기/지우기 |
| **콘텐츠** | **유저** |
| **색·폰트(무드)** | AI 추천 → 유저 확인 |

> 🔴 **자주 틀리는 네 가지**
> ① *"순서는 전부 목적 분류가 정한다"* ❌ — **보조 섹션끼리의 세부 순서는 주제**가 정한다. 같은 P2인데 `1-①`는 `폼 → 안내 사항`, `1-②`는 `안내 사항 → 폼`이다.
> ② *"기능은 주제가 정한다"* ❌ — 주제는 **「붙을 수 있다」까지만**. 실제 유무는 **유저**가 목적 문장에서 고른다.
> ③ *"목적 분류가 ★를 정한다"* ❌ — 목적 분류는 **★의 자리**만 정한다. **정체·정보 구조는 주제**. (3-1 맨 아래 ★ 표기 주석)
> ④ *"목적 분류가 멀티페이지를 정한다"* ❌ — **원/멀티 선택은 유저**다. 목적 분류는 **멀티를 골랐을 때의 분할 방식**만 정한다.

## 2. 공통 골격 — 주제 25개 전부 동일


```
┌ 여는 부분 ────────────────────────────────
│ [헤더]      선택 — 로고·발행처
│ [히어로]     필수 ★ — 페이지 첫 콘텐츠 섹션. 예외 없음
├ 본체 ─────────────────────────────────────
│ [도입]      선택 — 소개·스토리 (아래 규칙)
│ [★ 결정 섹션] 필수 ★ — 그 주제의 정체 (5절)
│ [보조 섹션]  0~n — 위치 안내 · 자료 · 안내 사항 ·
│                  프로모션 · 폼 · 핵심 정보 · 나열 …
├ 닫는 부분 ────────────────────────────────
│ [문의]      사실상 필수
│ [푸터]      선택 — 담을 게 있을 때만
└───────────────────────────────────────────

  ★ 진짜 고정된 건 둘뿐 — 「히어로」와 「★결정 섹션」.
    나머지는 전부 선택·조건부다.
```

### 2-1. 골격에 걸린 공통 규칙 (여기 한 곳에만 적는다)

| 규칙 | 내용 |
|---|---|
| 🥇 **첫 섹션 = 히어로** | 어떤 주제가든 **임팩트 있는 히어로로 연다.** 작은 소개·프로필 카드로 시작 ❌. 인물형(2번 대분류)은 **프로필을 히어로 자리로 끌어올려** 겸한다 |
| 🧢 **헤더** | 3안 중 **1안 이상 포함 · 3안 전부 ❌**(유무가 차별화 레버) · 페이지와 반드시 구분(면 또는 하단선) · 로고 헤더를 넣은 안은 **히어로에서 로고 반복 ❌** |
| 📮 **문의** | **3안 모두 다른 섹션** — 버튼만 있어 복붙되기 제일 쉬운 섹션. 채움/틴트/Outlined · 세로/가로 2단을 안마다 다르게 |
| 🦶 **푸터 = 선택** | **필수가 아니다** (2026-09-04 이선호). 푸터는 **담을 게 있을 때만** 둔다 — 브랜드 로고 · SNS 채널 · 발행처 · 사업자 정보. <br>❌ **단발성 페이지엔 두지 않는다** — `5-①` 설문 접수, `6-①` 일회성 공지처럼 **한 번 알리고 끝나는 페이지**는 브랜드·SNS를 늘어놓을 이유가 없다. 페이지는 **문의(연락처)로 끝난다**. <br>❌ 넣을 게 없는데 자리를 채우려고 빈 푸터를 만들지 말 것 |
| 🖼 **이미지 위 텍스트 ❌** | 레시피의 `[히어로: 화보 + 제목]`은 **이미지 위에 글을 얹으라는 뜻이 아니다.** 이미지 카드 + 별도 텍스트 카드 스택으로 |
| 🧱 **평탄화** | CdBd는 평면 카드 스택 — 섹션은 개념이지 컨테이너가 아니다. 여러 카드를 한 래퍼로 묶지 말 것 |
| 📏 **섹션 간 여백** | 각 섹션 **마지막 카드의 하단 여백 = 36** |
| 🏷 **섹션 타이틀** | 화면에 보이는 제목은 **고객 친화 국문**. 내부용어·업계용어 ❌ |

> 나머지 조립·통일·위계 규칙 = [[4-5. 섹션 라이브러리]] 「🧷 페이지 조립 규칙」 (통일 8항목 · 타이틀 팔레트 8종 · 차별화 레버).

> 🖼 **「이건 이미지로 둘 수밖에 없다」고 판단하기 전에** — 실측 **225장** 판정 결과 **약 79%가 카드로 100% 되는데 이미지로 구워져** 있었다(최다 = pill 배지 · 런별 스타일 본문 · 라벨↔값 표 행 · 배경 위 카피). **정말 CdBd에 기능이 없는 것은 14%뿐**이다(표 세로 격자선 · 임의 좌표 앵커 · 방향성 스크림 · 부분 라운드 · 자간 · 텍스트 외곽선/그라데이션/회전 · 양쪽정렬 · 2열 카드 컬럼별 배경).


### 2-2. 도입 섹션은 언제 넣나

> 🔑 **판정 한 줄** — **★결정 섹션만 봐서 무슨 페이지인지 모르면 넣는다.** 알 수 있으면 뺀다.

식순만 덜렁 보여주면 무슨 행사인지 모른다 → **도입 필요**. 링크 목록은 위에 프로필이 있으니 그것만으로 안다 → **도입 불필요**.

> ⚠️ **도입은 「히어로에 흡수」되지 않는다** — 히어로와 별개인 **독립 선택 섹션**이다. 넣을지 말지만 위 한 줄로 판정한다.

#### 넣지 않는 경우 3가지

| 경우 | 왜 | 해당 주제 |
|---|---|---|
| **① ★결정 섹션이 곧 내용이다** | 공지 본문·기사 자체가 읽을 것 — 앞에 설명을 또 붙이면 중복 | `6-①` `6-②` `6-④` |
| **② 전환이 목적이다** (P5) | 도입이 CTA를 아래로 밀어낸다. **스토리는 결정 섹션 뒤로** 보낸다 | `4-④` `4-⑥` |
| **③ 위에서 이미 알 수 있다 · 도입할 게 없다** | 링크 허브는 프로필만으로 "누구인지"가 끝난다. 자리를 채우려고 빈 소개문을 만들지 말 것 | `2-①` |

→ **도입 없는 주제 6개**: `2-①` `4-④` `4-⑥` `6-①` `6-②` `6-④`

#### 소개 / 스토리 — 무엇으로 쓰나

| | 무엇 | 길이 | 언제 |
|---|---|---|---|
| **소개** | **사실** — 누구인지 · 무엇인지 | 1~3줄 | 기본값. 행사·신청·명함 계열 전부 |
| **스토리** | **서사** — 왜 · 어떻게 | 문단 | **브랜드형**(4번 대분류 · 3-①) · 취지를 세워야 하는 것(5-② 모집 · 5-⑥ 후원) |

> 🛍 **브랜드형 고정 순서** — `히어로 → 브랜드 스토리 → 제품`. 제품·가격을 나열하기 전에 *브랜드가 누구이고 왜 이 컬렉션인지*를 먼저 짧게 세운다. *(4-④ 판매만 예외 — 전환 최우선이라 스토리가 뒤로.)*

#### ⚠️ 도입이 길어지면 도입이 아니다

도입은 **2~3줄**이다. 문단이 여러 개로 늘면 그건 **본체 섹션**이므로 **결정 섹션 뒤로** 옮긴다. 도입 자리에 긴 글이 오면 스크롤 절반을 먹고 ★결정 섹션이 화면 밖으로 밀린다.

#### ℹ️ 예외 — 도입 자리의 스토리가 ★결정 섹션인 주제

`3-①` 소개 홈 · `5-⑥` 후원·기부 는 **「우리가 누구인가」/「왜 이 후원인가」 자체가 그 페이지의 정체**다. 이 둘은 도입이 아니라 **결정 섹션**이므로 위 규칙(짧게·뺄 수 있음)을 적용하지 않는다.

### 2-3. 빈 자리 처리 — 유저가 안 채운 슬롯

> 🔑 **AI가 채운 내용은 플레이스홀더**라 유저가 직접 안 채우면 **에디터로 넘어가며 삭제**된다(이선호 확인). 그래서 *가짜 가격이 발행될* 위험은 없다.
> 🔴 **대신 남는 문제 = 「껍데기」** — 지워진 자리에 **제목만 덩그러니 남거나 섹션이 텅 빈다.** 레시피는 **지워진 뒤의 모습까지** 정의해야 한다.

| 무엇이 비었나 | 처리 | 예 |
|---|---|---|
| **값만 빔** (가격·요금·기간) | 🔁 **안전한 대체 문구로 바꾼다** — 빈칸으로 두지 않는다 | `12,000원` 삭제 → **「가격 문의」 + 문의 버튼** · `2026.03.01~` 삭제 → **「일정 문의」** |
| **반복 항목이 전부 빔** (메뉴 0개·상품 0개) | 🗑 **섹션째 제거** — 제목만 남는 게 최악 | 「메뉴」 타이틀 + 빈 공간 ❌ |
| **보조 섹션이 빔** (위치·자료·안내 사항) | 🗑 **섹션째 제거** (원래 선택 섹션) | — |
| **★ 결정 섹션이 빔** | 🚫 **제거 불가** — 그 주제의 정체가 사라진다 | → ③ 추가 정보에서 **★를 채우는 문항은 다시 묻는다** |
| **히어로가 빔** | 🚫 **제거 불가** — 텍스트만이라도 남긴다 | 이미지 없으면 **텍스트 히어로**로 |

- 🆕 **「아직 안 채움」과 「원래 없음」을 구분한다** — 지금은 둘 다 「빈칸」이라 껍데기가 생긴다. ③ 추가 정보의 **「이건 없어요」 버튼**을 누르면 **원래 없음** → 섹션째 제외, 그냥 넘어가면 **아직 안 채움** → 발행 전 경고. ([[4-2. AI 유저 플로우]] ③)
- ⚠️ **섹션을 빼면 위아래 여백이 겹친다** — 앞 섹션 마지막 카드 하단 36이 살아 있는지 확인(카드 간 통일 8항목 ③).

## 3. 목적 분류 6개 — 본체 순서 규칙


**목적 분류 6개에는 각각 「용건 이름」이 붙는다** — P1 알림 · P2 초대 · P3 접수 · P4 진열 · P5 권유 · P6 소개.

### 3-1. 용건 이름 — 「초대」라는 말을 모든 주제에 쓰면 안 된다

> 🎚 **이건 「톤」이 아니다** — 정하는 건 **첫 문장 동사 · 버튼 동사 · 페이지를 부르는 이름** 셋뿐이다.
> **어떤 목소리로 쓰는가**(격식 · 따뜻함 · 에너지)는 **[[MD-08-3. 시안: 텍스트 구성]]의 보이스톤 3손잡이**가 정하고, 근거는 **무드와 타겟**이다. 같은 「접수」라도 기업 채용과 동네 공방은 딴 페이지처럼 읽혀야 한다.

> 🔴 **폐업·이전 안내 같은 무거운 소식은 「초대」가 아니다.** AI가 붙이는 이름도, 페이지 문구도 달라야 한다.

**페이지가 독자에게 요구하는 행동**으로 갈린다. 주제 분류(25) 위에 얹는 **「톤·이름」 층**이다.

| 갈래 | 한 줄 | 목적 분류 | 대표 |
|---|---|---|---|
| **🎉 초대 — "와주세요"** | 오라고 부른다 | **P2 초대형** | 개업식 · 창립기념식 · 세미나 · 송년회 · 시상식 |
| **📢 알림 — "알아두세요"** | 사실을 전한다 (참석 요청 아님) | **P1 알림형** | 공지 · 감사장 · 이전/폐업 안내 · 연하장 · 휴관 안내 |
| **📝 접수 — "알려주세요"** | 받는 게 목적 | **P3 접수형** | 클래스 예약 · 수강 신청 · 공모전 · 참석 조사 |
| **📚 진열 — "골라 보세요"** | 대상을 펼쳐 보여준다 | **P4 진열형** | 메뉴·가격 · 상품 상세 · 룩북 · 카탈로그 · 매거진 · 도록 |
| **🛍 권유 — "지금 하세요"** | 기한·이득이 먼저 온다 | **P5 전환형** | 판매·주문 · 출시·사전예약 · 프로모션 |
| **🙋 소개 — "이런 곳입니다"** | 이력·정체가 내용 | **P6 인물형** | 프로필 · 명함 · 포트폴리오 · 이력서 |

> 📚 **업계에 이미 있는 축** — 일심초대장은 제품을 `초대장 5종 / 안내장 3종(통합·공지·감사)`로 나눠 판다.
> 🤖 **AI 문구**: 「이 내용에는 **폐업 안내**를 추천해요」 — 아무 데나 **「초대장」이라 부르지 말 것.**

#### 🕯 무거운 소식의 톤 규칙 (부정·무거운 소식)

> ⚠️ **알림 전용이 아니다** — 모집 취소·행사 취소처럼 **다른 용건에서도** 생긴다. 손잡이 값(에너지 약·차분·격식 ↑)과 함께 쓰는 풀버전 = [[MD-08-3. 시안: 텍스트 구성]].

| 항목 | 규칙 |
|---|---|
| **문구** | *"초대합니다"·"모십니다"* ❌ → *"알려드립니다"* · 축하 표현 ❌ |
| **색** | 밝은 채도·따뜻한 색 ❌ → **무채색·저채도** |
| **장식** | 이모지·꽃가루·애니메이션 ❌ |
| **버튼** | *"신청하기"·"참석하기"* ❌ → *"위치 보기"·"안내 보기"* |
| **공유 문구** | 카카오톡 썸네일 문구도 같은 톤 |

**해당**: 폐업·마지막 영업 · 매장 이전 · 휴관·중단 안내 · (확장 시) 리콜·사과문
**중간 톤**: 감사장 · 연하장 · 공지 — 조사는 아니지만 「초대」도 아님 → `6-①`

> 🧭 **원/멀티는 목적 분류가 정하지 않는다 (2026-09-04)** — **선택은 유저**다(보드 *"이 내용에는 [ ]를 추천해요"*). 목적 분류가 정하는 건 **멀티를 골랐을 때의 분할 방식**뿐.
> AI 추천의 근거는 **목적 분류의 선호 + 자료량**: `P1`·`P6`은 원페이지 선호(공지·링크 허브는 한 화면에서 끝나는 게 목적) · `P4`는 **아이템 수**에 따라(3개면 원 · 30개면 멀티) · `P5`는 원페이지 쪽(전환은 스크롤 한 번이 유리).

> 🔴 **`★`에 구체 이름을 붙이지 않는다 (2026-09-04 정정)** — 예전엔 `★때·장소`·`★폼/예약`처럼 적었으나 **여러 주제에서 틀렸다**:
> `1-①`의 ★는 **식순**(때·장소 아님) · `5-②`의 ★는 **모집 요강**(폼 아님) · `4-⑥`의 ★는 **혜택+마감**(CTA 아님) · `6-④`의 ★는 **단계 나열**(본문 아님).
> **목적 분류는 ★의 「자리」만 정하고 「정체」는 주제가 정한다.** 그래서 흐름 줄엔 `★`만 쓴다.
> 단 **`반복`(P4) · `1차/재노출`(P5) · `히어로 겸`(P6)** 은 **목적 분류 정의 자체**라 남긴다 — 그건 위치·횟수·형태이지 내용이 아니다.

### 3-2. 약칭 사전 — 흐름 줄에 쓰인 말들

아래 흐름 줄의 약칭은 **13개 서랍 이름이 아니라 「역할 묶음」**이다. 실제로 무엇인지 여기 밝힌다.

| 약칭 | 나오는 곳 | 실제 서랍 |
|---|---|---|
| **도입** | 전 목적 분류 | `[소개]` 또는 `[스토리]` (2절 골격) |
| **보조** | 전 목적 분류 | 보조 섹션 (4절) |
| **본문** | P1 | `[스토리]` — 글 본문 |
| **부가** | P1 | `[핵심 정보]` 관련 일시 + `[안내 사항]` |
| **때·장소** | P2 | `[핵심 정보]` |
| **유의** | P3 | `[안내 사항]` |
| **근거** | P5 | `[핵심 정보]` 가격 + `[프로모션]` 혜택 + `[자료]` 후기 |
| **상세** | P5 | `[자료]` 상세컷 + `[제품 설명]` + `[스토리]` |
| **실적·링크** | P6 | `[자료]` 또는 `[나열]` |

> 💡 **「근거」와 「상세」를 굳이 나눈 이유** — P4↔P5 차이를 설명하려면 필요하다.
> **근거 = "왜 사야 하나"**(싸다·혜택 있다·남들도 샀다) · **상세 = "무엇을 사는 건가"**(어떻게 생겼나·뭐가 들었나)
> **P5는 근거가 먼저**(살 이유를 던지고 더 알고 싶은 사람만 내려감) · **P4는 상세가 먼저**(제품을 보여주는 게 목적).
> **상세를 먼저 두면 그 순간 P4가 된다** — 즉 P4↔P5는 CTA 위치만이 아니라 **이 순서로도** 갈린다.

### 3-3. 한 주제가 여러 목적 분류를 쓴다 — 기본 + 조건부

> 🔴 **정정** — 처음엔 주제마다 목적 분류를 **하나씩 고정**해뒀다. 틀렸다.
> **기능이 붙거나 분량이 달라지면 배치가 바뀐다.** 전수 재점검 결과 **주제 25개 중 20개가 조건에 따라 목적 분류가 변한다** — 1:1 고정은 5개뿐이다.

#### 섞임 규칙 3 — 「+목적 분류」이 실제로 뜻하는 것

| 표기 | 조건 | 배치에 생기는 변화 |
|---|---|---|
| **＋P3** | 받는 기능이 붙는다 (참석·신청·예약·문의) | ★결정 섹션 **뒤에** `[안내 사항] 마감일·수집 항목` + `[폼]`/`[예약]` 삽입 · **문의 CTA가 "회신하기"·"신청하기"로** 바뀜 |
| **＋P4** | 아이템이 **여러 개**가 된다 | ★가 **반복 단위**가 되고, **앞에 `[스토리]`**가 붙어 묶음을 세운다 |
| **＋P5** | 결제·전환이 목적에 들어온다 | **구매 CTA를 상단에도** 추가(상하 2회) · **`[스토리]`를 뒤로** 민다 |
| **→P1** | 내용이 짧아지고 받을 것도 없다 | 폼·위치·반복이 전부 빠지고 **본문 하나로** 줄어든다 (**대체**이지 추가가 아님) |

> 🔑 **＋는 「추가」, →는 「대체」다.** `P2＋P3`는 초대형 골격에 폼이 끼는 것이고, `P5→P1`은 전환형이 아예 알림형으로 바뀌는 것.

### 3-4. 목적 분류별 본체 순서


#### P1 알림형 — 읽고 끝
> 말투 📢 **알림** "알아두세요"
```
히어로 → [★] → 부가 안내 → 문의(짧게)
```
- **가장 짧다** (5~7섹션) · **위치 ❌ · 폼 ❌**
- 긴급 상황이면 **로고·이미지·SNS를 전부 생략해도 성립**해야 한다
- ▸ **멀티가 되면 4P 이상** — P1 표지＋목차 / P2~ 대상별 상세(건수만큼 반복) / 마지막 공통 안내·문의. **대상 1건짜리 알림은 멀티가 안 된다**(4장이 안 나옴 → 원페이지)

#### P2 초대형 — 오게 함
> 말투 🎉 **초대** "와주세요"
> 🏷 **「안내형」 → 「초대형」 개명** (2026-09-04 이선호) — 이 목적 분류의 정의는 *「오라고 부른다」*이고, **「안내」는 6번 대분류(읽고 끝)와 헷갈린다.**
> ⚠️ `1-③ 개업·오픈`도 P2지만 화면 문구는 **「초대」가 아니라 「알리고」**다(오라고 부르지만 격식 있는 초청은 아님). 목적 분류 이름은 **내부 이름**이라 유저에게 노출되지 않으므로 충돌이 아니다([[4-3. 목적·주제별 분류]] 1-1 · 대분류 이름과 같은 논리).
```
히어로 → 도입(인사말·소개) → [★] → 보조 → 위치 안내 → 문의
```
- **위치 안내 필수** (「가야 할 곳」이 이 목적 분류의 정의)
- ▸ **멀티가 되면 4P** — P1 표지·초대의 말 / P2 프로그램·일정 / P3 안내 사항·준비물 / P4 회신·위치·문의. **4장을 못 채우면 원페이지**

#### P3 접수형 — 받는 게 목적
> 말투 📝 **접수** "알려주세요"
```
히어로 → 도입(짧게) → 보조(왜 신청하나 = 혜택·분야·조건) → [★] → 안내 사항(유의·마감) → 문의
```
- ⚠️ **폼이 화면 절반 안에** 들어와야 한다 — 설명이 길어져 폼이 바닥으로 밀리면 실패
- **문의는 폼과 별도로** 둔다(폼 거치지 않는 즉시 연결 = 전화·카톡)
- ▸ **멀티가 되면 4P** — P1 표지·왜 신청하나 / P2 모집 내용·조건 / P3 안내 사항·마감 / P4 폼·문의. **폼은 쪼개지 않는다** · **4장을 못 채우면 원페이지**

#### P4 진열형 — 여러 개 보여줌
```
히어로 → 스토리(브랜드·컨셉) → [★ 반복] → 보조 → 문의
```
- **아이템 반복이 본체의 8할** · 아이템 1개 = 독립 섹션 단위
- 브랜드형이면 **히어로 직후 스토리**를 먼저 세운다(왜 이 컬렉션인가)
- ▸ **멀티가 되면 4P 이상** — P1 표지＋목차 / P2~ 아이템 내지(**1건 = 1장** · 건수만큼 복제) / 마지막 마무리·문의. **아이템이 무거울수록 장이 늘어난다**(50종이면 50장이 정상)

**▸ P4 멀티는 두 모드로 갈린다** (백테스트 실측)

| 모드 | 판별 | 목차 |
|---|---|---|
| **넘겨보기형** | 챕터를 **순서대로** 읽음 (카탈로그·룩북·도록) | 🚫 **만들면 안 됨** — CdBd 뷰어가 하단 진행바＋썸네일 목차를 **직접 그린다** · 실측 핏플랍·수트서플라이 내비 카드 **0개** |
| **점프형** | **원하는 항목으로 건너뜀** (메뉴판·품목집·디렉토리·프로그램북) | ✅ 필요 — 빙그레 47카드·서초 88카드·양주 7카드를 **손으로 제작**했다 |

⚠️ **모드와 무관하게 드는 비용** = 페이지별 헤더·브랜드 반복(한섬 21카드 = 24.7%). *「넘겨보기형이면 멀티 뼈대 비용 0」은 틀렸다.*
⚠️ 서초는 목차를 **이미지로** 만들어 `link.href:""` = **클릭 안 되는 죽은 목차**가 됐다.

#### P5 전환형 — 사게 함
```
히어로 → [★ 1차] → 근거(핵심 정보·프로모션·리뷰) → 상세 → 안내 사항 → [★ 재노출]
```
- 🔑 **CTA가 최상단 + 최하단 두 번** — P4와의 유일한 결정적 차이
- 스토리는 **뒤로** (전환 최우선이라 P4와 반대)
- ▸ **멀티가 되면 4P** — P1 히어로·가격·구매 / P2 상세·스펙 / P3 근거(후기·프로모션) / P4 안내 사항·구매 재노출. **구매는 쪼개지 않는다** · **4장을 못 채우면 원페이지**

#### P6 인물형 — 사람이 주인공
```
[★ = 히어로 겸] → 소개 → [보조 ★] → 보조 → 문의(연락처 저장)
```
- **프로필이 최상단** — 갤러리·이력·연락처를 프로필보다 위에 ❌
- ⚠️ **예외 = `2-② 영업용 명함`** — 연락처(문의)를 **프로필 바로 다음**으로 올린다(2026-09-15 이선호). 명함은 연락이 곧 목적이라 맨 끝에 두면 늦다
- ▸ **멀티가 되면 4P** — P1 프로필＋주요 채널 / P2 이력·경력 / P3 작업·자료 / P4 연락처·문의. **4장을 못 채우면 원페이지**(인물형은 대개 원페이지)

## 4. 옵션 섹션 사전 — 어느 주제에나 붙는다


**유형을 가르지 않는 섹션.** 결정 섹션과 헷갈리지 말 것. 골격의 **[보조 섹션]** 자리에 들어간다.

`위치 안내 · 갤러리(자료) · 핵심 정보 · 나열 · 안내 사항 · 프로모션 · 폼 · 계좌 · FAQ · 첨부 문서 · 개인화`

> 📍 **위치 안내도 보조 섹션이다** (2026-09-04 이선호) — 골격의 고정 자리가 아니라 **찾아올 곳이 있을 때만 붙는 옵션**이다. 다만 **P2 초대형에서는 사실상 필수** — 「가야 할 곳」이 그 목적 분류의 정의이므로. 나머지 목적 분류에선 붙기도 하고 안 붙기도 한다.

> 📍 **「장소」와 「위치 안내」는 따로 받는다 (2026-09-15 이선호 확정)** — `[핵심 정보]`의 **장소 = 건물·공간 이름**(단순 텍스트 한 줄), `[위치 안내]`의 **주소 = 검색으로 고른 값**(그래야 지도·길찾기가 열린다) ＋ **상세주소**(층·호수 · 검색에 안 잡히므로 텍스트로 받아 지도 아래 주소 옆에 붙인다). **둘 다 들어가도 중복 아님** — 장소는 *「어디서 하나」*, 위치 안내는 *「어떻게 가나」*를 답한다. 입력 칸 구성 = [[4-7. 입력 단계 안내 문구]].

> 🔑 **개인화(수신자마다 다른 링크)는 유형이 아니라 「전달 방식」** — 주제 25개 어디에나 얹힌다. 구버전이 이걸 독립 세부(A③)로 뒀던 게 분류 오류였다.

### 4-5. 가격은 3층까지 온다 — 정상가 → 판매가 (채널가)

> 실측: 유료 고객 12건 중 **가격이 한 값이 아니었던 경우가 다수**(정상가/행사가 병기 · 온라인가와 매장가가 다름 · 쿠폰 적용가 별도). 입력 화면에서 `가격`을 **한 칸**으로만 받으면 이걸 못 받는다.

**받는 형태** — `정상가`(선택) · `판매가`(필수) · `채널·조건 단서`(선택 · 예 *온라인 전용* · *쿠폰 적용가*)

**표기 스펙 (조립 시 이대로)** — 섹션 = `18. 가격 3층` [Figma 6549:70](https://www.figma.com/design/24O01lprp5i2ufl7CbZXXx/CdBd-%ED%85%9C%ED%94%8C%EB%A6%BF--%EC%84%B9%EC%85%98-%ED%94%84%EB%A6%AC%EC%85%8B?node-id=6549-70)

| 층 | 크기 | 색 | 웨이트 |
|---|--:|---|---|
| 정상가 | 15 | `{텍스트색}` × **55%** | Regular |
| **→ 판매가** | **22** | **`{버튼색}`** | **Bold** |
| (채널·조건) | 14 | `{텍스트색}` × **70%** | Regular |

- 🚫 **취소선 ❌** — CdBd에 취소선 옵션이 없다. **크기·색·투명도만으로** 낮춘다(정상가 55%가 그 역할).
- 🚫 **빨강 ❌** — 할인 강조색은 무드 안의 액센트(`{버튼색}`). 화보·여리여리 무드에 빨강은 지양 규칙 위반.

- ⚠️ **정상가가 없으면 그 런을 통째로 지운다** — 빈 줄·`—` 잔존 ❌(CLAUDE.md ✂️ 규칙과 동일).

## 5. 주제별 레시피 카드 25

> 🧪 **같은 목적 분류 안에서 주제가 갈리는 축 = 「정보 구조」 하나로 환원된다** (2026-09-04)
> - **기능은 별도 축이 아니다** — 기능(예약·폼·구매)은 결국 **카드/섹션**이라 붙으면 정보 구조가 따라 바뀐다. **기능만 다르고 정보 구조는 같은 짝은 주제 25개에 하나도 없다.** 있으면 그건 같은 주제의 **변주**로 처리했다(`1-①` ± 참석 조사).
> - **톤은 단독으로 주제를 가르지 않는다** — `1-③` 개업이 `1-①` 행사 초대장과 갈리는 데엔 말투도 있지만, **정보 구조가 이미 다르다**(오픈 기간 vs 식순 2열). 톤은 항상 정보 구조 차이와 **함께** 온다.
> - **✅ 실무 규칙 한 줄** — **★결정 섹션의 정보 구조만 보면 된다.**
>   | 정보 구조가 | 처리 |
>   |---|---|
>   | **다르다** | **다른 주제** (`4-①` 제품1개=섹션여러개 ↔ `4-③` 품목1개=카드1장) |
>   | **같은데 기능이 붙는다** | **같은 주제의 변주** (`1-①` ± 참석 조사) |
>   | **같은데 항목만 다르다** | **조건부 필드** (`5-②` 채용/수강/가맹) |
>
> 표기 = 섹션 **목적**(괄호 = 담을 내용). `★` = 결정 섹션. **골격(헤더·히어로·문의·푸터)은 2절 참조** — 카드에는 그 주제에서 특별한 경우만 적는다.
>
> 🚨 **★는 「정보 구조」까지 읽어야 한다 (2026-09-04 이선호 지적)** — ★를 `이미지 + 캡션 나열`처럼 **한 줄 라벨로만 보면 다른 주제가 같아 보인다.** 실제로는 정보 구조가 전부 다르다:
> | 라벨이 비슷해 보이는 짝 | 실제 정보 구조 |
> |---|---|
> | `5-①` ↔ `5-④` 둘 다 「폼」 | **집계형**(선택지 다수·명단 집계) ↔ **서술형**(자유 서술·1건씩 회신) |
> | `4-①` ↔ `4-③` 둘 다 「품목 반복」 | **제품 1개 = 섹션 여러 개** ↔ **제품 1개 = 카드 1장** |
> | `6-②` ↔ `6-③` ↔ `2-③` 셋 다 「나열」 | 텍스트 카드 ↔ 이미지+캡션 4항목(2단 양끝정렬) ↔ 이미지 갤러리+설명 |
> | `1-①` ↔ `1-②` 둘 다 「시간+제목 나열」 | 2열(시간·순서) ↔ **연사 카드가 따로 서고** 세션이 3열 |
> → 그래서 각 카드에 **`┗ 정보 구조`** 줄을 붙였다. **주제를 합칠지 판단할 때 라벨이 아니라 이 줄을 볼 것.**

　　┗ **정보 구조** `그룹 제목 + 전폭 버튼 세로 반복` × **최대 3그룹**

> 🎖 **연락처 저장(vCard) = 주 CTA** — 전화·이메일과 같은 무게로 두지 말 것(위계 = 채움 > 틴트 > Outlined).

#### 2-④ 이력서·경력 🆕
**P6 인물형** 🔒고정 · ★ **시간순 경력 목록** (텍스트 중심)

### 4. 상품·홍보 (6)

> 🛍 **브랜드형 공통** — 순서는 **히어로 → 브랜드 스토리 → 제품**. 제품·가격을 바로 나열하기 전에 *브랜드가 누구이고 왜 이 컬렉션인지*를 먼저 짧게 세운다. *(전환 최우선인 4-④는 예외 — 구매가 위, 스토리는 뒤.)*

#### 4-① 상품 상세
**P4 진열형** ＋P5(구매 CTA 상하 반복) · ★ **제품별 상세 섹션 반복**
　　┗ **정보 구조** **제품 1개 = 섹션 여러 개** — 갤러리→이름·가격→설명→스펙→실측→구매 세로 스택
```
[헤더] 로고
[히어로] 브랜드 첫인상 + 컬렉션 제목
[스토리] 브랜드 설명
[★제품 섹션 반복] ─ 갤러리(여러 컷) → 이름·가격 → 설명 → 스펙/소재 → 실측 → 구매
[프로모션] 쿠폰 · 할인 (선택)
[안내 사항] 배송 · 교환 · 환불
[위치 안내] · [문의]
```
> 🛍 **"상세 정보가 있어야 상세 페이지"** — 제품마다 ①**여러 컷**(모델·정면·측면·내부·디테일) ②**스펙 상세** 필수. **2단 그리드 상품 카드로 압축 ❌** → 제품별 **전폭 단일 컬럼**.
> 🔁 **상세(스펙·실측·소재)는 「각 제품 바로 아래」** — 페이지 뒤에 모으지 말 것(어느 제품 건지 끊긴다).
> 🚫 **상세를 품은 제품 섹션을 쓰면 별도 상세 섹션 ❌**(중복).
> 🎠 **갤러리 표현 = 3안 차별화 레버** — 세로 나열 2 + 캐러셀 1. ⚠️ **제품당 이미지 4장 이상일 때만 캐러셀.**
> 💲 **텍스트 위계** — 상품명 18 Bold {텍스트색} / **가격 {버튼색} 강조** / 설명 {텍스트색}×70% / 스펙 라벨 100%·값 70%.

#### 4-② 룩북·컬렉션
**P4 진열형** ＋P5(구매 링크) · ★ **룩(look)별 화보 섹션 반복**
　　┗ **정보 구조** **룩 1개 = 독립 섹션** — `LOOK N` 타이틀 + 화보 + 설명 1줄

[★룩 섹션 반복] ─ 타이틀 「LOOK N」 → 화보·누끼 이미지 → 룩 설명 1줄

[문의]

> 👗 **룩 하나 = 독립 섹션 · 타이틀 = `LOOK 1`·`LOOK 2`…**(영문 넘버형). 한 덩어리로 뭉치지 말 것.
> 🚫 **룩북엔 상세 정보(소재·치수·실측·스펙) ❌** — 그건 4-① 전용. 룩북은 **화보 + 컬렉션 설명**만.
> 🎠 갤러리 = 3안 중 1안 이상 캐러셀 (룩당 이미지 4장 이상일 때만).

#### 4-③ 카탈로그 🆕
**P4 진열형** ＋P5(주문) · ★ **여러 품목 목록** (얕게 · 많이)
　　┗ **정보 구조** **품목 1개 = 카드 1장** — 이름 + 대표컷 + 1~2줄 (스펙 ❌)

[헤더] 로고
[히어로] 브랜드 / 카탈로그 제목
[스토리] 브랜드 소개 (짧게)
[나열] 분류 · 인덱스 (품목이 많으면)
[★구매] 품목 카드 반복 — 이름 + 대표컷 + 핵심 스펙 1~2줄

**P5 전환형** ＋P4(상품 여러 개) · ★ **구매 CTA** (상단 + 하단 반복)
