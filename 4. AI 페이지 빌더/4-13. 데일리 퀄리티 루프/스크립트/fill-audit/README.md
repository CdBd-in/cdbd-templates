## 쓰는 법

**S2를 돌리면 자동으로 붙는다** — `s2js.sh`가 단계마다 `snap.js`로 떠서 `<ID>-fill.jsonl`에 쌓고,
마지막 확인에서 `audit_fill.py`를 돌려 `<ID>-fill-audit.md`를 남긴다.

손으로 돌릴 때:
```bash
# 1) 지금 열린 내용 채우기 화면 한 장 뜨기 (읽기만 한다)
browse js "$(cat snap.js)" >> /tmp/case-fill.jsonl
# 2) 채점
python3 audit_fill.py /tmp/case-fill.jsonl
```

## 설계 메모

- **읽기 전용** — `snap.js`는 DOM을 바꾸지 않는다. 유저가 빌더를 쓰는 중에도 안전하지만,
  **같은 계정 동시 사용은 여전히 금지**(4-13 §0 · 409 충돌).
- **미리보기 패널 찾기** = 화면 오른쪽 절반의 「세로로 긴 가장 큰 박스」(기하 판정).
  못 찾으면 `previewFound:false` → 채점기가 **「미측정」으로 보고**한다(조용한 통과 방지).
- **흐린 견본 vs 진한 본문** = `opacity < 0.75` 또는 밝은 회색 계열이면 견본으로 본다.
- **미리보기 줄 쪼개짐 대응** — 한 칸의 글이 제목＋설명 두 줄로 렌더되면 완전 일치가 안 되므로
  **6자 이상 조각이 칸 글에 포함**되는지도 본다.
- **반복 묶음 판정은 「X 추가」 버튼을 쓴다** — `snap.js`가 `addButtons`(이름·y)를 함께 떠내므로, 같은 라벨이 N개여도 **그 라벨의 `X 추가` 버튼이 있으면 정상 반복**으로 통과시킨다(S5-02 오탐 제거 · 명사 목록을 늘려 가는 방식보다 정확).
- **반복 항목 오탐 방지** — 라벨 배열이 주기 ≥2로 되풀이되면(`[버튼 문구, 연락처] × N`) 정상으로 통과.
  주기 1(같은 라벨만 연속 = `본문 텍스트 × 2`)은 **섹션 원본 통합 대상 신호**로 남긴다.

## ⏳ 실측 검증 남음 (2026-10-27 작성 시점)

픽스처(오늘 지적 4화면 재현)로는 **결함 11건 전수 적발 · 정상 케이스 오탐 0** 확인.
다만 아래는 **실제 빌더 화면에서 한 번 돌려 봐야** 확정된다 — 빌더가 비는 때 10분:

1. **미리보기 패널 기하 판정**이 실제 DOM에서 맞는지(`previewFound`)
2. **필수/선택 표기**를 덤프에 못 담고 있다 → S5-29는 지금 「전부 빈 화면」만 잡는다.
   실제 화면에 필수 표식이 있으면 `snap.js`에 추가해 정밀도를 올린다.
3. **반복 묶음 UI**(항목 「추가하기」 버튼) 셀렉터 — 지금은 라벨 주기성으로 추정 중
